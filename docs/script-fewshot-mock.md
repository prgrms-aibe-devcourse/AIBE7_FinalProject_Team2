# 사건 1 대본 퓨샷 목업 (원본 ↔ 확장)

> FE-60. `frontend/src/content/case-1/script.json`의 확장 필드(`source` · `slots`)를 풀어 쓴 목업이다. 이 파일은 비교용 미리보기이며 코드에서 읽지 않는다. 대본을 바꾸면 다시 만든다.

## 확장한 구조

| 필드 | 위치 | 뜻 |
| --- | --- | --- |
| `source.type` | step | `fixed` 고정 대사 · `ai` 사건별 대사(사건 스크립트 생성 대상) · `api` 서버 값이 `{자리표시자}`로 들어가는 대사 |
| `source.api` · `source.fills` | `api` step | 값을 가져오는 API와, 자리표시자별 쓰는 응답 필드 |
| `source.basis` | `ai` step | 사건별 대사를 쓸 때 근거로 삼는 데이터(API 응답 · 대본의 `paper`) |
| `source.card` | step | 그 장면에 뜨는 카드(보드)의 출처. `api`면 `api` · `fields`, `ai`면 대본 안 `ref` |
| `slots` | 막(act) · step | 캐릭터 자리의 슬롯 값(무대 폭 60등분, 가운데 30). 막에는 기본 자리, step에는 자리가 바뀌는 곳만 적는다. **참고용이며 화면은 `spots`로 그린다** |

퓨샷에서는 `api` 출처의 `{자리표시자}`를 `(API 이름의 필드 데이터)`로 풀어 쓴다. 예: `{summary}입니다.` → `(API 10 AI 판결의 summary 데이터)입니다.`

### 구조 비교 예 (6막 비교 2번)

원본

```json
{
  "focus": "verdicts",
  "say": "naero",
  "look": {
    "naero": "read-thinking",
    "nambul": "idle-neutral"
  },
  "text": "{vsCourt}"
}
```

확장

```json
{
  "focus": "verdicts",
  "say": "naero",
  "look": {
    "naero": "read-thinking",
    "nambul": "idle-neutral"
  },
  "text": "{vsCourt}",
  "source": {
    "type": "api",
    "api": "API 14 · GET /cases/{caseId}/experience/comparison",
    "fills": {
      "vsCourt": [
        "judgments.USER",
        "judgments.COURT"
      ]
    }
  }
}
```

### 슬롯 값 기준 (표의 ✱ = 그 장면에서 자리가 바뀜)

- 슬롯 = 무대 폭 % × 0.6. 법정(역할 의상) 기본 자리 왼쪽 16% → 10, 오른쪽 84% → 50. 법정(평상복) 14% / 86% → 8 / 52. 신문 지면 8% / 92% → 5 / 55. 피고인석 `stand` = 가운데 → 30.
- 카드 · 보드가 뜨는 장면(10% / 90%)과 모바일(25% / 75%)은 화면이 자리를 따로 바꾼다. 위 값은 기본 화면 기준이다.
- 사건 1은 슬롯 · `row`를 화면에 쓰지 않는다. 앞뒤 줄은 모두 `front`다. 그대로 화면에 쓰면 카드 · 모바일 자리 보정이 사라져 FE-39에서 제외한 회귀 위험이 생긴다.
