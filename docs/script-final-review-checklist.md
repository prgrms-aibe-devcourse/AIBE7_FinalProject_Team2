# 대본 최종 검수 체크리스트

> 관리자가 생성된 사건 대본을 **공개 전에 승인할 때** 보는 목록이다. 1회 방식 등록(분류 → 대본 생성 → 적재(초안))은 중간에 멈추지 않으므로, 이 목록이 공개 전 마지막 안전장치다(`decisions/BE-125.md`, `decisions/BE-123.md`).
> 승인 흐름은 처음에 대본 전체를 통승인 · 통거절하고, 거절하면 블록(U0 ~ U4) 단위로 수정 · 재생성 · 승인한다(BE-126). 블록을 고치면 뒤에 딸린 블록은 "낡음" 표시가 붙으니 앞에서부터 고친다(`decisions/BE-129` 연동 표 참고).
> 실제 사건 내용은 이 문서에 적지 않는다.

## 1. `needsReview` 확인 (자동 표시)

- [ ] 검수 화면에 `needsReview` 표시가 있으면 해당 축 · 플래그를 하나씩 확인한다(BE-129 표시)
- [ ] 안내 대상 플래그(취약한 피해자 · 정신건강 · 자해 · 성범죄 · 가정폭력 · 혐오)는 **켜진 것이 맞는지**(잘못 켜지면 안내문이 잘못 뜬다) 판결문 요약과 대조한다
- [ ] 규칙(키워드)만 잡힌 플래그는 부정문 · 다른 뜻으로 오탐한 것이 아닌지 본다

## 2. 자동 표시가 놓치는 것 (사람이 본다)

`needsReview`는 모델 표가 갈릴 때만 켜진다. **모델이 일관되게 틀리거나 놓치면 표시가 없다.** 아래는 표시와 상관없이 직접 본다.

- [ ] **레드플래그 누락**: 판결문 · 사건 요약에 안내 대상 내용(자해 · 자살, 정신질환, 성범죄, 가정폭력, 미성년 · 장애 · 고령 피해자, 혐오)이 있는데 플래그가 꺼져 있지 않은지
- [ ] **분위기(톤) 오분류**: 사건의 무게와 대본 톤이 어긋나지 않는지(정신건강 · 자해 사건에 냉혹 · 계획 톤 금지, BE-123 후속)
- [ ] **쟁점 유형**: 신문 마지막 질문("공소사실 / 행위 사실을 인정합니까?")과 인정 여부가 사건과 맞는지
- [ ] **피해자 측 성향**(엄벌 · 합의 · 혼재 · 불명)이 실제 사정과 맞는지

## 3. 대본 본문

- [ ] 공개 범위: 대본이 단계별 공개 범위(S-03 개요 → S-04 이후 사실)를 지킨다. 구형 · 형량을 말하지 않는다(앵커링 방지)
- [ ] 사실을 주장으로 바꾸지 않았는지, 입력에 없는 숫자 · 감정 어휘가 없는지(자동 검수 BE-122가 못 잡는 맥락)
- [ ] 민감 플래그가 켜진 사건: 해당 가드대로 표현이 순화되었는지(구체적 방법 · 수단 묘사 없음)
- [ ] 캐릭터 말투 · 배역: 대사가 사건 배역(검사 · 변호인 이름)대로 쓰였는지, 배역 변경 시 U2 ~ U4를 다시 만들었는지

## 4. 연결된 데이터

- [ ] 사건 사진(주소 규칙 BE-141)이 사건과 맞고, 판결 없는 사진을 쓰지 않았는지
- [ ] `legal_case.cast_roles`와 대본 `cast`가 같은지(API 16 ↔ API 18)
- [ ] 판결(AI · 재판부) 값과 판단 요소가 사건과 맞는지

## 5. 승인

- [ ] 위 항목을 확인했고 문제가 없으면 **통승인**한다. 문제가 있으면 통거절하고 블록 단위로 고친다
- [ ] 공개한 뒤 고칠 일이 생기면 점검 상태로 체험을 잠그고 블록을 고쳐 재승인한다(BE-126). 큰 오류로 체험 기록을 초기화해야 하면 BE-144
