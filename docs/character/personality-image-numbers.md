> 성향 이미지는 `frontend/public/images/characters/personality/{이미지 번호}.webp`(`01.webp` ~ `32.webp`)로 둔다([캐릭터 에셋 아키텍처](character-asset-architecture.md) 6-4). 이미지 주소에 4글자 코드가 보이지 않게(성향 콘텐츠 6장 #8) 파일 이름은 번호로 한다.
> 이 표는 **이미지 번호 ↔ 유형 · 캐릭터** 연결과, 이미지를 만들 때 필요한 캐릭터 · 유형명 · 관용 지수 · 밈 장면을 함께 적는다. 유형 설명 · 밈 문구는 [성향 테스트 콘텐츠](../personality-test-content.md) 4장이 기준이다.
> 코드는 이 문서 · 내부 데이터에만 쓰고 화면에는 보이지 않는다.

## 번호 규칙

번호는 두 가지다. **유형 번호**(`01 ~ 16`)는 유형을 가리키고, **이미지 번호**(`01 ~ 32`)는 파일을 가리킨다.

- **유형 번호**: 성향 콘텐츠 4-2 유형 요약 표의 순서(관용 지수 오름차순, 같은 지수는 표 순서)로 매겼다(10/13). ESTJ = 01 … INFP = 16. 점수나 순위를 뜻하지 않는다.
- **이미지 번호**: 캐릭터별로 대역을 나눈다(10/14 결정).
  - **내로 `01 ~ 16`**, **남불 `17 ~ 32`**.
  - `이미지 번호 = 유형 번호 + 16 × (내로 0 · 남불 1)`. 거꾸로는 `유형 번호 = ((이미지 번호 − 1) mod 16) + 1`, 캐릭터는 번호가 16 이하면 내로 · 17 이상이면 남불.
  - 파일은 두 자리(`01.webp` ~ `32.webp`). 변형 접미사(`-2` 등)는 쓰지 않는다. 번호만으로 파일이 정해진다.
- **한 번 정한 이미지 번호는 바꾸거나 다시 쓰지 않는다**(`share_id`처럼). 이 이미지는 공유 링크 미리보기(OG)와 `personality_type.image_url`에도 쓰여서, 이름이 바뀌면 이미 공유된 링크가 깨지거나 캐시 때문에 다른 그림이 보인다. 4-2 표의 순서 · 관용 지수가 바뀌어도 번호는 그대로다.
- **유형이 새로 생기면** 다음 유형 번호(17 …)를 붙이되, 이미지 번호는 mod 16 규칙을 쓰지 않는다(`17 ~ 32`는 이미 남불이 쓴다). `33`부터 이 표에 따로 배정한다.
- **캐릭터 · 스킨 · 바리에이션이 늘면** 다음 대역(`33 ~ 48` …)을 같은 방식으로 붙인다. 유형마다 변형 수가 달라지면 mod 16 규칙을 버리고 **이 표의 대응을 기준으로** 한다.
- 원본 PNG(이미지 레포)의 이름은 `personality-{유형 번호}_{캐릭터}_{밈}.png`로 그대로 둔다. 웹 이미지 번호와는 위 표로 이어진다(예: `personality-02_nambul_….png` → `18.webp`).

## 화면에 보이는 이미지 (10/14 결정)

- **한 유형에 이미지 하나만 보여 준다.** 유형 → 이미지 번호를 돌려주는 함수 하나로 로직을 짜고, **지금은 기존에 정한 기본 캐릭터(내로 8 · 남불 8)를 하드코딩**한다(아래 번호표 "화면에 보이는 이미지").
- 나중에 사용자가 고른 캐릭터 · 무작위 같은 선택 방식이 생기면 이 함수 안만 바꾼다. 나머지 16장(기본이 아닌 캐릭터)은 만들어 두고 지금은 화면에서 쓰지 않는다.
- **OG 미리보기와 `personality_type.image_url`은 항상 유형별 "화면에 보이는 이미지"로 고정**한다. 공유 화면(`/test/types/{code}`)은 응답 없이 유형만 보여 주므로, 사용자별로 보이는 이미지가 달라져도 OG는 유형 하나로 정해져야 한다. `image_url`은 DB에 이미지 하나만 두므로 ERD는 바뀌지 않는다.
- 남은 일: OG용 가로형(약 1200 × 630) 이미지가 필요한지(지금 이미지는 4:5 투명 배경이라 미리보기에서 배경이 검게 나오거나 잘릴 수 있음), 유형별 메타태그를 Nginx · 서버 중 어디서 내려줄지는 7.6.8 이미지 공유 때 정한다.
