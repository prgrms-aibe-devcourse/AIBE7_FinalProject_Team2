## 1. 무엇이고 왜 있나

MVP는 AI 판결을 **오프라인에서 생성 · 검수한 결과를 DB에 적재**한다(REQ-046, [기술 스택](tech-stack.md) 6장). `tools/ai-judgment/`의 파이프라인이 판결문 한 건에서 적재 SQL까지를 자동으로 이어서 실행한다.

| 구분 | 내용 |
| --- | --- |
| 위치 | `tools/ai-judgment/` (서비스 코드 `backend/` · `frontend/`와 분리) |
| 언어 · 실행 | Python 3. 각 공급자의 HTTP API를 표준 라이브러리(`urllib`)로 직접 불러 LLM 호출에는 설치가 필요 없다(Claude 비식별화 경로만 `anthropic` 패키지). 판결문을 PDF로 넣을 때만 `pypdf` · `cryptography`가 필요하다 |
| 사람 검수 | 파이프라인 안에는 **없다.** 적재한 결과가 사용자에게 보이지 않게 넣고(`DRAFT` · 비공개 · `PENDING`), 관리자가 검수한 뒤 공개한다(후검수, BE-33 · FE-16 — 미구현) |
| 서비스 안 생성 파이프라인 | 확장 단계(REQ-040 ~ 045)에서 따로 만든다. 이 파이프라인과 별개다. **추가 고려 (COMMON-41)**: 신문 지면에 들어갈 내용 생성, 사건 스크립트 생성을 범위에 추가 검토한다. 사건 사진은 AI가 이미지를 직접 생성하지 않고 이미지 생성용 프롬프트만 만들어 제공하는 방식으로 검토한다. 아직 요구사항으로 확정하지 않았다 |

## 2. 전체 흐름

```
판결문 (PDF · txt, 1심 · 항소심)
  │
  ▼
① extract        비식별화 · 구조화              → 사건 입력(case.json) · 내부 파일(원본 정보 · 실제 판결 · 보고서)
  ▼
② court          재판부 판결(COURT) 초안        → court_draft.json (내부, 비공개 적재용)
  ▼
③ contamination  사전 학습 점검 (옵션, 기본 꺼짐) → 모델별 판정 CLEAN · SUSPECT · CONTAMINATED · INSUFFICIENT
  ▼
③-1 rag          참고 자료 RAG (옵션, 기본 꺼짐)  → 양형기준 버전 · 형량범위 · 양형인자 · 유사 판례 (references.json)
  ▼
④ generate       AI 판결 생성 · 검증            → 모델 × 회차별 기록
  ▼
⑤ select         적재할 회차 1건 선택           → 선택 결과
  ▼
⑥ load           적재 SQL 생성 · 로컬 DB 적재   → 사건(DRAFT) + COURT · AI 판결(비공개) SQL
  ▼
⑦ 관리자 후검수   (BE-33 · FE-16, 미구현)       → 공개
```

| # | 단계 | 입력 → 출력 | 모델 | 멈추는 경우 | Jira |
| --- | --- | --- | --- | --- | --- |
| ① | extract | 판결문 → 사건 입력 · 판단 요소 · 형벌 규칙 · 목록 카드 값 · 서비스 대상 판정 | Claude · Gemini · OpenAI (목록 가능) | 개인정보 잔존 · 실제 형량 누출 · 형식 오류 · 서비스 대상 아님 | BE-20, 35, 38, 45 |
| ② | court | 마스킹한 원문 → 재판부 판결 초안 (요약 · 이유 · 쉬운 설명 · 발췌 · 요소별 방향과 근거) | 위와 같음 (없으면 ①의 모델) | 원문 인용 불일치 · 주문 형량 불일치 · 개인정보 잔존 | BE-38, 45 |
| ③ | contamination | 사건 개요 · 죄명 → 모델이 사건을 아는지 판정 | 생성에 쓸 모델 | `CONTAMINATED` 등 (설정) | BE-37, 44 |
| ③-1 | rag | 사건 개요 → 양형기준 · 유사 판례 참고 자료 | `gemini-embedding-001` (검색어 임베딩만) | `required: true`인데 참고 자료를 못 만듦 (기본은 기존 참고 자료로 대체) | BE-54 |
| ④ | generate | 사건 입력 (+ ③-1 참고 자료) → AI 판결 JSON, 검증 | 설정한 모델 여러 개 × `runs`회 | 검증을 통과한 회차 없음 | BE-30, 44, 54 |
| ⑤ | select | 통과 회차 → 한 건 | — | 통과 회차 없음 | BE-31 |
| ⑥ | load | 선택 회차 + 사건 + 재판부 초안 → SQL | — | 제목 · 요소 불일치 등 | BE-31, 38 |

각 단계는 끄거나 건너뛸 수 있고(`enabled`, `--skip`), 끝난 단계는 다음 실행에서 건너뛰고 이어서 한다(상태 `out/pipeline/<name>/state.json`). 앞 단계가 다시 돌면 뒤 단계 결과는 함께 지운다(낡은 결과로 적재하지 않게).

## 3. 단계별 설명

### ① extract — 비식별화 · 구조화 (BE-20, 35, 38)

- 사건번호 · 법원명 · 선고일 · 심급을 **마스킹 전에 로컬에서** 정규식으로 꺼내 내부 파일(`source_internal.json`)에만 둔다. 모델에 보내지 않는다.
- 정규식으로 주민번호 · 전화 · 사건번호 · 법원명 · 주소 등을 가린 원문을 모델에 보내 사건 개요 · 섹션 · 판단 요소 · 형벌 규칙 · 서비스 대상 판정을 받는다.
- 모델은 Claude(구조화 출력으로 스키마 강제), Gemini · OpenAI(스키마를 프롬프트에 붙이고 어긋나면 최대 2번 다시 요청) 중에서 고른다(BE-35). 모델마다 비식별화 품질이 다르므로 어느 모델이든 원 판결문과 대조해 검수한다(REQ-075).
- 사건 발생일(`incidentDate`)은 모델이 예외적으로 정확한 날짜로 답하고 원문 · 선고일과 대조해 확인한 값만 내부 파일에 둔다. 이 값이 `legal_case.incident_date`에 들어간다(BE-38). 판결문에 날짜가 없으면 비운다.
- 오류(개인정보 잔존 · 실제 형량 누출 등)가 있으면 사건 입력을 만들지 않고 멈춘다. 요약어(`summaryTag`, 판결 카드 한 줄 요약) · 사전 판단 선택지(`preLabel`)도 사용자에게 보이므로 같은 검사를 한다(BE-53).
- **퓨샷 (BE-53, `extract-v6`)**: 시스템 프롬프트 뒤에 판단 요소 작성 예시(`extract_fewshot.md`)를 붙인다. 지어낸 상해 사건으로 사실 한 문장 · 공개 단계 · 요약어 · 가치관 축 쓰는 법만 보이고, 예시 값을 옮기지 말라고 적는다. 예시가 실제 검사 코드(스키마 · 개인정보 · 가치관 축)를 통과하는지 테스트로 지킨다.
- **요약어 후보 (BE-53, `stages.extract.summaryTags`, 기본 꺼짐)**: 요소마다 요약어를 공개 기준 목록(`summary_tags.json`)과 `SEMANTIC_SIMILARITY` 임베딩으로 비교해 상위 3개와 점수, 기준(0.90, 실제 사건 요약어로 다시 정할 값) 이상인 기존 요약어를 `report.json`의 `factorExtras[].summaryTagCandidates`에 남긴다. **요약어는 바꾸지 않고 제안만** 한다. 1 · 2순위 점수 차가 0.01 미만이면 `ambiguous`로 표시하고 제안하지 않는다. 보내는 값은 요약어뿐이다. 키가 없거나 임베딩이 실패하면 상태만 `SKIPPED`로 남기고 계속한다. 적재 SQL이 새 사건의 `factor.summary_tag_candidates`에 넣고 관리자 상세(A-6)에 내려 준다(BE-80, 가치관 축 투표 `value_axis_votes`와 같은 방식). 관리자 화면(S-19) 표시는 후속이다.

### ② court — 재판부 판결(COURT) 초안 (BE-38)

- 마스킹한 원문에서 재판부 판결의 요약 · 이유 · 쉬운 설명 · 발췌 · 요소별 방향과 근거를 받는다.
- **자동 검사**: 발췌 · 근거가 원문을 글자 그대로 인용했는지(바꾼 식별 정보만 `⟦ ⟧`), 형량이 최종 판결문 주문과 맞는지, 개인정보가 남았는지. 통과하지 못하면 오류를 알려 주며 최대 2번 다시 요청한 뒤 멈춘다.
- **퓨샷 (BE-53, `court-v2`)**: 시스템 프롬프트 뒤에 인용 · 요소 선택 예시(`court_draft_fewshot.md`, ① 예시와 같은 가상 사건)를 붙인다. 원문을 글자 그대로 옮기고 식별 정보만 `⟦ ⟧`로 바꾸는 법, 재판부가 언급하지 않은 요소는 고르지 않는 법을 보인다. 예시가 실제 초안 검사(`check_draft`)를 통과하는지 테스트로 지킨다.
- 인용에 미리 가린 표시(`[주소]` 등)가 남으면 오류다(BE-53). 원문 글자와 같아 인용 대조는 통과하기 때문에 따로 막는다.
- 초안은 **실제 판결이 들어 있는 내부 파일**이다. ③ · ④는 이 파일을 읽지 않는다(FR-4-1).

### ③ contamination — 사전 학습 점검 (BE-37, 44)

모델이 사건 개요만 보고 실제 형량을 맞히는지(사전 학습으로 이미 아는지) 확인한다(REQ-102). 사건 개요 · 죄명만 보내고 모델마다 `runs`회(기본 10) 묻는다.

- 응답 하나를 `KNOWS` · `EXACT` · `CLOSE` · `SAME_TYPE` · `INVALID` · `FAR`로 분류하고 **비율로 판정**한다(BE-37). `CLOSE`의 징역 허용 오차는 실제 형량의 15%(1 ~ 6개월로 제한), 벌금은 10%.
- 판정: `CONTAMINATED`(`KNOWS`가 있거나 `EXACT` 비율 50% 이상) → `INSUFFICIENT`(응답이 최소 5개 미만, 호출 실패 · 한도로 일부만 돌아온 경우) → `SUSPECT`(`EXACT`가 있거나 근접 비율 50% 이상 또는 `INVALID`) → `CLEAN`.
- 조치(설정): `onContaminated`(`stop` 기본 · `exclude`), `onSuspect`(`continue` 기본), `onInsufficient`(`stop` 기본). `exclude`면 그 모델만 생성에서 뺀다.
- 기본은 **꺼짐**이다. 켜면 모델을 번갈아 가며 회차 순서로 호출한다(BE-44, 5-3).

### ③-1 rag — 생성 참고 자료 RAG (BE-54)

- 사건 개요 · 섹션(비식별화한 사건 입력)을 `RETRIEVAL_QUERY`로 임베딩하고, 로컬 DB 함수로 찾는다(`rag_context.py`). 기본은 **꺼짐**(`stages.rag.enabled`).
- **양형기준**: 기준일(설정 `indictmentDate` → 없으면 발생일)에 시행 중이던 버전을 고르고, 그 버전의 형량범위 전체와 사건과 가까운 양형인자 · 정의(6개 · 하한 0.6)를 넣는다. 기준일은 프롬프트에 넣지 않는다.
- **유사 판례**: 자기 사건(사건번호 해시가 겹치는 사건 그룹)을 빼고 상위 5건(하한 0.70). 대상 사건의 사건번호가 없으면 자기 사건을 뺄 수 없어 붙이지 않는다. 상한 0.88 이상은 자기 사건 의심으로 뺀다. 같은 양형기준 버전 판례는 점수에 0.01을 더해 비슷한 점수 사이에서만 앞에 둔다.
- **대체**: 키 없음 · DB 접속 실패면 사건 입력의 기존 참고 자료를 통째로 쓴다(`FALLBACK`). 버전 · 형량범위가 없으면 **양형기준만** 기존 값을 쓰고, 판례가 없으면(사건번호 없음 포함) **유사 판례는 비운다**(사건 입력의 예시 판례를 남기지 않는다, `PARTIAL`). 사유는 보고에 남기고, `required: true`면 하나라도 못 찾을 때 멈춘다.
- **입력이 바뀌면**: rag는 자기 입력(검색어 · 기준일 · 사건번호 해시 · 설정)의 지문을 남긴다. 생성 · 적재 때 지문이 다르면 `--from rag`로 다시 만들라고 멈춘다. 적재는 다시 만든 프롬프트가 고른 회차의 프롬프트(`batch.json`)와 다르거나 `batch.json`이 없으면 멈춘다.
- 외부로 보내는 것은 검색어 임베딩 입력(비식별화한 사실관계)뿐이다. 사건번호는 해시로만 DB 검색에 쓰고 결과 · 보고에 남기지 않는다.
- 결정 · 근거: [RAG 인수인계](rag-handover.md) 2 · 5-4 · 5-5장, [양형기준 저장소](sentencing-guideline-rag.md) 6장.

### ④ generate — AI 판결 생성 · 검증 (BE-30, 44)

- 사건 입력(죄명 · 법조문 · 법정형은 고정값, 선고 가능 범위 · 권고 범위 · 판단 요소 목록 · 참고 자료)으로 프롬프트를 만들어 설정한 모델마다 `runs`회 생성한다. 실제 판결은 넣지 않는다.
- 회차마다 형식 · 선고 가능 범위 · 판단 요소 목록 · 금지 표현을 검증하고 기록한다. 호출이 실패한 회차도 기록해 비교표의 실패율에 넣는다.
- 검증 통과 회차가 하나도 없는 모델은 `maxRetries`회까지 한 번씩 더 생성한다.
- `compare.py`로 모델별 비교표(검증 통과율 · 형벌 분포 · 요소 방향 일관성 · 토큰 · 소요 시간)를 만든다(BE-30).
- 참고 자료: ③-1을 켜면 그 결과(양형기준 · 유사 판례)를, 끄면 사건 입력의 값을 쓴다. 시스템 프롬프트에는 항상 판결 형식 예시(퓨샷: 가상 사기 사건, 형량은 가림)가 붙는다(프롬프트 `judgment-v3`, BE-54). 유사 판례는 공통점 · 차이점으로만 쓰고 형량을 그대로 옮기지 않게 한다.
- **모델 고정 (예정, COMMON-40)**: 지금은 여러 모델 × `runs`회로 다수 생성해 비교 선택하지만, AI 호출 한도를 줄이기 위해 앞으로는 모델 하나로 고정할 계획이다. 어떤 모델을 쓸지는 직접 테스트로 검증 통과율 · 안정성을 확인한 뒤 정하고, 그 근거는 `compare.py` 비교표 등으로 별도 문서화한다. 아직 테스트 전이라 지금 동작(모델 여러 개 생성)은 바뀌지 않았다. **함께 정할 것**: generate를 모델 하나로 고정하면 ③ 사전 학습 점검(어떤 모델을 점검할지)과 ⑤ select(지금은 모델 · 회차 전체의 다수 의견으로 고름)도 영향을 받는다. 무료 등급 대체 체인(5-3 · 5-4, BE-45: 앞 모델이 막히면 다음 모델로 대체)을 모델 고정 뒤에도 남길지도 COMMON-40에서 함께 정한다.

### ⑤ select — 회차 선택 (BE-31)

`consensus`(기본): 후보 전체의 판단 요소별 다수 의견과 가장 많이 일치하는 회차. 같으면 경고가 적은 것, 그다음 앞선 것. `first-valid` · `fewest-warnings` · `manual`도 있다. 사전 학습 점검으로 뺀 모델은 후보가 아니다.

### ⑥ load — 적재 (BE-31, 38)

| 대상 | 내용 |
| --- | --- |
| 사건 | `legal_case.status='DRAFT'`로 넣고 섹션 · 형벌 규칙 · 판단 요소 · 원본 판결문(`case_source`)을 함께 넣는다. 사건 발생일 포함. 자동으로 공개하지 않는다 |
| 재판부 판결 | `judgment`(COURT) · `judgment_factor`를 **비공개**(`is_published=false`)로 넣는다. 기존 공개 판결은 건드리지 않는다. 다시 돌리면 비공개 후보가 하나 더 쌓인다 |
| AI 판결 | `judgment.is_published=false`, `ai_generation.review_status='PENDING'`. 입력 프롬프트 전체 · 원본 출력 · 프롬프트 버전 · 생성 정보(`generation_report`)를 남긴다 |
| 라벨 검증 (BE-32) | 생성 시점의 판단 요소 라벨 스냅샷(`run-NNN.factor-labels.json`)과 지금 사건 파일의 라벨을 비교한다(`to_seed_sql.py --factor-labels`). 사건 파일과 DB가 함께 재시딩돼도, 예전 AI 출력이 뜻이 달라진 같은 번호의 요소에 연결되는 것을 막는다 |
| 안전 | 같은 SQL을 두 번 실행해도 중복되지 않는다(`runKey`). 같은 제목의 공개 · 검토 중 사건이 있으면 멈춘다. SQL은 비공개 저장소(`backend/private-seed/loads/`)에만 둔다 |
| DB 적재 | 로컬에서만 한다. 운영은 보관한 SQL을 서버에서 실행한다 |

## 5. 호출이 막힐 때: 재시도 · 교차 호출 · 대체 · 무료 모델

무료 등급은 서버가 바쁘거나(503) 호출 한도(429)에 걸리는 일이 잦다. 원인마다 다르게 대응한다.

### 5-1. 재시도 (BE-36)

| 원인 | 응답 | 대응 |
| --- | --- | --- |
| 서비스 과부하 | 503 · 529 | 5 · 10 · 20 · 40초…로 늘려 가며 지터를 더해 다시 보냄 |
| 분당 한도 | 429 | 응답이 알려 준 시간(`Retry-After` · Gemini `retryDelay`) + 1초 기다림, 안내가 없으면 1분(단 최대 대기 `max_wait`가 1분보다 짧으면 그 값). 안내가 최대 대기보다 길면 기다리지 않고 끝냄 |
| 일 한도 · 크레딧 소진 | 429 | **다시 보내지 않음.** 그 모델의 남은 회차도 건너뜀 |
| 그 밖의 서버 오류 · 연결 실패 | 5xx 등 | 2 · 4 · 8초…로 다시 보냄 |

최대 시도 횟수(기본 5)와 한 번에 기다릴 최대 시간(기본 120초)은 설정 `retry` 또는 `generate.py --max-attempts · --max-wait`로 바꾼다. 최종 실패는 원인(과부하 / 분당 한도 / 일 한도)을 구분해 알리고 실행 기록의 `callErrorKind`에 남긴다. 한도를 아끼려면 단계의 `delay`(호출 사이 대기)를 둔다.

### 5-2. 모델 교차 호출 (BE-44) — 점검 · 생성

모델을 번갈아 가며 회차 순서로 부른다(`m1 1회, m2 1회, m1 2회 …`). 한 모델이 분당 한도에 연속으로 걸리지 않는다. **모델은 서로 독립된 투표자**라서 기록 · 회차 번호 · 점검 판정은 모델마다 따로이고, 한 모델이 막혔다고 다른 모델이 그 모델의 결과를 대신 만들지 않는다.

### 5-3. 비식별화 · 재판부 초안의 대체 체인 (BE-45)

이 두 단계는 결과 하나만 내므로 모델 **목록**을 줄 수 있다. 앞 모델의 호출이 과부하 · 한도로 막히면(앞 모델의 재시도를 다 쓴 뒤, 일 한도는 즉시) 다음 모델이 **같은 입력으로 처음부터** 다시 요청한다. 형식 · 인용 검사 실패 같은 **품질 문제는 대체하지 않고** 멈춘다(원인이 가려지지 않게). 응답한 모델과 건너뛴 모델 · 원인은 보고서(`modelChain` · `fallbacks`)에 남는다.

### 5-4. 무료 모델 자동 사용 (BE-45) — 점검 · 생성

`models`에 `"free:gemini"`(`free:groq` · `free:nim`도 된다, BE-84)를 적으면 `free_models.json`의 무료 등급 모델을 쓴다. `freeModels.max`(기본 3)개까지 동시에 쓰고, 사용 중인 모델이 일 한도로 막히면 대기 모델이 자리를 채운다. 새로 들어온 모델은 **독립 투표자**로 자기 이름으로 처음부터 기록하고, 막힌 모델이 끝낸 회차는 그 이름으로 남아 선택 후보에 들어간다. 대체 모델도 사전 학습 점검을 먼저 통과해야 한다.

### 5-5. 판결문 단계의 무료 등급 백업 (BE-45, 선택)

기본으로는 판결문 원문을 보내는 extract · court에 무료 키를 쓰지 않는다. 팀이 "이미 공개된 판결문에 한해" 허용하기로 해(구두 합의) `allowFreeTierForJudgment: true`일 때만 모델 목록 맨 끝에 `free:<공급자>`를 마지막 백업으로 둘 수 있다. 유료 모델이 모두 막힌 뒤에만 쓰고, 시작 안내 · 무료 모델로 넘어갈 때 · 실제 응답했을 때 경고하며 보고서에 `usedFreeTier`를 남긴다. 켠 설정 파일은 공개 판결문에만 쓴다.

## 7. DB에 남는 것

[ERD](erd.md)의 `legal_case` · `case_source` · `judgment`(AI · COURT) · `judgment_factor` · `ai_generation`에 들어간다. 이 파이프라인이 만든 변경은 다음과 같다.

- `ai_generation.generation_report`(jsonb, V8): 검증 경고 · 사전 학습 점검 판정과 분류별 개수 · 기준 · 회차 선택 이유 · 모델 · 토큰 · 실행 식별자(`runKey`). 예측 형량 · 실제 판결 값은 넣지 않는다.
- 적재 SQL이 `legal_case.title` · `factor(case_id, display_order)`를 조회 키로 쓰므로 두 값의 유일성을 DB 제약으로 막는다(V7, BE-15).
- 사건 발생일 `legal_case.incident_date`(BE-38), 비공개 재판부 판결(COURT 행, BE-38).
- 양형기준 버전 `legal_case.guideline_id`: 기준일(공소제기일 → 없으면 발생일)에 시행 중이던 버전(BE-54). 기준일이 없거나 버전이 없으면 NULL.
- `generation_report.rag`(③-1을 켰을 때): 상태 · 양형기준 버전 이름 · 기준 종류 · 판례 id · 점수 · 대체 사유. 사건번호 · 기준일 · 판례 본문은 넣지 않는다(BE-54).

| **generate 퓨샷 · RAG** | **구현됨 (BE-54)**: ③-1 `rag` 단계(기본 꺼짐) · 판결 형식 예시 퓨샷 · 프롬프트 `judgment-v3`. 판례 저장소(BE-51) · 양형기준 저장소(BE-52)를 쓴다 |
| **그 밖의 퓨샷 · 임베딩** | **extract · court는 구현했다(BE-53)**: extract 퓨샷(`extract-v6`) · 요약어 후보 임베딩(`stages.extract.summaryTags`, 기본 꺼짐), court 퓨샷(`court-v2`). 요약어 후보는 보고서에만 남고 DB 적재 · 관리자 화면 표시는 후속이다(3장 ①). **남은 위치는 select(판결 이유 임베딩, BE-55)**이고 contamination · load · 후검수에는 넣지 않는다. 임베딩 모델 · 판례 저장소 범위는 COMMON-21에서 정했다(아래 8-1). 양형기준 저장소는 RAG로 정했다(BE-52, 8-1) |
| **generate 모델 고정** | **방침만 정했고 미구현** (COMMON-40). 여러 모델로 다수 생성하는 지금 방식 대신 테스트로 검증한 모델 하나로 고정할 계획이다. 적용 시점 · 대상 모델은 성능 테스트 결과가 나온 뒤 정한다 |

### 8-1. 결정 사항 (COMMON-21)

| 항목 | 결정 |
| --- | --- |
| 임베딩 모델 | `gemini-embedding-001` 무료 등급, 3072차원. 컬럼은 `vector(3072)`이고 판례가 수백 건인 동안 인덱스 없이 전체를 비교한다. 수만 건으로 늘면 `halfvec(3072)` + HNSW(인덱스 한도 2000차원은 `vector` 타입에만 걸린다). task type은 저장 `RETRIEVAL_DOCUMENT`, 검색어 `RETRIEVAL_QUERY`, 회차 선택 · 요약어 비교 `SEMANTIC_SIMILARITY`, 유사도는 cosine |
| 임베딩 입력 | 공개 판결문을 비식별화한 텍스트만. 무료 등급은 입력을 제품 개선에 쓸 수 있어 원문 · 비공개 데이터 · 사용자 입력은 넣지 않는다. 행마다 모델명과 차원을 저장한다 |
| 판례 조건 | 필수: 양형 이유 있음 · 유죄 · 대상 죄명 · 비식별화 가능. 제외: 무죄 · 공소기각 · 양형 이유 없는 상고 기각. 표시만 하고 포함: 경합범 · 부인 · 미확정 |
| 규모 · 기간 | 살인 100건 안팎으로 시험하고, 샘플 사건 10건의 검색 상위 5건을 확인한 뒤 유형당 100건으로 확대. 기간은 넓게 잡고 판례마다 사건 발생일 · 적용 양형기준 버전을 저장해 검색 때 같은 버전을 우선하거나 필터한다 |
| 자기 사건 제외 | 사건 그룹 ID로 같은 사건의 다른 심급 · 공범 별도 판결 · 병합 사건 판결을 함께 제외. 사건번호는 해시로만 저장 |
| 수집처 | 케이스노트 · 대법원 종합법률정보 · law.go.kr · 사법정보공개포털. 자동 수집 가능 여부는 약관 확인 후 정한다 |
| 양형기준 | 담당 김해송. **RAG로 정했다**(BE-52, 2026-10-12): 유형이 늘어도 행만 늘고, 판례 저장소와 같은 스택을 쓴다. 형량범위 같은 구조 값은 같은 테이블에서 바로 읽는다. 버전 기준일은 공소제기일 → 없으면 발생일. [양형기준 저장소](sentencing-guideline-rag.md) |
| 점수 하한 | 예시값(요약어 0.85 · 판례 0.6 · select 가중치 0.3)으로 시작. 판례 확보 후 샘플 사건 10건의 상위 점수를 보고 확정한다. **generate는 확정**(BE-54, 2026-10-15): 판례 하한 0.70 · 상한 0.88, 양형기준 6개 · 0.6. 서비스 사건이 아직 적어 판례끼리 검색한 분포로 함께 정했다([RAG 인수인계](rag-handover.md) 5-4). **요약어는 0.90**(BE-53 리뷰, 2026-10-16): 샘플 17개 실측에서 0.85는 무관한 쌍(0.81 ~ 0.86)과 구분이 안 됐다(같은 뜻 0.877 ~ 0.984). 1 · 2순위 차 0.01 미만은 애매함으로 제안하지 않는다. 실제 사건 요약어로 다시 정할 값이다 |
| 요약어 기준 목록 (BE-53) | 문서 · BE-51 · 비공개 시드 어디에도 사건들이 함께 쓰는 목록은 없었다(사건별 요약어만 있음). **공개 목록만** 쓴다: `tools/ai-judgment/summary_tags.json`(가상 사건 시드 11개 + extract 프롬프트 예시 7개, 겹치는 1개 제외 17개). 실제 사건 요약어(비공개 시드 R__10)는 공개 저장소에 실제 사건 정보를 두지 않는 원칙(BE-17) 때문에 이 파일에 넣지 않는다. 공개 판결문을 비식별화한 값이라 임베딩은 판례(R__40)와 같은 기준으로 가능하므로, 비공개 시드 추가 목록은 지금 두지 않는다(BE-53 리뷰 결정, 10/16: 실제 사건이 아직 몇 건뿐이고 비공개 시드 · 공개 도구를 함께 읽는 경로가 하나 더 생김). 실제 사건 적재가 쌓이면(관리자 후검수 연결 뒤) 다시 정한다. 공개해도 되는 일반 요약어를 팀이 더해 간다 |
