# FE-81 의사결정 기록

> FE-77(PR #249)이 화면에서 이 브라우저(`localStorage`)에만 저장하던 값을 BE-104(PR #251)의 서버 API로 옮긴다.
> 계약의 근거는 `docs/decisions/BE-104.md`, 화면의 의미는 `docs/decisions/FE-77.md`에 있다.

## 문제 / 배경
- 공개 성향카드(`shownCard`) · 프로필카드 아래 성향(`profileCardType`) · 한 줄 소개(`bio`)가 브라우저에만 있어 다른 기기에서 보이지 않고, 커뮤니티가 읽을 수 없었다.
- 화면은 이 값을 렌더링 중에 동기로 읽는다(`shownSlot` · `selectedChoice` 등). 서버 값은 비동기로 온다.

## 검토한 대안
- 대안 A: 값을 쓰는 함수마다 서버를 부른다. 렌더링이 비동기가 되어 화면 코드를 크게 고쳐야 한다.
- 대안 B: `localStorage`를 계속 원본으로 두고 서버는 뒤따라 맞춘다. 원본이 둘이라 기기마다 다른 값이 남는다.
- 대안 C(선택): **서버가 원본, 화면은 동기로 읽는 사본(`utils/profileSettings.js`)**. 마이페이지를 받을 때 사본을 서버 값으로 맞추고, 바꿀 때는 사본을 먼저 바꿔 바로 보여 준 뒤 서버에 보낸다.

## 선택한 방법과 이유
- 기존 함수 이름(`getShownCard` · `setShownCard` · `getProfileCardType` · `setProfileCardType`)을 그대로 두고 안쪽만 사본으로 바꿔, 화면 코드 변경을 최소로 했다.
- 보내는 요청은 하나씩 차례로 간다. P-8이 보낸 칸만 저장(PATCH)이라 서로 다른 칸을 연달아 바꿔도 덮어쓰지 않는다.
- 거절되면 그 칸만 이전 값으로 돌리고(그 사이 새로 바꾼 칸은 건드리지 않는다) 마이페이지를 다시 받아 서버 값으로 맞춘 뒤 알린다. 꾸미기 저장(P-7)이 거절됐을 때와 같은 방식이다.
- 저장하는 동안 도착한 마이페이지 응답은 사본을 덮어쓰지 않는다(오래된 응답이 방금 고른 값을 되돌리는 것을 막는다).
- 한 줄 소개는 내 정보 수정의 저장 버튼에서 보내고, 저장하는 동안 버튼을 잠근다. 거절되면 입력칸을 서버 값으로 되돌린다.
- 목 API(`profileDecoMockApi.js`의 `patchProfileSettings`)는 서버와 같은 검증 규칙(빈 객체 · 모르는 칸 · `null` · 세 값 밖 · 40자 초과 · 줄바꿈 → 400)을 따른다.

## 고려한 제약 사항
- `localStorage`에 있던 기존 값(`nlnb-shown-card` 등)은 옮기지 않는다. FE-77 머지 직후라 쓰는 사람이 사실상 없다.
- 옛 서버처럼 `profileSettings`가 없는 응답이면 사본을 건드리지 않고 기본값(최근 · 최근 · 소개 없음)으로 둔다.

## 추후 재검토가 필요하면
- 한 줄 소개 금칙어 · HTML 처리는 BE-104 후속에서 정해지면 화면 안내를 맞춘다.
- 배포 환경(프록시)에서 `PATCH`가 통과하는지 확인이 필요하다.
