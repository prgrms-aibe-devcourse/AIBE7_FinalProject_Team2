# FE-73 의사결정 기록

> [FE-73](https://aibe7-team2-final.atlassian.net/browse/FE-73) · [FE-71 의사결정 기록](FE-71.md)의 대안 4 · 고려한 제약 사항을 이어받는다. FE-51과 같은 브랜치에서 진행했다([FE-51](FE-51.md)).

## 문제 / 배경

- 책갈피 설정의 원본은 서버(P-5 `profileDeco`)인데, 판결 체험 화면은 localStorage 거울을 동기로 읽는다. 거울은 마이페이지를 열 때만 서버 값으로 맞춰져서, 다른 기기에서 고른 책갈피는 이 기기에서 마이페이지를 한 번 열기 전까지 반영되지 않는다.

## 검토한 대안

- 책갈피만 가볍게 받는 API를 백엔드에 추가: 호출 비용은 줄지만 백엔드 작업이 따로 필요하다. 사이트 진입 때 한 번 부르는 정도라 P-5를 그대로 쓰기로 했다.
- 판결 체험 화면이 비동기로 읽기: 책갈피를 그리는 곳(`folderParts` 등)이 동기 읽기를 전제로 해 고칠 곳이 많다.
- 앱 시작 때 무조건 호출: 비로그인 첫 방문(쿠키 없음)에서 불필요한 호출이 생긴다.

## 선택한 방법과 이유

- `syncBookmarkFromServer(getMyPage)`가 P-5의 `profileDeco`를 거울에 옮긴다. 실패하면 거울을 그대로 둔다.
- 호출 시점은 두 곳이다: (1) 사이트에 들어올 때(`main.js`, 출석 기록과 같은 자리) 로그인한 회원이면, (2) 카카오 로그인을 마친 직후(`authCallbackPage`). 콜백 화면은 카카오를 거쳐 새로 열려 (1)의 시점에는 아직 로그인 전이라 (2)가 따로 필요하다.
- 비로그인 방문에서는 호출하지 않는다. 화면은 이 호출을 기다리지 않는다.
- 기다리는 사이 이 기기에서 책갈피를 바꿨으면(마이페이지) 늦게 온 응답으로 덮지 않는다. 호출 전 거울 값(`bookmarkSnapshot`)과 응답 뒤 값이 다르면 건너뛴다(PR 리뷰 반영, FE-81과 같은 경합).

## 고려한 제약 사항

- 거울이 맞춰지기 전에 판결 체험 화면이 먼저 그려지면(로그인 상태에서 판결 화면을 새로고침으로 바로 연 경우) 그 한 번은 이전 거울 값으로 보이고, 다음 화면부터 반영된다.
- 이 화면의 로그인 표시는 localStorage의 닉네임이다. 서버 세션이 만료됐으면 호출이 실패하고 거울을 그대로 둔다.

## 추후 재검토가 필요하면

- P-5는 마이페이지 전체 묶음이라 로그인한 회원이 사이트에 들어올 때마다 한 번 불린다. 접속이 늘면 책갈피만 받는 가벼운 API(검토한 대안 1)로 옮긴다.
