# BE-48 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #90 본문.

## 문제 / 배경
- 가치관 축(BE-47)은 AI가 기본값을 정하고 관리자가 후검수로 확정한다. 값만으로는 "관리자가 일부러 NULL로 둔 요소"와 "아직 채우지 않은 요소"를 구분할 수 없다.

## 선택한 방법과 이유
- `factor.value_axis_status`(`AUTO` 기본 / `CONFIRMED` — NULL 확정 포함)와 `value_axis_votes`(jsonb: 횟수 · 표 · `needsReview`)를 추가했다(V10).
- 재적재 규칙: 이미 적재된 DRAFT 사건은 건너뛰고, `AUTO`이면서 번호 · 라벨이 같은 요소의 축 · 투표 기록만 갱신한다. **투표 기록이 있는 값만** 반영해, 투표 없이 정한 값이 투표 결과를 덮지 않게 한다. 사람이 값을 바꾸는 경로는 관리자 확정 하나다(ERD v1.15에 명시).
- 적재 SQL이 투표 기록 형식 · 표 합계 = runs · 고른 축 = 최다표를 검사한 뒤 넣는다.

## 고려한 제약 사항
- CHECK `NOT VALID` 분리는 하지 않는다. 같은 트랜잭션의 `ADD COLUMN`이 이미 같은 잠금을 잡고 있고, `factor`는 수백 행 규모다.
- 마이그레이션 번호: BE-39(#79)도 V9를 쓰지만 나중에 머지되므로 #79가 번호를 바꾸기로 했다.
