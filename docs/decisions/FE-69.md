# FE-69 의사결정 기록

## 문제 / 배경
- 일부 브라우저(쿠키 · 사이트 데이터 차단)는 `globalThis.localStorage`를 읽는 것만으로 예외를 던진다. `session.js`의 `currentUser()` 같은 함수는 기본 인수(`storage = globalThis.localStorage`)로 저장소를 받는데, 기본 인수는 함수 본문의 `try`보다 먼저 평가되어 예외를 잡지 못한다. 공통 헤더가 매 화면에서 인수 없이 `currentUser()`를 부르므로 어느 화면에서나 헤더 렌더가 깨질 수 있었다.
- 로그인 화면(S-12)은 FE-52에서 틀만 만들어 둔 상태라, 메인 화면(책상)과 모양이 이어지지 않았다.

## 검토한 대안
- **저장소 접근 보호**
  - 대안 A: 호출하는 곳마다 `try/catch`로 감싼다. 호출처가 많고(헤더만 10곳) 새로 생기는 곳에서 또 빠뜨리기 쉽다.
  - 대안 B: 기본 인수에서 쓰는 공용 헬퍼(`utils/safeStorage.js`의 `localStore()`)로 접근을 한 곳에서 감싼다.
- **저장소가 막혔을 때 `saveUser` · `clearUser`의 동작**
  - 대안 A: 저장소가 없으면(`undefined`) 조용히 넘어간다(`storage?.setItem`). 로그인 직후 상태가 사라진다.
  - 대안 B: `?.`를 빼서 저장소가 없을 때도 예외 경로로 보내, 이번 방문 동안의 값(`unsaved`)으로 이어 간다.
- **로그인 박스 모양**
  - 대안 A: 밝은 종이 카드를 책상 위에 둔다(기존 `--color-card`).
  - 대안 B: 메인 책상의 데스크 패드(네이비 펠트 `--color-desk-pad`)를 그대로 가져온다. 글자색은 종이색으로 뒤집는다.
- **오류 문구 표시**
  - 대안 A: 오류 줄을 항상 한 줄 자리로 확보해 박스 높이가 변하지 않게 한다.
  - 대안 B: 오류가 있을 때만 줄이 생기고 박스가 늘어난다.
- **개발용 상태 넘어가기 버튼**: 화면 상태별(폼 · 오류 · 로딩 · 로그인됨 · 콜백)로 가려면 라우트마다 쿼리를 달거나 상태 전환 버튼 줄을 두는 방법이 있다.

## 선택한 방법과 이유
- 저장소 보호는 **B**: `session.js` · 목 저장소(`mockExperienceStore.js` · `caseListMockApi.js`)가 `localStore()`와 같은 감싸기를 쓰게 했다. FE-67(`bookmarkCharacter.js`) · FE-68(`profileDeco.js`)이 먼저 만든 헬퍼를 그대로 재사용해 방식을 하나로 맞췄다.
- `saveUser` · `clearUser`는 **B**: 저장소가 막힌 경우에도 로그인 상태가 이번 방문 동안은 유지된다. 테스트에서 `?.` 때문에 값이 사라지는 것을 확인하고 고쳤다.
- 로그인 박스는 **B**: 메인과 같은 나뭇결 책상 위에 가로로 긴 펠트 패드를 놓고, 입력 영역은 가운데 400px 단에 둔다. 새 색을 만들지 않고 기존 책상 토큰만 쓴다. 로그인됨 · 카카오 콜백 화면도 같은 패드(`loginDesk`)를 공유하고, 콜백 · 로그인됨에는 내로 · 남불이 패드 위로 고개를 내민다(장식).
- 오류 문구는 **B**(처음에 A를 시도했다가 되돌렸다): 박스 높이를 고정하는 것이 오히려 어색했고, 로그인 화면에서는 오류가 나면 줄이 늘어나는 쪽이 사용자에게 더 익숙하다고 판단했다. 오류 문구는 별도 상자 없이 펠트 위 글줄로 둔다.
- 개발용 버튼은 상태 전환 버튼 줄(`loginDevJump.js`)로 만들고, 목 모드(`API_MODE === 'mock'`)에서만 보이게 했다. 라우트마다 쿼리를 다는 것보다 한 화면에서 모든 상태를 오가며 보기 쉽다. 콜백 로딩만 재발급 호출 없이 머무르도록 `?dev=loading`을 둔다.

## 고려한 제약 사항
- 메인 책상은 1672×941 좌표계의 일러스트라 그대로 재사용할 수 없다. 나뭇결 그라디언트만 `login.css`에 같은 값으로 두었다(`stage.css` · `pageTurn.css`가 이미 이렇게 복사해 쓴다).
- 네이비 내로는 네이비 펠트 위에 올리면 묻히기 때문에, 패드 뒤에서 몸 아래쪽을 가리고 위쪽만 보이게 했다.
- 모바일 폭(720px 이하)은 화면으로 확인하지 못했다. 펜은 숨기고 이미지는 줄이도록 CSS만 넣어 두었다.

## 추후 재검토가 필요하면
- 로그인 화면 폴리싱 중 접근성 · 오류 문구 · 포커스 이동 점검 항목은 아직 정리하지 않았다(Jira 댓글에 남길 예정).
- 개발용 넘어가기 버튼(`loginDevJump.js`, `login.css`의 `login-dev-jump` 블록, 두 화면의 `devJumpBar` 호출)은 폴리싱이 끝나면 함께 지운다.
