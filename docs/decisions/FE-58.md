# FE-58 의사결정 기록

## 문제 / 배경
- BE-82(PR #214)에서 6막 화면 주소 · 화면 ID를 확정했다. 프론트 코드는 여전히 8막 시절 주소(`/start` · `/review` · `/summary` · `/result/*` · `/opinion`)를 쓰고 있었다. 주소표 · 역할 나누기는 [BE-82 결정 기록](BE-82.md)에 있다.
- 옛 주소로 된 공유 링크 · 북마크도 계속 열려야 했다.
- `/summary`를 어디로 보낼지 두 문서가 달랐다. BE-82 표는 `/letters`(리뷰 페이지)였고, IA v1.16(FE-61, PR #213)은 "지금처럼 `/verdict`로 넘긴다"였다.
- BE-82 리뷰 반영으로 IA에 "S-09는 진입할 때 API 3으로 `COMPLETED`를 확인한다"는 규칙이 생겼는데, 프론트에는 API 3 함수가 없었다.

## 검토한 대안
- 옛 주소 redirect 위치
  - 대안 A: `routes.js`에 옛 주소 화면을 한 줄씩 더 둔다(같은 render를 옛 path로). 표는 한 곳이지만 옛 주소가 그대로 주소창에 남고, 같은 화면이 두 주소를 갖는다.
  - 대안 B: 라우터가 주소를 판정하기 전에 옛 주소를 새 주소로 `replaceState`한다. 옛 주소 표는 작은 모듈(`app/legacyPaths.js`)에 둔다.
- 옛 `/summary`의 행선지
  - 대안 A: BE-82 표대로 `/letters`. 체험 중인 사용자가 아직 쓸 수 없는 리뷰 페이지에 먼저 들어간다.
  - 대안 B: `/verdict`. 옛 `/summary`는 실제 코드에서 판결 직전(`REVIEWED`)에만 거쳐 가던 주소였다.
- 기획 문서의 옛 화면 ID
  - 대안 A: BE-82가 넘긴 4개 문서(`docs/character` 3개 · `sample-virtual-murder.md`)만 고친다.
  - 대안 B: 옛 ID가 남은 기획 문서 전부를 고친다.

## 선택한 방법과 이유
- redirect는 **대안 B**. 주소창도 새 주소로 바뀌어 화면 하나가 주소 하나만 갖는다. 기존 정규화(`/cases/01/...` → `/cases/1/...`)와 같은 방식(`replaceState`)이라 뒤로 가기 순번이 흐트러지지 않는다. 표가 작아 단위 테스트(`legacyPaths.test.js`)로 확인한다.
- `/summary`는 **대안 B(`/verdict`)**(사용자 결정). 다른 상태로 들어와도 판결 화면의 `INVALID_STATE` 처리로 맞는 화면에 간다. IA 6장 · 4장, user-flow에 이유를 남겼다.
- `REVIEWED` → `verdict`(`screenByStatus`). 정리 화면(`summaryPage.js` · `summary.css` · `preview.html` 항목 · 쓰지 않는 무대 `summary-card` CSS)은 지웠다.
- 목 막 이동(`jumpActMock`)의 대본 4막(옛 정리)은 `/verdict`로 연다. 대본 키(1 ~ 8)는 FE-59 범위라 그대로 둔다.
- S-09 진입 확인은 IA 규칙대로 넣었다. `getExperience`(API 3)를 실제 · 목 api에 추가하고, 리뷰 페이지 별도 화면이 진입할 때 부른다. `COMPLETED`가 아니면 `screenByStatus` 화면으로 `replace` 이동한다. 체험이 없을 때와 사건이 없을 때는 공통 래퍼가 이동시킨다. 팝업(사건 디테일 · 마이페이지 · 6막)은 이미 완료 사건에만 입구가 있어 확인하지 않는다. 목 `getExperience`는 보기만 하므로 기록을 만들지 않는다(`peek`).
- API 6 `summary`는 **계속 쓴다**. 3막 내 판결 파일철 첫 장 "사건 요약"의 `핵심 사실`이 이 값이다(BE-82가 FE-58에 넘긴 판단). API 명세 · IA · ERD에 적었다.
- 기획 문서는 **대안 B**(사용자 결정). 옛 S-06 ~ S-09 → S-05 ~ S-08로 바꾸고, 없앤 정리 화면은 "옛 S-05"로 남겼다(그 시점 계획 · 작업 기록이라 지우지 않는다). 각 문서 작성 이력에 한 줄씩 추가했다. 작성 이력 행 안의 ID는 옛 뜻 그대로다.

## 고려한 제약 사항
- 서버 진행 상태 · API 경로 · 응답 형식은 바꾸지 않는다(BE-82).
- 화면 이름(`overview` · `review` · `ai` 등)은 그대로 두고 주소만 바꿨다. `navigate()` 호출부를 건드리지 않아 변경 범위가 작다.
- 시점 기록 문서는 내용을 고치지 않고 맨 위에 "BE-82 이전 ID 기준" 안내만 달았다: `document-consistency-report.md`(9/29 점검), `planning-review-prep.md`(10/6 리뷰 준비). 와이어프레임 쪽 번호(p.N) 참조가 섞여 있어 바꾸면 원본과 어긋난다.
- `docs/decisions/*.md`의 옛 ID · 주소도 고치지 않는다. 결정 당시 기록이고 소급 수정하지 않는다(CLAUDE.md 3-1).
- 문서 · 주석의 막 번호(예: "7막 · 8막", 대본 키)는 FE-59에서 정리한다.

## 추후 재검토가 필요하면
- 후기 API가 생기면 S-09 진입 확인을 그 API의 `409 INVALID_STATE`로 바꾸고 API 3 호출은 뺀다(IA 6장 S-09).
- 옛 주소 redirect는 공유 링크가 충분히 사라졌다고 판단되면 `legacyPaths.js`째 지운다.
