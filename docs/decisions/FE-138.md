# FE-138 의사결정 기록

> 근거: BE-140(마이페이지 · 레벨 · 꾸미기 데이터 회원 기준 전환) 결정 사항(Jira BE-140 댓글), FE-137(PR #345, 이 브랜치의 바탕)

## 문제 / 배경
- BE-140은 마이페이지 · 레벨 · 꾸미기 등을 로그인 전용으로 바꾼다. 서버가 먼저 바뀌면 화면이 401로 깨지므로 **프론트를 먼저** 올린다.
- 로그인 전: 레벨 없음, 마이페이지는 최초 진입 화면만, 카드는 틀만, 닉네임 · 직업 등 없음 + 로그인 안내. 성향 테스트는 로그인 전에도 되지만 로그인할 때 결과를 가져오지 않는다.

## 검토한 대안
- 로그인 전 화면 데이터: A 지금처럼 `GET /my-page`를 불러 빈 값을 그린다 / B **서버를 부르지 않는다**(선택)
- 카드 틀 모양: A 기본 꾸미기 카드를 흐리게 / B **점선 빈 틀**(선택)
- 새로고침 직후(로그인 표시는 있고 액세스 토큰은 없음) 요청: A 지금처럼 보낸 뒤 401이면 재발급 / B **보내기 전에 먼저 재발급**(선택)

## 선택한 방법과 이유
- **B: 서버를 부르지 않는다.** 지금 서버(익명 데이터 200)와 BE-140 뒤 서버(401) 어느 쪽이든 같은 화면이 나와 배포 순서와 상관없다. 익명 데이터를 그리지 않으므로 "로그인 전에는 껍데기" 결정과도 맞는다. 로그인한 채 불러오다 401이면 같은 화면으로 바꾼다.
- **B: 점선 빈 틀.** DESIGN.md의 "점선 빈 칸"(`.my-retake-slot`) · "성향카드 없음"(`.edit-fan-empty`)과 같은 언어라 "아직 없는 카드 자리"로 읽힌다. 기본 카드를 흐리게 두면 이미 무언가 있는 것처럼 보인다. 칸 나눔은 카드와 같아 로그인 뒤 카드가 같은 자리에 들어선다.
- **B: 먼저 재발급**(`client.js`): 서브에이전트 계획 검토에서 나온 위험 1번. 액세스 토큰은 메모리에만 있어 새로고침 직후 첫 요청은 토큰 없이 나간다. 로그인 없이도 되는 API(체험 · 성향 테스트)는 BE-140 뒤 401이 아니라 손님 요청으로 처리되어 **회원의 체험이 익명 쪽에 쌓인다.** 로그인 표시가 있으면 보내기 전에 재발급해 이를 막는다. 관리자 표시는 회원 토큰이 아니라 재발급하지 않는다(재발급 401이 관리자 로그인 표시를 지우게 됨). 재발급이 연결 오류여도 요청은 보낸다.
- 성향 테스트 결과 안내는 "결과 안내"(`noticeBlock`)에 한 줄을 더했다. 내가 한 결과 화면에만 붙이고(`own`) 공유 주소 화면에는 붙이지 않는다.

## 고려한 제약 사항
- 서버 API(M-9 ~ M-11)는 BE-140에서 만든다. 후보 응답 모양 `{ experienceCount, preJudgmentCount }`는 이 PR이 먼저 정한 것이라 BE-140 구현 때 맞춘다. 서버에 없는 동안 M-9는 404라 화면이 창을 띄우지 않는다(목 모드는 늘 후보가 있어 창이 보인다).
- 실제 서버 · 사파리 확인 전. 헤드리스 크롬으로 1440 · 760 · 390px 화면을 확인했다.

## 2차 (같은 PR): 로그인 전 화면 수정 + 첫 로그인 가져오기 확인 창

### 검토한 대안
- 로그인 전 왼쪽 카드: A 빈 틀 / B **샘플 카드 10종을 0.6초마다 무작위로**(선택, 사용자 결정). 로그인하면 이런 카드를 꾸밀 수 있다는 것을 보여 준다.
- 오른쪽 성향카드 자리: 점선 빈 틀 → 실선 틀 → (사용자 결정) **성향카드의 기본 디자인 그대로의 "?" 카드**. 위 · 아래 문구는 "카드를 눌러" / "로그인 하세요"이고 가운데 문구("우측 카드를 눌러 로그인하세요")는 뺐다. 창 안에 성향 카드 그림이 뿌옇게 겹쳐 바뀐다(움직이는 값은 불투명도뿐 — 합성만 쓰는 값이라 가볍다). 창 색은 한때 주 버튼 색이었으나 기본 카드 디자인(크림 창)으로 돌아갔다.
- 확인 창을 띄울 시점: 카카오 콜백 직후 / 로그인 · 가입 완료 직후 / 마이페이지 첫 진입 → **로그인 직후**(사용자 결정). 세 입구(로그인 · 가입 · 카카오 콜백)가 같은 `offerAnonymousImport`를 부른다.
- 닫기: 처음에는 닫을 수 없게 했다(무시하고 닫은 채 회원 체험을 시작하면 가져올 기회가 사라지므로). 이후 사용자 결정으로 **닫기 버튼(×, Esc) = 로그인하지 않기**(로그아웃, 익명 기록 그대로)가 생겼다. 닫아도 "가져오기 기회 없이 로그인"이 되지 않고, 로그인을 취소하는 것이라 기회가 사라지지 않는다.
- 오른쪽 성향카드 자리: 점선 빈 틀에서 **실선 카드**로, 위 · 아래에 서비스의 핵심 카피(PRODUCT.md "다 알고 나서도, 같은 판단일까?")를 나눠 적었다(처음에는 서비스 이름의 뜻을 넣었다가, 사용자 말씀에 따라 이미 있는 핵심 카피로 바꿨다). 가운데 창은 주 버튼 색이고, 창 안에 성향 카드 그림이 뿌옇게 겹쳐 바뀐다(움직이는 값은 불투명도뿐 — 합성만 쓰는 값이라 가볍다). 가운데에 "우측 카드를 눌러 로그인하세요"(굵게)를 더했다(사용자 결정).

### 선택한 방법과 이유
- 샘플 카드는 바뀌는 동안 낭독기를 어지럽히지 않게 `aria-hidden`, 움직임 줄이기에서는 멈춘다. 페이드 없이 바로 바꿔 0.6초 간격에서도 흐릿해지지 않게 했고, 그림은 미리 받아 둔다.
- 확인 창은 후보가 없거나 서버가 아직 모르면(404 · 204) 조용히 지나가 로그인을 막지 않는다. Esc를 두 번 누르면 브라우저가 닫기를 허용하므로 닫히면 다시 연다.
- 후보는 현재 브라우저의 익명 ID 하나뿐이다(Jira BE-140 결정): 로그인 연결은 익명 ID에 회원 ID를 붙이는 것이라 다른 익명 ID가 후보가 될 일이 없다.

### 추후 재검토가 필요하면
- 문구 · 모양은 임시다(결정: 만든 뒤 조정). 실제 서버 모드 · 사파리에서 확인한 뒤 BE-140 계약과 맞춘다.

### 3차 (같은 PR): 왼쪽 카드도 누르면 로그인, 오른쪽 카드를 더 누르고 싶게
- 왼쪽 샘플 카드도 버튼으로 바꿔 누르면 로그인 화면으로 간다(호버 · 눌림은 일반 카드와 같음). 둘 다 같은 목적지라 "카드 = 로그인 입구"로 읽힌다.
- 오른쪽 창 안 그림은 10장에서 성향 그림 **32장 전부**로 늘리고, 무작위 대신 내로 · 남불 번갈아 순서대로 돌린다. 32장을 한꺼번에 받지 않고 다음 한 장씩 미리 받는다(약 1MB를 첫 화면에서 받지 않으려고).
- "그냥 카드 같다"는 인상: 주목은 크게 움직이는 것보다 **가끔 한 번의 빛줄기 + 호버 보상(금빛 테두리, "?" 확대)**으로 풀었다(움직임은 `transform`만, 움직임 줄이기에서는 끔). 더 강한 안은 문구 옆 화살표 · "눌러 보세요" 칩, 카드 숨쉬기(천천히 떠올랐다 내려앉음) 등이 있고 화면을 보고 정한다.
- 가운데 제목은 임시 문구("판사가 되어 당신만의 판결을 내려보세요.")로 바꾸고, "공개된 사건 N개 · 일러스트 N장" 숫자를 더했다. **둘 다 서버**(사용자 결정)에서 받는다: 사건 수는 공개 사건 목록 API 1의 `summary.total`, 일러스트 수는 이 PR에서 새로 만든 일러스트 총 개수 API(I-1, BE-142 · [`BE-142.md`](BE-142.md))의 `total`(사건 컷 + 캐릭터 아이콘 포함 전부 = 212장)이다. 이 화면이 서버 없이도 그려지는 원칙은 유지하되 숫자만 늦게 채운다 — 둘을 함께 받고, 받기 전 · 한쪽 실패 시에는 줄을 숨긴다. 처음에는 화면의 대본으로 일러스트를 셌으나(사건 1건 분량 7장) 사건 수와 기준이 달라 서버 값으로 바꿨다.
- 오른쪽 카드 창의 뿌연 그림도 다른 카드와 같은 맞춤 함수(`fitPortraitIn`, `center: true`)로 창을 꽉 채워 가운데에 둔다. 캐릭터마다 다른 투명 여백을 걷어 그림 크기가 같아진다. 그림을 갈아 끼울 때마다 맞춤이 새로 붙으므로 `fitPortraitIn`이 크기 관찰을 멈추는 함수를 돌려주게 했다(떼어 낸 그림의 관찰이 쌓이지 않게).
- 일러스트 수 · 마이페이지 컬렉션 사진은 **저장소 이미지 기준**이라 DB 저장값(관리자 업로드)이 저장소와 다르면 어긋난다. 감수하기로 했고(관리자가 DB에 올릴 때 저장소에도 올리면 해결), DB 기준으로 맞추는 일은 필수가 아닌 후속 이슈 BE-143이다. 코드에는 "가능한 한 DB 기준으로 저장소를 최신화한다" 주석을 남겼다(`IllustrationCatalog` · `update-manifest.sh` · `collectionOf`).
