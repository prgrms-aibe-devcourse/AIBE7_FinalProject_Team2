# FE-145 의사결정 기록

## 문제 / 배경
- BE-126 2차(`scriptStatus` · 503 `SCRIPT_UNDER_MAINTENANCE`)가 아직 서버에 없다. 이름은 이슈 설명(READY · PREPARING · MAINTENANCE)을 따르고, 확정되면 `utils/scriptReady.js` 한 곳만 고친다.
- 점검 중 사건도 목록 · 상세에는 보이되 새 체험만 잠가야 하고, 이미 체험 중인 사용자는 끊기면 안 된다.

## 검토한 대안
- A. `loadCaseScript`가 503도 null로 돌려준다: 호출처 6곳이 그대로지만 "준비 중"과 "점검 중"을 구분할 수 없다.
- B. 503은 던지고, 새 체험 입구인 사건 상세에서만 잡는다: 구분이 되고 호출처 변경이 한 곳이다.

## 선택한 방법과 이유
- B. 점검 중 판정은 `scriptStatusOf`(`scriptStatus` → `scriptReady` → 로컬 대본 순)로 모으고, `isScriptReady`는 READY일 때만 true라 목록 · 커뮤니티는 코드 변경 없이 같은 기준을 쓴다.
- 사건 상세는 `scriptStatus`가 MAINTENANCE이거나 API 18이 503이면 "점검 중" 도장을 찍는다. 하던 · 마친 체험은 기존대로 이어서 볼 수 있다.
- 받아 둔 대본은 `loadCaseScript`가 기억하므로, 받은 뒤 점검이 켜져도 새로고침 전까지 끊기지 않는다.
- 목 API: 사건 2를 MAINTENANCE로 두고 API 18은 503 코드를 준다.

## 고려한 제약 사항
- 새로고침하면 기억한 대본이 사라져, 점검 중에 체험 화면을 새로고침하면 각 화면의 "다시 시도" 안내가 나온다. 대본을 저장해 두는 것은 범위 밖이다.

## 추후 재검토가 필요하면
- BE-126 2차 PR이 머지되면 `scriptStatus` 이름과 503 형식이 같은지 확인한다.
