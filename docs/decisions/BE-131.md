# BE-131 의사결정 기록

## 문제 / 배경
- 원본 판결문 정보(`case_source`)의 법원명을 꺼내는 `case-extractor/deidentify.py` `extract_source_info`가 **판결문 전체에서 처음 나오는 법원명**을 썼다.
- 실제 판결문 머리는 PDF에서 "○ ○ 지 방 법 원"처럼 글자 사이가 띄어지거나, 한 줄에 한 자씩 나오거나, "○○지법"처럼 약칭으로 시작한다. 이 경우 정규식이 머리를 못 찾고 본문의 판례 인용(대법원 등)을 잡거나 비워 뒀다.
- 실제 판례 21건 중 16건이 이 문제로 잘못 적재됐다(잘못된 값 9 · 빈 값 7). 관리자 화면(A-6 · A-7)에만 보이는 값이라 사용자 영향은 없다. 운영 데이터는 비공개 저장소 수정 SQL로 따로 고친다.

## 검토한 대안
- A. 기존 정규식에 글자 사이 공백(`\s*`)을 넣는다: 띄어 쓴 머리는 잡지만, 한 줄에 한 자씩 나온 머리 · 약칭은 못 잡고, 머리에 없으면 여전히 본문 인용을 잡는다.
- B(선택). **머리에서만 찾는다.** 앞쪽 줄을 공백 없이 보고 줄 전체가 법원명인 줄 → 약칭 줄 → 공백을 지운 앞부분(대법원 제외) 순서로 찾고, 없으면 비워 둔다.

## 선택한 방법과 이유
- 본문의 다른 법원명을 잡는 것보다 비워 두는 편이 안전하다. 빈 값은 파이프라인 설정 `sources[]`로 사람이 채울 수 있지만, 틀린 값은 눈에 띄지 않는다.
- 상고심 머리 "대 법 원"은 줄 전체가 법원명이라 1단계에서 잡힌다. 3단계(공백을 지운 앞부분)에서는 대법원을 빼고 찾는다 — 여기서 나오는 대법원은 판례 인용이다.
- 실제 판례 21건 원문으로 확인: 20건이 원문 머리에서 확인한 값과 일치, 1건은 2단 PDF에서 머리 글자가 다른 글자와 섞여 비워 둔다(수정 SQL에서 직접 넣음).

## 고려한 제약 사항
- 같은 `COURT` 정규식을 비식별화 가리기(`MASK_RULES` "법원명")에도 쓰지만 이번 범위에서는 바꾸지 않았다. 가리기 동작을 바꾸면 모든 사건의 모델 입력이 달라진다. 원문 단계는 유료 키로만 보내는 원칙(README)이 유지된다.

## 추후 재검토가 필요하면
- 가리기 쪽도 띄어 쓴 머리 법원명을 가릴지(모델 입력에 법원명이 남는 문제)는 별도 이슈로 판단한다.
