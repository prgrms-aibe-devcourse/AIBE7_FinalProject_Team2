# BE-71 의사결정 기록

> 확장 단계(WBS 7.2.3) · PR #129 · 담당 백승호

## 문제 / 배경
- 구조화 로그(JSON) + traceId 전파 + Loki 적재를 구현해야 했다. WBS 7.2.3은 수집기로 "Promtail(또는 Grafana Alloy)"를 모두 허용하고 있었다.
- traceId를 요청마다 생성·전파하고, 로그로 추적할 수 있어야 했다.
- 비밀번호·토큰·이메일 같은 민감정보가 로그에 그대로 남으면 안 됐다.

## 검토한 대안
- **로그 수집기: Promtail vs Grafana Alloy**: WBS가 둘 다 허용했으므로 어느 쪽을 쓸지 정해야 했다.
- **traceId를 Loki 라벨로 둘지, 로그 내용(JSON 필드)으로만 남길지**: 라벨로 두면 `{traceId="..."}`로 바로 필터링할 수 있지만, 요청마다 달라지는 고유값이라 카디널리티 문제가 있었다.
- **X-Request-Id 헤더 처리**: 클라이언트가 보낸 값을 검증 없이 그대로 재사용할지, 형식을 검증한 뒤에만 재사용할지 검토했다 (#129 리뷰).
- **컨테이너 파일 권한 범위**: 비루트(`spring`) 사용자에게 `/app` 전체 소유권을 줄지, 로그 디렉터리만 줄지 검토했다 (#129 리뷰).

## 선택한 방법과 이유
- **Promtail 대신 Grafana Alloy**를 선택했다. Promtail은 2026-03-02에 공식 EOL(지원 종료)됐고(커뮤니티 LTS 2025-02~, 상용 지원 종료 2026-02-28), 새로 시작하는 작업에 이미 수명이 끝난 도구를 쓸 이유가 없었다. 역할(로그 파일 tail → Loki push)은 동일해 교체 비용도 크지 않았다.
- **traceId는 Loki 라벨로 쓰지 않는다.** BE-66에서 Prometheus 메트릭에 사건 ID·체험 ID를 태그로 쓰지 않은 것과 같은 이유로, 라벨로 쓰면 스트림이 무한히 늘어난다. traceId는 JSON 필드로만 남기고, 조회는 `{job="backend"} | json | traceId="..."`로 한다. 라벨로 두는 건 `job`·`level`처럼 값의 종류가 적은 것뿐이다.
- `TraceIdFilter`를 `Ordered.HIGHEST_PRECEDENCE`로 등록해 관리자 세션·사용자 Bearer 두 보안 필터 체인보다 먼저 실행되게 했다. 모든 요청에 예외 없이 traceId가 붙어야 하기 때문이다.
- (리뷰 반영) `X-Request-Id`는 형식(영숫자·점·밑줄·하이픈, 64자 이하)을 검증한 뒤에만 재사용하고, 아니면 새로 생성하도록 했다. 클라이언트가 임의 문자열을 보내 로그 줄을 조작하거나 추적을 흐릴 수 있었기 때문이다.
- (리뷰 반영) `/error` 재디스패치에서도 `TraceIdFilter`가 다시 실행되도록 해, 최초 요청 때 응답 헤더에 써 둔 traceId를 에러 응답에서도 그대로 재사용하게 했다.
- (리뷰 반영) 콘솔 로그에도 파일(JSON)과 같은 수준의 마스킹을 적용했다. 운영에서 `docker logs`로 콘솔 로그가 그대로 노출될 수 있어, 파일만 마스킹하면 우회 경로가 남는다. 마스킹 정규식은 공용 property로 묶어 파일·콘솔이 같은 규칙을 쓰게 했다.
- (리뷰 반영) 컨테이너에서 `/app/logs`만 `spring` 소유로 바꾸고 `app.jar`는 계속 root 소유로 남겼다. 비루트 프로세스가 실행 파일 자체를 바꿔치기하지 못하게 하기 위한 최소 권한 원칙이다.

## 고려한 제약 사항
- 운영 이미지가 root로 `/app`을 만든 뒤 비루트(`spring`)로 전환하는 구조라, 로그 디렉터리를 만들 권한이 없어 Logback 설정 예외로 기동 자체가 실패하는 문제가 있었다. `USER spring` 전환 전에 `/app/logs`를 만들고 소유자를 바꿔 해결했다.
- 애플리케이션 포트(8080)에는 영향이 없어야 했고, 로그 파일은 `backend/logs/`(gitignore 추가)에만 생성되게 했다.
- Loki(`3100`)도 Prometheus(`9090`)와 동일하게 로컬에서만 접근 가능하도록 `127.0.0.1` 바인딩으로 제한했다.
- 운영 적용(백엔드 컨테이너와 로그 파일 공유 방식, Grafana Cloud 로그 전송 여부)은 BE-70(PR #120) "D와 협의할 것"과 같은 범위로 묶어 별도로 진행하기로 했다.
