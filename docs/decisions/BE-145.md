# BE-145 의사결정 기록

카카오로 처음 가입하는 사람이 **약관에 동의해야 회원이 만들어지게** 하고, 그 전에 가입한 회원(카카오 회원 · BE-133 이전 아이디 회원)은 다음 로그인 때 동의를 받는다. 담당 D(정민석), 방향 결정 A(김해송).

## 문제 / 배경

- 아이디 가입(M-5)은 BE-133에서 약관 동의를 가입 요청에 넣어 **동의해야 회원이 만들어진다.** 카카오는 첫 로그인(M-4)에서 회원 행이 먼저 만들어지고 그 전에 동의를 묻는 화면이 없다. 가입 화면의 "카카오로 시작하기"도 동의 줄보다 위에 있어 체크 없이 누를 수 있다(BE-133 결정 5, 후속으로 남김).
- 그래서 카카오 회원은 `terms_agreed_at` · `terms_version`이 NULL이다. NULL은 "동의 기록이 없다"는 뜻이다(BE-133 결정 4).
- 카카오 로그인은 동의항목(scope)을 요청하지 않아 **카카오 회원번호만** 받는다. 닉네임 등 개인정보는 받지 않는다(BE-62). 이번에 저장 · 보관하는 값도 이 회원번호뿐이다.

## 검토한 대안

### 1. 동의 방식 (BE-133이 남긴 후보)

- A — 카카오 버튼 아래 "시작하면 약관에 동의한 것으로 봐요" 안내 + 첫 로그인 때 자동 기록: 가볍지만 명시 동의가 아니라 개인정보 수집 동의로는 약하다.
- B — 동의 창에서 직접 동의해야 한다 (**선택**): 아이디 가입과 같은 수준의 명시 동의다. 해송님과 같은 의견(A는 개인정보 수집 동의로 약하다).

### 2. 동의를 받는 시점

- (가) 로그인 뒤 동의 창을 띄운다: 첫 로그인 때 회원 행이 먼저 만들어지고 그 뒤에 동의를 받는다. 구현은 가볍다(`termsRequired`만 있으면 된다). 하지만 **동의 전에 회원 행(카카오 회원번호)이 DB에 생긴다.**
- (나) 가입 대기 후 동의해야 회원을 만든다 (**선택**, 해송님 요청 "동의해야 회원가입 할 수 있게"): 처음 온 계정은 회원 행 없이 가입 대기만 두고, 동의 창에서 [동의하고 시작]을 눌러야 회원과 동의 기록이 한 번에 만들어진다. 아이디 가입과 같은 순서다.
- 비용: M-4의 동작이 바뀐다(처음 온 계정은 토큰 없이 동의 창으로 간다). 그래서 서버와 화면을 한 PR로 낸다(BE-133과 같다). 서버만 먼저 나가면 새 카카오 가입이 동의 창이 없어 막힌다.

### 3. 가입 대기를 어디에 두나

- DB 테이블(예: `member_signup_pending`): 동의하지 않고 떠난 대기를 지우는 배치가 필요하고, 동의 전 값이 DB에 남는다.
- Redis 토큰 DB + TTL (**선택**): 값은 사라지는 곳에 둔다. OAuth state(`OAuthAuthorizationRequestRepository`)와 같은 방식이라 새 위험이 없다 — 값은 Redis에, 브라우저에는 찾는 무작위 문자열만 짧은 HttpOnly 쿠키로 주고, 꺼낼 때 GETDEL로 한 번만 쓴다. 동의하지 않으면 DB에 아무것도 남지 않는다.
- 보관 시간은 **10분**이다. 약관을 읽고 누르는 시간을 넉넉히 주되 오래 두지 않는다(OAuth state는 5분).

### 4. 기존 회원

- 이번에는 새 가입만 고치고 기존 회원은 NULL로 둔다: 추정값을 동의 기록처럼 남기지 않는다는 BE-133 원칙에는 맞지만, 동의 기록이 없는 회원이 계속 남는다.
- 같은 PR에서 재동의까지 한다 (**선택**): M-8에 `termsRequired`(동의 기록이 없으면 true)를 더하고, 동의 창 → M-14로 기록한다. 대상은 카카오 회원과 BE-133 이전 아이디 회원이다. 창을 닫으면 로그아웃이다(첫 로그인 가져오기 창과 같은 닫기 동작). 이미 동의한 회원의 기록은 바꾸지 않는다.
- 이 회원들은 동의하지 않으면 로그인을 유지할 수 없다. 해송님이 의도라면 괜찮다고 확인했다.

### 5. 서버가 동의를 다른 API의 조건으로 걸까

- 가져오기(M-9 ~ M-11) 등에 서버가 동의를 확인하고 `TERMS_REQUIRED`로 거절한다: 3차 c(BE-140) 코드를 고쳐야 하고 BE-140과 BE-145가 서로 묶인다.
- 걸지 않는다 (**선택**, 해송님 제안): 두 기능이 독립으로 남고, 순서(동의 → 가져오기)는 화면이 지킨다. 한계는 아래에 적었다.

### 6. 순서와 닉네임

- **동의 → 가져오기.** 가져오기는 "이 계정으로 기록을 옮기는" 일이라 동의가 먼저여야 앞뒤가 맞다.
- 동의 창에서 닉네임도 받을까: 이번에는 넣지 않았다. 카카오 회원은 가입 뒤 M-7로 닉네임을 정한다(그 전에는 `방청객 {회원 ID}`). 필요해지면 동의 창에 칸을 더하고 M-12 요청에 `nickname`을 더하면 된다 — 중복(409)과 형식 검사가 가입 요청 안으로 들어와 창과 API가 커진다.

## 선택한 방법과 이유

- 서버
  - `OAuthLoginSuccessHandler`: 이미 가입한 회원(`MemberLoginService.loginExisting`)이면 지금처럼 로그인한다. 처음 온 계정이면 회원도 토큰도 만들지 않고 가입 대기(`KakaoSignupPending`)를 만든 뒤 `/auth/callback?signup=terms`로 보낸다.
  - M-12 `POST /api/v1/auth/kakao/signup`: 동의 검사(400)가 먼저, 그다음 가입 대기를 한 번만 꺼내 회원과 동의 기록을 한 트랜잭션으로 만들고(`signupWithTerms`) 로그인한다. 같은 계정의 가입 대기가 둘이어도(두 탭) 회원은 하나다(`ON CONFLICT DO NOTHING`).
  - M-13 `DELETE /api/v1/auth/kakao/signup`: 가입 대기를 지운다. 이미 없어도 204.
  - M-8 `termsRequired`, M-14 `POST /api/v1/members/me/terms-agreement`(별도 컨트롤러 `MemberTermsController`). `member.agreeTerms`는 이미 동의한 기록을 바꾸지 않는다.
  - M-12 · M-13은 리프레시 쿠키를 심거나 쿠키로 요청하므로 Origin 검증 대상에 넣었다(M-5 · M-6과 같다). Nginx는 아이디 가입과 같은 IP별 가입 제한(`member_signup_per_ip`)을 건다 — 해시를 쓰지 않아 합계 제한은 없다.
  - **스키마 변경이 없다.** V44의 두 칸을 그대로 쓴다.
- 화면: 카카오 콜백 화면이 `?signup=terms`면 재발급 대신 동의 창을 띄우고, 로그인 뒤(카카오 콜백 · 아이디 로그인 두 경로)에는 `termsRequired`가 true일 때 같은 창을 띄운다. 이 창은 가져오기 창(FE-138) 앞에 온다.
- 테스트 변경: `MemberLoginServiceTest`가 "카카오 첫 로그인으로 만든 회원은 동의 칸이 NULL"을 고정해 두었다(BE-133이 "후속 이슈에서 바뀌면 이 테스트도 바꾼다"고 적어 둠). 지금은 "동의하고 가입한 회원은 시각 · 버전이 함께 남는다"와 "처음 온 계정은 로그인만으로 회원이 만들어지지 않는다"로 바꿨다.

## 고려한 제약 사항

- **동의 전에 남는 것**: DB에는 아무것도 없다. Redis에 카카오 회원번호 하나가 최대 10분 있고, 동의하지 않고 닫으면 지운다. 브라우저에는 회원번호를 내리지 않는다(무작위 문자열만).
- **가입 대기를 꺼낸 뒤 실패하면** 그 대기는 이미 쓰인 것이라 카카오 로그인부터 다시 한다. 되살리지 않는다(재사용 방지가 우선).
- **서버가 동의를 강제하지 않는다**: 동의하지 않은 회원도 토큰으로 API를 직접 부르면 쓸 수 있다(지금도 같다). 동의 기록이 서버에 있어 동의한 회원과 아닌 회원은 구분된다. 모든 회원 API에 강제하려면 별도 이슈로 다룬다.
- **내 회원 정보(M-8)를 못 받으면** 화면은 동의 창 없이 로그인을 이어 간다(가져오기 창과 같다 — 로그인을 막지 않는다). 서버도 동의를 다른 API의 조건으로 걸지 않으므로, 이 경우 `termsRequired`인 회원이 다음 로그인 때 다시 묻게 된다.
- **동의한 직후 재발급이 실패하면**(M-12는 성공했는데 M-1이 실패) 가입 대기는 이미 쓰여 다시 동의하면 409 `KAKAO_SIGNUP_EXPIRED`가 난다. 회원은 이미 만들어졌으니 화면은 "카카오 로그인을 처음부터 다시 해 주세요"로 안내하고, 다시 로그인하면 이미 가입한 회원으로 바로 들어간다(`completeLogin`이 남은 리프레시 쿠키를 로그아웃으로 지운다).
- **약관 문서가 법무 검토 전 초안**이라 기록되는 버전도 `2026-10-draft`다. 문서가 확정되어 버전이 바뀌면 이미 동의한 회원에게 다시 묻는 일은 BE-133이 "약관 개정 · 재동의"로 남긴 별도 이슈다.
- **배포**: 서버와 화면을 한 PR로 낸다. 새 화면이 나가기 전에 열려 있던 탭에서 카카오 첫 가입을 하면 예전 화면은 재발급을 불러 "카카오 로그인을 마치지 못했어요" 안내가 나온다(이미 가입한 회원의 로그인은 영향이 없다). 새로고침하면 새 화면이 받는다.
- **API 명세 번호**: v0.79 · v0.80 · v0.85 · v0.86이 다른 작업에 쓰여 v0.87이다. ERD는 스키마가 같아 v1.55에 설명만 고쳤다.

## 추후 재검토가 필요하면

- 가입 때 닉네임 입력(위 6번), 약관 개정 시 재동의, 서버의 동의 강제.
