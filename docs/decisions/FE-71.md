# FE-71 의사결정 기록

> 확장 단계 · 담당 김해송 (A) · 관련: BE-96 (PR #230), BE-97 (PR #227), FE-68, BE-83

## 문제 / 배경
- FE-68은 꾸미기를 브라우저(localStorage)에 저장하고, 도전과제 진행도 · 열린 항목을 프론트(`statsOf` · `achievementProgress` · `unlockedBy`)에서 계산했다.
- BE-96이 꾸미기 저장(`PUT /profile-deco`, P-7)과 도전과제 판정(P-5 `profileDeco` · `achievements` · `unlocked`)을 서버로 옮겼고, BE-97이 출석 기록(`POST /attendance`, P-6)을 추가했다. 서버 계약은 [BE-96](BE-96.md) · [BE-97](BE-97.md)에 있다.
- 판결 체험 화면(`verdictPage.js`)이 책갈피 얼굴 · 리본 색을 localStorage에서 **동기로** 읽는다. 책갈피 설정도 서버가 원본이 되면서 이 읽기를 어떻게 이어 갈지 정해야 했다.

## 검토한 대안

### 1. 고른 꾸미기를 어디서 들고 있을까
- 대안 A: 화면이 서버 응답을 기다린 뒤에야 바꾼다(고를 때마다 PUT이 끝나길 기다림). 클릭마다 0.2초 이상 멈춰 보이고, 라디오 칸이 되돌아가는 깜빡임이 생긴다.
- **대안 B(선택): 고르면 바로 화면 값(`cache.profileDeco`)에 반영하고 PUT은 뒤에서 보낸다. 거절되면 서버 값으로 되돌린다.** 지금처럼 고르면 바로 바뀌는 느낌이 그대로다.

### 2. 저장 요청 보내기
- 대안 A: 고를 때마다 바로 보낸다. PUT은 전체를 덮어쓰므로 응답 순서가 바뀌면 옛 값이 이긴다.
- **대안 B(선택): 한 번에 하나씩 순서대로 보낸다(`saveQueue`).** 거절이 나면 줄 선 나머지는 건너뛰고(`saveEpoch`) 서버 값으로 다시 그린다.

### 3. 거절됐을 때
- 대안 A: 에러만 알린다. 화면에 서버가 받지 않은 값이 남는다.
- **대안 B(선택): 마이페이지를 다시 불러 서버 값으로 다시 그리고, 이유를 알린다.** 명세 P-7의 "409면 마이페이지를 다시 불러온다"와 같다. 열려 있는 꾸미기 창은 옛 선택을 들고 있어서 닫는다. 409는 `details[].field`로 어떤 칸이 잠겼는지 알린다.

### 4. 책갈피 설정을 판결 체험 화면에 전하는 방법
- 대안 A: 판결 체험 화면도 서버에서 읽는다. 화면마다 마이페이지(P-5)를 불러야 하고, 읽기가 비동기가 된다.
- **대안 B(선택): localStorage를 서버 값의 거울로만 남긴다(`applyBookmark`).** 마이페이지에서 서버 값을 받을 때와 고를 때 거울을 맞춘다. 판결 체험 화면 코드는 그대로 둔다.

### 5. 도전과제 표를 프론트에 남길까
- **선택: 목표 · 보상 · 처음부터 열린 것은 프론트에서 지우고 서버 응답만 쓴다**(BE-96 협의 결정). 프론트에는 id → 제목 · 문구(`ACHIEVEMENT_TEXT`)만 남는다. 서버에 새 id가 생기면 id를 제목으로 보여 준다.
- 목 모드도 서버처럼 보이도록 표를 `mocks/profileDecoMockData.js`로 옮겼다(목 서버의 표). 화면 쪽 표와 어긋나지 않는지 `profileDeco.test.js`가 확인한다.

### 6. 브라우저에 있던 기존 꾸미기
- 대안 A: 처음 한 번 서버로 올려 준다. 서버는 "저장한 적이 없음"과 "기본값을 저장함"을 구분해 주지 않아 올릴 시점을 알 수 없고, 잠긴 값이 섞이면 거절될 수 있다.
- **대안 B(선택): 올리지 않고 서버 값을 따른다.** 꾸미기는 FE-68(2026-10-21)에서 처음 나왔고 아직 운영 사용자가 없다. localStorage의 옛 꾸미기 값(`nlnb-profile-deco`)은 더 읽지 않는다.

### 7. 출석 기록을 부르는 위치
- BE-97 기록대로 "사이트 진입 시 한 번"이다. 앱이 시작될 때 `main.js`에서 한 번 부르고, 같은 날 다시 불러도 서버가 하루로 센다.
- 실패해도 화면은 그대로 쓸 수 있어서, 에러 화면으로 이동시키는 `createAppApi` 바깥(기본 api)에서 불러 조용히 넘긴다.
- **첫 방문날 출석(#233 리뷰)**: 처음 온 사용자는 앱 시작 때 쿠키가 없어 출석이 기록되지 않았다. 프런트에서 쿠키를 만드는 요청 뒤에 출석을 다시 부르는 임시 보정을 넣었다가, 서버가 익명 ID를 발급할 때 출석도 함께 기록하도록 바뀌어(BE-98, PR #234) 보정을 지웠다. 프런트는 앱 시작 때 한 번만 부른다.

## 선택한 방법과 이유
- 서버 계약대로 연동하고, 서버가 판정하는 것은 화면에서 계산하지 않는다. 화면에는 열려 있는데 저장은 거절되는 일이 없도록 열린 항목은 `unlocked`만 따른다.
- 수집 도전과제 2개(`status: PENDING`)는 "준비 중"으로 보이고 보상은 잠김이다(BE-83 전까지).
- 마이페이지 수치의 출석 일수는 서버 값이다. 레벨 · 직업은 아직 목이다.

## 고려한 제약 사항
- 판결 체험 화면의 책갈피는 거울(localStorage)을 읽으므로, **다른 기기에서 고른 책갈피는 이 기기에서 마이페이지를 한 번 열 때까지 반영되지 않는다.**
- 출석은 쿠키(익명 ID)가 있을 때만 기록된다(BE-97). 아무것도 하지 않고 떠난 첫 방문은 출석에서 빠진다.
- 저장은 낙관적이라, 네트워크가 끊겨 마이페이지도 다시 못 받으면 고른 값이 화면에만 남는다(새로 고치면 서버 값으로 돌아온다).
- 마이페이지의 "완료한 사건" 수치는 지금 기록으로 세고, 도전과제 `completed`는 서버 기준(완료한 회차가 하나라도 있는 사건 수)이라 다시 하기 중에는 값이 다를 수 있다(BE-96 결정 기록 참고).

## 추후 재검토가 필요하면
- 저장값이 잠겨 409가 반복되는 경우는 BE-98이 서버에서 해결했다(저장값과 같은 칸은 잠김 검사를 건너뛴다). 목 서버(`profileDecoMockApi.js`)도 같은 규칙을 따른다.
- 로그인 연동(BE-62 이후)에서 앱 시작 때 책갈피 설정을 서버에서 받아 거울을 맞출지.
- BE-83이 수집 상태를 저장하면 수집 도전과제 판정이 열린다. 화면 쪽 `collected` 계산은 그때 서버 값으로 바꾼다.
- "새로 열림" 알림(BE-83과 함께 검토).
