# BE-52 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #105 본문과 `docs/sentencing-guideline-rag.md`.

## 문제 / 배경
- 결정 문서 8-1에서 양형기준 검색은 "RAG와 바로 찾기 중 정한다"로 남아 있었다.

## 검토한 대안
- 대안 A: 바로 찾기(범죄 유형 · 버전으로 직접 조회).
- 대안 B: RAG(임베딩 검색) + 형량범위 같은 구조 값은 같은 테이블의 `meta`로 바로 읽기.

## 선택한 방법과 이유
- 대안 B. 범죄 유형이 늘어도 행만 늘고 구조 · 코드는 그대로이며, 판례 저장소(V11)와 같은 스택(pgvector · `gemini-embedding-001` 3072)을 쓴다.
- 양형기준은 버전(2009 최초 ~ 2026 수정)마다 달라서 기준일에 맞는 버전을 고르는 함수 `sentencing_guideline_at`을 둔다. 매칭 기준은 공소제기일, 없으면 발생일이다. 판례 검색은 같은 버전을 우선한다.
- 시행일은 현행 페이지의 개정 이력을 정본으로 교차 검증한다. 임베딩은 바뀐 조각만 다시 만들고, 임베딩이 없거나 낡으면 시드 SQL을 만들지 않는다.
- 데이터(R__41, 약 9.7MB)는 판례와 같이 비공개 시드에 둔다.

## 고려한 제약 사항
- 버전 경계 오차는 사소해 감수했다(바꿔도 됨).
- `top_k` · `min_score`는 임시값이며 샘플 사건으로 BE-54에서 정한다.
- 같은 (crime_category, version_name)이 이미 중복된 로컬 DB는 V13 유니크 추가가 실패하므로 DB를 비워야 한다.
