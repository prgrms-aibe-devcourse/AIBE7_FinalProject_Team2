# FE-125 의사결정 기록

> 근거: BE-116(`scriptReady`, `docs/decisions/BE-116.md`) · FE-33(서버 대본 소비, 별도) · FE-56(준비 중 도장) · FE-119(신문 면 구성)

## 문제 / 배경

- "체험 가능 / 준비 중" 판정이 세 곳(`caseListPage` 정렬 · 포스트잇, `caseDetailPage` S-20, `communityHomePage`)에 흩어져 있고, 모두 프론트에 든 로컬 대본(`scriptFor`)으로 정한다.
- BE-116으로 API 1 · 16이 `scriptReady`를 주므로 판정 기준을 서버로 옮긴다. 다만 서버 대본을 화면에 그리는 일(FE-33)은 아직 없어, 1막 무대는 여전히 로컬 대본이 있어야 그려진다.

## 검토한 대안

- A. 로컬 판정을 걷고 `scriptReady`만 쓴다: 가장 단순하지만 목 · 구버전 응답 · 값이 없는 사건 요약(커뮤니티)에서 전부 "준비 중"이 된다.
- B(선택). **서버 값이 있으면 그 값, 없을 때만 로컬 대본으로 판정**(`utils/scriptReady.js` `isScriptReady`). 세 화면이 같은 함수를 쓴다. FE-33이 로컬 대본을 걷을 때 대체 한 줄만 지우면 된다.
- C. 서버 `true` 또는 로컬 대본이 있으면 체험 가능(OR): 서버가 `false`여도 로컬 대본이 있는 사건이 열려, "기준이 서버"라는 이슈 목적과 어긋난다.

## 선택한 방법과 이유

- S-20은 `ready && 로컬 대본`이면 1막 무대(`drawStage`), 그 밖에는 지면(`drawPaper`)이다. `drawPaper`에서 `ready`면 "시작하기"를 열고 아니면 점선 "준비 중"으로 막는다(하던 · 마친 체험은 `myStatus`로 이어서 볼 수 있다).
- 목(mock)은 대본이 있는 사건 1만 `scriptReady: true`로 두어(`getCasePaper`와 같은 기준) 화면 동작이 이전과 같다.

## 고려한 제약 사항

- 서버는 `scriptReady`로 체험 시작을 막지 않는다(화면 정책, BE-116 리뷰). 직접 API 2를 부르면 시작된다.
- 대사 수정(A-13-13)으로 체험 중 `true → false`가 될 수 있다. 이때 S-20은 `myStatus`가 있으면 지면의 "이어서 하기"가 남는다.

## 추후 재검토가 필요하면

- 서버 `true`인데 프론트에 대본 무대가 없으면 "시작하기" 뒤 S-03이 "대본 없음" MVP 화면(첫인상)으로 간다. FE-33이 서버 대본을 무대로 그리면 해소된다.
- 서버가 `false`로 내려주는 사건 1(로컬 대본 있음)은 S-20이 "준비 중"이 된다. 사건 1의 대본이 서버에 승인돼 있어야 시연에 지장이 없다.
