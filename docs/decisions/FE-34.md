# FE-34 의사결정 기록

> [FE-34](https://aibe7-team2-final.atlassian.net/browse/FE-34) · 프론트 막대그래프는 FE-120에서 목 데이터로 먼저 만들었고, 이 작업은 그 자리에 들어갈 실제 집계 API다.

## 문제 / 배경

- 8막 독자 의견란에 "이 사건 독자들의 첫인상 분포"를 보여 주는 막대그래프가 있는데, 값이 목 전용(`preToFinal.crowd`)이었다.
- 사용자가 모일 때 쓸 수 있도록 API 14에 실제 집계를 붙여야 했다. 통계에는 1회차만 센다(요구사항 DR-7).

## 검토한 대안

- 별도 API(`GET /cases/{id}/crowd`)로 분리: 화면이 이미 `preToFinal`에서 `crowd`를 읽고 있고, 사전 판단은 완료 후 API 14에서만 공개한다는 원칙이 있어 같은 응답에 넣는 쪽이 일관된다. 프론트 API 모드는 값을 그대로 넘기면 된다.
- 집계 결과를 테이블이나 캐시에 저장: 지금은 사건당 사전 판단이 적고 인덱스 한 번 훑는 `group by`면 충분해 제외했다. 사용자가 크게 늘면 다시 본다.
- 숨김 기준 인원(예: 30명 미만이면 `crowd: null`): 논의 결과 일단 두지 않기로 했다. 한 명뿐이면 100%로 보이는 어색함은 있지만, 기준을 정하는 비용이 더 크다고 봤다.
- 사전 판단을 내지 않은 체험도 분모에 포함: 낸 사람만 센다. 분포의 의미가 "고른 구간의 비율"이기 때문이다.
- 반올림만 하기: 합이 99나 101이 되어 막대 옆 숫자를 더하면 어긋난다. 최대 잔여법으로 합을 100에 맞췄다.

## 선택한 방법과 이유

- API 14 `preToFinal.crowd { total, options[{rangeOptionId, label, percent}] }`로 내린다. 프론트가 이미 기대하던 모양과 같다.
- 구간은 사건 범죄 유형의 전부를 표시 순서대로 내린다(0명 구간 포함). 막대그래프가 구간 전체를 한 줄씩 그리기 때문이다.
- 집계는 `JudgmentRepository.countPreJudgmentsByRangeOption`(사건 · USER · PRE · 1회차 `group by` 구간)이고, 비율 계산은 `CrowdPercents`로 분리해 단위 테스트했다.

## 고려한 제약 사항

- 사전 판단은 완료 후 API 14에서만 공개된다. 이 필드도 같은 `COMPLETED` 이후 조회 제한 안에 있다.
- DB 스키마 변경 없음.

## 추후 재검토가 필요하면

- 사용자가 늘면 숨김 기준 인원 도입 여부, 집계 캐시.
- 회원 ID 전환(BE-115 계열) 뒤에도 회원 · 익명 체험이 모두 `experience`에 있어 같은 쿼리로 센다. 이관 정책이 바뀌면 중복 집계를 점검한다.
