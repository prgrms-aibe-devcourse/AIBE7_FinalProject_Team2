# FE-74 의사결정 기록

> 근거: PR #235 · BE-62(PR #229) · API 명세 10장 M-1 ~ M-4

## 문제 / 배경
- BE-62(PR #229)에서 카카오 로그인이 생긴다. 서버는 로그인을 마치면 리프레시 토큰 쿠키(`NLNB_RT`)만 심고 화면 `/auth/callback`으로 보낸다. 토큰은 URL에 싣지 않는다(API 명세 10장 M-3 · M-4).
- 화면은 콜백에서 M-1 재발급으로 첫 액세스 토큰을 받고, 401이 오면 다시 받아야 한다. 로그인 표시(`nlnb-session`)도 서버 상태에 맞춰야 한다.
- 회원 정보에 개인정보를 두지 않아 서버 닉네임이 없다 → 고정 문구 "카카오 회원"으로 표시한다(PR #229 합의).

## 검토한 대안
- 액세스 토큰 보관
  - 대안 A: localStorage. 새로고침해도 남지만 XSS에 그대로 노출된다.
  - 대안 B: 메모리(`api/client.js` 모듈 변수). 새로고침하면 사라지지만 401 → 재발급으로 다시 받는다. API 명세 10장이 정한 방식이다.
- 401 재발급 위치
  - 대안 A: 화면마다 401을 잡아 재발급한다. 화면 수만큼 같은 코드가 생긴다.
  - 대안 B: 공통 `request()`에서 한 번 재발급하고 같은 요청을 다시 보낸다. 화면은 몰라도 된다.
- 동시에 여러 요청이 401을 받을 때
  - 대안 A: 요청마다 재발급한다. 리프레시 토큰이 재발급마다 로테이션돼 두 번째 재발급이 401이 되고 로그아웃된다.
  - 대안 B: 진행 중인 재발급 약속 하나를 같이 기다린다. 이미 새 토큰을 받은 뒤에 끝난 401은 재발급 없이 새 토큰으로 다시 보낸다.
- 카카오 버튼의 api 모양
  - 대안 A: `api.startKakaoLogin` 같은 새 함수. 로그인 화면이 목 · 실제를 나눠 처리해야 한다.
  - 대안 B: 목과 같은 `login({ method: 'kakao' })`. 실제 구현은 M-3으로 브라우저를 이동시키고 끝나지 않는 약속을 돌려준다. 로그인 화면은 거의 그대로다.

## 선택한 방법과 이유
- 토큰은 **메모리(B)**, 재발급은 **공통 `request()`(B)**, 동시 401은 **하나로 묶기(B)**, 카카오 버튼은 **`login` 이름 유지(B)**.
- 재발급 · 로그아웃(`/auth/...`) 자신의 401은 다시 시도하지 않는다(무한 반복 방지). 다시 보낸 요청이 또 401이면 그대로 던진다.
- 토큰도 로그인 표시도 없으면(로그인한 적 없음) 401에 재발급하지 않는다. 리프레시 쿠키가 없어 항상 실패하는 요청이다(PR #235 리뷰).
- 재발급 중에 로그아웃하면 늦게 끝난 재발급이 토큰을 되살리지 않게, 로그아웃마다 세대 번호를 올리고 그 전에 시작한 재발급 결과는 버린다(PR #235 리뷰).
- 로그인 표시 삭제는 **재발급이 401일 때만** 한다. 연결 오류 · 5xx로 지우면 잠깐 끊긴 사이 로그아웃된 것처럼 보인다.
- 실제 모드의 아이디 · 비밀번호 칸은 관리자 로그인만 된다. 회원 로그인이 생겨 관리자 쪽 오류를 넘기던 규칙이 실제 모드에서 켜지지 않도록, 실제 모드에서는 관리자 오류를 그대로 알린다.
- 카카오 화면에서 뒤로 와 로그인 화면이 bfcache로 복원되면 버튼이 눌린 채 남는다 → `pageshow`(persisted)에서 `LOGIN_CANCELLED`로 끝내고, 로그인 화면은 오류 문구 없이 버튼만 되살린다.
- 라우터 시작 시 `history.replaceState`가 경로만 남겨 `?error=login_failed`가 지워졌다 → 쿼리 · 해시를 남기도록 고쳤다(옛 주소 이동과 같은 규칙).

## 고려한 제약 사항
- 운영에 `KAKAO_CLIENT_ID`가 이미 있어 #229가 먼저 머지되면 로그인 후 404가 보인다 → #229와 이 PR을 같이 머지한다.
- 백엔드 사용자 API는 지금 모두 `permitAll`이다. 새로고침 뒤에는 토큰 없이 익명으로 요청하고, 회원 전용 API가 생기면 그 401에서 재발급된다.
- 관리자 화면은 별도 클라이언트(`adminClient.js`, 세션 + CSRF)를 써서 이 재발급 흐름의 영향을 받지 않는다.

## 추후 재검토가 필요하면
- 로그인 후 원래 보던 화면으로 돌아가기: 카카오 이동으로 페이지를 떠나 `history.back()`을 쓸 수 없다. 지금은 메인으로 간다. 필요하면 떠나기 전 경로를 sessionStorage에 두는 방식을 검토한다.
- 로그인 성공 뒤 뒤로 가기: 카카오 이동이 `location.assign`이라 기록에 `/login`과 카카오 로그인 화면이 남는다. 메인에서 뒤로 가면 카카오 로그인 화면으로 돌아갈 수 있다(카카오 로그인 창을 거친 경우). `replace`로 바꾸면 이 문제는 없지만 bfcache 복원 처리(뒤로 와 버튼 되살리기)를 못 하는 맞바꿈이라 지금은 `assign`을 유지한다(PR #235 리뷰).
- 리프레시 토큰이 만료돼도 다음 401이 오기 전까지는 헤더에 "카카오 회원"이 남는다. 회원 전용 API가 생기면 앱 시작 시 재발급을 한 번 부를지 검토한다.
- 커뮤니티 · 사건 리뷰 작성자 표시명(`author.nickname`)은 범위 밖(커뮤니티 API에서 결정, `docs/decisions/BE-62.md`).
