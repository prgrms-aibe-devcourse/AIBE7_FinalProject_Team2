# FE-126 의사결정 기록

> 근거: [FE-123 의사결정 기록](FE-123.md)(면 정의 모델) · [FE-119 의사결정 기록](FE-119.md)(면 아홉 개 · 껍데기). FE-119에서 껍데기로 둔 색인 · 성향 테스트 · 오피니언 면에 전용 내용을 채우고, 신문 성향 테스트 지면의 결과 · 이동 연출까지 신문으로 잇는 이슈다.

## 문제 / 배경
- FE-119 이후 색인 · 성향 테스트 · 오피니언 면은 자리와 링크만 있는 껍데기였고, 신문 성향 테스트(`/test/paper`)는 끝나면 서류철 결과(`/test/result`)로 튀어 신문 흐름이 끊겼다.
- 사건이 늘면 색인 한 면에 제목 전체가 한 번에 나오고, 지면 목차는 12면 오피니언으로 갈 수 없었다.
- 신문 성향 테스트 지면에서 다른 면으로 나갈 때는 연출 없이 화면이 바뀌어, 사건 목록 안의 면 넘기기(0.5초)와 결이 달랐다.

## 검토한 대안
- **면 본문 파일**: (A) `caseListPage.js`에 계속 더한다 / (B) DOM 없는 내용 · 계산은 `faceContent.js`(단위 테스트), 그리는 쪽은 `featureFaces.js`로 나눈다. A는 파일이 이미 커서 면마다 테스트할 수 없다.
- **신문 테스트 문항 문구**: (A) 일반 테스트와 같은 문구를 쓴다 / (B) 같은 문항을 "사건사고 단신"으로 바꿔 싣는다 / (C) 문항 자체를 새로 만든다. C는 점수 뜻이 달라져 서버 시드 · 해석 문서를 건드린다.
- **신문 결과 지면**: (A) 서류철 결과를 그대로 쓴다 / (B) 결과 화면을 신문 모양으로 새로 만들되 내용 · 부품은 공유한다.
- **다른 화면으로 넘길 때 연출**: (A) 연출 없이 이동 / (B) 새 화면이 그려진 뒤 그 지면을 본떠 넘긴다 / (C) 누르자마자 장을 넘기기 시작하고 갈 지면이 그려지면 앞면에 붙인다.
- **칸 전체 호버 상자**: (A) `outline` / (B) 칸 `padding`을 재 `::after` 상자 자리를 정한다.
- **포스트잇**: (A) 모든 면에 붙여 둔다 / (B) 1면에만 둔다.

## 선택한 방법과 이유
- **본문 파일은 B.** 갤러리 정렬, 사설 순환, 독자 투고 추리기, 색인 쪽 나눔 같은 계산을 node 테스트로 확인할 수 있다. 면 정의 모델(FE-123)의 "정책은 DOM 없이" 방향과 같다.
- **문구는 B(`content/paperQuestions.js`).** 문항 id · 축 · A/B 방향을 그대로 두고 보이는 문구만 바꾼다. 서버에는 문항 id로 저장되므로 점수 뜻이 같다. 문구 제약(법률 용어 금지, 두 행동 모두 상식적, 진행자 한마디는 어느 쪽에도 기울지 않음)은 파일 머리에 적고 `paperQuestions.test.js`로 지킨다. 근거는 `docs/personality-test-content.md` 3-3.
- **결과 지면은 B(`/test/paper/result`).** 서류철 결과는 일반 테스트가 그대로 쓰고, 신문 테스트만 신문 결과로 간다. 서버 호출 · 부품(`descriptionSections` · `toleranceBlock` · `share` 등)은 공유하려고 `export`만 열었다.
- **연출은 C.** B는 클릭 뒤 0.3 ~ 0.4초 동안 화면이 멈춰 있었다(목 API 지연 + 그리는 시간). 헤드리스로 측정해 C로 바꿨다: 장이 움직이기 시작하는 시점이 0.3 ~ 0.4초 뒤에서 누르자마자로, 끝나는 시점이 약 1.0초에서 약 0.8초로 줄었다. 뒤 쪽 면(12면)은 기다릴 일이 없어 기존 방식(지금 지면이 넘어가며 밑에 갈 화면이 그려짐)을 그대로 쓴다. 갈 곳이 신문이 아니거나 2.5초 안에 못 그리면 넘기지 않고 흐려지며 걷힌다. 애니메이션 부분은 기존 `turnPage`와 같은 코드(`flip`)를 나눠 쓴다.
- **사건 정보 지면에도 같은 넘김(`caseNewspaper`).** 사건 정보(S-20)와 1막 무대가 이 한 함수로 지면을 만들어서, 목차 · "← 다른 사건 보기"에 `leaveByTurn`을 한 번 거는 것으로 둘 다 적용된다. 이 때문에 `leaveByTurn`을 성향 테스트 전용 파일(`personalityParts.js`)에서 `utils/pageTurn.js`로 옮기고, 화면 루트 class를 `scopeClass`로 받게 했다. 3면에서 10면 성향 테스트로 가는 것도 뒤 쪽 면이므로 지금 지면이 넘어가며 10면이 드러난다. 10면은 원래 `from: 'paper'`로 스스로 넘겨 들어왔는데 그러면 방향이 반대로 보여서, 넘기며 갈 때는 `pageIndex`가 `from`을 빼고 보낸다. 헤드리스로 이전으로(앞) · 12면(뒤) · 8면(앞) 네 경로(10면 포함)를 잰 결과 덮개가 클릭 20ms 안에 뜨고 0.55 ~ 0.75초에 걷히며 `/cases`에 도착한다.
- **넘김 덮개는 헤더 아래만(`clip-path`, `--site-header-h`).** 장이 상단 내비를 덮는다는 피드백에 대한 답이다. 사건 목록의 기존 넘기기도 같은 덮개를 쓰므로 함께 고쳐진다.
- **호버 상자는 B(`hoverBox.js`).** 칸마다 단 사이 padding이 달라 `outline`은 상자가 쏠리고 크기가 제각각이었다. 올릴 때 padding을 재는 비용은 작다(창 폭에 따라 값이 바뀌므로 올릴 때마다 잰다).
- **포스트잇은 B.** 오피니언 · 성향 테스트 면에 "눌러 보세요" 문구가 붙던 문제(FE-123 배경)를 구조로 막는다. 떼지 않은 포스트잇은 1면과 함께 넘어가도록 `has-tip`을 지면에 둔다(넘기는 장이 지면을 본떠 만들므로).
- **색인 쪽 나눔은 한 장 20건.** 사건 종류 버튼과 검색을 함께 걸러 나온 결과에 쪽 번호를 단다. 필터나 검색이 바뀌면 1쪽으로 돌아간다. 색인 줄의 분류 글자는 색깔 네모와 종류 버튼이 대신 말해 뺐다. 버튼 이름은 면 이름(살인 · 사기 …)이다. 분류명 "재산범죄"는 강도와 절도가 겹쳐 쓸 수 없다.

## 고려한 제약 사항
- 서버에서 늦게 받는 값(내 성향 결과 · 독자 투고)은 면을 먼저 그린 뒤 채운다. 면을 떠났거나 다른 면으로 넘겼으면 버린다(`faceActive`). 같은 면을 다시 그렸으면 새로 그린 지면만 받는다.
- 독자 투고는 커뮤니티 API가 없는 실제 모드에서는 칸을 숨긴다. 목 데이터일 때는 "목데이터" 표기를 단다.
- 뒤로 넘길 때(`back`) 갈 화면이 신문이 아닐 수 있다(8막 비교 · 마이페이지 결과 · 메인 책상으로 "← 이전으로"). 이 화면들에는 `.paper`가 없어 `nextPaper`가 2.5초를 기다리면 덮개가 새 화면을 가린 채 멈춘다. 그래서 `#route-view`가 바뀐 뒤 지면이 하나도 없으면 50ms 안에 `null`을 돌려 흐려 걷는다. `leaveByTurn`을 다른 화면에 붙일 때도 갈 곳이 신문 지면인지부터 확인한다.
- 색인 쪽 나눔 확인용 임의 사건 20건(caseId 12 ~ 31)을 목에 더했다. 모두 대본이 없어 "준비 중"이다. 실제 서버 데이터가 아니다. 시연에서 "준비 중"이 많이 보이는 것은 색인 쪽 나눔을 보여 주려는 의도이므로 그대로 둔다(PR #328 리뷰 확인).
- 연출 측정은 GPU 없는 헤드리스 크롬 기준이다. 사파리 체감은 사용자 확인이 필요하다.
- `@property`를 쓰는 종이 귀 들썩임 등 기존 제약은 그대로다.

## 추후 재검토가 필요하면
- 사파리에서 넘기는 도중 끊김이 느껴지면 넘기는 장에서 망점 사진 같은 무거운 효과를 빼는 쪽을 검토한다.
- 사설 다섯 편 · 독자 투고 추리기는 임시 규칙(날짜 순환, 공감 많은 순 3건)이다. 편집부 사설 API가 생기면 면 정의에 `load`를 더한다(FE-123 후속 메모와 같은 방향).
- 호버 상자는 DESIGN.md 호버 7패턴에 아직 넣지 않았다. 패턴 확정(FE-76) 때 같이 정리한다.
