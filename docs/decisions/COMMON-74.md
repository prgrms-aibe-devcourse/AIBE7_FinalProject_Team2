# COMMON-74 의사결정 기록

> 관련: COMMON-47(S3 버킷 세팅) · BE-91(사건 사진 업로드, `docs/decisions/BE-91.md` 11절에서 이 문제를 COMMON-47 재검토로 넘김) · COMMON-70(CSP `img-src`)

## 문제 / 배경
- 관리자 검수 화면에서 사건 대표 · 발단 · 결론 사진을 올려도, 공개 화면에는 범죄 분류별 공용 컷(기본 이미지)이 나왔다.
- 백엔드 흐름은 정상이었다. 업로드는 S3에 저장되고, DB(`legal_case.thumbnail_url` · `case_incident_photo.image_url`)에 주소가 들어가며, 공개 지면(API 17)도 저장된 주소를 그대로 내려준다.
- 원인은 브라우저가 그 주소를 열 때 S3가 **403**을 준 것이다(운영에서 `case-photos/case-2/representative-*.png` GET → 403 확인).
  - `S3FileStorage.upload()`는 서명 없는 객체 주소(`S3Utilities.getUrl`)를 돌려주는데, 버킷은 퍼블릭 액세스 전면 차단(COMMON-47)이다.
  - 문서(`deploy/README.md` · `docs/architecture.md` · `docs/tech-stack.md`)는 "Presigned URL로만 내려준다"고 적었지만, 코드에 Presigned URL 발급이 없었다. 문서와 구현이 처음부터 어긋나 있었다.
  - 프론트는 이미지 오류 때 공용 컷으로 바꿔 끼우므로(`useCommonPhotoOnError`) 오류 없이 "기본 이미지로 공개된" 것처럼 보였다. 관리자 미리보기는 대체 처리가 없어 깨진 이미지였다.
- 함께 의심했던 다른 원인은 해당하지 않았다. 검수 화면 업로드는 항상 역할(ORIGIN · CONCLUSION)을 붙여 저장하고, 파이프라인 등록 사건도 지면(case_paper)을 함께 저장한다. CSP는 Report-Only이고 `img-src`에 서울 리전 S3가 이미 들어 있다.

## 검토한 대안
- 대안 A: **Presigned URL 발급(BE 코드)**. DB에는 키를 두고, 사진을 내려주는 모든 응답(사건 목록 · 상세 · API 17 · 관리자 화면)에서 서명된 주소를 만든다.
  - 장점: 버킷을 전면 비공개로 유지하고, 문서상 원래 설계와 맞는다.
  - 단점: 운영은 EC2 IAM 역할 자격증명이라 서명 주소가 그 자격증명 만료(수 시간)와 함께 끊긴다. 응답마다 주소가 달라 브라우저 캐시가 듣지 않는다. 대표사진은 주소만 저장돼 있어 키를 다시 뽑아내야 하고, 사진을 내려주는 응답 여러 곳을 모두 고쳐야 한다.
- 대안 B: **사건 사진 경로만 버킷 정책으로 공개 읽기**. `case-photos/*`에 `s3:GetObject`만 익명 허용한다.
  - 장점: 코드 수정이 없고, 이미 저장된 주소가 그대로 살아난다. 주소가 고정이라 캐시가 듣는다.
  - 단점: 퍼블릭 액세스 차단 중 버킷 정책 관련 2개를 꺼야 한다. 공개 전 사건의 사진도 주소를 알면 열린다.
- 대안 C: **CloudFront + OAC**. 버킷은 비공개로 두고 CDN에만 읽기를 준다.
  - 장점: 가장 정석적인 구성이다. 캐시와 전송 속도에도 유리하다.
  - 단점: 배포 · 인증서 · 도메인 등 인프라 작업이 가장 크다. 저장된 주소(S3 주소)를 CDN 주소로 바꾸고 CSP `img-src`도 고쳐야 한다. 일정(11/04 마감 직전)에 맞지 않는다.

## 선택한 방법과 이유
- **대안 B**를 택했다.
  - 공개된 사건 사진은 원래 누구나 보라고 올리는 콘텐츠라, Presigned URL로 접근을 통제할 이유가 약하다.
  - 코드 · 데이터 변경 없이 콘솔 설정만으로 바로 고쳐지고, 이미 올린 사진도 다시 올릴 필요가 없다.
  - 공개 범위는 최소로 했다. 읽기(`GetObject`) 하나만, `case-photos/` 경로에만 연다. 목록(`ListBucket`)은 닫혀 있어 주소를 모르면 다른 객체를 찾을 수 없다. ACL 관련 퍼블릭 차단 2개는 켜 둬서, 공개 경로가 이 정책 한 곳뿐이게 한다.
- 문서 3곳(`deploy/README.md` · `docs/architecture.md` · `docs/tech-stack.md`)의 "Presigned URL로만"을 실제 구성에 맞게 고쳤다. 적용 절차 · 정책 JSON · 확인 명령은 `deploy/README.md` "파일 저장소 S3"에 둔다.

## 고려한 제약 사항
- 버킷 · IAM은 AWS 콘솔에서 인프라 담당이 관리한다. 저장소에는 정책 원문과 절차만 두고, 버킷 이름 같은 운영 식별자는 자리표시(`<운영 버킷 이름>`)로 둔다.
- 기본 암호화가 SSE-S3라 익명 읽기가 된다. SSE-KMS로 바꾸면 익명 요청이 KMS 키를 쓸 수 없어 다시 403이 난다.
- 로컬 실행(`S3_DIR_PREFIX=local`)의 `local/case-photos/*`는 열지 않았다. 운영 화면과 관계없고, 필요하면 `Resource`에 추가하면 된다.

## 추후 재검토가 필요하면
- **공개 전 사진 · 교체로 밀려난 사진도 주소를 알면 열린다.** 키에 밀리초 시각이 붙어 추측은 어렵지만 비밀은 아니다. 교체 · 삭제 때 이전 S3 객체를 지우지 않는 원칙(A-13-4 · A-13-9)과 맞물리므로, 공개 전 사진을 숨겨야 할 요구가 생기면 대안 A나 C로 옮기거나 이전 객체 정리를 함께 검토한다.
- 사진 외 파일(게시글 첨부 등)을 같은 버킷에 올리게 되면 `case-photos/`와 다른 경로를 써서 공개 범위에 섞이지 않게 한다.
- 트래픽이 커져 S3 전송 비용 · 속도가 문제가 되면 대안 C(CloudFront)를 다시 본다.
- 공유용 그림 `docs/assets/architecture.png`에는 "Presigned URL" 표기가 남아 있다(상단 점선 · S3 상자 · 외부 노출 경로 · 주요 흐름 6). PNG라 이번 PR에서는 고치지 않았고, 그림을 다시 만들 때 함께 고친다. 그 전까지는 `docs/architecture.md` 본문이 기준이다.
