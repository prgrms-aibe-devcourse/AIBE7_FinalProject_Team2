# FE-95 의사결정 기록

> 근거: 성향 테스트 impeccable critique(32/40, 2026-10-26) · DESIGN.md 모션 표 · PRODUCT.md(성향 테스트 → 판결 체험 동선)

## 문제 / 배경
- critique에서 성향 테스트가 끝나는 순간이 약하다는 지적이 두 가지 나왔다.
  - 주 동선인 "실제 사건으로 판결하러 가기"가 결과 두 번째 탭(풀이) 뒤에만 있었다.
  - 결과 공개가 조용했다. 철이 선 뒤 글자가 한꺼번에 나타나고, 유형 이름이 정점 순간인데도 눈에 띄는 연출이 없었다.
- 모바일 터치 크기(답한 칸 36x30 등)와 질문 글자의 포커스 링(모바일에서 파란 사각형)도 함께 정리했다.

## 검토한 대안
- **CTA 자리**: A 풀이 장의 버튼 줄을 결과 장으로 옮김 / B 결과 장 끝에 짧은 버튼 줄(판결하러 가기 + 공유하기)을 더함 / C 결과 장 위쪽(카드 옆)에 둠 / D 결과 장에는 두지 않고 풀이 장 끝에만 둠(원래대로).
  - critique가 "주 버튼이 두 번째 탭 뒤에 숨는다"고 지적해 B를 만들어 봤지만, **사용자 결정으로 D를 택했다**: 결과 장 끝에 판결하러 가기가 있으면 풀이를 읽지 않고 떠난다. 풀이(일상에서는 · 판결을 볼 때는)를 놓치지 않게 하는 것이 우선이다.
- **결과 공개 연출**: 큰 연출(종이를 뒤집는 등 화면을 통째로 움직임) / 요소를 차례로 나타냄 / 그대로. 이미 철 돌리기(1s)라는 큰 움직임이 있어, 그 뒤는 종이 위 물건이 놓이는 작은 움직임으로 이어 가기로 했다.
- **유형 이름의 등장 방식**: 페이드 / 타자기처럼 한 글자씩 / 도장 찍기. 판사의 집무실 은유에 맞는 건 판결문에 찍는 도장이라 도장을 택했다.
- **유형 이름 크기**: critique는 이름이 카드 그림보다 작다고 했다. 글자 크기 토큰(`--text-display` 34px)을 넘기면 타입 눈금이 깨져, 크기는 두고 등장 순서와 도장으로 시선을 모으기로 했다.
- **서류철 빈 공간**(격자와 질문 사이): 문항마다 높이를 줄이면 철이 들썩인다. 고정 높이를 유지하기로 했다(사용자 결정).

## 선택한 방법과 이유
- CTA는 D(원래대로 풀이 장 끝). 대신 결과 장 끝의 "풀이 보기" 종이 귀가 가만히 있어도 3초마다 크게 일렁이게 해 풀이로 넘어가도록 이끈다. 값은 판결 체험의 폴더 말림 idle(`folder-curl-idle`: `scale` 1.06 ↔ 1.3, `rotate` ±4deg, 3초 주기)을 그대로 쓴다(DESIGN.md 모션 표). 처음에는 풀이로 가는 귀만 움직였지만, 풀이 장의 "결과 보기" 귀도 같은 일렁임을 주기로 했다(사용자 결정). 이 귀는 좌우로 뒤집혀(`scaleX(-1)`) 있어 같은 키프레임을 쓰면 축이 어긋나므로, 모서리를 축으로 옮기고 회전 방향을 거꾸로 한 별도 키프레임(`turn-fold-idle-prev`)을 둔다. 귀 줄은 내용 끝과 16px 떨어뜨렸다. 움직임 줄이기에서는 멈춘다.
- 결과 공개: 철이 선 뒤 카드가 꽂히고 → 유형 이름 도장 → 한 줄 설명 → 나머지 → 4축 막대를 가운데 눈금에서 양쪽으로 긋는다. 막대는 "나는 어느 쪽에 가까운가"를 가운데(반반)에서 뻗어 가는 모양으로 보여 준다.
  - 막 제출했을 때만 한다(`takeFolderTurn`이 있을 때). 결과를 다시 볼 때마다 기다리게 하지 않는다.
  - 결과를 불러오는 동안에도 철은 돌고 있어, 시작 시점(`--reveal-at`)은 화면을 그릴 때 지난 시간만큼 빼서 철이 선 뒤에 맞춘다.
  - 다 끝나면 `.is-revealing`을 뗀다. 탭을 넘기면 결과 장이 `display: none` → 보임이 되면서 애니메이션이 다시 돌기 때문이다.
- 질문 글자(`.test-scenario`)는 문항이 바뀔 때 낭독기를 옮겨 오는 자리라 윤곽을 두지 않는다. 신문 경로(`.tp-headline`)와 같다.

## 고려한 제약 사항
- DESIGN.md 모션 규칙: 큰 연출은 모바일(≤ 720px)에서 건너뛴다. 결과 공개는 화면을 움직이지 않는 작은 연출이라 모바일에서도 하되, 철 돌리기 없이 곧바로 시작한다. 동작 줄이기 · 연출 끄기(`data-motion="off"`)에서는 하지 않는다.
- 답한 칸 격자는 16칸을 8열 2줄로 둔다. 폭까지 44px로 맞추면 3줄이 되어 머리가 무거워져, 높이만 44px로 올렸다(폭 36px, WCAG 2.5.8 24px은 넘는다).

## 추후 재검토가 필요하면
- 제출 직후 채점 카드("답안을 정리하는 중이에요")도 평평하다는 지적이 있었다. 결과 공개와 이어지는 기대감을 줄지 다음에 본다.
- 결과 첫 장에 4축 · 관용 지수가 한꺼번에 나오는 정보량, 퍼센트의 의미 설명은 이번에 손대지 않았다.
