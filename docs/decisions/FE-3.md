# FE-3 의사결정 기록

> MVP 단계(WBS 3.8) · PR #60 · 담당 정민석

## 문제 / 배경
- S-14(404 · 오류 화면)가 자리표시자 상태였고, 알 수 없는 주소 · 없는 사건에 대한 안내 화면이 필요했다.
- S-14는 다른 화면과 달리 와이어프레임이 없어, IA 4장 · API 명세 1-5 기준으로 직접 구성해야 했다.
- 기존에 헤더 · 푸터 공통 스타일이 `landing.css`(S-01 전용)에만 있어서, S-14와 라우터가 붙이는 공통 푸터가 화면 CSS를 빌려 쓰는 상태였다 (FE-2 리뷰에서 "화면 CSS를 빌리지 않는다" 원칙이 나왔다).
- 반응형 기본 대응(390px · 360px 기준)이 전체 화면에 되어 있는지 점검이 필요했다.

## 검토한 대안
- 헤더 · 푸터 공통 스타일을 `landing.css`에 계속 의존할지, 공통 스타일시트에 같은 값으로 새로 정의할지 검토했다. FE-2 리뷰 원칙(화면 CSS를 빌리지 않는다)에 맞추기 위해 `src/style.css`에 공통 버튼과 같은 방식으로 중복 정의하는 쪽을 택했다. `landing.css` 쪽 중복 규칙을 정리하는 작업은 이번 PR에 넣지 않고 FE-4 담당자와 협의 후 별도로 진행하기로 했다.
- S-09(판단 요소 비교 표)의 좁은 화면 가독성 문제는 발견했지만, 그 화면의 CSS(`comparison.css`, FE-9) 수정이 필요해 이번 PR 범위에서 뺐다.

## 선택한 방법과 이유
- S-14는 사이트 헤더(로고 · 사건 목록 · 서비스 소개) + 제목 · 안내 문구 + 버튼 2개(`사건 목록으로`, `처음으로`)로 구성했다. 공통 푸터는 화면이 아니라 라우터가 붙인다(`ownsFooter` 없음).
- 헤더의 "서비스 소개" 메뉴는 S-02와 같은 방식으로 랜딩 소개 섹션(`navigate('landing', { section: 'intro' })`)으로 이동하게 해, 화면마다 다른 동작이 되지 않게 했다.
- `.message-panel button`의 위 여백이 S-14 버튼 간격(`gap`)과 겹치는 문제는 선언 순서가 아니라 CSS 우선순위로 해결했다.

## 고려한 제약 사항
- 반응형 점검은 390px · 360px 기준으로 S-01 ~ S-09 · S-14 전체를 확인했고, 코드 수정 없이 "깨지지 않는 수준"을 충족하는지만 봤다. 768px 태블릿 폭과 가로 모드는 점검하지 않았다.
- `role="alert"`는 다른 화면과 같은 방식(패널 전체)으로 맞췄다.

## 추후 재검토가 필요하면
- `landing.css`와 `style.css`에 중복된 헤더 · 푸터 규칙 정리는 FE-4 담당자(김해송)와 합의 후 진행.
- S-09 비교 표의 좁은 화면 가독성 개선 여부는 FE-9 담당자(백승호)의 의견에 따라 결정.
