# BE-28 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #71 본문.

## 문제 / 배경
- 실제 사건(비공개 서브모듈)을 보려면 실행 직전 셸에 `FLYWAY_LOCATIONS`를 정확히 넣어야 했다. 다른 터미널 탭 · IDE 실행 · 붙여 넣기 줄 깨짐으로 값이 빠지면 **오류 없이** 가상 사건만 떠서 프론트에서 "목업만 보인다"로 오인했다.

## 선택한 방법과 이유
- `backend/build.gradle`의 `bootRun`이 Flyway 위치를 자동으로 정한다. 기본은 가상 시드, `private-seed/seed`에 SQL이 있으면 `filesystem:` 경로를 덧붙인다. 기동 로그에 포함 여부와 이유를 출력한다.
- `FLYWAY_LOCATIONS`를 직접 주면 그 값이 우선한다(기존 실행 방식 호환).
- 실행 방법을 `./gradlew bootRun` 하나로 고정해 팀원 모두 같은 문제를 겪지 않게 했다.

## 고려한 제약 사항
- 운영(jar · Docker) · 테스트 · CI는 바꾸지 않는다. `application.yml` 기본값(스키마만)을 유지하고 `bootRun` 작업에만 적용한다.
- 권한 없는 팀원은 서브모듈이 빈 폴더라 자동으로 제외된다(해당 환경 확인은 PR에서 미완료로 남음).
