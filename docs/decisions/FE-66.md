# FE-66 의사결정 기록

## 문제 / 배경
- 마이페이지만 헤더를 화면 안(`.my-page`)에 직접 그려서(`ownsHeader`), 메인과 같은 컴포넌트(`renderSiteHeader`)를 쓰는데도 높이 · 로고 크기 · 메뉴 글자 크기 · 하단 선이 달랐고, 내용 폭 상자(`max-width`, 테두리) 안에 갇혀 화면 전체 폭으로 퍼지지 않았다.
- 요구는 "메인과 똑같은 내비를 쓰되 색만 다르게"였다. 화면이 바뀔 때도 헤더와 아래 페이지가 같은 속도로 함께 바뀌어야 한다.

## 검토한 대안
- 대안 A: 라우터가 공통 헤더(`#route-header`)를 붙이게 하고(`ownsHeader` 제거), 마이페이지 CSS는 색만 덮어쓴다.
- 대안 B: 마이페이지가 헤더를 직접 그리는 구조는 두고, `myPage.css`의 크기 · 여백 · 하단 선 규칙을 걷어 색만 남긴다(헤더를 `.my-page` 상자 밖에 그림).

## 선택한 방법과 이유
- **대안 A**. 모양 · 높이 · 고정(sticky) · 높이 측정(`--site-header-h`)이 다른 화면과 항상 같아지고, 헤더 코드가 한 곳에서만 그려진다.
- 색은 지금의 커피 팔레트를 그대로 쓴다(바탕 `coffee-25`, 메뉴 `coffee-500`, 로고 `coffee-900`). 헤더가 `.my-page` 밖에 있어 그 안의 역할 토큰을 못 쓰므로 팔레트를 직접 가리킨다. 구분선은 높이가 늘지 않게 `box-shadow: inset`으로 둔다.
- 전환 깜빡임은 A/B와 무관했고, 원인이 둘이었다. 둘 다 `coffeeDive.js` · `myPage.css`에서 고쳤다.
  1. 커피잔 연출이 메인 **화면 루트만 복제**해 걷는데, 공통 헤더는 루트 밖(`#route-header`)에 있어 복제에서 빠졌다. 이동하는 순간 헤더만 즉시 바뀌고 아래 페이지는 천천히 바뀌었다. → 헤더도 복제해 아래 페이지와 같은 시점 · 같은 속도로 걷는다.
  2. 헤더 복제본은 `body`에 얹히므로, 마이페이지가 그려지는 순간 `body:has(.my-page) .site-header` 색 규칙이 **복제본에도 번져** 복제본이 곧바로 커피색이 됐다. → 규칙을 `body:has(.my-page) #route-header .site-header`로 좁혀 복제본은 네이비로 남아 아래 페이지와 함께 걷힌다.
- 확인: 헤드리스 Chrome(CDP)으로 클릭 직후 프레임을 찍어, 헤더 띠와 아래 페이지의 흐려지는 정도가 프레임마다 같음을 확인했다.

## 고려한 제약 사항
- 마이페이지 전용 `scroll-padding-top`(80px) 예외는 지우고, 다른 화면과 같이 측정된 `--site-header-h`를 쓴다.
- 헤더 복제본 처리는 커피잔 연출에만 있다. 노트북(커뮤니티) · 신문(사건 목록) 연출은 같은 증상이 있는지 따로 확인하지 않았다.

## 추후 재검토가 필요하면
- 다른 화면 전환 연출(노트북 · 신문)도 헤더 복제본이 필요한지 같은 방법으로 확인한다.
