# FE-67 의사결정 기록

> 근거: PR #215

## 문제 / 배경
- 마이페이지 대표 이미지(프로필카드)의 캐릭터가 허리 아래부터 잘렸다. 원인은 그림 창의 그리드 행이 `auto`라 이미지의 `height: 100%`가 창 높이로 풀리지 않고 이미지 원래 높이(327px)가 되어, 창(201px)이 넘친 아래를 잘라 낸 것이었다.
- 성향카드와 대표 이미지가 비슷한 크기로 보여야 하고, 성향 이미지는 지금보다 조금 더 크게 보여야 한다. 그런데 성향 이미지(800 × 1000)는 캐릭터가 이미지 높이의 62 ~ 78%만 차지하고 투명 여백이 이미지마다 다르다(위 70 ~ 170px, 아래 127 ~ 240px). 역할 이미지(높이 560, 너비 266 ~ 368)는 여백이 거의 없다.

## 검토한 대안
- 대안 A: CSS만 고친다(창의 행을 고정해 `contain`). 잘림은 사라지지만, 이미지마다 여백이 달라 성향 이미지의 캐릭터가 작고 제각각으로 보인다.
- 대안 B: 불투명 부분(캐릭터)의 경계 상자를 재서(alpha bbox), 캐릭터가 창에서 같은 높이를 차지하도록 크기와 자리를 JS로 정한다(`utils/portraitFit.js`).
- 대안 C: 이미지 파일마다 여백을 잘라 다시 내보낸다. 이미지 32장 + 새 이미지마다 손이 가고, 담당(이미지 작업자)과 맞춰야 한다.

## 선택한 방법과 이유
- 먼저 **A**로 잘림을 없앴고, 성향 이미지를 직접 나란히 놓아 본 뒤(여백 차이가 눈에 띄었다) **B**를 더했다. C는 이미지 작업 흐름에 의존해 배제했다.
- 계산은 순수 함수(`fitPortrait`)로 두어 `node --test`로 검증하고, 캔버스를 쓰는 측정(`measureOpaqueBox`)과 반응형 재계산(`ResizeObserver`)은 브라우저 쪽 함수에 따로 둔다.
- 카드 비율을 7 / 12에서 7 / 14로 키워 그림 창을 키웠다(대표 이미지와 성향 이미지가 더 크게 보이게). 아치(둥근 위쪽)가 머리를 깎지 않도록 윗 여백(22px)을 둔다.

## 고려한 제약 사항
- 다른 출처 이미지(실제 모드의 CDN 등)는 캔버스를 읽을 수 없어 측정이 막힌다. 그때는 맞추지 않고 CSS 기본(`contain`)으로 보인다.
- 맞추는 동안은 크기가 튀어 보이지 않게 이미지를 가려 둔다(`.is-fitting`). 측정이 실패해도 이 클래스는 걷힌다.

## 추후 재검토가 필요하면
- 만난 모습 썸네일과 책갈피 얼굴에도 같은 크기 맞춤이 필요한지 본다(지금은 적용하지 않음).

## 2차 (PR #215 추가 커밋)

### 문제 / 배경
- 마이페이지 "만난 모습"이 체험을 마친 사건의 의상 · 일러스트만 보여 줘서, 어떤 이미지가 어떻게 모이는지 한눈에 볼 수 없었다. 이미지를 사건별이 아니라 **종류별**로 보고 싶다는 요구가 나왔다.
- 책갈피 얼굴은 내로 · 남불 두 칸(표정 `happy` 고정)뿐이었고, 판결 화면의 진행 책갈피는 고른 값과 무관하게 `naero_face-happy`로 하드코딩돼 있었다.
- `icon/`에는 새로 생성한 얼굴 12장과, 원본을 잘라 만든 로 아이콘(`mascot/`)이 구분 없이 있었다. 생성본은 나중에 다시 만들 수 있어 "다시 만들 것 / 그대로 쓸 것"을 나눠 둘 필요가 있었다.

### 검토한 대안
- 컬렉션 묶음: (A) 사건별 유지 + 종류 필터, (B) 종류(폴더)별 묶음, 사건 고유 이미지는 "사건 이미지" 아래 사건별. 사건 이미지가 사건마다 3장뿐이라 (A)는 종류를 가로지르는 화면이 된다.
- 이미지 목록: (A) 코드에 목록을 적는다, (B) `import.meta.glob`으로 `public/images`를 읽는다. (A)는 이미지를 추가할 때마다 코드를 고쳐야 한다.
- 이미지 이동에 따른 주소 처리: (A) 옛 주소를 새 주소로 잇는 매핑 · 리다이렉트, (B) 코드의 참조만 모두 고친다.
- 잘라 만든 얼굴: (A) 새 아이콘을 다시 생성 요청, (B) 장면 컷에서 머리를 잘라 128 × 128로 임시 제작.
- 책갈피 고르기: (A) 이미지를 눌러 확대 창에서 정함(1차 시도), (B) 상단 고르기 칸에 전부 모음.

### 선택한 방법과 이유
- **종류별 묶음(B)**: 종류 = 폴더로 정하고 표시명은 `myPageView.js`의 `KINDS` 표 하나로 둔다. 순수 함수(`imageKinds`)라 `node --test`로 검증한다. 실제 모드는 체험한 사건의 의상 · 일러스트만 같은 틀에 담고, 목 모드는 전부 펼친다.
- **glob(B)**: 개발 서버(`import.meta.env.DEV`)에서만 읽어 빌드 결과에는 들어가지 않는다. 배포본에서 목 모드로 봐도 전체 펼침은 나오지 않는다(미리 보기 용도).
- **주소 매핑 불필요(B)**: 옮긴 파일(`icon/*_face-*.webp` → `icon/generated/`, `mascot/law-*_icon.webp` → `icon/cropped/`)의 옛 주소를 쓰는 곳을 코드 · 문서 · DB 시드에서 찾았다. 서버가 가진 이미지 주소는 성향 이미지(`characters/personality/`)와 사건 썸네일(`cases/`)뿐이다. `cases/`의 사건 1 발단 · 결론 컷은 FE-63에서 이름을 바꿨고(`-sub` → `-origin`, `-detail` → `-conclusion`), 서버 · 비공개 시드에는 옛 이름을 쓰는 곳이 없다. 옮긴 파일은 프런트 코드(`stage.js` · `caseListPage.js` · `bookmarkCharacter.js`)만 참조해 모두 고쳤다. 사용자에게 공유된 주소도 없어 매핑 · 리다이렉트는 만들지 않는다.
- **잘라 만든 얼굴(B)**: 장면 컷의 불투명 경계로 머리 영역을 잡아(내로 52% · 남불 62%, 남불은 불꽃 머리라 비율이 크다) 정사각형으로 잘랐다. 기존 얼굴처럼 투명 배경에 목 스카프까지 담는다. 나중에 다시 생성하거나 그대로 쓸 때 `cropped/` 경로만 바꾸면 된다.
- **얼굴 고르기**: 캐릭터 · 표정 · 종류(`generated` · `cropped`)를 따로 저장하고, 로는 표정 없는 아이콘 한 장이라 캐릭터 값(`law-*`)만 쓴다. 기존 저장값(`naero` · `nambul`)은 그대로 읽힌다. 확대 창에서 정하는 방식은 롤백하고 상단 한 곳에 모았다(고르는 자리가 둘로 갈리지 않게).
- **크기 맞춤 확장**: 컬렉션 카드에도 `portraitFit`을 쓴다. 단색 배경 그림은 네 모서리 색으로 배경을 걷고 경계를 잰다(`foregroundBox`). 처음에 "그림 전체가 경계면 맞추지 않는다"는 예외를 뒀다가, 가장자리까지 꽉 찬 역할 이미지가 틀 끝에 붙어 잘려 보여서 예외를 없애고 모든 그림에 위 · 아래 여백을 준다.

### 고려한 제약 사항
- 경로를 `icon/${who}_face-…`처럼 조립하는 코드(`stage.js`)는 문자열 검색에 걸리지 않아 이동 때 한 곳을 놓쳤다(무대 얼굴 아이콘이 깨질 뻔했고 바로 고침). 같은 사고를 막으려고 책갈피 얼굴 경로가 실제 파일을 가리키는지 확인하는 테스트를 더했다.
- 서버 저장은 아직 없다. 책갈피 선택은 이 브라우저(localStorage)에만 남는다(BE-83에서 검토).
- 이미지 저장소 `NaeLawNamBul_Images`의 원본 폴더 구조에는 이 분류를 반영하지 않았다.

### 추후 재검토가 필요하면
- 잘라 만든 얼굴을 계속 쓸지, 다시 생성할지 정해지면 `generated/` 와 `cropped/` 중 하나로 합치고 책갈피 고르기의 "종류" 구분을 없앤다.
- 종류 표시명(`KINDS`)은 임시 이름이다. 이미지 담당과 맞춰 확정한다.
- 컬렉션이 실제 수집 상태(BE-83)와 이어지면 목 모드 전체 펼침은 제거한다.
