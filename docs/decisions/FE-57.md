# FE-57 의사결정 기록

## 문제 / 배경
- BE-77(PR #198)이 API 14에 `preToCourt.direction`(재판부 기준)을 추가했지만, 프론트는 사전 판단 구간 이름(label)을 문자열로 파싱해 편집부 의견을 만들고 있었다.
- 같은 PR 논의에서 "1막부터 다시 보기 삭제"가 언급됐으나, 프론트에는 삭제 작업본이 없고 선택지·`playAgain()`이 그대로였다.

## 검토한 대안
- direction 매핑: (A) 서버 값을 그대로 쓰되 화면 문구에서 뒤집어 읽기 / (B) 프론트 비교 함수의 기준(사전 판단 기준)에 맞춰 서버 값을 변환해 기존 `PRE_HEAVIER` 계열로 되돌리기
- 다시 보기: (A) 삭제 / (B) 유지하고 완료 사건에도 같은 질문 추가

## 선택한 방법과 이유
- direction은 (A). 변환 계층을 두면 기준이 둘이 되어 헷갈린다. `HEAVIER`(재판부가 더 무거움)는 "실제 사건보다 가볍게 판단", `LIGHTER`는 "무겁게 판단"으로 한 곳(`preJudgmentCompare.js`)에서만 뒤집는다. label 파싱은 모두 제거했다.
- 다시 보기는 (B). 진행 중에는 사전 형량을 다시 보여 주지 않고 "이미 보냈어요" 안내만 낸다(리뷰 반영: BE-77의 "최종 판단 전 재확인 금지"). 완료 사건만 API 14의 사전 판단을 엽서에 보여 준다. 처음엔 진행 중에도 이 브라우저 저장값(localStorage)으로 형량을 보여 줬지만 정책과 어긋나 저장 자체를 없앴다. 완료 사건은 "시작하기"가 묻지 않고 바로 1막을 재생하던 것을 `결과만 보기` / `1막부터 다시 보기` 질문으로 바꿨다. 오른쪽 귀 버튼은 그대로 둔다.
- Mock API 14는 기존 `directionFromBucket`을 재사용해 `preToCourt`를 만든다(preToFinal과 같은 구간 · 같은 계산).

- 캐릭터 컷 주소: 원본 이미지 레포의 `base/`가 `scene/` · `cheek/` 하위 폴더로 나뉘어 옛 주소가 404였다. 파일 이름(동작-표정)은 그대로라 대본은 건드리지 않고 `stage.js` · `landingPage.js`의 경로만 맞췄다.
- 확대 사진: 투명 PNG가 확대되며 컬러가 될 때 뒤 지면이 비쳐, 확대용 사진(`.zoom`)에만 신문지색 배경을 채웠다. 신문 속 작은 사진은 곱하기 합성이 지면과 섞이는 지금 모습을 유지한다.

## 고려한 제약 사항
- 서버 direction은 label을 해석하지 않으므로 프론트도 문자열 형식에 의존하지 않아야 한다.
- 팀 논의(10/20)의 "다시 보기 삭제 확정"과 달라지므로 `docs/api-specification.md`·`docs/decisions/BE-77.md` 문구 정정이 필요하다(BE-77 담당과 합의).

## 추후 재검토가 필요하면
- "1막부터 다시 보기"는 지금 1막(첫인상)만 다시 보여 주고 이어서 하기로 저장된 단계에 간다. 2~6막까지 읽기 전용으로 전체 재생하려면 화면 주소 · 리다이렉트를 건드려야 하므로 BE-82(주소 정리) 확정 뒤에 별도 이슈로 다룬다.
- 진행 중 체험의 1막을 다시 볼 때 "이미 보낸 엽서"는 형량 없이 안내만 나온다(정책상 의도). 완료 사건은 API 14가 실패하면 형량 없이 안내만 나온다.
- 리뷰의 권장 사항(Mock API에서 잘못된 `rangeOptionId`를 기본 구간으로 대체하지 않기)은 이번에 반영하지 않고 후속 작업으로 분리한다.
