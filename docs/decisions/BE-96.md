# BE-96 의사결정 기록

> 확장 단계 · 담당 김현중 (B) · 관련: FE-68, BE-97, BE-83

## 문제 / 배경
- FE-68에서 프로필 꾸미기(대표 이미지 · 카드 테두리 · 배경 · 카드 책갈피)와 도전과제 해금을 프론트에서 먼저 만들었다. 고른 꾸미기는 브라우저(localStorage)에만 있고, 도전과제 진행도 · 해금 검증도 프론트에서만 한다(`frontend/src/utils/profileDeco.js`). 그래서 기기 · 브라우저 사이에 유지되지 않고, 잠긴 항목도 요청을 조작하면 저장할 수 있다.
- 책갈피 캐릭터 · 얼굴 · 리본 색(`bookmarkCharacter.js`)도 같은 이유로 서버에 둔다.
- 계약은 FE-68 담당과 협의해 정했다(2026-10-21, 아래 "선택한 방법과 이유").

## 검토한 대안

### 1. "모은 일러스트 수"(collected) 판정
- 프론트는 완료한 체험 + 사건 대본(`content/scripts.js`의 역할 의상 · 신문 사진 · 증거 사진)으로 센다. 대본은 서버에 없어 **서버가 같은 값을 만들 수 없다.** 수집 상태 저장은 BE-83이다.
- 대안 A: BE-83을 먼저 하고 BE-96을 그다음에 한다. 꾸미기 저장 전체가 늦어진다.
- 대안 B: 그 전까지 수집 도전과제 2개는 검증에서 뺀다(아무나 열림). 해금 검증의 의미가 없어진다.
- **대안 C(선택): 나머지 6개만 서버가 판정하고, 수집 2개는 `PENDING`(판정 대기)으로 내려 주며 잠김으로 다룬다.** 보상은 BE-83 전까지 저장을 거절한다. 프론트도 로컬 계산을 빼고 서버 응답만 따른다(화면에는 열려 있는데 저장은 거절되는 일을 막는다).

### 2. 도전과제 · 보상 표의 원본
- 대안 A: 프론트 · 서버에 같은 표를 두고 테스트로 맞는지 확인한다. 바꿀 때 두 곳을 함께 고쳐야 한다.
- **대안 B(선택): 서버가 원본이다.** 마이페이지 응답에 도전과제(목표 · 진행도 · 상태 · 보상)와 열린 항목을 내려 주고, 프론트는 id → 제목 · 문구 · 그림만 남긴다. 표는 아직 임시안이라 서버 상수 한 곳(`ProfileDecoCatalog`)에 모은다. 표를 바꾸면 백엔드 배포가 필요하다.

### 3. 대표 이미지 검사 단위
- 대안 A: 후보 130장 목록(`content/portraitPool.js`)을 서버에도 두고 한 장씩 검사한다. 이미지를 더할 때마다 두 곳을 고쳐야 한다.
- **대안 B(선택): 경로에서 종류(폴더)만 뽑아 그 종류가 열렸는지 검사한다.** 파일이 실제로 있는지는 보지 않는다(없으면 프론트가 대체 이미지). 대신 경로가 그대로 `<img src>`에 들어가므로 **형식은 반드시 검사**한다.

### 4. 저장 API 모양
- 대안 A: 바꾼 필드만 보내는 PATCH.
- **대안 B(선택): 꾸미기 전체를 한 번에 보내는 PUT.** 프론트가 지금 상태를 모두 갖고 있고, 서버는 매번 전체를 검증하면 된다.

## 선택한 방법과 이유

### 저장
- **테이블 `profile_deco`(V23)**: 익명 사용자당 한 줄(`anonymous_user_id` 기본 키 · FK). 칼럼은 `portrait` · `frame` · `background` · `sash_style` · `sash_color_short` · `sash_color_long` · `sash_icon_left` · `sash_icon_right` · `bookmark_character` · `bookmark_face` · `bookmark_face_style` · `bookmark_color` · `updated_at`. 테이블 추가뿐이라 BE-60 규칙에 맞는다.
- **쿠키 없이 저장**하면 익명 ID를 새로 발급한다(사용자가 직접 고른 행동이라 P-2와 같다. 자동 호출인 출석 P-6은 발급하지 않는다).
- **저장 기록이 없으면 기본값**을 내려 준다(FE-68 `DEFAULT_DECO` · 책갈피 기본값과 같다: 내로 스탠딩 · 기본 테두리 · 크림 · 책갈피 없음 · 내로 · 기쁨 · 생성한 얼굴 · 브론즈).

### 도전과제 판정
- 진행도는 저장하지 않고 DB 값으로 그때그때 계산한다.

| stat | 서버 값 |
| --- | --- |
| `completed` | **완료한 회차가 하나라도 있는 사건 수.** 프론트는 "사건별 최근 회차가 완료"를 세서 다시 하기를 시작하면 줄 수 있는데, 서버는 줄지 않게 센다(열렸던 도전과제가 다시 잠기지 않는다) |
| `hasType` | 성향 테스트 현재 결과가 있으면 1 |
| `attendanceDays` | 누적 출석 일수(BE-97) |
| `collected` | 계산하지 않는다 → 해당 도전과제는 `PENDING` |

- 도전과제마다 `status`: `CLEARED` · `IN_PROGRESS` · `PENDING`. `PENDING`이면 `value`는 `null`이고 `cleared`는 `false`(잠김)다.
- 열린 항목(`unlocked`)은 처음부터 열린 것(FE-68 `FREE`)과 `CLEARED` 도전과제의 보상을 합친 것이다.

### 검증 (P-7 `PUT /profile-deco`)
- **값 목록**: 테두리 · 배경 · 카드 책갈피 모양 · 모양별 색 · 아이콘, 책갈피 캐릭터 · 얼굴 · 얼굴 종류 · 리본 색은 정해진 값 중 하나여야 한다. 아니면 `400 VALIDATION_ERROR`.
- **대표 이미지 형식**: `/images/`로 시작하고 `.webp`로 끝나며, `..` · `//` · 백슬래시가 없어야 한다. 아니면 `400 VALIDATION_ERROR`. 종류는 `/images/`와 파일명 사이 부분이다(예: `characters/scene`, 프론트 `kindOfPortrait`와 같은 규칙).
- **잠김**(지금 화면에 쓰이는 칸만 본다 — 고른 모양의 색, 짧은 책갈피일 때 좌우 아이콘. 쓰이지 않는 칸은 기본값이 잠겨 있을 수 있다: 긴 띠 색 기본 `wine`은 첫 판결 전까지 잠김): 대표 이미지 종류 · 테두리 · 배경 · 카드 책갈피 모양 · 고른 모양의 색(`모양:색`) · 좌우 아이콘이 열린 항목에 없으면 `409 DECO_LOCKED`. 잠긴 필드는 공통 에러 형식(API 명세 1-4)의 `details`(`{ field, reason: DECO_LOCKED }`)에 담는다 — 협의 때 제안한 `fields` 대신 다른 에러와 같은 형식을 쓴다. 기본 대표 이미지 2장(`standing/naero` · `standing/nambul`)은 항상 허용한다. 책갈피 캐릭터 · 얼굴 · 리본 색은 잠금이 없다.
- 하나라도 실패하면 아무것도 저장하지 않는다.
- (BE-98 보완) 이미 저장해 둔 값은 다시 거절하지 않는다. 아래 "2차" 참고.
- **조회는 거절하지 않는다.** 표가 바뀌어 이미 고른 항목이 잠기더라도 저장된 값을 그대로 내려 주고, 화면에서만 기본값으로 보여 준다(프론트 `shownDeco`).

### 응답
- 마이페이지(P-5)에 `profileDeco`(저장값 또는 기본값) · `achievements` · `unlocked`를 더한다(화면 한 번 진입에 한 번 호출).
- `PUT /profile-deco` 성공 시 저장된 `profileDeco`를 돌려준다.

### 로그인 이관
- 익명 ID 기준으로 저장한다. 로그인으로 여러 익명 ID가 한 회원에 묶이면 `updated_at`이 가장 최근인 꾸미기를 쓴다(구현은 로그인 연동 때).

## 고려한 제약 사항
- 수집 도전과제 2개(5장 · 20장)의 보상(대표 이미지 `cases` · `characters/law` · `characters/adult`, 배경 `news`, 아이콘 `naero` · `nambul`, 카드 책갈피 색 `green`)은 BE-83 전까지 열 수 없다.
- 기존 사용자가 브라우저에 저장해 둔 꾸미기는 서버로 옮기지 않는다. 처음 서버에 저장할 때 프론트가 지금 값을 PUT하면 그대로 옮겨진다(잠긴 값이면 거절).
- "새로 열림" 알림은 범위에서 뺀다(BE-83과 함께 검토).

## 추후 재검토가 필요하면
- BE-83이 수집 수를 저장하면 `collected`를 계산하고 수집 도전과제의 `PENDING`을 풀어 준다.
- 도전과제 · 보상 표가 확정되면 `ProfileDecoCatalog`만 고친다.
- 표를 운영 중에 자주 바꿔야 하면 DB 테이블로 옮기는 것을 검토한다.

## 2차 (BE-98 — 저장값과 같은 칸은 잠김을 다시 보지 않음)

### 문제 / 배경
- FE-71(PR #233) 리뷰: 표가 바뀌어 사용자가 이미 저장해 둔 값 중 쓰이는 칸이 잠기면, 다른 칸만 바꿔도 PUT 전체가 매번 `409 DECO_LOCKED`로 거절된다. 화면은 그 칸을 기본값으로만 보여 주므로(`shownDeco`) 사용자는 보이지 않는 칸 때문에 저장이 막힌다. 프론트가 잠긴 칸을 기본값으로 채워 보내면 저장값이 바뀌어, 다시 열려도 돌아오지 않는다.

### 검토한 대안
- 대안 A: 프론트가 잠긴 칸을 보이는 값으로 바꿔 보낸다. 저장값을 잃는다.
- 대안 B: 저장값과 같은 칸은 무조건 건너뛴다. 안 쓰이는 칸(예: 책갈피 없음일 때의 짧은 책갈피 색)은 1차에서 잠김 검사를 하지 않으므로, 잠긴 값을 넣어 두었다가 모양만 바꿔 여는 빈틈이 생긴다.
- **대안 C(선택): 저장값과 같고, 저장할 때도 쓰이던 칸만 건너뛴다.** 그때 잠김 검사를 통과한 칸만 인정하는 셈이다.

### 선택한 방법과 이유
- `ProfileDecoValidator.validate(꾸미기, 열린 항목, 저장값)`: 잠김 검사에서 저장값과 같은 칸을 건너뛰되, 그 칸이 저장값에서 쓰이던 칸일 때만이다(대표 이미지 · 테두리 · 배경 · 책갈피 모양은 늘, 짧은 책갈피 색 · 아이콘은 저장값 모양이 짧은 책갈피일 때, 긴 띠 색은 긴 띠일 때).
- 형식 · 값 목록(400)은 저장값과 같아도 늘 전체를 검사한다. 처음 저장(저장값 없음)은 1차와 같다.
- 조회는 지금처럼 거절하지 않고 저장값을 그대로 내려 준다.
