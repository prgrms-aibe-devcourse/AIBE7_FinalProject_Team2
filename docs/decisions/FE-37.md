# FE-37 의사결정 기록

## 문제 / 배경
- 판결 체험의 목 데이터 전용 테스트 코드(막 버튼 · 처음부터 다시 · 발표 판사 고르기 · 테스트용 벌금 선택지)가 화면 코드에 섞여 있었다.
- 7막 → 8막 이어 가기(`onCompared`)가 `aiPage.js` · `courtPage.js`에 똑같이 두 벌 있었다.
- 출처: PR #151(FE-31) 리뷰에서 보류한 항목.

## 검토한 대안
- `onCompared` 공통 함수 위치
  - A: `courtStage.js`에 `openComparison()`을 둔다. 두 화면이 이미 `renderCourtStage`를 여기서 가져오고, 8막 무대(`comparisonStage.js`)를 쓰는 곳도 7막 무대 쪽이라 새 import 방향이 생기지 않는다.
  - B: `mocks/` 또는 `utils/`에 새 파일. 화면 흐름 코드라 목 코드도 유틸도 아니어서 맞지 않는다.
- 막 버튼 · 처음부터 다시의 노출
  - 현행 유지: 목 모드(`API_MODE === 'mock'`)에서만 보이고 실제 모드에서는 사라진다.
  - 플래그로 숨기기(`VITE_SHOW_ACT_TEST` 등): 목 데이터를 쓰면서 버튼만 감춘다.
  - 삭제: 코드가 가장 깔끔하지만 막 이동 수단이 없어진다.

## 선택한 방법과 이유
- `openComparison()`은 `courtStage.js`에 둔다. 동작은 그대로(7막 장면 자리에서 신문으로 빠져나오고 주소만 S-09로 바꾼다).
- `restartMock` · `jumpActMock`은 `mocks/mockStageButtons.js`로 옮긴다. 목 전용 코드가 `mocks/`에 모이고, 화면 파일은 목 파일에서 가져다 쓴다.
- 발표 판사 고르기와 테스트용 벌금 선택지는 삭제한다(시연용 확인이 끝났다).
- 막 버튼 · 처음부터 다시는 **현행 유지**한다. 이후에도 목 모드로 화면을 확인할 일이 계속 있어, 지금 지우는 이득보다 확인 수단을 잃는 손해가 크다.
- 개발 서버 내비에 목 ↔ 실제 API 스위치를 둔다. 값은 `localStorage`에 두고 개발 서버(DEV)에서만 환경변수보다 우선한다. 배포 빌드는 환경변수만 읽는다.

## 고려한 제약 사항
- 실제 모드 번들에서 목 전용 코드가 빠지는 것은 `API_MODE`가 빌드 시점 상수여서다. 스위치가 이 값을 런타임에 바꾸면 이 성질이 깨지므로, 스위치는 DEV로만 허용해 배포 빌드의 값을 건드리지 않게 했다.
- `verdictPage.js`의 벌금 처리 코드는 실제 사건에서 벌금형이 나올 수 있어 남겼다(삭제한 것은 목 데이터의 테스트용 선택지뿐).

## 추후 재검토가 필요하면
- 목 모드로 화면을 확인할 일이 사라지면 막 버튼 · 처음부터 다시(`stage.js` · `stage.css` · `mocks/mockExperienceStore.js`)를 지운다.
