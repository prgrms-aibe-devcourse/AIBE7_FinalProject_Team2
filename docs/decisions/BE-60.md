# BE-60 의사결정 기록

> 근거: [`deploy/README.md`](../../deploy/README.md) "자동 배포(CD)", WBS 7.1.3 · 7-5 범위 조정안 6번, 10/16 로컬 검증.

## 문제 / 배경
- BE-58까지는 이미지 빌드 · GHCR 업로드만 자동이고, 서버 반영은 배포 담당이 SSH로 들어가 손으로 했다(`pull` → `up` → 스모크 테스트).
- 10/16 수동 배포에서 백엔드가 뜨기 전에 스모크 테스트를 돌려 502 오탐이 났다. 배포 순서 · 대기 · 되돌림을 사람이 기억해야 했다.

## 검토한 대안

**어느 브랜치를 배포하나**
- `develop` → 스테이징, `main` → 운영 (WBS 원안): 서버가 한 대라 스테이징을 둘 곳이 없다.
- `develop` → 운영: 머지마다 운영이 바뀐다. 리뷰 중 기능이 섞여 나갈 수 있다.
- **`main` → 운영 (선택)**: 범위 조정안 6번. 운영 반영은 `develop → main` PR로만 한다(CLAUDE.md 4장 규칙과 같다).

**GitHub Actions가 서버에 어떻게 반영하나**
- A. Session Manager(SSM) + GitHub OIDC: 포트 · 키 없이 원격 명령. IAM 역할 2개가 필요한데 **팀 계정에 IAM 생성 권한이 없다**.
- B. SSH 키를 GitHub Secrets에 두고 22번 개방: GitHub 러너 IP 대역이 넓고 자주 바뀌어 22번을 사실상 전체에 여는 것과 같다.
- **C. 서버가 스스로 확인 (선택)**: 서버가 2분마다 GHCR의 `main` 이미지를 보고 바뀌었으면 배포한다. 새로 여는 포트 · AWS 권한 · GitHub에 저장하는 서버 키가 없다.
  - 단점(결과가 Actions에 안 보임)은 web 이미지의 `/version.json`(커밋 해시만)을 공개된 80번으로 확인해 보완했다.

## 선택한 방법과 이유
- `deploy.sh`: **커밋 고정 태그(`sha-xxxxxxx`)**로만 배포한다(`main` 같은 움직이는 태그는 받지 않음) → 무엇이 떠 있는지 분명하고 되돌리기가 정확하다.
- 배포 순서: **백엔드 먼저 → healthy 확인 → 웹 교체 → 스모크 테스트**. 한 번에 `up` 하면 Compose가 웹을 먼저 내려 두고 새 백엔드를 기다려 배포 중 화면까지 안 열렸다(10/16 로컬 실측). 이 순서면 기존 웹이 화면을 계속 내주고, 새 백엔드가 실패해도 웹은 바뀌지 않는다.
- 실패하면 직전 태그로 **자동 되돌림**. 되돌린 커밋은 기록해 두고 다시 시도하지 않는다(2분마다 실패 · 되돌림 반복 방지).
- **DB 스키마는 되돌리지 않는다.** 데이터 손상 위험이 있어 경고만 남기고 사람이 판단한다. 이전 앱은 모르는 새 마이그레이션을 무시하고 뜬다(Flyway 기본 `ignoreMigrationPatterns`).
- 백엔드 healthcheck는 `/actuator/health`가 아니라 **readiness**를 쓴다. 전체 상태는 Redis 장애 때 DOWN이 되지만 API는 정상이다(BE-61 실측).
- 업로드 순서: sha 태그를 먼저, `main` 태그를 마지막에 옮긴다. 서버가 `main`이 바뀐 걸 봤을 때 sha 태그가 이미 있게 하기 위해서다.
- 서버는 이미지 라벨의 커밋이 **`origin/main` 최신 커밋과 같을 때만** 그 커밋으로 저장소를 옮기고 스크립트를 실행한다. 라벨만 믿으면 main에 없는 커밋의 코드가 서버에서 돌 수 있다(셀프 리뷰 반영).
- 성공한 배포 뒤 지금 · 직전 sha 이미지만 남기고 지운다. 배포마다 약 700MB씩 쌓여 30GB 디스크가 찬다(셀프 리뷰 반영).

## 고려한 제약 사항
- 서버 한 대(t3.small)라 무중단 배포는 아니다. 백엔드가 다시 뜨는 20 ~ 40초 동안 API는 끊긴다(화면은 열림).
- GHCR이 비공개라 서버가 임시 토큰으로 로그인한다. 토큰 만료(11/14경)는 최종 제출(11/04) 뒤라 프로젝트 기간은 덮는다. 만료되면 서버 로그와 Actions 확인 job이 실패로 보인다.
- 반영까지 최대 2 ~ 3분 지연(확인 주기).
- 되돌릴 때 Compose · 스크립트는 새 커밋 것을 쓴다(이미지 태그만 되돌림).

## 추후 재검토가 필요하면
- IAM 권한이 생기면 A(Session Manager)로 바꿔 지연을 없애고 결과를 Actions에 바로 남긴다.
- RDS 전환(BE-59, 10/28): `postgres` 서비스가 빠지면 마이그레이션 비교를 다른 방법으로 한다.
- GHCR 공개 전환 시 서버 로그인 · 토큰 만료 문제가 사라진다.
