# FE-22 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #119 본문.

## 문제 / 배경
- 성향 테스트 결과를 공유하는 화면을 만들면서, 공유받은 사람에게 무엇을 보여 줄지와 공유 주소 형식을 정해야 했다.

## 선택한 방법과 이유
- 공유 화면은 **유형 설명만** 보여 준다(응답 · 축 점수 · 체험 기록 없음, FR-8-6).
- 공유하기는 OS 공유 창(Web Share) → 안 되면 링크 복사 → 그것도 안 되면 주소를 보여 주는 순서로 단계적으로 대체한다. 이미지 공유는 캐릭터 이미지(7.6.8) 뒤로 미뤘다.
- 사용자 화면에서 4글자 코드(INTP 등)와 축 글자를 뺐다(상표 우려, 10/13 결정). 이에 맞춰 공유 주소를 코드 대신 **해시 `shareId`**(영숫자 6 ~ 16자, 대소문자 구분)로 바꿨고, 공유 조회 응답에는 유형 코드를 넣지 않는다. 옛 4글자 주소는 404.
- 라우터에 `:code` 자리표시자를 추가하되 기존 `:caseId` 동작은 그대로 뒀다.

## 고려한 제약 사항
- 공용 라우터 파일을 건드리는 변경이라 리뷰 요청에 명시했다.
- OS 공유 창의 실제 동작은 자동화 클릭이 사용자 클릭으로 인정되지 않아 확인하지 못했다.
- 7.6.4 계약에 넣어야 할 내용(shareId 등)은 PR 댓글로 백엔드 담당에게 전달했다.
