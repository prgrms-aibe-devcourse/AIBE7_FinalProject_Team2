# BE-84 의사결정 기록

## 문제 / 배경

COMMON-40(generate 모델 고정)에서 google-genAI · Groq · NVIDIA NIM의 무료 모델을 여러 사건으로 비교 테스트하기로 했다. 그런데 `tools/ai-judgment/llm.py`가 지원하는 공급자는 `openai` · `anthropic` · `gemini`뿐이라, 테스트를 하려면 두 공급자를 먼저 붙여야 했다.

## 검토한 대안

### 1. 공급자를 어떻게 붙일 것인가

- **대안 A — 공급자마다 `_call_<공급자>` 함수를 따로 만든다.** 기존 문서(`llm.py` 모듈 설명)가 안내하는 방식이다. 공급자마다 독립적이라 한쪽을 고쳐도 다른 쪽에 영향이 없다. 다만 Groq · NIM · OpenAI는 요청 · 응답 모양이 같아서 거의 같은 함수가 셋이 된다.
- **대안 B — `OPENAI_BASE_URL`처럼 기존 `openai` 공급자의 주소만 바꿔 쓴다.** 코드를 아예 안 고쳐도 된다. 하지만 모델 지정이 `openai:llama-3.3-70b-versatile`이 되어 실행 기록 · 비교표 · 전송 안내에 **실제로 데이터를 받은 곳이 Groq인데 OpenAI로 남는다.** 외부 전송 대상을 정확히 알리는 원칙(6장)과 어긋나고, 여러 공급자를 동시에 쓰는 비교 테스트 자체가 불가능하다(환경변수는 하나뿐).
- **대안 C(선택) — OpenAI Chat Completions 형식 공급자를 설정 표(`OPENAI_COMPATIBLE`) 하나로 묶고, 호출 함수는 공유한다.**

### 2. 무료 모델 목록을 어떻게 채울 것인가

- **대안 A — 문서 · 블로그를 보고 `free_models.json`에 옮겨 적는다.** 기존 Gemini 항목이 그렇게 되어 있다. 공급자가 모델을 자주 바꾸고, 3자 블로그는 서로 숫자가 어긋나 틀리기 쉽다.
- **대안 B — 공급자의 `/models`를 불러 `free_models.json`을 자동으로 갱신한다.** 항상 최신이 된다. 그러나 응답에는 임베딩 · 음성 · 코드 · 비전 · 안전 분류 모델이 섞여 있어서, 그대로 넣으면 `free:<공급자>` 자동 선택이 판결 생성에 쓸 수 없는 모델(예: 임베딩 모델)을 골라 회차 전체가 실패한다.
- **대안 C(선택) — 조회 도구(`list_models.py`)만 만들고, 무엇을 목록에 넣을지는 사람이 고른다.**

## 선택한 방법과 이유

### 1. OpenAI 호환 공급자를 설정 표로 묶었다 (대안 C)

`OPENAI_COMPATIBLE`에 공급자별로 네 가지(기본 주소 · 주소를 바꾸는 환경변수 · 생성 토큰 상한 필드 · JSON 모드 지원 여부)만 적고, 호출은 `_openai_compatible` 하나가 한다. `PROVIDERS`에는 `functools.partial`로 공급자 이름만 고정해 등록한다.

- 같은 코드가 셋으로 늘지 않으면서, **공급자 이름은 실제 데이터를 받는 곳으로 남는다**(`nim:nvidia/…`). 외부 전송 안내 · 실행 기록 · 비교표가 모두 정확해진다.
- 실제로 흡수해야 했던 차이는 셋뿐이었다. ① NIM은 `max_completion_tokens`를 받지 않아 `max_tokens`를 쓴다(OpenAI · Groq는 반대로 `max_tokens`가 deprecated). ② NIM은 JSON 모드(`response_format`) 지원이 모델마다 달라 400이 올 수 있다. ③ 기본 주소가 다르다.
- 다음에 OpenAI 호환 공급자를 또 붙일 때는 함수 없이 표에 한 줄만 더하면 된다.

### 2. 모델 목록은 조회만 하고 자동으로 넣지 않는다 (대안 C)

`list_models.py <공급자>`가 공급자에게 직접 물어 모델 ID를 보여 준다. `free_models.json`은 그 결과를 보고 사람이 고쳐 넣는다.

- 자동 갱신의 위험(판결 생성에 쓸 수 없는 모델이 자동 선택됨)을 없애면서, 옮겨 적다 틀리는 문제도 없앤다. 실제로 이 도구로 NIM 모델 ID 9개가 카탈로그에 있는지 확인하고 넣었다.
- Groq의 preview 모델은 공급자가 "예고 없이 내릴 수 있다"고 안내하므로 `previewModels`로 따로 적어 자동 선택(`free:groq`)에서 뺐다. 직접 지정은 된다.

### 3. 한도 · 오류 분류를 두 공급자에 맞게 넓혔다

`429`가 **분당 한도**(기다리면 풀림)인지 **일 한도 · 크레딧 소진**(기다려도 안 풀림 → 그 모델을 건너뜀)인지는 BE-45 대체 체인의 분기점이라 정확해야 한다.

- Groq는 429 본문에 창(窓)을 문장으로 적는다(`on requests per day (RPD)` / `on tokens per minute (TPM)`). 본문 문구로 구분하도록 `DAILY_QUOTA_TEXTS`를 뒀다. 분당 한도 문구(`per minute`)는 걸리지 않는다.
- NIM은 오류 본문이 RFC 7807 모양(`detail` · `title`)이라, 기존처럼 `error.message`만 찾으면 사유가 `{'detail': …}` 같은 문자열로 남았다. 읽을 수 있게 키 탐색 순서를 뒀다.
- JSON 모드 안내를 붙이느라 오류를 감싸면서, **한도 · 과부하 오류는 그대로 올려** `kind`(재시도 · 대체 판단)가 바뀌지 않게 했다. 테스트로 지킨다.

### 4. NVIDIA NIM은 Gemini 무료 등급과 같은 기준으로 다룬다

[NVIDIA API Trial 약관](https://assets.ngc.nvidia.com/products/api-catalog/legal/NVIDIA%20API%20Trial%20Terms%20of%20Service.pdf)은 입력(User Content) · 응답(Generated Content)을 **AI 모델을 포함한 제품 · 서비스 개선에 쓸 수 있다**고 적고 있다. 따라서 비식별화한 사건 내용을 보내는 점검 · 생성에만 쓰고, 판결문 원문 단계(extract · court)에는 쓰지 않는다([파이프라인 문서](../ai-judgment-pipeline.md) 6장과 같은 기준).

Groq는 추론 입력 · 응답을 기본으로 보관하지 않고 고객 데이터를 학습에 쓰지 않는다고 적고 있어 조건이 더 낫다. **다만 무료 등급을 따로 떼어 규정한 조항은 확인하지 못했다.** 그래서 판결문 원문 단계는 다른 무료 등급과 똑같이 유료 키만 쓰는 쪽으로 뒀다(확인되지 않은 유리한 해석으로 원문을 내보내지 않는다).

## 고려한 제약 사항

- **설치 없이 실행**: `tools/ai-judgment`는 표준 라이브러리만 쓴다. `openai` 패키지를 쓰면 두 공급자 모두 훨씬 간단해지지만 이 원칙을 깬다. 기존 `urllib` 경로를 그대로 썼다.
- **기존 동작을 바꾸지 않음**: `_openai`를 공통 함수로 바꾸면서 OpenAI 호출의 요청 모양(`max_completion_tokens` · `OPENAI_BASE_URL`)은 그대로 뒀다. 전체 테스트 362건이 그대로 통과한다.
- **키 없이 도는 테스트**: 공급자 호출 테스트는 `options["http"]`에 가짜 함수를 넣어 네트워크 없이 요청 모양 · 오류 분류를 확인한다(기존 테스트 방식과 같다).
- **모델 목록의 수명**: 공급자가 모델을 자주 바꾸므로 `free_models.json`에 적은 목록은 확인일(`checkedAt`) 기준 스냅샷이다. 쓰기 전에 `list_models.py`로 확인한다.

## 추후 재검토가 필요하면

- **Groq 무료 등급의 데이터 약관**: 무료 등급을 따로 규정한 조항을 찾으면, 판결문 원문 단계에 백업으로 쓸지(5-5) 다시 판단할 수 있다.
- **`free_models.json`에 넣은 모델 순서**: 지금은 모델 크기 · 범용성만 보고 적었다. COMMON-40 테스트로 한국어 판결 생성 품질 · 검증 통과율이 나오면 그 순서로 다시 정한다(`freeModels.max` 기본 3이라 앞쪽 모델이 먼저 쓰인다).
- **NIM의 JSON 모드**: 어느 모델이 지원하는지 목록 API로는 알 수 없어 400으로만 알 수 있다. COMMON-40 테스트에서 모델별로 확인되면 `free_models.json`에 적어 둘 수 있다.
