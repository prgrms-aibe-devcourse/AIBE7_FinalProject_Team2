# FE-148 의사결정 기록

관리자 대본 블록 검수 화면 · 공개 중 수정 점검 안내. 서버는 BE-126 2차(PR #383 블록 단위 검수 · 낡음, PR #384 `scriptStatus` · 점검 중)이고, 이 이슈는 PR #384 리뷰 1번("공개 중 문장 하나 고치면 대본 전체가 503 — 관리자 쪽 안전장치")에서 나왔다.

## 1차 블록 검수 · 낡음 표시 · 점검 안내 (PR #388)

재생성 화면(A-13-15 ~ 17)과 분류 수정(A-11 `classification`)은 다음 PR로 나눈다. 이 PR은 이미 있는 대본을 블록 단위로 검수하는 데까지다.

### 문제 / 배경

- 관리자 대본 화면(FE-106)은 증거조사 대사(U3)만 그렸다. 대본이 블록 U0 ~ U4로 바뀐 뒤(BE-126 1차) 다른 네 블록은 화면에서 볼 수도 고칠 수도 없었다.
- 블록 단위 승인 · 반려 · 확인했음 · 문장 수정(A-13-18 ~ 21)과 낡음 표시(A-13-10)가 서버에만 있었다.
- 공개 중인 대본의 승인을 푸는 요청은 서버가 막지 않고 점검 중(API 18 503)으로 바꾼다. 화면이 묻지 않으면 오탈자 하나로 그 사건 체험이 잠긴다.

### 검토한 대안

- **블록 내용을 그리는 방법**
  - 블록마다 전용 화면(U0 질문 · 답 표, U2 카드 등): 보기 좋지만 블록 모양(파이프라인 계약)이 바뀔 때마다 화면을 고쳐야 하고, 다섯 가지 화면을 만들어야 한다.
  - **문자열 자리를 JSON Pointer로 꺼내 한 자리씩 그린다 (택함)**: A-13-21이 고치는 단위(이미 문자열이 있는 자리)와 검수 결과의 `path`가 같은 JSON Pointer라, 자리마다 그 자리의 오류 · 경고를 바로 붙이고 그 자리에서 고친다. 모양을 몰라도 된다. 자리 이름은 마지막 키를 한국어로 바꾸고(`/questions/0/q` → "질문 1 · 질문") 모르는 키는 그대로 보인다. 원래 path도 함께 보여 검수 결과와 대조할 수 있다.
- **공개 중 수정의 안전장치**
  - 서버에서 막기: PR #384에서 일부러 뺐다(점검 상태로 고칠 수 있게 한 것이 그 PR의 목적).
  - 화면에서 버튼을 잠그기: 공개 사건의 대본을 고칠 길이 없어진다.
  - **승인을 푸는 요청 전에 확인을 받기 (택함)**: `releasedAt`이 있고 지금 `READY`일 때만 묻는다. 이미 점검 중이면 사용자가 보던 것을 새로 거두지 않고, 나간 적 없는 대본(초안 사건에서 승인만 함)은 사용자가 본 적이 없어 묻지 않는다 — DESIGN.md 확인 기준("사용자가 보던 것을 거두는 작업만 묻는다")과 같다.
- **블록 승인 확인**: 블록 승인은 운영 기록이라 묻지 않는다. 다만 공개 사건에서 마지막 블록 승인이면 사용자에게 새로 공개하는 작업이라 묻는다(`opensToUsers`).
- **승인 버튼 잠금 조건**: 서버(A-13-18)와 같은 순서로 이유를 보인다 — 대본 조건(멈춤 · 만들지 못한 것 · 대본 전체 검수 오류)이 먼저다. 그때는 블록을 고쳐도 풀리지 않아 "다시 생성"이 길이다. 같은 이유가 화면 위쪽(대본 안내 · 낡음 안내)에 이미 보이면 버튼 설명으로만 잇는다.

### 선택한 방법과 이유

- 계산은 순수 함수(`adminScriptBlocks.js`)로 모아 테스트한다: 문자열 자리 · 자리 이름 · 승인 막힘 이유 · 공개 중 수정 확인 문구 · 마지막 블록 승인 판단 · 길이 규칙. 화면 파일은 그리기만 한다.
- 목 API를 블록 기준으로 바꿨다(대본 값은 블록에서 계산 — 서버와 같은 규칙). 사건 12는 오류 블록 · 승인을 막는 낡음 · 경고를, 사건 13은 사용자에게 공개 중인 대본(점검 흐름)을 보여 준다.
- 승인한 블록은 내용을 접어 두고, 검수할 블록만 펼친다(다섯 블록을 펼치면 화면이 너무 길다).
- 블록은 상자 대신 위 괘선으로 나눈다 — 블록 안에 대사 · 문장 상자가 들어가서, 블록까지 상자면 카드 안에 카드가 된다(DESIGN.md).
- 사유 코드가 없는 409(`INVALID_STATE`)는 서버 문구를 그대로 보인다. 대본 블록 승인의 409는 어느 블록이 왜 막혔는지를 문구에 담는다(사유 코드 없음). 전에는 "지금 상태에서는 할 수 없어요"로 뭉개졌다.
- 대사 측(`role`)과 배역(`character` · `cast`)은 서버 저장값(소문자 코드)을 받아 화면 이름으로 바꾼다. 목도 서버처럼 소문자로 맞췄다.

### 고려한 제약 사항

- 관리자 화면은 사용자 화면 코드를 쓰지 않는다(README "사용자 화면과 분리"). 배역 이름(내로 · 남불)도 관리자 쪽에 따로 둔다.
- 길이 규칙(100자 · 2줄, 줄바꿈 제외)은 서버 · 파이프라인과 같은 값이다. 화면은 미리 알리기만 하고 서버가 다시 거절한다.
- 확인 창은 `window.confirm`(`confirmChange`)이다. 기존 관리자 화면과 같은 방식이라 바꾸지 않았다.

### PR #388 리뷰 반영

해송님 리뷰(1부 코드 · 2부 파이프라인 설계자 관점).

- **길이 규칙 범위 (1부 1번)**: 파이프라인 검수는 대사 길이를 **말하는 대사**에만 건다(`script_review.unit_lines`의 guide · narrator · prosecutor · defense). 화면은 모든 문자열 자리에 걸고 있었고, 확인해 보니 서버(A-13-21)도 같았다. 서버는 BE-153으로 고치고, 화면은 같은 자리 목록(`SPOKEN_PATHS`)을 쓴다. 목록은 계약 파일 `spokenPaths`에 두고 프론트 테스트도 그 파일을 읽어 비교한다. 대사가 아닌 자리는 빈 값 · 500자만 본다.
- **서버 거절 (1부 2번)**: 서버는 A-13-21도 거절한다(컨트롤러에서 길이 검사). 다만 범위가 너무 넓었던 것이 1번이다.
- **배지 (1부 3번)**: 나간 적 없는 READY(`releasedAt` 없음)는 "승인 완료 · 사건 공개 대기"로 보인다.
- **라벨 · 목 (1부 4번)**: U0 `tone` 이름을 더했다. 목의 혐의 인정 계산을 서버 · 파이프라인과 같은 한 낱말 규칙(`admits`)으로 바꾸고 계약 파일 `admits` 사례로 테스트한다.
- **실서버 확인 (1부 5번)**: 로컬 개발 DB에 백엔드를 띄우면 그 DB에 마이그레이션이 적용되고 관리자 계정 · 대본을 넣어야 해서 하지 않았다. 대신 화면 · 목이 읽는 필드를 서버 응답 레코드(`CaseScriptResponse` · `Block`)와 코드로 대조했고 모두 일치했다. 요청 경로 · 본문은 컨트롤러와 같다.
- **고친 문장 재검사 (2부 1번)**: 서버가 고친 문장에 검사를 다시 돌리지 않는다 — BE-154로 올렸다. 그 전까지 고치기 폼에 "고친 문장은 다시 검사하지 않아요. 금지어 · 형량 표현 · 말투를 직접 확인해 주세요"를 둔다.
- **`fix: unit` (2부 2번)**: 블록 오류에 `fix: unit`이 있으면 "다시 생성해야 해요"로 안내한다(문장 수정은 이미 있는 자리만 고쳐 줄을 더할 수 없다). 재생성이 유일한 길인 안내(멈춤 · 만들지 못한 것 · 대본 전체 검수 오류 · 새 민감 플래그 · 앞 블록 변경)에는 "재생성 화면은 다음 배포에 들어가요"를 붙였다.
- **생성 문맥 (2부 3번)**: 대본 머리에 분위기 · 민감 플래그를 읽기 전용으로 보인다(A-6 사건의 지금 값). 고정 대사와 합친 미리보기는 2차 이후 후보.
- **프롬프트 · 틀 버전 (2부 4번)**: BE-155로 올렸다.
- **새로 생긴 민감 플래그 (2부 5번)**: 블록 근거의 플래그와 사건의 지금 플래그를 비교해(서버 `addedSensitiveFlags`와 같은 규칙) 새로 생긴 것이 있으면 "확인했음"을 잠그고 이유를 보인다. 누르고서야 409를 받지 않게.
- **U0 수정 뒤 (2부 6번)**: 낡음 이유에 앞 블록(U0 · U2)이 있으면 "다시 생성 권장"을 경고로 보인다.

### 추후 재검토가 필요하면

- 2차: 재생성 화면(A-13-15 ~ 17 — 블록 고르기 · cascade · 미리보기 · 수동 수정 줄 경고 · 반영), A-11 분류 수정(`classification` · `classificationNeedsReview`).
- 블록마다 전용 화면이 필요해지면(예: U2 카드 미리보기) 그 블록만 따로 그리고, 나머지는 지금 방식으로 둔다.
