# FE-56 의사결정 기록

## 문제 / 배경
- 10/19 impeccable 크리틱(메인 · 신문 · 마이페이지 · 성향검사)에서 시연(11/04) 흐름을 막거나 오해를 주는 항목이 나왔다.
  - 대본이 없는 사건(2 ~ 9번)도 "시작하기"가 열려, 목에서는 이후 화면이 대본 사건 기준이라 막다른 길이 된다.
  - 참여 수 · 레벨 · 직업 · 출석 일수 · 체험 평균 건수가 목 값인데 실제 수치처럼 보인다.
  - `/cases` · `/test`를 주소로 바로 열면 데이터를 받는 동안 빈 화면이다.
  - 공통 헤더 로고가 `/me` · `/test` · `/login` · 404에서 워드마크 글꼴을 잃는다.

## 검토한 대안
- 대본 없는 사건
  - A. 목록에서 숨긴다: 지면이 1건만 남아 신문 메타포가 무너진다.
  - B. 기사 · 사건 정보(S-20)는 읽게 두고 체험 시작만 "준비 중"으로 막는다 (선택).
  - C. 대본 없이 MVP 화면으로 진행: 실제 API에서는 가능하지만 목에서는 이후 화면이 대본 사건 기준이라 막힌다. 시연 안정성을 우선했다.
- 목 수치
  - A. 목 값이면 줄을 숨긴다: 실제 데이터가 들어올 자리라 화면 구성을 유지하고 싶다는 결정에 따라 택하지 않았다.
  - B. 값 옆에 "목데이터" 딱지를 붙인다 (선택). 공통 부품 `mockTag()`(components/siteLayout.js) 하나로 쓴다.
- 로고 글꼴
  - A. 로고 규칙의 명시도를 억지로 올린다(`.site-header .logo-button.logo-button` 등): 읽기 어렵다.
  - B. 화면별 `.xx-page .site-header button { font: inherit }`에서 `:not(.logo-button)`으로 로고를 뺀다 (선택). 원인이 있는 곳을 고친다.

## 선택한 방법과 이유
- "준비 중" 판정은 대본 유무(`scriptFor(caseId, title)`)로 한다. 목 · 실제 API 모두 같은 기준이고, FE-33에서 대본이 생기면 자동으로 풀린다.
- 목데이터 표기는 `API_MODE === 'mock'`이면 참여 수 · 체험 기록 수치에, 마이페이지 레벨 · 직업 · 출석은 응답에 값이 없어 `MOCK_PROFILE`로 채운 경우에 붙인다(실제 API에도 아직 이 필드가 없다).
- 메인 물건에는 라벨 · 헤드라인을 붙이지 않는다(FE-50 결정: 내로를 가린 포스트잇으로 "물건 = 클릭"을 학습시킨다). 대신 누를 수 있는 물건의 호버를 더 밝게 하고 그림자를 길게 해, 움직이지 않고 "뜬 것"처럼 보이게 했다. 준비 중 물건은 예전 그대로.
- `/test`는 책상에서 올라올 때 그동안 책상이 보이므로 기존 순서(문항을 받은 뒤 철)를 지키고, 주소로 바로 들어올 때만 철 + "문항을 불러오는 중이에요."를 먼저 그린다.
