# BE-115 의사결정 기록

> 근거: FE-47 · FE-88 · FE-89 · FE-116(화면 목 `frontend/src/mocks/communityMockApi.js`) · BE-106(경험치 수급처) · BE-114(카드 아래 줄). 계약은 API 명세 12장(v0.68), 테이블은 ERD 14장(v1.48 · V38)

## 문제 / 배경
- 커뮤니티 화면(목록 · 상세 · 글쓰기 · 메인 · 명함 · 랭킹)은 목으로만 돌고 서버 API가 없었다.
- 글쓴이 명함에 레벨 · 직업 · 카드 아래 줄을 넣고, 글 · 댓글 · 좋아요 때 경험치(`LevelService.award`)를 줘야 했다.
- 회의 결정(10/29): 로그인 없이는 체험만, **커뮤니티 글쓰기는 로그인 전용**. 마이페이지 · 레벨 · 꾸미기 데이터를 회원 기준으로 옮기는 일은 별도 이슈로 한다(체험만 이관, 나머지 초기화).

## 검토한 대안

### 1. 글쓴이와 명함 기준
- A: 글쓴이 = 회원, 명함 · 경험치 = **쓴 요청에서 회원에 연결된 익명 ID** (선택)
- B: 회원에 연결된 익명 ID 중 "대표"를 매번 골라 명함을 만든다 — 회원 단위 프로필 규칙을 이 이슈에서 새로 정하는 셈이고, 마이페이지(브라우저 기준)와 값이 어긋날 수 있다
- C: 레벨 · 꾸미기 테이블을 회원 기준으로 바꾼 뒤 만든다 — 범위가 너무 크고 회의에서 별도 이슈로 정했다

### 2. 카카오 회원(닉네임 없음)의 이름
- 자동 이름(선택) / 글쓰기 막기 / "카카오 회원" 고정 — 사용자 결정

### 3. 좋아요 · 댓글 수
- A: 글에 수를 함께 센다(선택) — 좋아요순 · 댓글순 정렬과 쪽 나누기가 한 쿼리로 된다
- B: 조회 때마다 센다 — 정렬하려면 집계 서브쿼리가 필요하고 목록이 무거워진다

### 4. 첫 PR 범위
- 사진 올리기만 빼고 전부(선택) / 전부 / 핵심만 — 사용자 결정. 사진은 S3 업로드 · 용량 · 검수가 따로 필요하다

## 선택한 방법과 이유
- **명함 기준 익명 ID**(대안 1-A): 쿠키의 익명 ID가 이 회원에 연결돼 있으면 그것, 아니면 이 회원에 연결된 익명 ID 중 가장 최근에 접속한 것. 연결된 것이 하나도 없으면 회원에 연결된 익명 ID를 새로 만든다(로그인 처리가 늘 만들어 두므로 드물다). 글 · 댓글 행에 그 익명 ID를 남겨 명함을 그 기준으로 그린다. 마이페이지에 보이는 값과 같고, 규칙이 `CommunityActorResolver` 한 곳에 모여 회원 기준 전환 때 여기만 바꾸면 된다.
- **자동 이름**: `방청객 {회원 ID}`. 사람마다 다르고 바뀌지 않는다. 회원 번호가 드러나지만 표시용이고 다른 API가 회원 번호를 받지 않아 악용할 곳이 없다. 닉네임 설정 기능이 생기면 그 값을 쓴다.
- **로그인 확인**: `SecurityConfig` 사용자 체인에 `POST /api/v1/community/**` `authenticated()`를 더했다(체인 주석의 "회원 전용 API를 만들 때 authenticated()를 추가" 방침). 컨트롤러도 회원이 없으면 같은 401을 던진다. 에러 코드는 목의 임시 `LOGIN_REQUIRED` 대신 기존 `UNAUTHORIZED`를 쓴다 — 화면 연동 때 매핑한다.
- **경험치**: BE-106 `XpSource` 키 규칙 그대로. 좋아요 받기 대상은 `"글 ID:누른 회원 ID"`(익명 ID가 아니라 회원 ID — 같은 회원이 브라우저를 바꿔 다시 눌러도 한 번). **내 글에 누른 좋아요는 경험치를 주지 않는다**(스스로 쌓는 것 방지). 좋아요 두 건(누른 사람 · 글쓴이)은 `award`가 사용자 행을 잠그므로, 서로의 글에 동시에 누르면 잠금 순서가 엇갈려 교착이 날 수 있어 **익명 ID 순서로 차례를 고정**했다.
- **좋아요 켜고 끄기**: `INSERT … ON CONFLICT DO NOTHING`이 1이면 켬, 0이면 지움. 수는 한 문장 UPDATE로 ±1. 동시에 눌러도 행 · 수가 어긋나지 않는다.
- **판결 공유**: 화면은 판결 값을 보내지 않고 서버가 붙인다(목과 같다). 판결 확정(`VERDICT_CONFIRMED`) 이후 체험의 내 최종 판결, `caseId`를 보냈으면 그 사건 것. 글에는 **붙인 시점 값을 jsonb로 남긴다** — 다시 체험해도 이미 쓴 글은 바뀌지 않아야 하기 때문이다.
- **목록 쪽 나누기**: 목처럼 "첫 글부터 page쪽 끝까지"를 내려 준다. 화면의 "더 보기"를 고치지 않고 붙일 수 있다. 한 번에 읽는 양을 묶으려고 page는 50(300개)까지만.
- **C-7 판결 없음 = 204**: 목은 `null`을 돌려준다. 200에 빈 본문은 JSON 해석이 깨지고, 404는 "오류"로 보이므로 204로 했다.
- **메인 이야기 수**: 목 주석대로 최근 하루 글 + 댓글. 추천은 이야기 수 → 판결한 사람 수.

- **메인(C-6) 응답 캐시**(PR #341 CodeRabbit 리뷰): 메인은 공개 API인데 글 · 댓글을 쓴 회원 전원의 명함을 계산해 부를 때마다 비용이 회원 수만큼 는다. 후보를 최근 활동자로 줄이면 "글이나 댓글을 쓴 회원" 전체 랭킹이라는 계약이 달라지므로, 후보는 그대로 두고 **계산한 응답을 일정 시간 서버 메모리에 둔다**(기본 1시간, 설정으로 하루까지). 랭킹 · 이야기 많은 사건이 그만큼 늦게 반영되는 것은 감수한다(사용자 결정: 반영이 늦는 것은 괜찮다). 응답에 보는 사람에 따라 달라지는 값이 없어 모두가 같은 응답을 공유한다. 만료되면 한 요청만 다시 계산하고 나머지는 기다려 같은 결과를 받는다. 서버가 여러 대면 대마다 따로 계산하고(공유 캐시는 후속), 재시작하면 비워진다. 명함 계산 자체의 배치화는 하지 않았다.

## 고려한 제약 사항
- 레벨 · 꾸미기 · 설정이 익명 ID 단위라 명함도 익명 ID 기준일 수밖에 없다(대안 1-C는 별도 이슈).
- 성향카드 꾸미기(FE-82)는 서버에 없어 `shownType.deco`는 늘 `null`이다(화면이 기본 꾸미기로 그린다).
- 사진 올리기 · 글 삭제 · 수정 · 신고 · 닉네임 설정은 범위 밖이다. `images`에 값이 오면 400(`NOT_SUPPORTED_YET`)으로 막아, 사진이 조용히 사라지지 않게 했다.

## 추후 재검토가 필요하면
- **글 목록 비용**(PR #341 리뷰): C-1은 첫 글부터 `page × 6`개(최대 300개)를 한 번에 읽고 글쓴이마다 명함을 계산한다. 로그인 없이 `?page=50`을 반복해 부를 수 있다. 메인과 같이 명함 계산을 배치화하거나 글쓴이별 명함을 캐시하는 쪽으로 바꾼다(회원 · 글이 늘면).
- **공개 취소된 사건의 글**(PR #341 리뷰): C-1 · C-2는 공개 사건에서만 제목을 찾아, 공개 취소(BE-118)된 사건의 글은 `caseTitle: null`로 계속 나오고 붙인 판결도 보인다(화면 목도 사건 제목이 없으면 `null`로 처리한다). 내린 사건의 글을 숨길지는 BE-118 "숨김" 범위와 함께 정한다.
- **자동 이름의 회원 ID 노출**(PR #341 리뷰): `방청객 {회원 ID}`는 순차 증가하는 내부 회원 ID라 이름만 보고 전체 회원 수를 짐작할 수 있다. 닉네임을 정하면(BE-139) 사라지는 임시 이름이고 지금은 회원이 적어 그대로 두기로 했다(사용자 결정). 회원이 늘거나 닉네임 없는 회원이 많아지면 회원 ID를 섞은 비순차 고유 값으로 바꾼다.
- **좋아요 누르기 경험치 기준**(PR #341 리뷰): `LIKE_GIVEN` 대상 키가 글 ID뿐이고 사용자 단위가 익명 ID라, 같은 회원이 다른 기기(다른 익명 ID)에서 껐다 켜면 같은 글로 다시 받을 수 있다. 하루 10개 상한이 있어 영향은 작고, 회원 기준 전환(BE-140)에서 함께 정리한다.
- **명함 계산 비용**: 글쓴이마다 열 개 남짓 조회한다(설정 · 통계 · 레벨 · 꾸미기 · 성향). 한 응답 안에서는 같은 글쓴이를 한 번만 계산하지만, 랭킹은 글 · 댓글을 쓴 회원 **전원**의 명함을 계산한다. 회원이 수백 명을 넘으면 레벨을 미리 계산해 두거나(캐시 · 집계 테이블) 랭킹 후보를 최근 활동자로 줄인다.
- **회원 기준 전환**(별도 이슈): 옮긴 뒤에는 `community_post.anonymous_user_id` · `community_comment.anonymous_user_id`를 쓰지 않고 회원으로 명함을 그린다. `CommunityActorResolver` · `AuthorCardAssembler`만 바꾸면 된다.
- 경험치 회수(글 삭제 · 좋아요 취소 시)는 하지 않는다(BE-106과 같다). 글 삭제가 생기면 다시 본다.
- 쓰기 횟수 제한(도배 방지)은 없다. 경험치는 상한이 있지만 글 자체는 계속 쓸 수 있다. 신고 · 운영 기능과 함께 본다.
