# FE-8 의사결정 기록

> MVP 단계(WBS 3.6) · PR #42 · 담당 백승호

## 문제 / 배경
- 와이어프레임 S-07(AI 판결)·S-08(실제 판결) 화면을 BE-10(API 10~13)이 완성되기 전에 mock으로 먼저 구현해야 했다.
- 공개 상태가 `VERDICT_CONFIRMED → AI_REVEALED → COMPLETED` 순으로 전이되는데, 새로고침 시에도 이 상태가 그대로 유지돼야 했다.

## 검토한 대안
- **새로고침 시 재호출 범위**: 전체 흐름(공개 요청 포함)을 다시 실행할지, 조회(GET)만 다시 호출할지 검토했다. 공개 요청(POST)을 새로고침마다 다시 보내면 멱등이어도 불필요한 호출이 반복된다.
- **구현 범위**: 와이어프레임에는 있지만 MVP 확장 예정인 유사 판례 펼치기, "이 사건에 대하여" 사이드바를 이번 PR에 포함할지 검토했다.

## 선택한 방법과 이유
- 새로고침 시 조회(GET) API만 다시 호출하도록 했다. 공개 전이는 사용자의 명시적 행동(버튼 클릭)에 대해서만 요청하고, 페이지 진입/새로고침은 현재 상태를 "읽기"만 하는 것으로 책임을 분리했다.
- 유사 판례 펼치기·사이드바는 확장 범위로 보고 이번 PR에서 제외했다. BE-10 API 응답에 해당 데이터가 아직 없었고, MVP 범위(WBS)에서도 확장 단계 작업으로 분류돼 있었다.

## 고려한 제약 사항
- BE-10(API 10~13)이 이 PR 시점에 아직 머지 전이라, 목(mock) 데이터로 연동 계약을 먼저 맞추고 실제 API로 교체하는 순서로 진행했다.
- S-08에 직접 진입했는데 AI 판결을 아직 확인하지 않은 경우 S-07로 안내해야 했다(상태 기반 라우팅).
