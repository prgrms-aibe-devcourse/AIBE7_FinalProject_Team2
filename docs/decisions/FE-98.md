# FE-98 의사결정 기록

> 근거: 판결 체험 impeccable critique 3묶음(2026-10-26) · PRODUCT.md 원칙 1(판단은 사용자의 것, 세 판결은 대등) · FE-97 의사결정 기록 · FE-48(6막 구조) · BE-82
> 이 이슈는 구현보다 **방향 결정**이 먼저였다. 아래는 결정한 방향과 그대로 옮긴 구현이다.

## 문제 / 배경
- critique에서 방향을 정해야 하는 항목이 남았다: 판단 요소 입력 UX(C), "정답 없음" 카피(E), 2막 몰입(F), 문서 정리(G).
- 공통 기준은 PRODUCT.md 원칙 1이다. 화면 · 대사가 실제 판결이나 AI를 정답처럼 잣대로 삼거나, 사용자를 "놓친 쪽"으로 틀거나, 남의 점수가 내 판단을 앞서 묶으면 안 된다.

## 검토한 대안과 결정

### C. 판단 요소 · 서명 (3막)
- **버튼 위계**: ① 조용한 기본 + 고른 쪽 채움 / ② 행마다 세그먼트 하나 / ③ 유지. ②는 구조 변경이 커서 ①로 했다(11행 × 3버튼 유지).
  - 예전에는 기본 "고려 안 함"이 가장 진한 남색 채움, 고른 "무겁게 · 가볍게"는 옅은 색이라 "아무것도 안 고려함"이 켜진 상태로 읽혔다. 이제 "고려 안 함"은 윤곽선(켜져 있으면 글자만 진하게), 고른 쪽은 방향 색 채움이다. 머리에 "고른 요소 n / N"을 보인다.
- **요소 0개로 서명**: ① 한 줄 확인 문구만 / ② 최소 1개 선택으로 막기 / ③ 그대로. 판단은 사용자의 것이라 막지 않는다. ②는 서버에 최소 개수 규칙이 있는지도 확인이 필요해 하지 않았다. 서명 장에 "판단 요소를 하나도 고르지 않았어요. 그대로 서명할까요?"를 둔다.

### E. "정답 없음" 카피 (6막)
- **편집부 의견**: 첫인상 ↔ 실제 판결(`preToCourt`) 비교였다. 실제 판결이 잣대처럼 읽혀("실제 사건보다 가볍게 판단했어요") **첫인상 ↔ 내 최종 판결**(`preToFinal.direction`, 서버가 이미 계산 · 응답에 있음)로 바꿨다. "처음 생각보다 무겁게 판결했어요" 식이다. PRODUCT 핵심 카피("다 알고 나서도, 같은 판단일까?")와 같은 방향이고 새 서버 값이 필요 없다.
- **행렬 분류 · 차이 문장**: 분류 이름 "나만 고려하지 않은 요소" → "AI · 재판부만 고려한 요소", 문장 "AI와 재판부는 ○○을 고려했지만, 내 판결에서는 고려하지 않았어요." → "…고려했고, 내 판결에는 들어가지 않았어요." 차이 대사 순서는 내 → AI → 실제(내로가 AI와, 남불이 실제 판결과 비교).
  - 내부 값 `ONLY_ME_MISSED`는 **서버 enum이자 API 계약**(`docs/api-specification.md`, `MatrixCategory.java`)이라 이름을 바꾸지 않고 화면 라벨만 바꿨다.
- **독자 엽서 평균 별점**: 내 의견보다 평균이 먼저 보였다. 내가 엽서를 보낸 뒤에 평균과 다른 독자의 엽서가 보이게 했다(보내기 전에는 안내 한 줄). 결정은 평균 별점이었지만 다른 독자의 엽서에도 별점 · 의견이 있어 같은 규칙으로 함께 숨겼다.

### F. 2막 · 대본 · 개발용 조작
- **2막 시점**: 첫 장면이 이미 "재판장은 당신이에요"를 말하는데 critique는 어디에도 없다고 보았다(25번 넘기며 잊힌다). 구조(증거 고르기)는 별도 이슈로 두고, **맺음**에 한 줄을 더했다: "재판은 여기까지예요. 이제 재판장, 당신이 판결할 차례예요." 변호인 대사로 갑자기 끊기던 3막 인계도 함께 해결한다("판결로" 확정은 이 줄로 옮김).
- **법률 용어 설명**: 이번에는 하지 않는다(법률 내용 검수 부담).
- **4막 "징역 12년" 반복**: 판결문 · 판사 대사 · 내로 대사에서 세 번 나왔다. 판사 대사는 두고 내로의 "AI 판사는 {형량}을 선고했어요."를 지워 남불의 "그렇다면 실제 판결은 어떨까요?"로 바로 이어지게 했다(FE-48 대본 결정을 사용자 확인 후 바꿈).
- **`/letters` 헤더 두 번**: 라우터가 공통 헤더를 이미 그리는데 페이지가 또 그렸다(라우터에 헤더 로직이 들어온 뒤 남은 중복). 페이지의 호출을 지웠다.
- **개발용 조작**(막 칩 "테스트용", 이름표 끄기, 처음부터 다시)은 이미 목 모드 한정(`jumpActMock` · `restartMock`)이라 코드는 두고, 모바일 조작 줄에서만 FE-97에서 숨겼다.

### G. 문서

## 고려한 제약 사항
- **BE 후속**: 실제 서버의 `RuleSentences.java`가 차이 문장("…고려했지만, 내 판결에서는 고려하지 않았어요")을 만든다. 실제 모드에서는 서버 문구가 나오므로, 목과 같은 문구로 바꾸는 BE 후속이 필요하다. 라벨은 프론트에서 `ONLY_ME_MISSED` → 화면 이름으로 바꾸므로 영향이 없다.
- 편집부 의견은 `preToFinal.direction`이 없거나 모르는 값이면 줄을 숨기는 기존 동작을 유지한다.
- 새 문구 · 대본은 사용자 결정(2026-10-26)을 그대로 옮겼다.
