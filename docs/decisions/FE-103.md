# FE-103 의사결정 기록

10/26 critique 전 화면에서 수정 PR(FE-93 · 95 · 97 · 98 · 99 · 100 · 102)에 넣지 않은 P3 · 사소한 관찰 모음. 두 영역으로 나눠 PR을 따로 올린다.

## 1차 (PR #301, 영역 A: 화면 외곽 — 공통 헤더 · 메인 · 마이페이지 · 내 결과 · 커뮤니티 · 성향 테스트)

### 문제 / 배경
- 항목이 70개 가까이이고 대부분 작아서, 하나씩 고치기 전에 현재 코드로 재현되는지 먼저 재야 했다. 앞선 수정으로 이미 풀린 것도 있었다.

### 검토한 대안
- 모바일 Tab 순서: (A) 시각 순서를 DOM에 맞춰 로그인을 메뉴 아래로 내리기 (B) `tabindex` 양수 (C) 화면 폭에 따라 DOM 자리를 옮기기. A는 로그인이 눈에 안 띄게 되고, B는 쓰지 않는다. C를 택했다.
- 내 결과 그래프 키보드: (A) 점마다 `tabindex=0` (B) 그래프당 한 자리 + 방향키(roving). A는 한 화면에 Tab 정지점이 50개 안팎이 된다. B를 택했다. `role="img"`는 자식을 숨기므로 `group`으로 바꿨다.
- `/me` 진입 CLS: (A) 로딩 자리에 골격(skeleton) 그리기 (B) 컨테이너 `min-height`로 높이만 맞추기. 골격은 과하다. B로 CLS 0.424 → 0을 실측으로 확인했다.
- 끝난 일(첫 성향 테스트 · 재심) 표시: (A) 비활성 버튼 유지 (B) 상태 글. 누를 수 없는 것이 버튼처럼 보이는 것이 문제라 B를 택했다. 아직 조건이 안 맞아 못 누르는 "재심 청구하기"는 비활성 버튼으로 둔다.
- 커뮤니티 2단 기사 양쪽 맞춤: 좁은 폭에서 단어 사이가 벌어져 왼쪽 맞춤 + `text-wrap: pretty`로 바꿨다.

### 선택한 방법과 이유
- 위 대안 중 택한 것. 이유는 각 항목에 적었다.
- 공유 화면 유형 이름 중복: 뒤 카드(`.is-back`)의 밈이 앞 카드와 같은 글이라 삐죽 나온 자리에 잘려 보이고 낭독기가 두 번 읽었다. 뒤 카드 밈을 `visibility: hidden`으로 숨겼다.

### 처리하지 않은 것과 사유
- **`?view=` 주소 보존**: 마이페이지 하위 화면은 `history.state`로 새로고침 · 뒤로 가기가 이미 보존된다. URL까지 남기려면 라우터를 바꿔야 하는데 개인 화면이라 공유 이득이 적다.
- **모바일 헤더 메뉴 가로 스크롤 단서 · "목 데이터" 스위치 노출**: `import.meta.env.DEV`로 막혀 있어 운영에서는 해당 없음. "연출"은 사용자 설정이라 유지.
- **비활성 컨트롤 `opacity .55`**: 비활성 컨트롤은 WCAG 대비 기준에서 면제.
- **메인 포스트잇 문구**: 10/27 김해송 결정으로 그대로 둔다.
- **로그인 후 "이어서 하기"**: 새 기능에 가까워 FE-113으로 분리(Low, 필요 여부부터 결정).
- **책상 아래 나무 띠 약 90px**: 1440×900 실측 결과 패드 위 · 아래 여백이 비슷해 이상하지 않다.
- **프로필카드 글자 하한 · "성향 테스트 전" 대비**: 1~3위 단상 15.1px 이상, 4위 이하 11px는 FE-93의 의도된 하한. 대비는 5.97:1.
- **목데이터 딱지 일괄 숨김 토글**: "숨기지 않고 목데이터로 표기" 방침과 충돌.
- **마이페이지 성향카드 3겹 합치기**: 세 구역이 서로 다른 질문(지금 · 변화량 · 흐름)에 답해 합치면 정보가 빠지거나 클릭이 늘고, 유지하기로 한 레벨 · 시상대 결정과 부딪칠 수 있다. 10/27 김해송 결정으로 하지 않는다.
- **내 결과 헤드라인**: FE-100에서 이미 `{판사}의 판결은 {형량}`으로 바꿨고 사건 제목은 deck에 있다. 변경 없음.
- **성향 테스트 종이 페이지 모양(쿠폰 같은 모양 · 외톨이 단)**: 시안 판단이 필요한 시각 문제라 이번에는 건드리지 않았다.

### 고려한 제약 사항
- 헤드리스 크롬은 터치 · Safari 전용 동작을 재현하지 못한다. 모바일 헤더(로그인 위치 · Tab 순서)와 그래프 키보드 이동은 사파리 실기기 확인이 필요하다.
- 카드 설명 글자 대비(그라디언트 위)는 자동 측정이 안 돼 확인하지 못했다.

### 추후 재검토가 필요하면
- 시연 전에 성향카드 화면과 성향 테스트 종이 페이지를 직접 보고 어색하면 별도 이슈로 다룬다.

## 2차 (PR #302, 영역 B: 판결 체험 무대 · 3막 판결 · 4~6막 · 엽서)

### 문제 / 배경
- 영역 A와 같이 항목마다 현재 코드로 재현되는지 먼저 쟀다. 앞선 수정(FE-97 · 98 · 99)으로 이미 풀린 항목이 많았다.

### 검토한 대안
- 장면 순서 표시: (A) 조작 줄 상태 문구(`.sp`)에 "3 / 7" (B) 대사창의 "▶ 클릭 · Space" 안내에 합치기. A는 `.sp`가 비면 안 되는 모바일 CSS(`.sp:not(:empty)`)가 줄을 한 줄 더 만들고 대사창을 올려 버려, 모바일 화면이 좁아진다. B를 택했다.
- 3막 감경 회색 칸: (A) 감경 영역 전체를 형벌 선택 전에는 감추기 (B) 안내 문구만 바꾸고 라디오는 체크 전까지 감추기. A는 선택 후 영역이 갑자기 나타나 레이아웃이 크게 움직인다. B를 택했다.
- 막힌 이유 표시: 위치를 옮기는 안(대사창 · 카드 안)도 있었으나 모바일 줄 구성이 바뀌어, 기존 자리의 색 · 굵기만 키웠다.
- 숫자 칸 Enter: 무대 전역 키 처리가 입력칸 위의 키를 받지 않는 규칙을 바꾸지 않고, 입력칸 쪽에서 `stageNext.run()`을 부르게 했다.
- 엽서 팝업 포커스: 팝업이 열릴 때 바로 입력칸으로 보내면 내용이 아직 없어(비동기 로딩) 못 간다. 내용이 준비된 뒤, 포커스가 아직 팝업에 있을 때만 옮긴다.

### 선택한 방법과 이유
- 위 택한 방법. 마스코트(남불 빼꼼)는 높이를 84px에서 64px로 줄여 링크와 겹치지 않는 것을 실측했다(마스코트 위 126px > 링크 아래 123px).
- 글자 하한: 무대 안 읽는 글자의 `max(10 · 11px, …)` 하한을 12px로 올렸다.

### 처리하지 않은 것과 사유
- **막 칩 Tab 정지점 · "이름표 끄기" · "처음부터 다시"**: 목 데이터(`API_MODE === 'mock'`)나 개발 서버(`import.meta.env.DEV`) 전용이라 운영에서는 나오지 않는다. 막 칩은 운영에서는 버튼이 아닌 글이다.
- **막간 길이 4.2초 vs 1.6초**: 코드의 실제 값은 1→2막 3.6초, AI 대기 4.2초이고 클릭 · Space로 바로 넘어간다. 평가에서의 1.6초는 클릭한 시점이다.
- **comparisonStage.js 주석 불일치**: FE-98에서 이미 맞춰져 있다.
- **입력칸 이름 "징역 년년" · 입력칸 크기**: FE-97에서 해결(단위는 `aria-hidden`, 칸 56×44px).
- **4막 판단 요소 보드와 판사 겹침 · 모바일 말풍선 40% · 6막 요약 줄 잘림**: 현재 코드 기준 재현되지 않았다(보드 아래 346px < 판사 위 406px, 모바일 6막 대사창 약 13%).
- **"시작하기 ▶" 알약이 기사 첫 단을 덮음**: 화면 아래를 따라오는 플로팅 버튼의 성격이라 스크롤하면 지나간다. 없애거나 위치를 옮기면 시작 입구가 약해진다.
- **사이트 헤더 약 113px(모바일)**: 공통 헤더 구조를 바꿔야 해서 이번에는 하지 않았다.
- **첫 장에서 서명 단계로 바로 점프 · 20번째 장면 Space가 글을 먼저 완성**: 모두 판결 입력 규칙(확정은 다 정해져야 가능) · 타자기 효과의 의도된 동작.
- **"다음 ▶"과 점선 제출 버튼 비슷함 · 사건 정보 아래 250px 빈 자리 · 4막→5막 전환 대사 한 줄 · 4장 설명 줄 쌓임**: 시안 · 문구 판단이 필요한 항목이라 하지 않았다.
- **엽서 별점 라디오(1×1) 숨김 스타일 의존**: 별 칸(44px) 안의 입력이라 포커스 링이 `:has(input:focus-visible)`로 칸에 그려진다. 현재 구조로 충분하다.

### 고려한 제약 사항
- 헤드리스 크롬이라 터치 · 사파리 전용 동작은 재현하지 못했다. 모바일 대사창의 장면 번호와 막힌 이유 문구는 사파리 실기기 확인이 필요하다.

### 추후 재검토가 필요하면
- 사건 정보 화면의 시작 CTA 위치와 모바일 공통 헤더 높이는 시연 뒤 반응을 보고 다시 본다.

### #301 리뷰 반영 (jms0326)
- 헤더 `matchMedia` 리스너가 화면마다 쌓이던 것: 폭 변화 감지를 모듈에서 한 번만 걸고 지금 보이는 헤더의 로그인 자리만 옮긴다(옛 헤더를 붙잡지 않는다).
- 그래프 점 `role="button"`: 누를 일이 없어 `role="img"` + 이름으로 바꾸고, 방향키에 Home · End(처음 · 끝 점)를 더했다.
- 1차 기록에서 "사용자 결정"으로 적은 곳은 정한 사람과 날짜(10/27 김해송)를 적었다.
