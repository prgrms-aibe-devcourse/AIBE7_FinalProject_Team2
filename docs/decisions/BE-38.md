# BE-38 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #78 본문.

## 문제 / 배경
- BE-31 파이프라인은 사건(DRAFT) · AI 판결만 적재하고 재판부 판결(COURT)은 넣지 않아 사건을 공개할 수 없었다. 기존에는 사람이 판결문을 읽고 JSON을 직접 작성했다(BE-14 방식).

## 검토한 대안
- 대안 A: 사람이 계속 작성한다. 정확하지만 사건 수만큼 수작업이 든다.
- 대안 B: LLM이 초안을 쓰고 자동 대조 검사를 거친 뒤 비공개로 적재하며, 공개 전 관리자가 원문과 대조한다.

## 선택한 방법과 이유
- 대안 B. 자동 검사는 요약의 의미가 아니라 **형식적 정확성**을 보장하는 데 집중한다.
  - 원문 인용 대조: 발췌 · 근거는 원문을 글자 그대로 옮기고 식별 정보를 바꾼 부분만 `⟦ ⟧`로 감싼다. 밖의 글자가 다르거나 대부분을 감싸 대조를 피하면 오류.
  - 형량은 모델이 쓰지 않고 추출기 값을 쓰며, 판결문 주문을 로컬 정규식으로 읽어 교차 확인한다. 맞지 않으면 모델 호출 전에 멈춘다.
- 출력은 BE-14 JSON 형식으로 맞춰 기존 SQL 변환기와 새 `court_seed_sql.py`가 둘 다 받게 했다.
- 사건 발생일은 `incidentDate`만 예외로 정확한 날짜를 받되, 형식 · 원문에 실제로 나오는지 · 선고일 이전인지 확인한 값만 쓴다. AI 입력 · 보고서에는 넣지 않는다.
- 재판부 판결은 `is_published=false`로 적재하고 기존 공개 판결은 건드리지 않는다.

## 고려한 제약 사항
- 요약 · 이유의 왜곡 여부와 요소 방향은 자동 검사가 못 막는다. 공개 전에 사람이 원문과 대조한다(REQ-075 · 077).
- 재판부 판결 초안은 AI 판결 프롬프트에 들어가지 않는다(테스트로 확인).
