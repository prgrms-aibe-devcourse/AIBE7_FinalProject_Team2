# FE-114 의사결정 기록

## 문제 / 배경
- 프로필카드 아래 줄이 성향(초심 · 재심 · 최근)뿐이라, 서명 · 직업 · 레벨도 보여 주고 싶었다.
- 서버 `profileCardType`(P-8)은 `initial` · `retake` · `current` 세 값만 받는다. 레벨 · 직업 API(BE-106)는 develop에 머지돼 있었지만 화면은 목 값(Lv.7)을 쓰고 있었다.

## 검토한 대안
- 표시 방식 A: 성향 · 서명 · 직업 · 레벨을 모두 체크박스로 고른다. 카드 아래 칸이 늘어 카드 비율 · 명함 크기를 다시 맞춰야 한다.
- 표시 방식 B: 성향 · 서명 · 직업 중 하나만 고르고, 레벨은 켜고 끄는 접두로 둔다. 한 줄 칸을 그대로 쓴다.
- 저장 A: 서버 `profileCardType`을 확장한다. BE 변경이 먼저 필요해 프론트가 막힌다.
- 저장 B: 줄 종류 · 레벨 접두는 이 브라우저(localStorage)에만 두고 서버로 보내지 않는다(서버에 모르는 값을 보내면 400).
- 직업 저장 A: 화면에서만 고른다. B: 서버 L-2(`PUT /level/job`)에 저장한다. 서버가 이미 고른 직업을 가지고 있다.

## 선택한 방법과 이유
- 표시는 B, 줄 종류 저장은 B(후속에 서버 확장), 직업은 서버 L-2 저장.
- 한 줄 칸을 키우지 않고 기존 카드 비율을 지키며, 서버 계약이 바뀌기 전에도 화면을 먼저 쓸 수 있다.
- 레벨은 항상 윗줄, 서명은 칸 높이 · 띠 안쪽 폭에 비례해 맞춘다.

## 고려한 제약 사항
- 커뮤니티 명함은 다른 사람의 줄 종류를 모르므로 성향만 보인다(서버에 값이 생기면 확장).
- 목에서는 직업 해금을 확인할 수 없어 개발용 버튼(레벨 +1 · 다음 직업 해금 · 처음으로)을 두었다.

## 추후 재검토가 필요하면
- 줄 종류 · 레벨 접두를 서버 설정(P-8)으로 옮기고 커뮤니티 명함에도 반영.
- 닉네임 규칙(한글 8자 · 영문 12자)은 서버 닉네임 API 명세와 맞춘다.

## 2차 (FE-116)
- 서버 저장 준비: 카드 아래 줄 종류 · 레벨 접두를 서버가 알 때만 보낸다. 대안은 (A) 플래그 상수로 켜기, (B) P-5 `profileSettings`에 `cardLine`이 오면 지원으로 보는 자동 감지. A는 BE 배포와 프론트 배포를 사람이 맞춰야 하고, 어긋나면 400이 나므로 B를 택했다. 목은 항상 두 칸을 내려 이 경로를 쓴다.
- 커뮤니티 목 글쓴이는 `level` · `job { code, name }` · `cardLine { line, showLevel }`로 서버 계약 모양을 맞췄다. 실제 커뮤니티 API는 아직 없어 연동은 후속이며 BE 요청 사항은 Jira FE-116에 적었다.
- 경험치 진행률은 L-1이 주는 `xp` · `currentLevelXp` · `nextLevelXp`로 계산하고 최고 레벨은 막대를 채운다.
