# FE-143 의사결정 기록

관리자 "준비 중" 화면이 서버를 부르지 않고 안내만 보이게. 담당 D(정민석). 10/30 운영 점검 후속(FE-142 · FE-144와 같은 점검).

## 문제 / 배경

- 실제 모드에서 회원 · 게시글 · 신고 · 관리자 계정 · 공지 화면은 서버 API(A-16 ~ A-41)가 아직 없다. 메뉴는 `adminMenu.js`의 `serverReady: false`로 "준비 중"이라 누를 수 없지만, 주소로 직접 들어가면 화면이 그대로 API를 불러 404를 받고, 공통 `createLoader`의 눌러도 소용없는 "다시 시도" 버튼을 보였다.
- 대시보드도 `/dashboard`를 불러 404를 받은 뒤 안내를 보였다. 버튼은 없어 다른 다섯 화면과 모양이 달랐다.

## 검토한 대안

- 대안 A — 다섯 화면 각자 `draw` 첫 줄에서 `isMenuReady`를 보고 안내만 그린다(이슈에 적은 방향): 같은 분기가 다섯 곳에 복사되고, 대시보드까지 맞추려면 여섯 곳이 된다. 새 운영 화면이 생기면 또 넣어야 한다.
- 대안 B — 공통 `createLoader`가 404일 때 "다시 시도"를 빼고 안내만 보인다: 사건 검수 목록(`adminListPage`)도 같은 함수를 쓴다. 사건 검수의 404는 실제 실패라 "다시 시도"가 필요하고, API 요청 자체는 여전히 나간다.
- **대안 C — 공통 틀(`adminShell`)이 `draw`를 부르기 전에 화면의 메뉴 항목을 보고 막는다(선택)**: 메뉴 설정(`serverReady`) 한 곳만 보고 여섯 화면이 한 번에 같은 모양이 된다. 각 화면 코드 · `createLoader`는 바꾸지 않는다.

## 선택한 방법과 이유

- `adminMenu.js`에 `isSectionReady(section, mode = API_MODE)`를 더했다. 화면이 `renderAdminShell`에 넘기는 `section`(메뉴 key)으로 메뉴 항목을 찾아 `isMenuReady`로 본다. 메뉴에 없는 key는 준비된 것으로 본다(사건 상세 등은 `section: 'cases'`라 열린다).
- `adminShell.enter`가 로그인 확인 뒤 `isSectionReady(section)`이 거짓이면 `draw` 대신 `drawNotReady()`(제목 + 안내 한 줄)를 그린다. 이어지는 제목 포커스 · 틀 오류 처리는 그대로다.
- 서버가 생기면 지금처럼 메뉴의 `serverReady`만 지우면 메뉴 · 화면이 함께 열린다(기존 규칙 유지).
- 안내 문구는 `adminLabels.js`의 `NOT_READY_TEXT` 하나로 모았다. 준비 중 화면 · `createLoader`의 404 기본 문구 · 대시보드 404 안내가 같은 값을 쓴다(값은 그대로, 동작 변화 없음).
- 안내는 오류가 아니라 고정 상태라 `role="status"`로 두었다(대시보드 404 안내는 `alert`였다).

## 고려한 제약 사항

- `createLoader`는 해송님과 합의한 대로 동작을 바꾸지 않았다(사건 검수 목록이 같이 쓴다). 기본 문구를 상수로 바꾼 것뿐이다.
- 목 모드는 `isMenuReady`가 늘 참이라 여섯 화면이 지금처럼 목 데이터로 열린다.

## 확인

- `adminMenu.test.js`: 실제 모드에서 막히는 화면 6개 · 열리는 화면 2개(사건 검수 · 사건 등록), 목 모드는 모두 열림, 메뉴에 없는 key는 열림
- 로컬 실제 모드(develop 백엔드 + 빈 임시 DB): 여섯 주소를 직접 열어 보낸 요청이 `admin/auth/me`뿐이고 "다시 시도"가 없음, 사건 검수는 `admin/cases`를 불러 목록 그대로 (PR #360 테스트 표)

## 추후 재검토가 필요하면

- 대시보드의 404 안내 분기(`adminDashboardPage.js`)는 실제 모드에서 이제 닿지 않는다. 서버가 생겨 `serverReady`를 지운 뒤에도 API가 404를 주면 다시 쓰이므로 남겨 두었다.
