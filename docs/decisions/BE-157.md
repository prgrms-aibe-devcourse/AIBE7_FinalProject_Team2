# BE-157 의사결정 기록

> 근거: COMMON-72(PR #398) 리뷰의 후속. 스모크 테스트는 BE-58, 자동 배포 · 되돌림은 BE-60.

## 문제 / 배경

- COMMON-67에서 `nosniff`를 켠 뒤, nginx 기본 MIME 표에 없는 `.mjs`(pdf.js 작업 파일)가 `application/octet-stream`으로 나가 관리자 사건 등록의 PDF 읽기가 깨졌다(COMMON-72에서 수정).
- 이런 누락은 브라우저에서만 드러나고, 지금 스모크 테스트는 `/assets/*.js`의 캐시만 봐서 잡지 못한다. 다음에 같은 일이 생기면 CI가 막아야 한다.

## 검토한 대안

- **고정 이름 시험 파일**(`public/` 아래 작은 `.mjs` 하나)을 두고 그 주소만 확인: 가장 단순하지만 운영에 쓰지 않는 파일이 남고, 실제 작업 파일이 들어가는 `/assets/` 경로 규칙은 확인하지 못한다.
- **CI에서 이미지 안의 파일 목록으로 이름을 알아내 넘기기**(`docker compose exec web ls /usr/share/nginx/html/assets`): 서버의 `deploy.sh` 스모크 테스트에서는 같은 방법을 쓸 수 없어 CI와 서버의 검사가 달라진다.
- **스모크 테스트가 `/assets/*.js`를 따라가며 실제 `.mjs`를 찾기**: 해시가 바뀌어도 되고, CI · 서버가 같은 스크립트로 실제 작업 파일을 확인한다.

## 선택한 방법과 이유

- 세 번째 방법을 택했다. `index.html`이 부르는 `/assets/*.js`에서 시작해, 각 조각이 부르는 조각(`assets/x.js` · `./x.js`)을 따라가며 `/assets/*.mjs`를 찾는다(최대 200개). 이름에 `pdf`가 든 조각(대소문자 무시)을 먼저 본다 — 지금 빌드 기준 57개 → 30개(약 0.7초).
- 찾은 `.mjs`가 200 + `application/javascript` 또는 `text/javascript`면 통과.
- **기본은 경고만, CI는 실패**(`SMOKE_REQUIRE_MODULE_MIME=1`): `deploy.sh`는 되돌릴 때 이 새 스크립트로 COMMON-72 이전 이미지(매핑 없음)나 pdf.js 이전 이미지(`.mjs` 없음)도 검사한다. 실패로 치면 되돌림까지 실패하므로, COMMON-67(보안 헤더) · BE-75(확인 경로) 검사와 같은 방식으로 나눴다.

## 고려한 제약 사항

- bash 3.2(macOS)에서도 돌게 `mapfile` · 연관 배열 · `${var,,}`를 쓰지 않고, 빈 배열 펼치기는 `${arr[@]+...}`로 쓴다(`set -u`에서 막히지 않게). macOS `/bin/bash` 3.2.57에서 확인했다.
- 탐색은 요청 수(200개)와 함께 **시간(기본 120초, `SMOKE_MODULE_SEARCH_SECONDS`)**으로도 막는다. 요청마다 최대 15초라 횟수만으로는 느린 서버에서 최악 약 50분 걸리고, 그동안 `deploy.sh`의 되돌림이 늦어진다(CodeRabbit 리뷰). 제한에 걸려 멈추면 "못 찾음"과 구분해 알려, 느린 응답을 매핑 누락으로 오해하지 않게 한다.
- 로컬 Nginx로 확인했다: 지금 이미지 통과 · COMMON-72 이전 이미지는 기본 경고 / CI 실패 · `.mjs`가 없는 이미지는 기본 경고 / CI 실패. 다시 확인하는 법은 아래 "검사를 고칠 때 다시 확인하는 법".
- 경고 · 실패 안내를 경우마다 나눴다(#399 리뷰): **MIME이 아님** → nginx `types` 매핑, **못 찾음** → 빌드가 `.mjs`를 더 이상 내지 않거나 조각이 200개를 넘은 것(매핑은 멀쩡할 수 있다), **시간 제한** → 응답 속도. CI 실패 줄에도 같은 안내가 붙는다.
- 조각 이름 정규식은 `.js` 뒤가 이름 글자면 잡지 않는다(`./manifest.json`이 `manifest.js`로 잘려 헛요청하던 것, #399 리뷰). `\b` 대신 경계 글자를 잡고 `sed`로 뗀다 — macOS grep과 GNU grep에서 같게 동작시키려는 것이다.
- COMMON-72(PR #398)가 develop에 들어간 뒤에 이 변경을 올려야 한다. 그 전에는 CI가 지금 이미지에서 실패한다.

## 검사를 고칠 때 다시 확인하는 법

스크립트 자체의 자동 테스트는 없다. 웹 이미지를 로컬에서 띄우고(`deploy/README.md` "로컬에서 운영 구성 확인") 아래 네 상황을 만들어 `SMOKE_REQUIRE_MODULE_MIME=1 ./smoke-test.sh http://localhost`로 본다.

| 만드는 상황 | 방법 | 기대 결과 |
| --- | --- | --- |
| 지금 이미지 | 그대로 | ✅ `… → 200 (application/javascript)` |
| 매핑 없음(COMMON-72 이전) | `frontend/nginx/default.conf`의 `types { application/javascript mjs; }`를 잠시 지우고 웹 이미지를 다시 빌드 | ❌ "JavaScript MIME이 아님" + `types` 안내 |
| `.mjs` 없는 빌드 | 띄운 web 컨테이너에서 조각 안의 이름을 바꾼다: `docker compose … exec web sh -c "sed -i 's/\.mjs/.mjx/g' /usr/share/nginx/html/assets/*.js"` | ❌ "찾지 못함" + 찾기 범위 안내 |
| 시간 제한 | `SMOKE_MODULE_SEARCH_SECONDS=0` | ❌ "제한에 걸림" + 응답 속도 안내 |

`SMOKE_REQUIRE_MODULE_MIME`을 빼면 아래 세 경우가 ⚠ 경고로만 바뀌고 종료 코드가 0이어야 한다(서버 되돌림 경로). 확인이 끝나면 컨테이너를 다시 만든다(`sed`로 바꾼 파일은 이미지에 남지 않는다).

## 추후 재검토가 필요하면

- 작업 파일이 `/assets/` 밖으로 옮겨지거나 조각이 200개를 넘으면 찾기 범위를 다시 정한다.
- **빌드가 `.mjs`를 더 이상 내지 않으면**(pdf.js를 올리면서 작업 파일이 인라인 · `.js` 워커로 바뀌는 등) CI가 "찾지 못함"으로 배포를 막는다. 매핑 문제가 아니므로 그때는 이 검사의 대상(찾을 확장자 · 시작 조각)을 새 빌드에 맞추거나, 작업 파일이 `.mjs`가 아니게 된 것이 의도라면 검사를 끈다(#399 리뷰).
