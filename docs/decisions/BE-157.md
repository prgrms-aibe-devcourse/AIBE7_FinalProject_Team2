# BE-157 의사결정 기록

> 근거: COMMON-72(PR #398) 리뷰의 후속. 스모크 테스트는 BE-58, 자동 배포 · 되돌림은 BE-60.

## 문제 / 배경

- COMMON-67에서 `nosniff`를 켠 뒤, nginx 기본 MIME 표에 없는 `.mjs`(pdf.js 작업 파일)가 `application/octet-stream`으로 나가 관리자 사건 등록의 PDF 읽기가 깨졌다(COMMON-72에서 수정).
- 이런 누락은 브라우저에서만 드러나고, 지금 스모크 테스트는 `/assets/*.js`의 캐시만 봐서 잡지 못한다. 다음에 같은 일이 생기면 CI가 막아야 한다.

## 검토한 대안

- **고정 이름 시험 파일**(`public/` 아래 작은 `.mjs` 하나)을 두고 그 주소만 확인: 가장 단순하지만 운영에 쓰지 않는 파일이 남고, 실제 작업 파일이 들어가는 `/assets/` 경로 규칙은 확인하지 못한다.
- **CI에서 이미지 안의 파일 목록으로 이름을 알아내 넘기기**(`docker compose exec web ls /usr/share/nginx/html/assets`): 서버의 `deploy.sh` 스모크 테스트에서는 같은 방법을 쓸 수 없어 CI와 서버의 검사가 달라진다.
- **스모크 테스트가 `/assets/*.js`를 따라가며 실제 `.mjs`를 찾기**: 해시가 바뀌어도 되고, CI · 서버가 같은 스크립트로 실제 작업 파일을 확인한다.

## 선택한 방법과 이유

- 세 번째 방법을 택했다. `index.html`이 부르는 `/assets/*.js`에서 시작해, 각 조각이 부르는 조각(`assets/x.js` · `./x.js`)을 따라가며 `/assets/*.mjs`를 찾는다(최대 200개). 이름에 `pdf`가 든 조각(대소문자 무시)을 먼저 본다 — 지금 빌드 기준 57개 → 30개(약 0.7초).
- 찾은 `.mjs`가 200 + `application/javascript` 또는 `text/javascript`면 통과.
- **기본은 경고만, CI는 실패**(`SMOKE_REQUIRE_MODULE_MIME=1`): `deploy.sh`는 되돌릴 때 이 새 스크립트로 COMMON-72 이전 이미지(매핑 없음)나 pdf.js 이전 이미지(`.mjs` 없음)도 검사한다. 실패로 치면 되돌림까지 실패하므로, COMMON-67(보안 헤더) · BE-75(확인 경로) 검사와 같은 방식으로 나눴다.

## 고려한 제약 사항

- bash 3.2(macOS)에서도 돌게 `mapfile` · 연관 배열 · `${var,,}`를 쓰지 않고, 빈 배열 펼치기는 `${arr[@]+...}`로 쓴다(`set -u`에서 막히지 않게).
- 로컬 Nginx로 확인했다: 지금 이미지 통과 · COMMON-72 이전 이미지는 기본 경고 / CI 실패 · `.mjs`가 없는 이미지는 기본 경고 / CI 실패.
- COMMON-72(PR #398)가 develop에 들어간 뒤에 이 변경을 올려야 한다. 그 전에는 CI가 지금 이미지에서 실패한다.

## 추후 재검토가 필요하면

- 작업 파일이 `/assets/` 밖으로 옮겨지거나 조각이 200개를 넘으면 찾기 범위를 다시 정한다.
