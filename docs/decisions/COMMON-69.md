# COMMON-69 의사결정 기록

## 문제 / 배경
- 이미지 전수 검수(10/30) 결과 사건 재연 컷 41장을 다시 뽑고, 캐릭터 이미지를 보강하게 됐다. 뽑은 이미지를 규칙대로 옮기고, 웹 변환 · 화면 연결 · 문서까지 한 번에 맞춰야 했다.
- 사건 재연 컷은 10/29에 "배경 포함이 기본"으로 정했지만(COMMON-68), 프롬프트가 투명 배경 · 합성 전제로 남아 있었다.
- 사건 범죄 유형에 강도(`ROBBERY`) · 절도(`THEFT`)가 늘었는데(V31), 공용 컷은 재산 분류를 그대로 쓰고 있었다.

## 검토한 대안
- 배경 처리
  - 대안 A: 공용 배경 B01 ~ B16을 참조 이미지로 첨부해 장소를 맞춘다. 장소는 일정하지만 사건 내용과 어긋나는 컷이 생긴다.
  - 대안 B: 배경 이미지를 첨부하지 않고, 컷마다 사건 내용 · 장면에 맞춘 장소 설명을 프롬프트에 직접 적는다.
- 강도 · 절도 공용 컷
  - 대안 A: 재산 분류(`property`) 세트를 계속 쓴다. 파일을 더 만들 필요가 없지만 사건 성격과 사진이 맞지 않는다.
  - 대안 B: `robbery` · `theft`를 별도 세트로 뽑아 연결한다.
- 새 볼따구 · 역할 표정 컷 연결
  - 대안 A: 이번에 대본 · 무대까지 연결한다. 역할 표정은 무대 `look`과 대본 지정 설계가 필요하다.
  - 대안 B: webp와 대표 이미지 후보(포트레이트 풀)까지만 넣고, 볼따구는 이미 읽을 수 있는 `cheek:` look과 404 화면에만 쓴다.

## 선택한 방법과 이유
- 배경은 대안 B로 했다. 사건마다 장소가 달라 16개 공용 배경으로는 맞지 않았다. 배경 이미지를 첨부하지 않아 생성 단계도 줄었다.
- 강도 · 절도는 별도 세트(대안 B)로 했다. 단, 라벨이 재산범죄여도 `crimeType`이 `ROBBERY` · `THEFT`면 별도 세트를 쓰고(`commonCategoryOf`), 분류를 끝내 모를 때 seed로 돌려 쓰는 폴백은 재산 · 신체 · 생명 3종만 남겼다(강도 · 절도 컷이 엉뚱한 사건에 섞이지 않게).
- 볼따구 4표정은 `stage.js`가 이미 `cheek:{표정}` look을 읽어 코드 변경 없이 쓸 수 있어 webp만 넣고, 404 화면에 두 표정(미안 · 놀람)을 나눠 썼다. 역할 표정은 후속으로 미뤘다.
- 신문 여백 사진 칸에는 탐구 컷 6장을 세 번에 한 번씩 섞었다. 공용 재연 컷만 돌리면 같은 그림이 빨리 되풀이되기 때문이다.
- 란마(`deform/*_ranma.webp`)는 삭제하고, 그 종류(`characters/deform`)를 쓰던 대표 이미지 후보 · 보상 종류 · 컬렉션 이름표도 함께 걷어냈다. 라인업 시트 활용은 보류했으므로 종류 자체를 비웠다.

## 고려한 제약 사항
- 백엔드는 이미지를 갖고 있지 않고 목록 파일(`illustration-images.txt`)로 개수를 센다(BE-142). 이미지를 더하고 지우면 `tools/illustrations/update-manifest.sh`로 목록을 다시 만들어야 `IllustrationCatalogTest`가 통과한다.
- 같은 파일 이름으로 교체하는 사건 webp는 브라우저 캐시에 옛 이미지가 남을 수 있다.
- 사건 컷은 비공개 저장소의 실제 사건을 바탕으로 한 장면이다. 사건 내용을 설명한 프롬프트 문서는 이 저장소에 두지 않는다.

## 추후 재검토가 필요하면
- 역할 표정 컷 10장을 판결 체험 무대(피고인 · 피해자 표정)에 연결하는 일(무대 `look` 확장 + 대본 지정).
- 라인업 데포르메 시트 6장의 사용처(컬렉션 `characters/deform` 재도입 · 프로필 카드 선택지). 쓸 곳이 정해지면 개별 컷을 다시 뽑는다.
- 사진 CSS(망점 · 테두리)가 투명 컷 합성을 전제로 짜였다면 배경 포함본에서 겹쳐 보이는지 화면 확인.
