# FE-105 의사결정 기록

## 문제 / 배경
- 관리자 화면(`/admin/*`) critique(24/40)에서 P1 2건 · P2 6건 · P3 8건이 나왔다. 운영 도구라 책상 은유는 평가에서 뺐다.
- P1: 사건 상세에서 승인 · 반려 · 축 확정을 하면 화면 전체를 다시 그려, 맨 위 성공 문구가 스크롤 밖에 뜨고 펼친 상세가 접히고 포커스가 문서 처음으로 갔다. 신고 · 게시글 · 회원 작업은 성공 문구가 아예 없었다.
- P1: 후보 내용은 "자세히 보기" 뒤에 접혀 있는데 승인 버튼은 바로 눌렸고, 승인 버튼 문구가 후보마다 같았다. 대조할 원본 판결문은 3천 px가 넘는 화면의 맨 아래였다.
- P2: 위험 작업 확인이 화면마다 달랐다(삭제 · 승인은 확인창, 숨김 · 정지 · 공지 공개 · 반려는 없음).

## 검토한 대안
- 상태 변경 뒤 갱신
  - A. 바뀐 카드 · 줄만 부분 갱신: 가장 매끄럽지만 공개 조건 · 사건 상태 · 축 미확정 수가 같이 바뀌어 화면 여러 곳을 따로 맞춰야 한다.
  - B. 지금처럼 전체를 다시 그리고, 누른 자리(`data-anchor`)로 돌아가 포커스 + 펼친 후보 다시 펼치기: 갱신 정확성은 그대로 두고 사용자가 잃던 위치만 되찾는다.
- 완료 문구 자리
  - A. 맨 위 문구로 스크롤: 작업한 자리에서 멀어진다.
  - B. 화면 아래에 떠 있는 알림줄(`role="status"`, 6초): 스크롤과 상관없이 보이고, 모든 관리자 화면이 같은 부품을 쓴다.
- 후보 내용을 보지 않은 승인 막기
  - A. 후보 목록에 요약을 기본으로 싣기: 목록 API(A-6)에 요약이 없어 후보마다 A-8을 따로 불러야 한다.
  - B. 원문 | 후보를 나란히 보는 작업대: 상세 화면 구조를 다시 짜는 일이라 따로 설계가 필요하다.
  - C. 그 후보의 "자세히 보기"를 한 번 연 뒤에만 승인 버튼이 켜짐 + 버튼에 `#번호` + 맨 위 "바로 가기"(원본 판결문 등): API · 구조를 바꾸지 않는다.
- 확인 방식: 화면마다 판단 / 기준 하나를 정해 공통 부품(`confirmChange`)으로.
- 거르기 줄: `role="tab"`에 화살표 키 · 탭 패널을 붙이기 / 누르면 목록을 다시 부르는 버튼 묶음이라 `role="group"` + `aria-pressed`로 바꾸기.

## 선택한 방법과 이유
- 갱신은 B(다시 그리기 + 자리 복귀), 완료 문구는 B(알림줄). 서버 응답이 화면 여러 곳을 함께 바꾸는 구조를 그대로 두는 것이 안전하다고 봤다.
- 승인 막기는 C. 작업대(B)는 아래 재검토로 남긴다.
- 확인 기준: 되돌릴 수 없거나, 사용자가 보던 것을 거두거나, 새로 공개하는 작업만 묻는다. 이 기준에 따라 신고 처리(숨김 · 정지) · 게시글/댓글 숨기기 · 회원 정지 · 공지 공개 전환 · 후보 반려에 확인을 더했고, 되돌리는 작업인 회원 "정지 해제"의 확인은 뺐다(게시글 복구 · 계정 다시 사용과 맞춤). 신고 기각 · 상단 고정 · 축 확정 · 내용 저장은 묻지 않는다.
- 거르기 줄은 `group` + `aria-pressed`(사건 등록의 넣는 방법 버튼과 같은 방식).
- 사건 목록도 다른 관리자 목록과 같은 공통 부품(`createLoader` · `dataTable` · `pager` · `tabBar`)으로 바꿨다. 사건 제목은 진짜 링크(`<a href>`)라 새 탭으로 열 수 있다.
- 모바일: 내용이 짧으면 메뉴 줄이 남는 높이를 가져가던 것을 `grid-template-rows: auto 1fr`로 막고, 옆으로 미는 메뉴 양 끝에 스크롤 그림자를 두고 지금 화면 항목으로 밀어 둔다. 입력칸은 16px, 손가락 화면에서 버튼 · 고르기 · 메뉴 44px.
- 목 모드 머리줄에 "목데이터" 꼬리표(목 수치는 숨기지 않고 표기하는 방침).

## 고려한 제약 사항
- 운영 메뉴(대시보드 · 회원 · 게시글 · 신고 · 계정 · 공지)는 서버 API가 없어 목으로만 확인했다. 서버가 있는 실제 모드 흐름은 확인하지 못했다.
- 신고를 대상 단위로 한 번에 처리하는 API가 없어, 같은 대상 신고는 "같은 대상 신고 N건" 꼬리표로 알리기만 한다(한 쪽 안에서만 센다).
- 넓은 화면 마우스용 버튼은 36px를 그대로 둔다(밀도). 44px는 720px 이하 · `pointer: coarse`에서만.
- 실제 모드의 "준비 중" 메뉴는 `aria-disabled`로 Tab에 남긴다(무엇이 준비 중인지 키보드 사용자도 알 수 있게). 대신 점선 꼬리표로 눈에 띄게 했다.

## 추후 재검토가 필요하면
- 원문 | 후보 비교 작업대: 검수 흐름이 "원문 읽기 → 후보 비교 → 승인"으로 굳으면 `shape`로 설계해 별도 이슈로.
- 반복 처리 효율(다음 사건 이동 · 일괄 확정 · 단축키 · 목록 검색): 하루 검수량이 정해지면 다시 본다.
- 승인 취소 경로: 되돌리기 정책을 서버와 함께 정해야 한다.
- 신고 대상 단위 일괄 처리: 서버에 일괄 처리 API가 생기면.
- 관리자 로그인 이메일 칸 자동 포커스 직후 포커스 링이 안 보인다는 측정은 헤드리스 환경 값이라 실제 브라우저에서 다시 확인한다.
