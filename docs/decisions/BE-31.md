# BE-31 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #75 본문. 이후 확장은 BE-36 · 37 · 38 · 44 · 45 · 49 기록 참고.

## 문제 / 배경
- 판결문에서 AI 판결 적재까지 사람이 단계마다 손으로 이어 붙이던 과정을 한 명령으로 자동화해야 했다.

## 검토한 대안
- 대안 A: 적재 전에 사람이 검수하는 단계를 파이프라인에 둔다(기존 흐름).
- 대안 B: 사람 검수 없이 **비공개로 적재**하고, 관리자가 공개 전에 검수한다(후검수).

## 선택한 방법과 이유
- 대안 B. 사건은 항상 `DRAFT`, AI 판결은 `is_published=false` · `PENDING`으로만 넣고 자동 공개하지 않는다. 관리자 공개 승인이 비식별화 검수를 겸한다(BE-33 · FE-16).
- 공개 전 검수 원칙(REQ-075 · 078)은 유지하고, 검수 **시점**만 관리자 공개 승인으로 옮겼다. 요구사항 · 기능 명세 · MVP 정의서 · ERD에 반영했다.
- 단계를 `extract → contamination → generate → select → load`로 나누고 `--from` · `--until` · `--skip` · `--rerun`으로 분기한다. 끝난 단계는 `state.json`으로 건너뛰고, 앞 단계를 다시 돌리면 뒤 단계 결과는 지운다.
- 사전 학습 점검은 기본 꺼짐(옵션). 회차 선택 기본은 판단 요소 다수 의견 일치(`consensus`).
- 사건번호 · 법원명 · 선고일은 마스킹 전에 로컬 정규식으로 꺼내 모델로 보내지 않는다.

## 고려한 제약 사항
- 파이프라인은 운영 DB에 접속하지 않는다. DB 직접 적재는 로컬만, 운영은 SQL 파일을 서버에서 실행한다.
- 적재 SQL은 비공개 저장소(`private-seed/loads/`, Flyway 경로 밖)에 보관한다. 같은 SQL을 두 번 실행해도 중복이 없다(사건 제목 · `runKey`).
