# FE-70 의사결정 기록

## 문제 / 배경
- 마이페이지 성향카드 화면에 "성향이 얼마나 바뀌었는지(변경폭)"와 "어떻게 바뀌어 왔는지(흐름)"를 보여 줘야 했다.
- 기존 "성향 변화 흐름"은 축마다 엄격 ↔ 관대 막대 위에 체험 번호 점을 겹쳐 찍는 방식이었다. 점이 가까우면 서로 겹쳐 순서가 안 읽혔고, 변경폭은 문장 한 줄로만 나왔다.

## 검토한 대안
- 변경폭의 기준점
  - A: 첫 체험 → 가장 최근 체험. 판결 기록만 쓰므로 단순하다. 다만 성향 테스트 결과와는 이어지지 않는다.
  - B: 성향 테스트 → 가장 최근 체험. 테스트 점수(`personality.axisScores`)와 체험 점수가 같은 척도(0 ~ 1, 관대 쪽 비중, API 명세 9장)라 바로 비교할 수 있다. "테스트에서 답한 나"에서 "판결하는 나"로 얼마나 움직였는지가 서비스 의도에 더 맞는다.
  - C: 성향 테스트 → 판결 평균(`judgmentPersonality`). 평균은 흐름을 눌러 버려서 "변경"보다 "차이"에 가깝다.
- 흐름 그래프 형태
  - 네 축을 한 꺾은선에 겹치기: 축마다 위 · 아래 끝의 의미(관대 · 엄격 이름)가 달라 세로축을 공유할 수 없고, 네 가지 색이 필요하다.
  - 축마다 작은 꺾은선 4개(small multiples): 색 하나로 충분하고, 축마다 끝 이름을 따로 붙일 수 있다.

## 선택한 방법과 이유
- 변경폭은 B로 정했다. 테스트를 안 했으면 A로 내려간다(첫 체험이 처음). 화면 안내에 "빈 점 = 처음(성향 테스트, 없으면 첫 체험)"이라고 적었다.
  - 처음(빈 점)과 지금(진한 점)을 엄격 ↔ 관대 막대 위에 이어 보여 주는 dumbbell 형태다. 움직였으면 지금 점 바로 앞에 방향 화살촉을 둔다. 화살촉만으로는 지금 위치가 잘 안 보여서 양 끝 점을 함께 두고, 지금 점을 더 크고 진하게 했다.
  - 처음에는 가장 많이 움직인 축만 진하게 칠하고 머리 문장으로도 말했으나, 한 축만 강조하면 나머지 축이 덜 중요해 보여 걷어냈다. 네 축을 같은 무게로 보여 준다.
  - 5%p 미만은 "거의 그대로"로 본다(기존 `STEADY_POINTS` 유지).
- 흐름은 축마다 작은 꺾은선 4개로 그린다. 가로는 테스트 → 체험 순서, 세로는 위 관대 · 아래 엄격이고 가운데 줄이 반반이다.
  - 세로 눈금은 툴팁 · 표와 같이 "기운 쪽 비중"으로 읽는다: 위 끝 관대 100, 75, 가운데 50(반반), 75, 아래 끝 엄격 100. 0 ~ 100 한 방향 눈금(관대 쪽 비중)은 아래쪽 25가 툴팁의 "엄격 75%"와 어긋나 쓰지 않았다.
  - 가로 칸은 네 그래프가 같이 쓴다. 어떤 체험에서 값이 없는 축(null)도 칸은 남겨 두고 점만 건너뛴다. 그래야 그래프끼리 같은 체험이 같은 세로줄에 놓인다.
  - 색은 기존 커피 강조색 하나만 쓴다. 위 · 아래 반쪽은 4축 막대와 같은 두 색(엄격 · 관대)을 아주 옅게 깔았다. 계열이 하나라 범례는 두지 않는다.
  - 마우스를 올리거나 점을 누르면 사건 이름과 비중이 툴팁으로 뜬다. 같은 값을 "표로 보기"(접힘 표)와 그래프의 `aria-label`로도 제공해, 스크린리더 · 키보드 사용자가 툴팁 없이도 읽을 수 있다.
- 계산은 `utils/myPageView.js`(`axisTrend` · `axisChange` · `leanText`)로 떼어 `npm test`로 확인한다. 쓰이지 않게 된 `trailSummary` · `biggestChanges`는 지웠다.

- "지금" 성향은 **최근 첫 회차 체험 3건의 평균**(현재 판결 성향)으로 정했다. 판결에서 드러난 성향 · 변경폭의 "지금" 점 · 아래 "지금" 유형 카드가 모두 이 값이다.
  - 대안 A: 화면이 `history`로 최근 3건 축 평균을 계산. 축 수치는 되지만 그 평균의 **유형 카드**(이름 · 이미지)는 화면이 만들 수 없다(유형 정보 · 4글자 코드는 서버만 가진다). 수치와 카드 기준이 어긋난다.
  - 대안 B: 기존 전체 평균 유지. 오래된 체험이 계속 같은 무게를 가져 "지금" 경향이 묻힌다.
  - 선택: 서버 정의 변경. P-5 `judgmentPersonality`를 최근 3건 평균 + 그 유형으로 바꾸고(API 명세 v0.42, 성향 산식 v0.8), 목도 같이 맞췄다. 서버 구현(`MyPageService`)은 후속 백엔드 작업이다(BE-64 Jira 댓글).
- 변경폭 오른쪽 글자는 최종 비중이 아니라 **움직인 양**("관계형 쪽으로 38%p")이다. 처음 · 지금 위치는 막대의 두 점이 보여 준다.
- 변경폭 아래에 처음(성향 테스트) 유형 → 지금 유형 카드를 나란히 둔다. 지금 유형은 네 축이 모두 있을 때만 있고, 없으면 빈 카드로 안내한다.

- 성향 변화 흐름은 시작점(성향 테스트, 없으면 첫 체험)과 **최근 체험 10건**만 그린다(`trendOrders`). 체험이 쌓여도 가로 눈금이 붙지 않게 하고, 시작점은 남겨 "어디서 출발했는지"를 잃지 않는다. 사이에 빠진 체험은 눈금 숫자(체험 순서)가 건너뛰는 것으로 드러난다. 표로 보기도 같은 칸만 보여 준다.
- 목 데이터는 사건 목록 목 9건을 완료 순서대로 체험한 한 사용자로 맞췄다(체험 기록 · 체험한 사건 목록 · 완료 건수 · 최근 3건 평균 유형이 서로 맞는다). 점수는 축별 개수 비율이라 0 · 1로 튀지 않는 분수로 둔다.

## 고려한 제약 사항
- `history` · `judgmentPersonality`는 체험 성향 저장(7.6.7, BE-64) 전까지 빈 값이라, 지금은 목 모드에서만 채워진다. 목 수치에는 "목데이터"를 표기한다.
- 차트 라이브러리를 새로 들이지 않고, 기존 화면과 같은 방식(DOM 조립 + 인라인 SVG)으로 그렸다.
- FE-68(PR #224)이 같은 파일을 고치고 있어 FE-68 브랜치 위에서 작업을 시작했고, #224 머지 뒤 최신 develop 위로 옮겼다.
