# BE-17 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #56 · #57 · #63 본문. 주입 방식 비교의 원문은 Jira BE-17 댓글.

## 문제 / 배경
- 실제 대표 사건 데이터를 공개 저장소에 두지 않으면서, 팀원이 로컬에서 같은 방식으로 불러올 수 있어야 했다.

## 검토한 대안
- 대안 A: 공개 저장소의 시드 SQL에 실제 데이터를 둔다. 가장 단순하지만 사건 내용이 공개된다.
- 대안 B: 비공개 저장소를 서브모듈로 연결하고 Flyway 위치(`filesystem:`)로 주입한다.
- (주입 방식별 장단점 비교는 Jira BE-17 댓글에 있다. PR 본문에는 결론만 있다.)

## 선택한 방법과 이유
- 대안 B. 공개 저장소에는 `.gitmodules`(주소 · 경로)와 커밋 해시만 들어간다.
- 접근 권한이 없는 팀원은 서브모듈이 빈 폴더로 남아 기존 가상 시드로 그대로 개발할 수 있다.
- 실제 사건 파일은 `docs/cases`에 두지 않는다. 판결문 PDF가 비공개 저장소에 있고 `case-extractor`로 바로 JSON 초안을 만들 수 있기 때문이다.

## 고려한 제약 사항
- 유출 방지: `.dockerignore`에 `private-seed/` 추가, 서브모듈이 `src/main/resources` 밖이라 jar에 안 들어감, CI는 `submodules: false` 유지(접근 토큰 없음).
- 판결문의 "영리목적 이용 · 무단 배포 금지" 문구를 지킨다. 사용자 응답에는 `source_org`만 쓰고 값은 `법원 공개 판결문`으로 고정한다.
- 공개 저장소의 커밋 · PR · Jira 댓글에 사건 내용을 쓰지 않는다.

## 추후 재검토가 필요하면
- 서브모듈은 `develop` 최신 커밋을 가리켜야 하므로, 비공개 저장소가 바뀔 때마다 포인터 갱신 PR이 필요하다.
