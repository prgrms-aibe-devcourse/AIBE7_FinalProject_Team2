# FE-99 의사결정 기록

10/26 메인(랜딩) critique(22/32) 반영. 1차 = P1 + P2 (P3는 같은 이슈에서 이어서).

## 문제 / 배경
- 데스크톱 첫 화면에 "여기서 시작"이라는 단서가 없다. 핵심 카피는 `visually-hidden` h1이고, 가장 눈에 띄는 것은 포스트잇 놀이였다.
- 모바일에서 러그 위 서류가 W의 절반 남짓으로 줄어 종이 안 글씨가 5 ~ 7px로 렌더됐다. 첫 화면은 위아래가 비어 있었다.
- Tab 첫 자리가 포스트잇이고 핵심 물건(신문)은 4번째였다. 건너뛰기 링크와 `<main>`이 없었다.
- 소개 구역 끝에 마무리 행동 유도가 없었다.

## 검토한 대안
- 물건 이름표: (A) 이름표 부활 (B) 호버 · 포커스 때만 명패 (C) 신문에만 도장 한 개. FE-50에서 "책상 위 이름표 없음"을 결정했으므로 C를 택했다.
- 모바일 서류: (A) 가로 겹침 유지 + 글자 하한만 (B) 한 장씩 세로로 쌓기. A는 종이 안에서 글자가 넘치고 B는 스크롤이 길어진다. 글자 하한(`max()`)은 두고, 5px대 문제 자체는 B로 풀었다(W를 1.2로 나눠 종이 폭이 러그 안에 들어가게).
- Tab 순서: (A) `tabindex` 양수 (B) DOM 순서를 바꾸고 `z-index`로 겹침 유지. 양수 tabindex는 쓰지 않고 B를 택했다.
- 건너뛰기 링크: (A) 메인에만 (B) 공통 헤더에 두고 본문(`#route-view`)으로 포커스 이동. 헤더가 모든 화면 공통이라 B로 했다(해시를 바꾸면 라우터가 주소를 쓰므로 `preventDefault` 후 포커스만 옮김).
- `<main>`: 전역(`#route-view`를 main으로) 대신 메인 화면 안에서만 감쌌다. 다른 화면의 구조(이미 `<main>`을 두는 약관 화면 등)를 건드리지 않기 위해서다.

## 선택한 방법과 이유
- 시작점 단서: 처음에는 신문 위 "판결 체험 시작" 도장을 만들었으나 마음에 들지 않아(사용자 피드백) 글자 없이 움직임으로 바꿨다. 맨 앞 지면의 오른쪽 아래 모서리(약 40%)가 옆바람에 곡선으로 말려 들렸다 내려앉기를 되풀이한다. 처음에는 지면 전체를 `rotateY`로 돌렸으나 딱딱해 보이고 범위가 너무 커서, 모서리만 접히는 방식으로 바꿨다. 대안으로 지면을 세로 띠로 나눠 휘는 방식(DOM 복제 · 성능 부담)도 검토했으나, 접힌 변을 곡선으로 오려 내고 뒷면을 그라디언트로 둥글게 말아 보이게 하는 쪽이 가볍고 2D 평면 원칙도 지킨다. 밑 종이 세 장이 늦게 따라 들리는 뒤따름도 넣어 봤으나, 2D 오려내기 방식에서는 밑 장의 말린 부분이 윗장 말린 부분 아래에 그려져 실제와 겹침이 반대로 보였다(실제로는 밑 장의 말린 면이 윗장 위로 와야 함). 뒤따름은 없애고 맨 앞 장만 들리게 했다. 들린 모서리 밑에 다음 면 기사를 보이게 하는 안도 만들어 봤으나 사용자 결정으로 되돌렸다(밑은 빈 종이 겹). 이름표를 늘리지 않고, 동작 줄이기면 멈춘다.
- 끝 행동 유도: "사건 보러 가기" 도장도 없앴다(없어도 충분히 알 수 있다는 결정). 대신 맨 아래 신문 끝자락이 스크롤이 닿고 1초 뒤 문 밑에서 슥 밀려 나온다.
- 포스트잇은 1.15배 → 1배(최대 1.4배)로 줄였다. 놀이 자체는 유지(P3의 톤 완화는 후속).
- 모바일 메뉴 카드는 위쪽 정렬로 바꾸고 빈 곳은 내로가 고개를 내미는 장식으로 채웠다(책상 위 캐릭터 은유 유지).
- 운영 환경 헤더 메뉴 줄 넘침은 개발 전용 "목 데이터" 스위치 때문이라 운영에서는 넘치지 않는다(390 · 360 모두 맞음). 별도 수정 없음.

## 고려한 제약 사항
- 책상 겹침 순서는 기존 DOM 순서에 의존했다. Tab 순서를 바꾸려면 `z-index`를 명시해야 했다(엽서 1 < 펜 2 < 서류철 3 < 신문 4 < 노트북 5 < 커피잔 6 < 내로 10 < 포스트잇 11).
- 헤드리스 크롬은 `pointer: coarse`를 에뮬레이션하지 않는다. 실기기(iPhone Safari) 확인은 PR 체크리스트에 남긴다.

## 추후 재검토가 필요하면
- 모바일 서류를 세로로 쌓은 뒤 스크롤이 길어졌다(문서 높이 약 3000px). 모바일 소개 구역의 길이는 실기기에서 다시 본다.
- 펄럭임 세기 · 주기, 등장 지연(1초)은 실제 화면을 보고 조정할 수 있다.

## P3 (같은 PR)
- 숨은 인터랙션: 안내문 종이는 이미 늘 들썩이고, 맨 아래 신문은 1차에서 스크롤이 닿으면 밀려 나오게 바꿨다. 남은 러그 귀퉁이만 마우스가 없는 기기(`hover: none`)에서 5초마다 혼자 살짝 들썩이게 했다. 모든 기기에서 늘 움직이게 하는 안은 데스크톱에서 화면이 산만해져 택하지 않았다.
- 포스트잇 톤: 1차에서 크기를 줄여(1.15 → 1배) 첫 화면의 주인공에서 내렸다. 문구는 그대로 둔다(놀이 자체는 FE-50 결정).
- 터치 높이: 로그인 버튼은 보이는 테두리(36px)를 바꾸지 않고 `::after`로 누르는 범위만 44px로 넓혔다. 헤더 높이 · 모양이 모든 화면에서 같아야 해서다. 푸터 약관 링크는 `min-height: 44px`.
- 노트북 화면 `익명` 라벨: 옅은 테두리색(3.5:1) → 보조 글자색(6.3:1).
- 파비콘: `/favicon.ico` 404를 없애려 임시 SVG 아이콘(네이비 바탕 · 놋쇠 "L")을 넣었다. 로고가 정해지면 바꾼다.
