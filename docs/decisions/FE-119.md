# FE-119 의사결정 기록

> FE-118([FE-118 의사결정 기록](FE-118.md)) 후속. FE-118의 면 구조 위에 면 구성 · 색인 · 사건 정보 시작 버튼을 올렸다. FE-109(종이 귀 "다음 장")를 이 이슈로 흡수했다가, 신문 안의 귀 · 화살표를 모두 빼기로 해서 귀는 만들지 않았다.

## 문제 / 배경
- "전체" 탭은 사건이 늘면 한 면이 끝없이 길어지고, 신문의 "1면"답지 않았다. 사건이 0건인 유형 탭도 눌러야 비어 있음을 알았다.
- 면을 넘겨 가며 읽을 수 있는데 사건 전체를 한눈에 훑거나 찾을 곳이 없었다.
- 사건 정보의 "시작하기"는 신문 밖에 뜬 알약이었다. 신문이 낮아지거나 스크롤이 길면 지면과 따로 놀았다.

## 검토한 대안
- 시작하기 버튼(시안 HTML로 비교): A 신문 위 도장형 / B 신문 밖 알약 유지 / FE-109의 종이 귀가 알약을 대체.
- 도장 자리: 지면 우하단 sticky(지금), 지면 위 오른쪽 위(페이지 머리 귀 근처), 제목 줄 사건 메모 왼쪽, 사건 메모 바로 밑(오른쪽 칸).
- 색인 · 성향 테스트 · 오피니언을 `?type=`와 별개의 주소/화면으로 두는 안, 지금의 탭 하나 = 면 구조에 얹는 안.
- 유형 면 더보기: 페이지 전환, 같은 종이가 아래로 펼침(시안에서 결정).
- 1면 9건 밖의 사건: 1면에서 "더보기"로 여는 안 / 버리고 유형 면 · 색인에서 보게 하는 안.

## 선택한 방법과 이유
- 시작하기는 **도장형**(사용자 결정)으로 정하고 FE-109의 알약 대체 논의를 흡수했다. 종이 귀 "다음 장"은 도장과 같은 동작을 하는 두 번째 입구로 한 번 달았으나, 신문 안의 모서리 귀 · 양옆 화살표를 모두 빼기로 하면서(사용자 결정) 없앴다. 시작은 도장 하나가 맡는다.
- 도장 자리는 처음에 사건 메모 왼쪽 · 기자 줄 높이로 잡았으나(부제와 15px 틈, 1100px 이하는 겹쳐 내려야 했다), 사건 메모 **바로 밑(오른쪽 칸)**으로 옮겼다(사용자 결정). 오른쪽 칸을 메모 → 도장 순으로 쌓으면 반응형 예외가 줄고(768px 이하 한 단만 풀면 된다), 도장은 지면 위에 찍힌 물건이라 sticky가 아니다. 왼쪽에 생긴 빈 자리는 후속에서 기존 데이터(범죄 유형 알아두기 · 같은 유형의 다른 사건 등)로 채운다.
- 면은 기존 `?type=` 탭 구조에 얹었다. 색인 · 성향 테스트 · 오피니언도 `?type=INDEX | TEST | OPINION`으로 같은 탭 · 같은 넘김을 쓴다(키보드 · 밀기가 그대로 먹고, 새로고침 · 공유도 된다). 범죄 유형이 아닌 면은 API에 유형을 보내지 않고 전체 목록을 받는다.
- 0건 면 숨김은 `visibleFaces`(순수 함수 · 테스트 있음). 지금 보고 있는 면은 0건이어도 남긴다 — 주소로 들어온 면이 목록에서 갑자기 사라지는 것보다 "해당하는 사건이 없어요"가 낫다. 건수를 아직 모르는 로딩 중에는 전부 보인다.
- 1면은 9건만 싣는다(나머지는 유형 면 · 색인). 유형 면은 9건 뒤를 "이 면 더 보기"(펼침)로 연다. 신문 최소 높이를 `max(100dvh + 120px, 신문 폭 × 1.4)`로 잡아(폭이 넓은 화면에서 신문이 짧아 보이지 않게 하한을 더했다) 짧은 면은 법적 고지를 아래로 밀고(flex), 펼침으로 종이가 늘어나는 모습은 대개 화면 밖에서 일어난다. 더보기 버튼이 화면 끝에 걸친 경우까지 일부러 가리지는 않는다.
- 최소 높이는 S-02 지면(`.paper:not(.case-paper)`)에만 건다. S-20 기사 지면은 1막 무대의 카메라 · 스크롤 계산과 함께 쓰여 건드리면 무대가 흔들릴 위험이 있다.
- 신문 안 모서리 종이 귀(S-02 앞 · 다음 면, S-20 다음 장)를 뺐다(사용자 결정). 양옆 화살표는 한 번 뺐다가 다시 남겼다. 넘김은 탭 · 양옆 화살표 · ← → · 손가락 밀기로 한다. 색인의 진행 중 · 완료 도장은 줄 오른쪽에 글자 위로 겹쳐 찍는다(제목 폭을 줄이지 않는다). 준비 중 도장 위의 흰 안내 상자와 설명은 없앴다.
- 왼쪽 빈 자리(도장을 메모 밑으로 옮겨 생김)는 기존 데이터로 채웠다: 범죄 유형별 [알아두기](`TYPE_NOTES`, S-02와 공용 모듈 `content/typeNotes.js`로 옮김) + 같은 유형의 다른 사건 둘(목록 API 재사용). 새로 쓴 문장이 없다. 다른 사건은 못 받아도 화면이 그대로여야 해서 비동기로 채운다.
- "이 면 더 보기"는 임시 목(살인 사건 9건을 `caseListMockData.js` 끝에 넣어 확인, 확인 뒤 지움)으로 눌러서 확인했다. mock 데이터에는 유형당 9건을 넘는 사건이 없어 평소에는 열리지 않는다.
- S-20 지면 목차를 "1면 오늘의 지면 · 3면 사회 · 8면 색인 · 10면 성향테스트"로 바꿨다(사용자 결정, 옛 8면 오피니언 · 10면 독자 · 마이페이지 대신). 8면은 S-02의 색인 면으로 열도록 `navigate`에 `openAt` 옵션을 만들었다(`?type=`는 주소 쿼리라 `navigate`가 못 실어서). 신문 안의 성향 테스트 진입은 모두 신문 버전(`/test/paper`)이다. 시작하기 도장 호버는 기울기를 바꾸지 않고 색만 바뀐다(기울기가 평소와 같아야 한다는 결정).
- 진행 상태는 글자 배지 대신 작은 도장(진행 중 · 완료)으로 바꾸고 "준비 중" 표시는 없앴다(사용자 결정). 건수 요약 줄("상해 3건 · 전체 11건")과 색인의 "(3면에 계속)"도 없앴다. 좌우 하단 면 넘김 귀의 들썩임(`paper-fold-lift`)은 껐다(호버 · 포커스에서만 접힘). 성향 테스트 면 · 광고는 `/test`가 아니라 신문 버전 `/test/paper`로 보낸다.
- 우상단 귀는 "오늘의 사건 n건"만 두고 왼쪽 귀와 같은 높이(64px)로 맞췄다(유형별 건수는 건수 요약줄이 이미 보인다).

- 세로 여백 채움은 **면 종류와 상관없이 모든 면에 붙는다**(PR #314 리뷰에서 의도를 확인했고 사용자 결정으로 유지). 색인 · 성향 테스트 · 오피니언 면은 후속에서 전용 내용을 더 채울 예정이며, 그때 내용이 모자라거나 전용 내용이 없는 동안은 여백 채움이 받친다. 면별로 끄고 켤 수 있게 하는 것은 FE-123(면 모델 리팩터링)에서 한다.
- **세로 여백 채움(신문 레이아웃을 고려한 로직)**: 최소 높이를 신문 폭의 1.4배로 올리면서 짧은 면 아래에 빈 종이가 크게 남아, 칸 수만 세던 채움(추천 반쪽 · 마지막 줄 빈 칸 · 3칸 띠)을 손봤다.
  - 대안: 남는 높이를 재서 채우기(채택) / 항상 같은 개수의 띠를 깔기(기사 높이에 따라 비거나 넘침) / CSS만으로 늘리기(내용이 없는 상자만 길어짐).
  - 여백 칸은 flex-basis 0이라 자기 안의 내용이 높이에 영향을 주지 않는다. 그래서 "남는 높이 → 칸 구성 → 다시 높이" 되먹임 없이 한 번 재서 짤 수 있고, 사진이 늦게 와 기사가 길어지면 `ResizeObserver`로 다시 짠다.
  - 줄 높이는 남는 높이를 줄 수로 나눈 값으로 빈틈이 없고, 줄은 최대 2줄(그 이상은 읽을거리가 모자라 글자 없는 큰 상자만 늘어난다 — 3줄로 시험했더니 법정 상식 칸이 텅 비어 보였다). 높은 줄(190px 이상)에는 공용 재연 컷에 망점을 씌운 사진 지면을 대각선으로 섞어 한 줄에 사진이 몰리지 않게 했다.
  - 기사 칸 안의 빈 칸과 면 아래 여백이 같은 덱에서 뽑아 한 면 안에서 같은 지면이 되풀이되지 않는다. 다시 짤 때 결과가 달라지지 않게 덱을 `fork()`해서 쓴다. 채움 로직은 `newspaperFaces.js`의 순수 함수(`planFiller` · `createFillerDeck`)에 두어 DOM 없이 테스트한다.
  - 3칸 띠(`filler-strip`)는 이 로직으로 대체돼 없앴다.

## 고려한 제약 사항
- mock 데이터가 11건이라 "이 면 더 보기"가 실제로 열리는 경우(유형 면 9건 초과)가 없다. 펼침 CSS는 손으로 만든 마크업으로 확인했고, 배치 계산은 단위 테스트로 확인했다.
- 사진 지면은 공용 재연 컷 9장을 돌려 쓰므로 한 면에 두 장이 나오면 같은 분류의 컷이 섞일 수 있다.
- 모바일은 전체 손질 때 함께 하기로 해서, 면 탭만 가로로 밀 수 있게 했다.

## 추후 재검토가 필요하면
- 사건이 많아지면 색인에 페이지 나누기 · 정렬 선택(최신순 · 참여순)이 필요한지 본다.
- 색인 · 성향 테스트 · 오피니언 면의 전용 내용(소개 · 편집부 사설 등)은 후속 이슈로 한다. 그 전까지는 세로 여백 채움이 이 면들도 받친다.
- 면 종류별 분기(`selected` 문자열에 범죄 유형 키와 색인 · 성향 테스트 · 오피니언이 함께 들어 있어 `draw()`의 if/else 체인과 `isCrimeFace` · `apiTypeOf` 같은 보조가 흩어져 있다)는 **FE-123**에서 면 정의 모델(`{ key, label, apiType, count, tip, fill, render }`)로 정리한다. PR #314 리뷰에서 나온 포스트잇 문구 오류도 같은 원인이었다.
- 사파리 · 실기기에서 도장 호버(터치에는 호버가 없어 기울어진 채 남는다) 모양과 `rotate`/`scale` 개별 속성 지원을 확인한다.
