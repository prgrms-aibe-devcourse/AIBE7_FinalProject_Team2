# FE-86 의사결정 기록

## 문제 / 배경
- 메인 책상의 엽서 · 펜을 누르면 의견 보내기 창이 바로 떠서, 책상 위 물건과 창이 이어지지 않았다.
- 창이 열려 body 스크롤이 잠기면 스크롤바가 사라지며 화면 폭이 변해 뒤 화면이 움찔했다.
- 입력칸으로 직접 의견을 받는 대신 외부 링크로 받기로 해, 창 구성이 바뀌었다.

## 검토한 대안
- 대안 A: 엽서 모양 유령 요소를 날리고, 도착하면 창과 교차 페이드. 유령과 창이 따로라 크기 · 위치를 두 번 맞춰야 하고, 교차하는 순간 두 개가 겹쳐 보인다.
- 대안 B: 창 자체를 엽서 자리 · 크기 · 기울기에서 출발시켜 제자리로 키운다. 엽서 앞면은 창 안에 겹쳐 함께 커지다가 사라진다. 창이 곧 엽서라 이어짐이 자연스럽다.
- 스크롤 잠금 움찔: `overflow: hidden`만 쓰기(움찔 발생) / 스크롤바 폭을 재서 padding 보정 / `scrollbar-gutter: stable`.

## 선택한 방법과 이유
- 대안 B. 창을 엽서와 같은 비율(236:156)로 만들어 비율 왜곡 없이 크기만 키운다. 움직임은 transform · opacity만 써서 합성 단계에서 끝난다.
- 펜은 유령 요소로 날려 창 오른쪽에 둔다. 책상의 원본은 숨겨 두고 창을 닫으면 되돌린다.
- 스크롤 잠금은 `scrollbar-gutter: stable`. 6막 엽서(caseReview)가 이미 쓰는 방식과 같아 일관된다. 스크롤바가 없던 화면은 건드리지 않는다.

## 고려한 제약 사항
- 책상 그림은 기준 좌표계(1672px)를 `--desk-scale`로 줄여 쓰므로, 시작 크기는 상자 크기(offsetWidth)와 화면 크기(rect)의 비율로 맞춘다.
- 좁은 화면(메뉴 카드)이나 연출 끔 · 동작 줄이기에서는 연출 없이 바로 열린다.

## 추후 재검토가 필요하면
- 의견 링크 주소(`FEEDBACK_URL`)가 아직 정해지지 않아 `#`이다. 정해지면 교체한다.

## 리뷰 반영 (PR #261)
- 스크롤 잠금은 6막 엽서와 같은 코드여서 `utils/scrollLock.js`로 합쳤다. 클래스 이름만 인자로 받고 CSS 규칙(`.feedback-gutter` · `.case-review-gutter`)은 각자 둔다.
- `FEEDBACK_URL`이 비어 있는 동안에는 새 탭으로 앱이 한 번 더 열리지 않도록 입구를 "링크 준비 중" 비활성 버튼으로 막는다. 링크가 정해지면 값만 넣으면 링크로 바뀐다.
- 펜은 열릴 때 계산한 자리에 고정돼 창 크기가 바뀌면 어긋나므로, 열려 있는 동안 창 크기가 바뀌면 닫는다(다시 누르면 새 자리로 열린다).
