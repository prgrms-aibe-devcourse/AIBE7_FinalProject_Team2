# FE-102 의사결정 기록

10/26 사건 목록(신문 지면) critique(29/40, P1 1 · P2 4 · P3 4) 반영. 결정: 9건 지면은 실제 상태 그대로 두고, 추천 칸만 체험 가능한 사건 우선.

## 문제 / 배경
- 머리기사 · 추천 칸 모두 "준비 중"이었고 포스트잇은 "눌러 보세요"라고만 말했다(체험 가능한 사건은 1건).
- 오른쪽 귀("오늘의 사건 9건…")가 포스트잇에 가려 테두리 일부만 비쳤다.
- 필터: 건수가 `aria-label`에만 있고, 요약은 탭을 바꿔도 "총 9건"이며 모바일은 숨겨졌고, 주소에 안 남고, 탭을 누르면 포커스가 body로 사라졌다.
- 오류 · 로딩에서 탭이 사라졌다. 로딩 뒤 푸터가 밀려 데스크톱 직접 진입 CLS가 0.12였다.
- 모바일 포스트잇이 첫 화면 상단 약 30%를 차지했다.

## 검토한 대안
- 준비 중 사건: 숨기기 / 한 줄로 접기 / 그대로 두고 추천만 체험 가능 우선 → 사용자 결정으로 마지막. 지금은 체험 가능한 사건이 머리기사 1건뿐이라 추천이 여전히 "준비 중"이지만 규칙은 사건이 늘면 바로 작동한다. 대신 포스트잇 문구를 사실대로 바꿨다.
- 포스트잇과 귀: 귀를 없애기 / 포스트잇을 귀 밖으로 옮기기 / 떼기 전에는 귀를 감추기 → 포스트잇이 안내 · 놀이를 맡고(FE-50) 귀를 지우면 지면이 비대칭이라, 떼면 귀가 드러나는 쪽을 택했다(귀 내용은 어느 탭에서나 채운다).
- 선택한 탭 보존: 라우터 이동(`navigate`) / `replaceState`로 `?type=` → 이동은 화면을 다시 그려 지면 넘김 연출과 부딪히므로 replaceState. 라우터는 pathname만 매칭해 쿼리는 영향이 없다.
- 로딩 CLS: main 최소 높이 예약 / 아래 푸터 감추기 → 최종 높이를 모르므로 `visibility: hidden`(레이아웃 이동으로 세지 않는다).
- 모바일 포스트잇: 지면 아래로 옮기기 / 한 줄 띠로 줄이기 → 안내 위치(맨 위)는 유지하고 크기만 줄였다(약 126px → 64px).

## 선택한 방법과 이유
- 정렬: 체험 가능 → 참여 많은 순. 문구 3단계(전부 열림 · 일부 · 없음).
- 탭: 건수 글자 + 선택에 맞는 요약, 목록 자리만 오류 상자(탭 유지), 키보드로 눌렀으면 같은 탭으로 포커스 복구, 처음 목록을 받는 동안은 탭 비활성.
- 같은 사건의 영역은 호버를 함께 보여 하나의 기사로 읽히게 했다.

## 고려한 제약 사항
- 헤더 Tab 순서(모바일에서 마이페이지가 화면 맨 위인데 Tab은 nav 뒤)는 FE-99(#287)가 같은 `siteLayout.js` 헤더를 고치고 있어 충돌을 피하려고 이번에는 건드리지 않았다. FE-99가 합쳐진 뒤 후속으로 한다.
- 사진이 사건을 구별하지 못하는 문제는 정식 이미지가 올 때까지 캡션을 사건 제목 한 줄로만 보완했다.

## 추후 재검토가 필요하면
- 체험 가능한 사건이 늘면 추천 칸이 실제로 체험 가능한 사건으로 채워지는지 확인.
- 실제 API 연동 뒤 `?type=` 보존과 `myStatus` 기준 정렬 확인.
