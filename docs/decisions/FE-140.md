# FE-140 의사결정 기록

## 문제 / 배경
- 판결 체험을 직접 써 보며 나온 사용감 문제 세 가지: 서명하고 제출 때 서명란이 안 보임, 첫인상 엽서가 지면을 가려 사건 정보를 못 봄, 1막에서 화면이 "휙휙" 움직임.

## 검토한 대안
- **1막 스크롤**
  - 대안 A: `scroll-behavior: smooth` / `behavior: 'smooth'`(기존). 브라우저가 시간을 정해 거리와 상관없이 짧고 빠르며, 사파리는 더 짧다. 키보드로 넘길 때는 이미 `auto`(즉시)로 두어 "휙"이 그대로였다.
  - 대안 B: CSS 변환(transform)으로 지면을 움직이는 카메라. 합성 스레드에서 돌아 부드럽지만 지면이 "스크롤되는 문서"라는 구조(읽기 모드, 사파리 주소창, 포커스)를 바꿔야 해 범위가 크다.
  - 대안 C(채택): `requestAnimationFrame`으로 `window.scrollTo`를 직접 굴린다. 거리에 비례한 시간 + easeInOutCubic.
- **엽서 내려놓기**
  - 대안 A: 엽서를 접어 화면 아래로 내리고 모서리만 남기기(translate). 모양은 좋지만 엽서 높이가 사건마다 달라 모서리 위치 계산이 필요하다.
  - 대안 B(채택): 엽서를 숨기고(내용 유지) 다시 펼치는 버튼을 둔다. 뒤 지면 잠금(`inert`)은 내려놓은 동안 푼다.
  - 리뷰 · 사용 확인 뒤 정한 것(#353):
    - **내려놓는 법:** 넓은 화면(733px 이상)은 아래 버튼 대신 엽서 왼쪽 위 ✕(모바일은 알약 버튼 유지)와 엽서 바깥 클릭. ✕는 처음 36px였는데 "첫인상"을 가려 24px로 줄였다가 잘 안 보여 30px에 진한 바탕으로 정했다.
    - **다시 펼치는 법:** 넓은 화면은 알약 대신 엽서를 던진 남불 곁의 작은 엽서 버튼, → · Enter 키. 처음엔 "내려놓은 동안 첫 클릭(다음 버튼 포함)은 펼치기만 하기"로 했다가 작은 엽서 버튼이 생겨 화면 아무 곳 클릭은 뺐다(대안: 그 클릭을 평소대로 동작 — 읽던 중이 아닌데 장면이 넘어가는 사고가 나서 버림).
    - **작은 엽서 위치:** 엽서를 던지는 인물은 코드가 늘 남불로 고정한다(배역이 바뀌면 남불이 서는 쪽만 바뀐다). 처음엔 화면 기준 고정 위치였는데 창 너비에 따라 남불과 멀어져 남불 곁으로 붙였다.
      - 대안 A: 남불 그림 안에 자식으로 둔다. 자리는 따라오지만 남불 그림(`z-index: 19`)의 쌓임 맥락에 갇혀 하단 조작 줄(`28`)을 가리지 못한다(줄과 겹치는 낮은 화면에서 확인).
      - 대안 B(채택): 무대 바깥(`wrap`)에 `position: fixed`, `z-index: 29`로 두고, 스크립트가 남불 그림의 자리를 읽어 곁에 놓는다. 창 크기를 바꾸면 남불 그림이 전환으로 자리를 옮겨 한 번만 재면 옛 자리에 남으므로, 엽서가 보이는 동안만 프레임마다 따라간다(읽기 한 번 · 쓰기 두 번).
    - **`aria-modal` 제거:** 내려놓기 버튼이 모달(엽서) 밖에 있어 낭독기가 닿지 못한다. CodeRabbit의 "버튼을 dialog 컨테이너 안으로"는 `.stage:has(> .board)` 규칙이 깨져 채택하지 않았다. `role="dialog"`와 뒤 지면 · 조작부 `inert`는 그대로 두어 포커스는 엽서에 머문다.
    - **커서:** 지면 무대(`.scene`)에 손 모양 커서가 남아 있어 빈 곳을 누를 수 있는 듯 보였다. 지면 무대는 빈 곳을 눌러도 넘어가지 않으므로 기본 커서로 바꾸고, 열린 엽서의 바깥 배경만 손 모양으로 둔다.
- **서명 스크롤**: 서명란이 가려져 있을 때만 `scrollIntoView(center)`로 굴리고 멈출 때까지 기다린 뒤 서명한다(기존 "서명 중 카드 스크롤 고정"이 굴린 위치를 지켜 주도록 순서를 맞춤).

- **리뷰 반영(CodeRabbit, #353)**: 무대가 떠나면 지면 굴리기 중단(`isConnected`), 서명란 보임 판정에 상단 고정 헤더 반영, 스크롤을 기다리기 전에 입력 잠금(예전 값이 제출되는 문제), 기다리는 동안 서명 카드가 떠나면 제출하지 않음. 6막 사진 테스트는 같은 함수로 기대값을 다시 계산하던 부분을 실제 5막 대본의 마지막 판사 장면과 비교하도록 바꿨다. 모바일의 안내 문구 줄이 알약 버튼에 살짝 가리는 지적은 사용 확인에서 신경 쓰일 정도가 아니라 위치를 그대로 둔다.

## FE-141 (6막 신문 사진, 같은 PR)
- 6막 1면 사진이 5막 마지막 화면과 달랐다(판사 = 내로, 피고인 = 남불로 고정). 대본 배역(`script.cast`)의 묶음 A를 판사로 왼쪽, 묶음 B를 피고인 역으로 오른쪽에 세우고 무대처럼 가운데를 보게 뒤집는다(`courtPhotoCast`, FE-128의 `flipFor`).
- 대안: 사건마다 사진을 따로 두기 — 이미지가 늘고 5막과 어긋날 여지가 남아 버렸다.

## 선택한 방법과 이유
- 1막 스크롤은 메인 스레드 일이지만 `scrollTo` 한 번/프레임이라 부담이 작고, 도중에 새 목표로 이어 굴릴 수 있어 연달아 넘겨도 느려지지 않는다. 합성 스레드 카메라(B)는 효과 대비 범위가 커서 보류한다.
- 엽서는 숨기기만 해서 쓰던 선택이 유지되고(폼 상태를 따로 저장하지 않는다), 접근성은 `aria-expanded` 버튼 + 포커스 이동으로 챙겼다.

## 고려한 제약 사항
- 사용자는 사파리로 확인한다(기본 smooth가 특히 빨랐다). 헤드리스 크롬은 `smooth`를 즉시로 처리해 기존 동작을 직접 못 재 봤고, 새 동작의 프레임당 이동량(504px 이동 시 프레임당 최대 약 420px → 59px)으로 비교했다.

## 추후 재검토가 필요하면
- 1막이 길어져 스크롤 비용이 보이면 합성 스레드 카메라(대안 B)를 다시 본다.
