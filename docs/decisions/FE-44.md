# FE-44 의사결정 기록

## 문제 / 배경
- S-17 마이페이지에 종합 판결 성향(4축)과 성향 변화 흐름을 더하고, 성향 API(P-1 ~ P-5)를 실제 API 쪽에 연결해야 했다.
- 체험 → 성향 저장(7.6.7, BE-64) 전에는 `judgmentPersonality`가 `null`, `history`가 빈 배열로 온다.
- WBS 예비 조정안 9순위가 "성향 변화 그래프 제외"였지만, FE-44 완료 조건에 변화 흐름이 있어 범위대로 구현하기로 했다.

## 검토한 대안
- 변화 흐름 표현 A: 4축을 한 차트에 선 4개로 그린다. 축마다 양 끝 이름이 달라 한 Y축에 설명하기 어렵고, 색으로만 선을 구분하게 된다.
- 변화 흐름 표현 B: 축마다 기존 엄격 ↔ 관대 막대 위에 체험 번호가 붙은 점을 찍는다.
- 종합 4축 그래프: 성향 결과(S-16)의 막대 줄을 그대로 쓸지, 마이페이지용으로 새로 만들지.

## 선택한 방법과 이유
- 변화 흐름은 B. 결과 화면의 막대와 같은 언어라 따로 배울 것이 없고, 번호로 순서를 읽으니 색에 기대지 않으며, 모바일 폭에서도 줄이 겹치지 않는다. "처음보다 ○○ 쪽으로 ○○%p 움직였어요" 문장을 함께 둔다(계산은 `utils/myPageView.js`, 테스트 포함).
- 종합 그래프는 막대 줄을 `components/axisRow.js`로 빼서 S-16과 S-17이 함께 쓴다. 값이 없는 축(`null`)은 막대 대신 "체험 자료가 아직 없어요"로 보인다.
- `realApi.js`에 P-1 ~ P-5를 추가했다. 함수 이름 · 인자 · 응답은 목과 같다.

## 고려한 제약 사항
- 점수 방향은 API 그대로 "관대 쪽 비중"이고 화면은 왼쪽 = 엄격 쪽이다(S-16 막대와 같다).
- 목 `getMyPage`는 화면 확인용으로 체험 기록 3건을 채운다. 실제 API는 BE-64 전까지 비어 있다. 빈 상태는 `?empty=history`로 본다.

## 추후 재검토가 필요하면
- 체험이 많아져 점이 겹치면(10건 이상) 최근 N건만 보이는 방식을 검토한다.
- BE-64가 붙어 실제 `history`가 채워지면 실제 모드(`VITE_API_MODE=real`)에서 한 번 확인한다.
