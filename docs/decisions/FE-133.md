# FE-133 의사결정 기록

로그인 폼 오류 시 입력칸 `aria-invalid` 적용 (FE-117 후속). 담당 D(정민석). BE-134 · FE-134 · FE-135와 한 PR.

## 문제 / 배경

- 2026-10-29 운영 점검: 로그인 실패 때 오류 문구(`#login-error`)는 나오지만 입력칸에 `aria-invalid`가 붙지 않아 스크린리더가 "잘못된 입력"으로 읽지 못했다. 가입 폼은 붙인다.
- 그 뒤 빈칸 제출은 빈칸에 `aria-invalid`를 붙이도록 바뀌어 있었다(develop 확인). 남은 것은 **아이디 · 비밀번호가 틀린 경우**다.

## 선택한 방법과 이유

- 인증 실패(`INVALID_CREDENTIALS`) · 형식 400(`VALIDATION_ERROR`)이면 **두 칸 모두** `aria-invalid="true"`. 서버가 아이디 없음 · 비밀번호 틀림을 나누지 않으므로(BE-113 결정 3) 한 칸만 표시할 근거가 없다.
- 카카오 로그인 · 연결 실패 · 요청 제한(429) · 토큰 발급 실패는 입력이 틀린 것이 아니라 표시하지 않는다.
- 다시 입력하면 그 칸은 풀린다(기존 `field`의 input 처리). 모양은 가입 폼과 같은 `.login-field input[aria-invalid="true"]`를 이미 쓰고 있다.
- 판단은 `loginRule.js isCredentialFailure`로 떼어 node 테스트로 고정하고, 실패 문구(`failureMessage`)도 같은 판단을 쓴다.

## 확인

- `loginRule.test.js`: 아이디 로그인의 401 · 400만 표시, 연결 실패 · 429 · 토큰 실패 · 카카오는 표시하지 않음
