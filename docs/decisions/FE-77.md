# FE-77 의사결정 기록

## 문제 / 배경
- 마이페이지 "내 정보 수정" 화면이 비어 보였다. 무엇을 넣을지, 서버 API가 없는 항목을 어떻게 둘지 정해야 했다.
- 성향카드가 화면마다 다른 값을 보였다. 마이페이지 첫 화면은 테스트 결과를, 성향카드 화면은 판결 성향을 보였다. 또 "처음" 카드가 재응시하면 바뀌는 값이라 엄밀한 최초 결과가 아니었다.
- 처음 성향을 바꾸고 싶은 수요에 어떻게 답할지 정해야 했다.

## 검토한 대안
- 현재 성향카드의 값
  - 대안 A: 테스트 현재 결과(`personality.type`). 판결을 많이 해도 카드가 바뀌지 않는다.
  - 대안 B: 현재 판결 성향(`judgmentPersonality.type`)을 우선하고, 없으면 테스트 결과로 대신한다. 성향카드 화면 위쪽이 이미 이 규칙이었다.
- 처음 성향을 바꾸는 방법
  - 대안 A: 바꾸지 못하게 한다. "처음 → 지금" 변화의 의미는 지키지만 대충 응시한 사용자를 구제하지 못한다.
  - 대안 B: 1회에 한해 처음 결과를 갈아끼운다. 처음 기록이 사라진다.
  - 대안 C: 출석 등 도전과제 보상으로 변경을 허용한다. 정보의 정합성이 게임 보상에 묶여 복잡해진다.
  - 대안 D: 1회에 한해 "다시 정한 결과"를 하나 더 남긴다. 처음 결과는 그대로 둔다.
- 다시 정하기와 일반 재응시의 관계
  - 대안 A: 재응시를 1회로 제한한다.
  - 대안 B: 일반 응시는 언제든 무제한으로 두고, 다시 정하기만 특별한 1회 응시로 둔다.

## 선택한 방법과 이유
- 현재 성향카드는 대안 B로 정했다. 마이페이지 첫 화면, 내 정보 수정, 성향카드 화면 위쪽이 같은 함수(`currentType`)로 같은 카드를 보인다. 처음 성향은 성향카드 화면 아래에만 둔다.
- 처음 성향은 서버가 새로 저장하지 않고 가장 오래된 응시 행으로 정한다. 테스트 전이면 첫 판결(완료 순서로 처음 3건 평균)이 대신하고, 테스트를 하면 첫 테스트가 대신한다. 이미 이력이 남는 구조(`is_current`)라 새 테이블이 필요 없다.
- 다시 정하기는 대안 D와 대안 B(일반 응시 무제한)로 정했다. 처음 기록을 지우지 않고 "처음 → 다시 정함(체험 n건 뒤) → 지금"을 이어 보일 수 있다. 응시마다 그 시점의 완료 사건 수를 남겨 "몇 건 체험한 뒤 다시 했는지"를 기록한다.
- 다시 정하기 입구는 성향카드 화면의 가운데 칸(카드 크기의 점선 빈 칸이 버튼)과 내 정보 수정 두 곳이다. 확인 창과 상태 판단은 `pages/myPage/baselineRetake.js` 한 곳에 모았다.
- 서버 API가 없는 내 정보 수정 항목(한 줄 소개, 공개 범위, 기록 옮기기, 초기화, 최근 로그인)은 화면 틀만 만들었다. 저장은 이 브라우저에만 하거나 "서버 연동 후 열려요"로 안내한다.

- 공개 카드: 성향카드 화면의 "처음 · 다시 정함 · 지금" 중 누른 카드에 결재 도장 "공개"를 찍고, 그 카드를 커뮤니티에서 다른 사람에게 보여 줄 성향카드로 삼는다. 다시 정하기 전에는 가운데 칸이 테스트 버튼이고, 다시 정하면 그 카드도 공개 후보가 된다. 고른 칸에 카드가 없으면 지금 → 처음 순으로 대신 고른다(`utils/shownCard.js`).
  - 표시는 처음에 왕관으로 만들었다. 하지만 "판사의 책상" 컨셉 밖의 물건이라 책상 위 물건인 결재 도장으로 바꿨다. 클립(공개라는 뜻이 약함)과 봉랍(봉인 = 감춘다로 읽힘)도 검토했다. 도장 잉크는 네이비다(빨강은 오류에만, FE-76 `DESIGN.md`).
  - 저장 위치는 프로필 꾸미기(P-7 `profileDeco`)에 넣는 안도 검토했다. 하지만 P-7은 전체를 덮어쓰는 저장이라, 서버가 모르는 필드를 보내면 실제 모드의 꾸미기 저장까지 깨질 수 있다. 그래서 서버 API 전까지는 이 브라우저에만 저장한다.
  - 성향카드의 타로카드 모양도 컨셉 밖이라 재해석이 필요하다. 범위가 커서 FE-76(디자인 정리)에 안건으로 넘겼다.

- 화면 이름: 처음 테스트 · 다시 정함 · 최근 평균을 법정 용어 **초심 · 재심 · 최근**으로 정했다. 판사의 책상 컨셉과 맞고, 재심은 확정된 판결을 예외적으로 다시 심리하는 절차라 "1회"라는 성격과도 맞는다. 서류(첫 기록 · 고친 기록)와 평이한 말(첫 성향 · 바꾼 성향)도 검토했다. 그래프 가로축에 들어가므로 두 글자인 것도 고려했다.
- 성향 변화 흐름 그래프에서 재심은 가로 칸을 만들지 않고 두 칸 사이에 세로 점선과 마름모로 얹는다. 칸을 하나 끼우면 체험 사이 간격(기울기)이 사람마다 달라지기 때문이다. 초심 바로 뒤나 최근 바로 앞에 끼면 그 사이만 조금 띄운다. 기준점(초심 · 재심 · 최근)은 한 번의 판결이 아니라서 체험 선과 잇지 않고 마름모로 찍는다.

## 고려한 제약 사항
- 백엔드 `Member`에 닉네임 필드가 없고, P-5에 처음 성향과 다시 정하기 필드가 아직 없다. 실제 모드에서 필드가 없으면 화면은 이전처럼 동작한다(처음 = 테스트 현재 결과, 다시 정하기 = 서버 연동 후).
- 명세 변경은 [API 명세 v0.50](../api-specification.md), [ERD v1.36](../erd.md), [성향 산식 v0.9](../personality-scoring.md)에 있다.
- 디자인은 FE-76 `DESIGN.md` 기준에 맞췄다. 되돌릴 수 없는 동작은 주의 색, 비활성은 `opacity .6`, 터치 대상은 44px, 입력칸은 16px이다.

## 추후 재검토가 필요하면
- 서버 구현(컬럼 2개, 1회 제한, P-5 필드)은 후속 BE 이슈다. 구현되면 실제 모드에서 다시 확인한다.
- 다시 정하기 횟수를 늘릴 수요가 생기면 도전과제 보상으로 "+1회"를 얹는 방식을 검토한다.
- 한 줄 소개와 공개 범위는 지금 이 브라우저에만 저장한다. 서버 API가 생기면 옮긴다.
