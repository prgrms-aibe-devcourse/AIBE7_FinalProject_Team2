# FE-12 의사결정 기록

> MVP 단계 · PR #69 · 담당 정민석

## 문제 / 배경
- FE-2(PR #55) 리뷰 이후 상태 불일치(`INVALID_STATE`) 이동을 공통 래퍼(`app/errorRedirect.js`)로 모았지만, 화면마다 예전 방식의 이동 코드(`redirectByState`, `screenByStatus`)가 그대로 남아 있었다.
- 래퍼와 화면이 동시에 이동을 시도하는 코드가 섞여 있어, 실제로 어떤 코드가 동작하는지, 어떤 코드가 죽은 코드인지 확인이 필요했다.

## 검토한 대안
- 화면에 남은 이동 코드를 그대로 둘지, 삭제할지 검토하기 위해 실행 순서를 먼저 확인했다: 래퍼가 먼저 이동시키면 다음 화면이 첫 `await` 전에 컨테이너를 교체해서 이전 화면의 `active()`가 `false`가 된다. 이 때문에 화면에 남아 있던 이동 코드는 실행되지 않는 죽은 코드임을 전 화면에서 확인했다.
- "지금 단계에서는 이 화면을 볼 수 없어요" 안내 분기를 죽은 코드와 함께 지울지, 남길지 검토했다. 래퍼가 이동하지 못하는 경우(화면 표에 없는 상태값, 이미 같은 화면이라 라우터가 이동을 건너뛴 경우)에는 사용자가 볼 수 있는 유일한 안내라 남기기로 했다.

## 선택한 방법과 이유
- 원칙을 "이동은 래퍼, 안내는 화면"으로 정리하고, `overviewPage.js` · `courtPage.js` · `comparisonPage.js`의 `redirectByState` 함수 · 호출부 · 쓰지 않는 `screenByStatus` import를 삭제했다. `aiPage.js` · `verdictPage.js`의 FE-2 관련 TODO도 함께 지웠다.
- 이동하지 못하는 경우의 안내 분기는 남기고, 다음 사람이 죽은 코드로 오해해 지우지 않도록 그 위에 이유를 주석으로 남겼다.
- (리뷰 범위 외 함께 정리) S-03의 상태 불일치 안내가 다른 화면과 다르게 "불러오지 못했어요 · 다시 시도"로 떠 있던 것을, 같은 안내 문구 + `사건 목록으로` 버튼으로 맞췄다 (S-03은 상단 바가 없는 화면이라 갈 곳을 제공해야 했다).
- `preview.html`은 래퍼를 거치지 않고 화면 쪽 `redirectByState`가 이동을 맡고 있던 상태였어서, 실제 앱과 같은 래퍼로 감싸 기존 사용법을 유지하도록 고쳤다.

## 고려한 제약 사항
- 이 변경으로 동작이 바뀌는 지점(`preview.html`에서 상태를 일부러 틀리게 열어 안내 문구를 확인하던 기존 점검 방식이 더 이상 통하지 않음, S-06 · S-07을 상태 안 맞게 열면 이제 맞는 화면으로 자동 이동함)을 PR에서 표로 남기고 리뷰어들에게 영향 여부 확인을 요청했다.
- D5(연동) 작업 파일과 각 화면의 `catch` 부분이 겹쳐, 머지 후 `develop`을 받고 연동을 시작해야 한다고 안내했다.

## 추후 재검토가 필요하면
- 앞으로 화면에 상태 불일치 이동 코드(`navigate(screenByStatus[...])`)를 다시 넣지 않고, 안내만 그리는 원칙을 유지한다.
