# FE-100 의사결정 기록

10/26 마이페이지 + 내 결과 critique(28/40) 반영. 결정: 내 결과는 신문 장면을 유지하고 마이페이지와의 연결만 부드럽게.

## 문제 / 배경
- 내 결과: 헤드라인이 "…의 판결, 다시 펼치다"라 정작 내 판결은 사진 아래 작은 글씨였다. 아래 광고 3칸 중 2칸은 칸 모양인데 누를 수 없었고, 성향 테스트를 이미 한 사람에게도 테스트 광고가 나왔다. 제호 귀의 "고민 중" 메모는 판결을 마친 지면과 맞지 않았다. 화면에 떠 있는 "마이페이지로"가 좁은 화면에서 그래프 · 푸터 글자를 가렸다. `<main>`이 없었다.
- 프로필카드: 모바일에서 열린 개수 표의 이름이 한 글자씩 세로로 쪼개졌고, 잠긴 그림까지 대표 이미지 130장이 모두 펼쳐졌다(운영 빌드에서도 같다 — 개발 분기는 컬렉션 화면만이다).
- 환경 설정: "곧 적용" 4개가 눌리고 저장도 됐지만 아무 변화가 없었다. 연출은 헤더(즉시)와 설정(저장하기)의 반영 시점이 달랐다.
- 닉네임: 목 모드는 서버 닉네임이 없어 헤더는 세션 닉네임, 마이페이지는 "익명의 판사"로 갈렸다.

## 검토한 대안
- 내 결과 톤: 커피 테마로 통일 vs 신문 장면 유지 → 사용자 결정으로 유지, 연결(귀 · 버튼)만 손봤다.
- 공용 함수 수정 vs 내 결과에서 덮어쓰기: `comparisonStage.js`(masthead · advertisements)는 6막과 함께 쓰고, 열린 PR(FE-97 · 98)이 같은 파일을 고쳐서, 내 결과 쪽에서 만든 뒤 글자 · 칸만 바꿨다.
- 돌아가기: 6막처럼 떠 있는 버튼 / 어두운 책상 바닥 위 버튼 / 광고 단의 세 번째 칸. 떠 있으면 좁은 화면에서 그래프 · 푸터를 가렸고, 바닥 위 남색 버튼은 묻혔으며 색을 바꾸면 6막 버튼과 일관성이 깨졌다 → 사용자 결정으로 6막의 "첫인상 엽서 모집" 자리(세 번째 광고 칸)를 "마이페이지로" 칸으로 바꿨다. 세 칸은 폭 · 테두리(3px 실선)를 같게 했다.
- 잠긴 대표 이미지: 숨기기 vs 한 줄로 접기 → 무엇을 깨면 무엇이 열리는지 보는 재미(레벨 · 꾸미기 동기)를 남기려 `details`로 접었다.
- 곧 적용 항목: 숨기기 vs 비활성 + 설명 → DESIGN.md 규칙("지금 할 수 없는 버튼은 숨기지 않고 비활성 + 설명")을 따랐다.
- 닉네임: 저장 뒤 "연동 전이라 반영되지 않아요" 안내 vs 세션 닉네임을 대신 쓰기 → 헤더와 같은 이름을 쓰는 쪽이 간단하고 실제 API에서는 서버 값이 먼저라 영향이 없다.

## 선택한 방법과 이유
- 헤드라인 = 내 판결(값 뒤에 조사 없이 "○○의 판결은 징역 15년"), 부제 = 첫인상.
- 광고 단은 6막과 같은 3칸(테스트 여부에 따라 "내 성향카드" / "판결 성향 테스트", "오늘의 지면"은 사건 목록, "마이페이지로"). 귀는 마이페이지(내가 체험한 사건)로, 메모는 "판결 확정".
- 연출은 즉시 적용, 곧 적용 항목 비활성, 바꿀 항목이 없으면 저장 줄 없음.
- `myNickname(data, session)`: 서버 → 세션 → 임시 문구.

## 고려한 제약 사항
- 6막 지면(`comparisonStage.js`, `courtSketch.css`)은 건드리지 않았다(열린 PR과 충돌 방지).
- 헤드리스 크롬으로만 확인했다. 사파리 · 실기기는 PR 체크리스트에 남긴다.
