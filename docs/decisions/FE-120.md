# FE-120 의사결정 기록

## 문제 / 배경
- 닉네임이 길면(한글 8자 · 영문 12자) 카드 책갈피(굵은 띠) 사이에서 잘리고, 마이페이지 · 카드 · 헤더에서 `...`로 말줄임이 됐다.
- 마이페이지 경험치 막대는 보기만 할 뿐, 레벨별 직업 · 필요 경험치 · 얻는 방법을 알 방법이 없었다.
- 카드 꾸미기 창에서 미리 보기 카드 위로 휠을 굴리면 창이 아니라 뒤 화면이 스크롤됐다.

## 검토한 대안
- 이름 길이
  - 대안 A: 입력 제한을 한글 6자 · 영문 9자로 줄인다. 확실하지만 이미 8자로 만든 닉네임과 충돌하고, BE 검증도 바꿔야 하며, 한글 · 영문을 따로 세는 규칙은 설명하기 어렵다.
  - 대안 B: 말줄임으로 자른다. 가장 단순하지만 "닉네임인데 다 보여야 한다"는 요구와 맞지 않는다.
  - 대안 C: 입력 제한은 그대로 두고, 넘칠 때만 글자 크기를 줄여 한 줄에 맞춘다.
- 경험치 페이지: 획득 로그까지 보여 주는 안(서버에 내역 조회 API가 없어 BE 작업이 필요)과, 표만 보여 주는 안.
- 카드 꾸미기 스크롤: 뒤 화면 스크롤만 잠그는 안과, 잠그면서 미리 보기 위의 휠을 고르기 칸으로 넘기는 안.

## 선택한 방법과 이유
- 이름: 대안 C. 글자 폭은 글자 종류마다 달라 CSS만으로는 맞출 수 없어, 칸 폭이 바뀌거나 글자가 바뀔 때 다시 재는 작은 도우미(`utils/fitText.js`)로 줄인다. 한글 8자가 책갈피 사이에서 카드 폭 200px 기준 약 14px, 모바일 약 12px까지 줄어든다.
- 경험치 페이지: 표만 보여 준다. 로그는 이번에 만들지 않는다. 값은 서버 L-1(`GET /level`)의 `jobs`(해금 레벨 · 해금 누적 XP)를 그대로 쓰고, 얻는 방법 표는 API 명세 11장 수급처 표를 옮긴 고정 문구다.
- 카드 꾸미기: 잠금 + 휠 넘기기. 잠금만 하면 미리 보기 위에서는 아무 일도 안 일어난다.

## 6막 읽기 지면 (같은 이슈, 피드백 반영)
- 우하단에 떠 있던 "메인으로" 알약을 없애고, 지면 맨 아래 광고 단의 오른쪽 칸을 "메인으로", 가운데 칸을 "공유하기"로 바꿨다. 메인 가는 길을 사건 목록으로 하는 안도 있었지만, 목록을 거듭 보게 되는 피로감 때문에 메인으로 정했다.
- 오른쪽 귀 "고민 중" 메모는 없애고 누르지 않는 사건 번호 칸으로 채웠다. 사건 분류 이름은 6막 데이터에 없어 번호와 "판결 확정"만 둔다.
- 독자 의견 엽서의 빈 손글씨 줄 자리에 "이 사건 독자들의 첫인상" 막대그래프를 넣었다. 통계 API가 없어 목 데이터(`preToFinal.crowd`, 목 전용)이고 "목데이터" 딱지를 붙였다. 값이 없으면 예전 손글씨 줄을 그대로 둔다.
- 광고 칸의 공유 · 메인으로는 읽는 상태가 된 뒤에만 눌린다(무대 중 지면 클릭이 "다음"이라 미리 달면 튀어 나간다).

## 고려한 제약 사항
- 닉네임 규칙(`utils/nickname.js`)은 임시 규칙이고 서버 규칙이 정해지면 바뀔 수 있어, 입력 제한은 건드리지 않았다.
- 시상대(커뮤니티 메인) 카드는 작아서 가장 긴 닉네임이 11px 하한보다 더 줄어든다.

## 추후 재검토가 필요하면
- 가장 긴 닉네임이 읽기 어려울 만큼 작아지면 입력 제한(대안 A)을 다시 검토한다.
- 획득 로그가 필요해지면 BE에 내역 조회 API를 먼저 만들고 이 페이지에 칸을 더한다.
- 독자 첫인상 통계는 서버가 구간별 집계를 내려줄 때(API 14 확장) 목 값을 실제 값으로 바꾼다.
- 일러스트 수집 XP는 서버가 아직 지급하지 않아 표에 "준비 중"으로 적었다. 지급이 시작되면 문구를 고친다.
