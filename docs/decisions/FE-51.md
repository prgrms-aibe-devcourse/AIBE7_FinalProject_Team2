# FE-51 의사결정 기록

> [FE-51](https://aibe7-team2-final.atlassian.net/browse/FE-51) · FE-73과 같은 브랜치에서 진행했다([FE-73](FE-73.md)).

## 문제 / 배경

- 판결 체험은 막(화면) 단위만 URL · 서버 상태로 복원된다. 막 안의 대사 위치(`stage.js`의 `index`)는 메모리 변수라 새로고침하면 그 막의 첫 대사로 돌아간다.

## 검토한 대안

- 서버에 대사 위치 저장: 새로고침 한 번을 위해 백엔드 API · 저장 구조가 필요하고, 위치는 일시적인 값이라 과하다. 제외했다.
- localStorage에 저장: 탭을 닫은 뒤 며칠 후에도 중간 대사로 열려 어색하다. 새로고침 · 뒤로가기 범위에는 탭 수명(sessionStorage)이면 충분하다.
- 막 번호 + 대사 번호를 화면별로 따로 키로 관리: 화면(`pages/*`)마다 코드를 넣어야 한다. 주소(`location.pathname`)가 사건 · 막마다 달라 그 자체가 키가 되므로 `renderStage` 안에서 한 번에 해결된다.

## 선택한 방법과 이유

- `renderStage`가 장면을 그릴 때마다 `{ path, index, length }`를 주소별로 `sessionStorage`에 남기고, 시작할 때 같은 주소 · 같은 장면 수면 그 장면에서 시작한다(`resumeIndex`). 주소별로 남겨서 막 B로 넘어가도 막 A의 위치가 남아 뒤로가기에서도 이어 본다(PR 리뷰 반영, 한 사건의 막 수만큼만 쌓인다).
- 우선순위는 막 점프(`nlnb-act-jump`) > 화면이 정한 재진입 장면(`start`) > 기다리는 지면(`parked`, 저장도 안 함) > 이어 보기다. 서버 상태나 점프와 충돌하지 않는다.
- 입력 카드 · 선택지 장면은 입력한 값 · 고른 답을 되살릴 수 없어 같은 막의 앞쪽 일반 장면으로 물러나 이어 본다. 증거 카드는 장면(`step.ev`)에서 만들어져 그대로 복원된다.
- 대본이 바뀌어 장면 수가 다르면 믿지 않고 처음부터 시작한다. "처음부터 다시"(목 전용)와 "1막부터 다시 보기"(`caseDetailPage`의 `playAgain`)는 저장값을 모두 지우고 들어간다. 다시 보기는 처음부터 보려고 누르는 버튼이라 마지막 장면에서 열리면 기능과 반대가 된다(PR 리뷰 반영).

## 고려한 제약 사항

- 저장값은 탭 수명이다. 탭을 닫으면 사라지고, 다른 탭과 공유하지 않는다.
- 오른쪽 귀 "이어서 하기"로 들어가는 막은 저장값이 있으면 그 장면에서 열린다(의도한 동작).

## 추후 재검토가 필요하면

- 다시 보기 말고도 끝낸 막이 마지막 장면에서 열리는 게 어색하다는 의견이 나오면 막을 끝낼 때 그 주소의 저장값을 지우는 방안(뒤로가기 이어 보기와 맞바꿈).
