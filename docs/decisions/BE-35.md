# BE-35 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #77 본문.

## 문제 / 배경
- 판결문 비식별화(`case-extractor`)가 Claude API 전용이라 Anthropic 키가 없으면 파이프라인 첫 단계(extract)를 실행할 수 없었다.

## 선택한 방법과 이유
- `--model`로 공급자를 고른다. Claude는 기존 SDK 경로(구조화 출력)를 그대로 쓰고, `openai:` · `gemini:`는 BE-30의 `llm.py` 경로로 보낸다.
- Claude 외 공급자는 응답 스키마를 강제할 수 없으므로 스키마를 프롬프트에 붙이고, 응답을 `validate_against_schema`로 검사해 틀리면 오류 내용을 알려 주며 최대 2번 다시 요청한다. 그래도 안 되면 멈춘다(조용히 통과시키지 않음).
- 비식별화 이후 검사(개인정보 잔존 · 실제 판결 누출 · 서비스 대상 판정)는 모델과 무관하게 동일하다. 모델 품질 차이는 이 검사가 걸러 낸다.
- 보고서에 요청 모델과 실제 응답 모델을 기록한다.

## 고려한 제약 사항
- 모델마다 품질이 달라 결과는 반드시 원문과 대조해야 한다(README 명시). 실제 검증에서 Gemini 쪽은 `reviewNotes`의 정확한 나이를 검사가 잡아 중단했다.
- 과부하 · 한도 재시도는 BE-36, 모델 대체 체인은 BE-45에서 다룬다.
