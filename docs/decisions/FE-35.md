# FE-35 의사결정 기록

## 문제 / 배경
- 화면 코드가 이미지 저장소(`NaeLawNamBul_Images`) PNG를 직접 읽는 곳을 `public` webp로 옮기는 이슈다. 대부분(`stage.js` · `landingPage.js` · `caseListPage.js` · `verdictPage.js` · `bookmarkCharacter.js`)은 COMMON-48에서 처리했고, 사건 1 대본(`content/case-1/script.json`)의 신문 사진 · 증거 사진 3곳이 남아 있었다.
- 3곳은 헤드라인 PNG(약 976KB) 두 곳과 `sub-1` PNG(약 770KB) 한 곳으로, 같은 이미지의 webp(`case-1-reenact.webp` 70KB · `case-1-sub.webp` 42KB)가 `public/images/cases/`에 이미 있었다.

## 검토한 대안
- 대안 A: PNG를 계속 이미지 저장소에서 읽는다.
  - 장점: 변경 없음.
  - 단점: 첫 화면에서 PNG 약 1.7MB를 외부에서 받는다. 이미지 저장소 폴더 구조가 또 바뀌면 신문 · 증거 사진이 깨진다(COMMON-46 때 장면 컷이 깨진 것과 같은 문제).
- 대안 B: `script.json`의 3곳을 이미 있는 `public` webp 경로로 바꾼다.
  - 장점: 용량이 약 1.7MB에서 약 112KB로 줄고(약 15분의 1), 이미지 저장소 구조와 화면이 분리된다. 변환 작업이 없다.
  - 단점: 이미지를 바꿀 때 webp를 다시 만들어 `public`에 넣어야 한다.

## 선택한 방법과 이유
- 대안 B. 같은 이미지의 webp가 이미 있고 투명 배경(RGBA)이라 신문 지면의 곱하기 합성이 PNG와 똑같이 동작한다. 화면 코드(`stage.js` · `newspaperFront.js`)는 사진 출처만 바뀔 뿐 그대로다.
- 헤드라인은 `case-1-reenact.webp`, `sub-1`은 `case-1-sub.webp`를 쓴다.

## 고려한 제약 사항
- 이미지가 PNG(1672 × 941)에서 webp(1200 × 675)로 줄지만 비율(16:9)이 같고, 신문 속 사진과 확대 사진 모두 표시 크기가 1200px 이하라 화질 차이는 눈에 띄지 않는다.

## 추후 재검토가 필요하면
- 사건이 늘어 사건별 재연 컷을 `public/images/cases/`에 둘 때(관리자 페이지에서 올리는 경우 포함) 같은 규칙(`case-{id}-{reenact|sub|detail}.webp`)을 쓴다.
