# FE-96 의사결정 기록 (FE-101 함께)

> 근거: FE-95(PR #279) · [FE-95 결정 기록](FE-95.md) · PR #279 리뷰 2번(FE-101) · FE-99 신문 모서리 넘김(`landing.css` `news-curl`) · DESIGN.md 모션 P7 표 · "현재 코드와 차이" 21번

## 문제 / 배경
- 판결 체험의 말린 모서리(`verdict.css` `.folder-curl`)와 성향 결과의 종이 귀(`personality.css` `.turn-fold`)는 같은 물건인데 코드가 따로였다. 색(회색빛 · 크림), 크기(64 · 52px), 호버(계속 넘실 · 14px 커짐), 눌림(.96 · 없음)이 달랐다.
- 성향 쪽 앞 장 귀(`turn-fold-idle-prev`)는 `scaleX(-1)` 뒤집기를 키프레임 7구간마다 translate 샌드위치로 다시 적고 있었다. 뒤집는 줄이 바뀌면 키프레임이 조용히 어긋난다(FE-101).
- 두 귀 모두 "일렁임"이 삼각형 그림을 통째로 키우고 돌리는 방식이라 종이가 접힌 것처럼 보이지 않았다(김해송: "너무 가짜").
- 진행 책갈피도 두 화면이 각자 정의해 모양이 달랐다(폭 22 · 28px, 윗모서리 각짐 · 둥긂).
- 바꾸기 전 화면을 찍어 보니 성향 결과 귀가 가장 크게 일렁일 때(1.3배) 화살표 "→" · "←"를 덮고 있었다.

## 검토한 대안
- **움직임**
  - A 일렁임 유지(삼각형 그림을 `scale` · `rotate`): 처음에 이것으로 합쳤지만 사용자가 "가짜"라고 했다. 접힌 선은 그대로인 채 그림만 커지고 기울어, 잘려 나간 자리까지 함께 커진다.
  - B **들썩임**(FE-99 신문 모서리 넘김과 같은 방식): 접힌 변 길이 하나만 움직이고, 잘려 나간 자리와 뒤집힌 뒷면이 같은 점을 쓴다. 종이가 실제로 더 접혔다 펴진다.
- **앞 장 귀 뒤집기(FE-101)**
  - 지금 그대로(translate 샌드위치): 동작은 맞지만 중복이 크고 깨지기 쉽다.
  - 요소에 `scale: -1 1`을 주고 `transform-origin`만 옮김(이슈 제안): 뒤집기와 움직임이 같은 속성을 써서 키프레임마다 부호를 다시 적어야 하고, 축이 `0 100%`면 귀가 왼쪽 바깥으로 넘어갈 위험이 있다.
  - **그림(`::before` · `::after`)만 뒤집기**: 요소(누르는 자리)는 그대로 두고 그림만 왼쪽 아래 꼭짓점에 붙여 `scale: -1 1`. 키프레임은 하나로 끝난다.
- **호버 · 눌림을 움직임과 어떻게 겹칠지**: 호버에서 움직임을 끄기(끄는 순간 모양이 튐) / 일시정지(정점에서 멈추면 지나치게 큼) / 서로 다른 값으로 겹치기.
- **크기**: 역할별 유지(글자 없는 귀 64 · 글자 붙은 귀 52) / 둘 다 56 / 둘 다 64.
- **색**: 성향(크림 → 크라프트) / 판결(회색빛 + 접힌 선) / 둘을 섞음.
- **책갈피**: 성향 모양으로 합침 / 판결 모양으로 합침 / 이번엔 귀만.

## 선택한 방법과 이유
- 공용 부품 `components/folderParts.js` · `.css`를 만들었다. 종이 귀 `paperFold({ flipped })`와 진행 책갈피 `folderBookmark()`. 귀는 그림만 만들고, 누르는 버튼은 쓰는 곳이 만든다(판결 체험은 글자 없는 버튼, 성향은 글자 + 귀 버튼이라 손잡이 모양이 다르다).
- 움직임은 **B 들썩임**(김해송 결정). 접힌 변 길이 d = `--fold-size` × `--fold-lift`(들썩임) × `--fold-hand`(호버 · 눌림). 접힌 변 곡선 · 뒷면 그라디언트 · 순서(휙 들림 → 망설임 → 한 번 더 → 떨어져 살짝 튐 → 쉼)는 FE-99 신문을 그대로 따르고, 귀 크기에 맞춰 최대 1.4배 · 3.2초 주기로 줄였다. 뒷면 색은 김해송이 고른 따뜻한 크림(그늘을 크라프트로)이다.
  - 신문 쪽 `@property --d`와 이름이 겹치지 않게 `--fold-lift` · `--fold-hand`를 따로 등록했다. FE-99가 아직 develop에 없어 코드를 공유하지 않는다.
- 뒤집기는 그림만 뒤집는 방식(FE-101). 바꾸기 전 일렁임 기준으로는 크롬에서 앞 장 귀 바깥 상자가 쉼 · 정점 모두 같은 자리였다. 들썩임으로 바꾼 뒤에는 키프레임이 방향을 몰라도 되므로(접힌 길이만 움직임) 회전 방향 변수도 그림자 방향에만 남았다.
- 호버 · 포커스는 더 접히고(`--fold-hand` 1.1), 누르면 꾹 눌려 납작해진다(.85). 등록한 숫자 속성이라 .2s 전환이 걸리고, 들썩임과 곱해져 서로 끊지 않는다. 판결 체험의 "계속 넘실"은 뺐다. 자주 지나가는 손잡이라 계속 움직이면 산만하다.
- 성향 결과 쪽 width · height로 키우던 호버는 레이아웃을 다시 계산하고 글자를 밀었다. 이제 요소 크기(누르는 자리)는 그대로이고 그림만 넘쳐 그린다.
- 크기 · 색 · 책갈피는 김해송 결정: 크기는 역할별 유지(`--fold-size`), 책갈피는 성향 모양(폭 28 · 얼굴 24 · 둥근 머리)으로 합치고 길이만 화면별(`--bookmark-length` · `--bookmark-hang`).
- 성향 결과 귀와 글자 사이를 4px → 32px로 넓혔다. 들썩임 정점(1.4배)과 호버 중 정점(1.54배)에도 화살표를 덮지 않는다(호버 배수 1.15에서는 정점에 화살표 끝이 닿아 1.1로 낮췄다).

## 고려한 제약 사항
- 등록한 사용자 속성(`@property`) 애니메이션은 합성만으로 끝나지 않고 매 프레임 귀 그림(작은 가상 요소 2개)을 다시 그린다. 이전 `scale` · `rotate`보다 비싸지만 그리는 면적이 작고(최대 128px 상자), FE-99 신문(260px)과 같은 방식이라 받아들였다.
- 움직임 줄이기에서는 들썩임 · 전환이 없다(쉬는 모양 그대로). 연출 끄기(`data-motion="off"`)는 전역 규칙이 길이를 0으로 만들어 쉬는 모양으로 멈춘다.
- 사용자는 사파리로 화면을 본다. 헤드리스로는 크롬만 확인했다. `@property` 애니메이션 · 전환은 사파리 16.4(2023년 3월)부터 된다. 그보다 낮은 브라우저는 값이 뚝뚝 바뀌므로 `main.js`가 `CSS.registerProperty` 지원을 확인해 `.has-css-property`를 달고, 그 표시가 있을 때만 들썩임 · 호버 전환을 켠다(FE-110, 모르는 브라우저는 쉬는 모양 그대로). 지원하는 브라우저에서도 들썩임과 앞 장 귀 모양은 사파리에서 직접 확인이 필요하다(FE-101 완료 조건).

## 추후 재검토가 필요하면
- FE-99가 develop에 들어오면 신문 모서리(`news-curl`)와 종이 귀가 같은 곡선 · 그라디언트를 각자 갖게 된다. 모양 계산을 공용으로 뺄지 본다.
- 메인 집무실의 러그 귀퉁이(`landing.css` `.rug-flap`)도 접힌 귀 모양이지만 크기 기준(`--fold`)과 연출이 달라 이번에 합치지 않았다.
