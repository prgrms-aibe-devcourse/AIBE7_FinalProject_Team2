# BE-36 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #81 본문.

## 문제 / 배경
- Gemini 과부하(503)와 무료 등급 한도(429)가 잦아 기존 재시도(3회)로는 파이프라인이 자주 멈췄다.

## 선택한 방법과 이유
- 원인별로 다르게 대응한다.
  - 과부하(503 · 529): 5 · 10 · 20 · 40초 지수 백오프 + 지터.
  - 분당 한도(429): `Retry-After` 헤더 또는 Gemini 본문 `retryDelay`(+1초)를 따른다. 안내가 없으면 1분 대기, 안내가 `maxWait`보다 길면 기다리지 않고 종료한다.
  - 일 한도 · 크레딧 소진: 재시도해도 소용없으므로 즉시 실패 처리하고 해당 모델의 남은 회차를 건너뛴다.
- 실패 원인을 `LLMOverloadedError` · `LLMRateLimitError` · `LLMQuotaExhaustedError`로 구분해 기록(`callErrorKind`)한다.
- 기본 5회 · 최대 대기 120초(`retry` 설정, CLI 옵션으로 조정).

## 고려한 제약 사항
- 여러 API 키로 한도를 우회하는 방식은 권장하지 않기로 했다(사유는 README "무료 등급 한도 대응").
- 모델 교차 호출(BE-44)과 대체 체인(BE-45)은 범위 밖으로 나눴다.
