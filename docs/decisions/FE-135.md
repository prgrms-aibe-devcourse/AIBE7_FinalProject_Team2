# FE-135 의사결정 기록

운영 빌드에서 관리자 목업 API 묶음 제외 (빌드 시점 분기로 변경). 담당 D(정민석). BE-134 · FE-133 · FE-134와 한 PR.

## 문제 / 배경

- 2026-10-29 운영 점검: 운영 사이트에 `assets/adminMockApi-*.js`(약 34KB)가 배포되어 누구나 받을 수 있었다. 민감 정보는 없지만 관리자 화면 구조 · 목 데이터가 드러나고 쓰지 않는 파일이 배포된다.
- 확인해 보니 관리자만이 아니었다. 배포 빌드(`VITE_API_MODE=real`)에 사용자 화면 목까지 **목 파일 23개(188KB)**가 들어 있었다.
- 원인: 목 · 실제를 고르는 조건이 `API_MODE`(실행 시점 값 — 개발 서버에서는 localStorage 스위치가 섞인다)라 번들러가 접지 못하고, 동적 import 양쪽을 모두 청크로 만든다.

## 검토한 대안

- 대안 A — `config.js`에 빌드 시점 상수(`MOCK_AVAILABLE`)를 두고 각 곳에서 import: 해 보니 **다른 모듈의 상수는 접히지 않아** 목 파일이 그대로 남았다(Vite 8 · Rolldown, 빌드 결과로 확인).
- 대안 B — **목을 고르는 자리에서 `import.meta.env?.VITE_API_MODE` · `DEV`를 직접 읽는다(선택)**: Vite가 그 자리를 값으로 바꿔 넣어 조건이 빌드 시점에 `true`로 접히고, 목 분기와 동적 import가 빠진다. 세 곳이다 — `api/index.js loadApi` · `pages/admin/adminApi.js loadAdminApi` · `mocks/mockStageButtons.js`(무대의 목 전용 버튼이 목 저장소를 불러온다).
- `.env.production` · 새 변수(`VITE_USE_MOCK`)는 만들지 않았다. 배포는 이미 `VITE_API_MODE=real`로 빌드한다(Dockerfile · frontend-ci). 개발 서버(`DEV`)는 지금처럼 내비 스위치로 목 · 실제를 오간다.

## 선택한 방법과 이유

- 조건: `(import.meta.env?.VITE_API_MODE === 'real' && !import.meta.env?.DEV) || API_MODE === 'real'` — 배포 빌드는 앞이 `true`, 개발 서버 · 목 빌드는 앞이 `false`라 지금처럼 `API_MODE`를 본다. node 테스트에는 `import.meta.env`가 없어 `?.`로 읽는다.
- **빌드가 스스로 막는다(PR #354 리뷰)**: `vite.config.js`의 `no-mocks-in-real-build` 플러그인이 배포 빌드에서 청크마다 담긴 모듈 경로(`moduleIds`)를 보고 목 모듈(`src/mocks/` · 이름에 Mock이 든 파일)이 있으면 빌드를 멈춘다. 파일 이름만 보면 목을 정적으로 import 해 이름에 mock이 없는 청크에 섞인 경우를 놓치기 때문이다. 예외는 `mocks/mockStageButtons.js`(실제 화면이 정적으로 쓰는 껍데기, 안쪽 목 import는 접힌다) 하나만 명시했다. Dockerfile도 `VITE_API_MODE=real`로 `npm run build`를 하므로 같은 검사를 받는다.
- CI(`frontend-ci.yml`)에도 "배포 빌드에 목 파일이 없는지" 파일 이름 검사를 더했다(한 번 더). 허용 모듈 `mockStageButtons`가 따로 청크로 나뉘어도 실패하지 않게 그 이름은 뺀다(PR #354 리뷰).
- 플러그인은 `.env`를 Vite가 정한 `envDir`에서 읽는다(`configResolved`). `frontend/` 밖에서 빌드해도(`--root` 등) 같은 판단을 한다(PR #354 리뷰).

## 확인

- `VITE_API_MODE=real npm run build`: 목 파일 23개(188KB) → 0개, `assets` 3.0MB → 2.8MB
- 목 빌드(`VITE_API_MODE` 없음): 목 파일 23개 그대로(개발 · 목 모드 동작 유지)
- 회귀 확인: 관리자 분기를 `API_MODE === 'real'`로 되돌려 배포 빌드하면 `no-mocks-in-real-build`가 `adminMockApi.js` · `adminOpsMockApi.js` · `adminMockBase.js`를 짚고 빌드가 실패한다
- 프런트 테스트 전체 통과

## 추후 재검토가 필요하면

- 실제 코드가 목 데이터 파일을 정적으로 import 하게 되면(예: 화면이 목 표를 기본값으로 씀) CI 검사에 걸린다. 그때는 그 데이터를 목 폴더 밖으로 옮긴다.
