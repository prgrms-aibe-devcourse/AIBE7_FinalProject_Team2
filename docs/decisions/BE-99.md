# BE-99 의사결정 기록

> 담당 정민석 · 관련: FE-70(PR #231), BE-64

## 문제 / 배경
- FE-70에서 P-5 `judgmentPersonality`의 정의를 **첫 회차 체험 전체 평균 → 최근 첫 회차 체험 3건의 평균**으로 바꾸기로 했다(API 명세 v0.44, 성향 산식 v0.8 4장). 오래된 체험이 계속 같은 무게를 가져 "지금" 경향이 묻히는 것을 막기 위해서다.
- 프론트(목 모드)는 이미 새 정의로 동작하고, 서버는 아직 전체 평균을 내려줘 실제 모드에서 화면 문구("최근 체험 n건의 평균이에요")와 어긋난다.

## 검토한 대안
- 대안 A: 리포지토리에 최근 3건만 가져오는 쿼리(`LIMIT 3`)를 따로 둔다. 흐름(`history`)은 전체가 필요해 쿼리가 두 번 나간다.
- **대안 B(선택): 지금 쿼리(`findFirstAttemptsByAnonymousUser`) 결과에서 뒤쪽 3건만 잘라 평균한다.** 흐름과 같은 목록 · 같은 순서를 쓰므로 둘이 어긋날 일이 없고 쿼리도 한 번이다.
- (#238 리뷰) 대안 C: 정렬을 `e.completedAt` 단독으로 바꾼다. 기여 저장 순서(`p.createdAt`)와 완료 순서가 어긋나는 문제 자체는 고치지만, PostgreSQL 오름차순 정렬에서 `NULL`이 맨 뒤로 가 완료 시각이 없는 기여(완료되지 않았거나 과거 데이터로 `completedAt` 기록이 없는 경우)가 "가장 최근"으로 잘못 뽑힌다. 기각하고 `COALESCE(e.completedAt, p.createdAt)`로 대체.

## 선택한 방법과 이유
- `MyPageService.build()`에서 `contributions.subList(max(0, n − 3), n)`만 `PersonalityScoring.overall()`에 넘긴다. 순서는 쿼리의 `ORDER BY COALESCE(e.completedAt, p.createdAt), p.id`(완료 순서)를 쓴다.
  - (#238 리뷰) 처음에는 기존 정렬(`p.createdAt`, 기여 저장 시각)을 그대로 썼다. 그런데 비교 공개(API 13)는 `completedAt`을 남기는 조건부 갱신 뒤에 기여를 저장한다. 그래서 두 요청이 동시에 처리되면 저장 순서가 완료 순서와 달라지고, 최근 3건 경계의 체험이 잘못 골라질 수 있다. 이 때문에 완료 시각 기준으로 바꿨다. 흐름(`history`)도 같은 목록이라 완료 순서로 그려진다.
  - `e.completedAt`만으로 정렬하면 PostgreSQL 오름차순에서 `null`이 맨 뒤로 가 "가장 최근"으로 잡힌다. 그래서 완료 시각이 없는 기여는 `HistoryItem.of`와 같이 기여 저장 시각으로 대신한다.
- `experienceCount`는 평균에 쓴 체험 수(최대 3)다. 축 자료가 모두 빈 체험도 센다(v0.22 규칙 그대로).
- 산식(`PersonalityScoring`) · 응답 형식 · `null` 규칙은 바꾸지 않는다. 그래서 최근 3건이 네 축 모두 자료가 없으면, 더 오래된 체험에 자료가 있어도 `judgmentPersonality`는 `null`이다. 프론트 목(`personalityMockApi.js` `judgmentOf`)도 같은 결과를 낸다.

## 고려한 제약 사항
- 사용자당 첫 회차 체험 수는 공개 사건 수를 넘지 않아 전체를 읽고 자르는 비용은 작다.
- 프론트 목은 축 평균 ≥ 0.5로 글자를 정하고 서버는 Σ (down − up) / (down + up)의 부호(정확한 분수)로 정한다. 수학적으로 같은 기준이라 0.5 바로 근처의 실수 오차 말고는 결과가 같다.
- (#238 리뷰) 기여 저장 순서 ≠ 완료 순서는 같은 사용자가 두 개 이상의 비교 공개 요청을 동시에 보낼 때만 생긴다(흔치 않음). 다만 발생하면 최근 3건 경계의 체험이 조용히 잘못 골라지고 겉으로는 드러나지 않아, 발생 빈도가 낮아도 정렬 기준 자체를 고쳤다. `PersonalityApiTest#myPage_recentThreeByCompletedAt_notContributionOrder`로 기여 저장 순서와 완료 순서가 다른 경우를 재현해 회귀를 막는다.
