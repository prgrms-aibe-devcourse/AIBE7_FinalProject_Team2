# FE-59 의사결정 기록

## 문제 / 배경
- 판결 체험은 FE-48에서 8막 → 6막으로 바뀌었지만, 대본(`content/case-1/script.json`)의 막 키와 코드 · 주석의 막 번호는 옛 8막(1 ~ 8)이었다. `ACT_GROUPS`가 두 체계를 이어 주고 있어 `order: ['7']`이 5막이고 "8막 신문"이 6막인 식으로 읽을 때마다 바꿔 셈해야 했다.
- 옛 4막(판결 전 정리) 대본은 어디서도 재생하지 않는데 남아 있었다(정리 화면은 FE-58에서 없앰).
- BE-82에서 화면 주소 · ID(FE-58)와 나눠 후속으로 하기로 했다.

## 검토한 대안
- 1막(첫인상)의 기사와 엽서를 어떻게 둘지. 대본 엔진(`stage.js`)은 막 경계에서 건너뛰기를 멈추고, 모습 · 이름표 · 지면 초점을 새로 시작한다.
  - 대안 A: 한 막 안의 두 부분으로 둔다. 키를 `1a`(기사) · `1b`(엽서)로 하고 `ACT_GROUPS`의 첫인상이 둘을 묶는다. 경계 동작은 지금과 같다.
  - 대안 B: 키 `1` 하나로 합친다. 가장 단순하지만, 기사에서 건너뛰기를 누르면 엽서 입력판까지 한 번에 가고 엽서 시작 때 초점이 다시 잡히지 않는다(`stage.test.js`의 건너뛰기 경계 테스트도 바뀐다).
- 키 이름: 숫자(1 ~ 6) / 화면 이름(`trial` · `verdict` 등). 화면의 막 칩이 숫자로 보이고 이슈가 "6막 체계"라 숫자로 했다.

## 선택한 방법과 이유
- **대안 A**(사용자 결정). 키는 `1a` · `1b` · `2` ~ `6`, 옛 4막 대본은 지웠다.
- 키가 숫자가 아니게 되어, 막 칩 진행 표시(`done`)의 숫자 비교를 `ACT_GROUPS` 순서 비교로 바꿨다. 막 이동(`onJump`)도 숫자로 바꾸지 않고 대본 키를 그대로 넘긴다. 목 막 이동 표(`ACT_SCREENS`) · 막별 목 상태(`ACT_STATUS`)도 대본 키로 둔다.
- FE-60(#226)이 같은 대본의 장면마다 `source` · `slots`를 붙여 먼저 머지됐다. 막 키만 바꾸는 이 작업과 방향이 달라서, #226 머지 뒤 develop 대본에 같은 키 변환을 다시 적용했다(옛 4막은 `source`째 삭제). `docs/script-fewshot-mock.md`의 단락 머리글도 새 키로 바꿨다.
- 장면이 같은지는 develop의 대본과 새 대본을 막마다 `flatten`해 비교했다(`source` · `slots` 포함). 6개 막 모두 장면 수 · 내용 · 막 경계가 같다(장면의 `actId`만 다름).
- `ACT_GROUPS`와 대본 키가 어긋나지 않게 테스트를 하나 더 두었다(`stage.test.js`).
- 주석 · 문서의 막 번호는 옛 8막 번호만 6막으로 바꿨다(1 · 2막 → 1막, 옛 2막 = 사전 판단은 "1막 엽서", 3막 → 2막, 5 ~ 8막 → 3 ~ 6막). FE-48 이후 이미 6막 번호로 적힌 줄(예: 재판 막의 "2막 시작", "6막 세 판결 비교")은 그대로 두었다.

## 고려한 제약 사항
- 화면에 보이는 막 이름 · 번호, 서버 진행 상태, 주소는 바뀌지 않는다(내부 키만 바뀜).
- 대본 JSON은 프론트만 읽는다(백엔드 `case_paper`는 `paper` 필드만 옮겨 갔다, BE-92).
- 지난 결정 기록(`docs/decisions/*.md`) · 작성 이력 행의 막 번호는 당시 기록이라 고치지 않는다.

## 추후 재검토가 필요하면
- 대본을 DB · 생성 파이프라인(COMMON-41 · BE-92)으로 옮길 때 같은 키(`1a` · `1b` · `2` ~ `6`)를 쓰도록 맞춘다.
