# FE-64 의사결정 기록

## 문제 / 배경
- S-20 사건 디테일(기사 지면)과 1막 무대의 증거조사는 그동안 사건 1에 한해 대본(`content/case-1/script.json`)의
  고정 이미지 경로(`paper.photo` · `paper.extraPhotos` · `evidencePhotos`)만 썼다(BE-78 2차 검토, FE-63).
- BE-102가 공개 신문 지면 API(`GET /cases/{caseId}/paper`, API 17)를 신설해 서버 사진(대표 · 발단 · 결론)을
  내려주므로, 프론트가 이 API를 연동해 대본 경로를 서버 사진으로 바꿔야 한다(BE-78 "FE-64에서 할 일").

## 검토한 대안

### 1. API 17을 못 받았을 때(지면 미생성 · 네트워크 오류) 어떻게 보일까
- 대안 A — 사건 디테일(API 16) 자체를 실패로 처리하고 오류 화면을 보인다.
- 대안 B(선택) — `getCasePaper`는 실패해도 `.catch(() => null)`로 삼켜 `casePaper`를 `null`로 두고,
  `paperFromCase`가 예전처럼 API 16 데이터 + 대본 지면(fallback)으로 채운다. API 17은 BE-102가 "확장" API로
  표시했고(API 16도 같은 표시), 지면을 아직 안 만든 사건(`PAPER_NOT_FOUND`)도 많을 수 있어 화면 전체를 막을
  이유가 없다고 판단했다.

### 2. `casePaper`를 받았지만 `extraPhotos.origin` · `.conclusion` 중 한쪽만 있을 때 나머지 자리를 대본 사진으로 채울까
- 대안 A — 받은 쪽만 서버 사진으로, 못 받은 쪽은 대본의 고정 이미지로 채운다(자리가 항상 사진으로 차 있다).
- 대안 B(선택) — `casePaper`를 받았으면 그 안의 `extraPhotos`만 쓰고, 없는 자리는 (대본이 아니라) 공용 컷으로
  채운다. API 17 명세가 "공용 컷으로 바꾸는 처리는 프론트가 한다(FE-63)"고 이미 정해 뒀고, 서버 사진과 대본
  사진을 자리마다 섞으면 어느 쪽이 실제 사건 사진인지 알 수 없어진다. `casePaper` 자체를 못 받았을 때만
  (대안 1) 대본으로 전체를 채운다 — "부분적으로 받음"과 "전혀 못 받음"을 다르게 다룬다.

### 3. 증거조사(`evidenceBoard`) 사진을 어디서 연결할까
- 대안 A — `script.evidencePhotos`(대본 고정값)를 그대로 두고 손대지 않는다.
- 대안 B(선택) — `extraPhotos.conclusion` → 검사 측, `extraPhotos.origin` → 변호인 측으로 연결하는
  `evidencePhotosFromPaper`를 만들어 무대에 넘긴다(BE-102 Jira 댓글 확인: "검사 = 결론, 변호인 = 발단").
  API 17 명세에도 "증거조사 `evidencePhotos`는 `extraPhotos.origin` · `.conclusion`을 그대로 연결해 쓴다 —
  같은 사진을 두 번 받지 않는다"고 돼 있어, 기사 지면 작은 사진과 같은 서버 사진을 재사용하는 쪽이 맞다.

## 선택한 방법과 이유
- `realApi.js` · `caseListMockApi.js`에 `getCasePaper(caseId)`(API 17) 추가. 목은 대본이 있는 사건 1만
  대본 값을 API 17 모양(`extraPhotos`가 배열이 아니라 `{ origin, conclusion }` 고정 자리)으로 바꿔 돌려주고,
  나머지 사건은 실제 서버와 같은 `PAPER_NOT_FOUND`를 던진다.
- `utils/newspaper.js`에 `extraPhotosFromApi`(API 17 `extraPhotos` → `extraPhotosOf`가 쓰는 배열 모양으로
  변환) · `evidencePhotosFromPaper`(증거조사 두 칸 매핑) 추가.
- `newspaperFront.js`의 `paperFromCase(data, casePaper, fallback)`에 `casePaper` 인자를 추가. `casePaper`가
  있으면 `headline · deck · article · photo · caption · desk · extraPhotos`를 그 값 우선으로, 없으면 예전
  그대로(API 16 데이터 + 대본 fallback)로 채운다.
- `overviewPage.js`의 `caseStage`에 `evidencePhotos` 인자를 추가해 무대에 넘길 `script`에 덮어쓴다(값이 없으면
  대본의 `script.evidencePhotos`를 그대로 쓴다 — 하위 호환).
- `caseDetailPage.js`(S-20)와 `overviewPage.js`(S-04, 대본 있는 사건 한정)의 로딩 지점에서 `getCaseDetail`과
  `getCasePaper`를 함께 불러(`Promise.all`, API 17은 실패해도 삼킨다) 위 함수들에 넘긴다.

## 고려한 제약 사항
- 마이페이지 컬렉션(`utils/myPageView.js`의 `collectionOf`)은 대본의 정적 `paper` · `evidencePhotos`를
  그대로 쓰며, 이번 범위에 넣지 않았다(BE-102 확인: "마이페이지 일괄 조회는 범위 밖, 완료한 사건마다 API 17을
  사건별로 부르는 방식은 이후 별도 이슈").
- API 명세(v0.53)의 `photo` · `imageUrl` 필드명, `extraPhotos` 고정 자리 형태는 BE-102 문서에서 이미 확정된
  대로 그대로 썼다(재협의 없음).
