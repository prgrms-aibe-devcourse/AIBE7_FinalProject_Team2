# FE-123 의사결정 기록

## 문제 / 배경
- FE-119에서 사건 목록(S-02)의 면이 아홉 개(1면 · 범죄 유형 다섯 · 색인 · 성향 테스트 · 오피니언)가 되었는데, 이 아홉 개를 하나의 `selected` 문자열로 나타내고 면 종류는 `special` 플래그 · `CRIME_TABS` · `isCrimeFace` · `apiTypeOf` · `faceName`으로 그때그때 가려냈다.
- 그래서 "면마다 달라야 하는 것"(API 호출 유형, 탭 건수, 0건 숨김, 포스트잇 문구, 세로 여백 채움, 본문 모양, 귀 · 화살표 이름)이 `draw()`의 if/else 체인과 `renderTabs` · `visibleFaces` 등 여러 곳에 흩어졌다. PR #314 리뷰에서 같은 원인의 문제가 나왔다(성향 테스트 · 오피니언 면 포스트잇이 "눌러 보세요"를 말함, 세로 여백 채움이 의도인지 코드로 알 수 없음). 배경은 [FE-119 의사결정 기록](FE-119.md)에 있다.
- 색인 · 성향 테스트 · 오피니언을 전용 내용으로 채우는 후속 작업 전에, 면을 더하거나 바꾸는 자리를 한 곳으로 모은다. 동작은 바꾸지 않는다.

## 검토한 대안
- 대안 A: 면 정의에 `render(ctx)`까지 넣어 `faces.js` 한 파일에 둔다(이슈 제안 그대로). 면 하나가 정말 한 객체가 되지만, `render`가 DOM · 화면 안 함수(`pickable` · `fillers` · `navigate`)를 써야 해서 면 정의 파일이 화면에 묶이고 node 테스트에서 불러올 수 없다(화면 파일은 JSON · 다른 화면 모듈을 가져온다).
- 대안 B: 면 정의는 DOM 없는 정책만 갖고, 본문은 `view` 이름으로 고른다. 화면 쪽 `FACE_VIEWS` 표(`cases` · `index` · `test` · `opinion`)가 이름을 그리는 함수에 잇는다. 면 하나를 더할 때 두 곳(정의 + 새 모양이면 `FACE_VIEWS`)을 보지만, 정책 부분은 모두 단위 테스트할 수 있다.
- 대안 C: 면 종류별 클래스(1면 · 유형 면 · 특별 면)로 나눈다. 아홉 개 면에 비해 과하고 이 코드베이스의 함수 · 객체 스타일과 맞지 않는다.
- 0건 숨김: `visibleFaces(faces, byCrimeType, selected)`에 `hideWhenEmpty`만 더하는 방법과, 면 정의의 `count(summary)`를 그대로 써서 `visibleFaces(faces, summary, selected)`로 바꾸는 방법을 비교했다. 뒤쪽은 "숨김 기준 건수"와 "탭에 보이는 건수"가 같은 함수라 어긋날 수 없다.

## 선택한 방법과 이유
- **대안 B**. `pages/caseList/faces.js`의 `FACES`가 면마다 `key · label · name · view · apiType · front · count · hideWhenEmpty · tip · fill`을 갖는다. 화면은 `faceOf(selected)`로 정의를 찾아 따르며 면 이름으로 분기하지 않는다. `draw()`는 `FACE_VIEWS[face.view](face, ordered)` 한 줄로 본문을 받는다.
  - 이슈 제안의 `render(ctx)`를 `view` 이름 + `FACE_VIEWS`로 바꾼 이유: 정책(무엇을 보일지)과 그리기(어떻게 그릴지)를 나눠 정책을 DOM 없이 시험하기 위해서다. 같은 모양의 면(1면 · 유형 면 다섯)은 `cases` 하나를 함께 쓴다.
- 기본값 + `crimeFace` 도우미: 면마다 모든 속성을 적지 않고 기본값(숨기지 않음 · 건수 없음 · 전체 건수 포스트잇 · 여백 채움)에서 다른 것만 적는다. 범죄 유형 다섯 면은 `crimeFace(key, label)` 한 줄씩이다.
- `visibleFaces`는 면 정의의 `count(summary)`를 그대로 쓰도록 바꿨다(위 비교). `utils/newspaperFaces.js`에 남겨 둔 것은 이 함수가 면 정의의 모양(`key · hideWhenEmpty · count`)만 알면 되는 일반 계산이고, FE-118 · FE-119의 다른 면 계산 함수들과 같은 자리에 있기 때문이다.
- `fill: false`(세로 여백 채움 끄기)는 지금 쓰는 면이 없지만, 후속에서 전용 내용으로 높이를 채우는 면이 끌 수 있게 경로를 열어 두었다(여백 칸을 만들지 않고 이전 면의 `ResizeObserver`만 끊는다). 오피니언 면에 잠깐 켜서 헤드리스로 확인했다.

## 고려한 제약 사항
- 동작 변경 없음: 리팩터링 전후로 헤드리스 크롬에서 33개 상태(넓은 화면 · 모바일의 모든 면 주소 · 잘못된 `?type=`, 키보드 ← → 로 끝까지 넘기기 · 되돌아오기, 탭 누르기, S-20 지면 목차의 8면 색인 `openAt`)의 `main` 전체 DOM · 포스트잇 · 귀 · 양옆 화살표 · 지면 클래스를 떠서 비교했고 모두 같았다. 목 데이터에는 0건 유형이 없어 0건 숨김은 단위 테스트(`faces.test.js` · `newspaperFaces.test.js`)로 확인했다.
- 채움 덱의 시작값(면마다 다른 법정 상식 · 사진)은 예전과 같은 면 순서 번호(`FACES.indexOf(face) * 3`)라 같은 지면이 나온다.
- 화면 쪽 이름 바꿈(`crimeType` → `key`)은 면 열쇠를 가리키는 변수에만 했다. 사건의 `item.crimeType`은 그대로다.

## 추후 재검토가 필요하면 (선택)
- 색인 · 성향 테스트 · 오피니언에 전용 내용을 넣을 때 그 면이 높이를 채우면 `fill: false`를 검토한다(FE-119 결정: 지금은 모든 면이 채운다).
- 면 본문이 사건 목록 말고 다른 데이터(사설 · 의견 등 별도 API)를 받게 되면, 지금은 모든 면이 `getCases(apiType)` 하나를 받는 구조라 면 정의에 데이터 불러오기(`load`)를 더하는 것을 검토한다.
