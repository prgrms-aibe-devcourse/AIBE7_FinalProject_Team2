# FE-90 의사결정 기록

## 문제 / 배경
- Safari에서 탭을 갔다 오면 메인 집무실 러그 위 종이(`--W`)가 작아지고, 창 크기를 바꾸면 돌아온다.
- `--W`는 `.room`(`container-type: inline-size`)의 `cqw`로 계산한다. 원인은 Safari가 탭 복귀 뒤 `cqw`를 갱신하지 않고 옛 값으로 남기는 것으로 추정한다(작아진 순간의 `--W` 값은 확인하지 못함).

## 검토한 대안
- 대안 A: `cqw`를 `vw` 기반으로 교체. 단순하지만 `vw`는 방 폭이 아니라 창 폭이라 스크롤바 · 방 폭 제한이 있을 때 값이 어긋난다.
- 대안 B: 방 폭을 `ResizeObserver`로 재서 px 변수(`--cqw`)로 넣고, 탭 복귀(`visibilitychange`, `pageshow`) 때 한 번 더 계산.

## 선택한 방법과 이유
- 대안 B. 기존 계산식의 `cqw`만 `var(--cqw, 1cqw)`로 바꿔 식 모양과 크기를 그대로 두고, JS 값이 없으면 기존 `cqw`로 동작한다.

## 고려한 제약 사항
- 헤드리스 크롬에서는 Safari 증상이 재현되지 않아, 최종 확인은 Safari 직접 확인에 의존한다.

## 추후 재검토가 필요하면
- Safari 확인에서 해결되지 않으면 원인(추정)이 틀린 것이므로, 작아진 상태의 `--W` 계산값부터 다시 확인한다.
