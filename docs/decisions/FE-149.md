# FE-149 의사결정 기록

> 근거: BE-146(PR #392, 순차 해금 · API 명세 v0.91 API 1 · 2 · 16, [BE-146 결정 기록](BE-146.md)). 화면 값은 서버가 원본이고 이 문서는 화면이 어떻게 보이는지만 다룬다.

## 문제 / 배경
- 서버가 완료한 사건 수에 따라 사건을 단계로 열고(0건 → 3개, 1건 → 6개, 3건 → 12개, 5건 → 전체), 잠긴 사건의 체험 시작(API 2)을 409 `CASE_LOCKED`로 막는다. 화면이 잠김을 모르면 잠긴 사건에도 "체험 시작"이 보이고 눌러야 409가 난다.

## 검토한 대안

### 1. 목록에서 잠긴 사건을 어떻게 보이는가
- A: 기사를 흐리게 하고 누를 수 없게 한다 — 기사를 읽을 수 없다. 이 서비스는 준비 중 사건도 기사는 읽게 둔다(FE-56).
- B: 목록에서 숨긴다 — "다음에 열릴 사건이 있다"는 동기가 사라지고 사건 총 수 표시와 어긋난다.
- **C(선택): 기사는 그대로 두고 분류명 줄 · 색인 줄에 점선 도장 "잠김"만 찍는다.** 진행 중 · 완료 도장과 같은 자리 · 크기라 새 시각 요소가 없고(집무실 물건 은유 유지), 점선은 S-20의 "준비 중" 도장과 같은 "아직 찍히지 않은 자리" 언어다.

### 2. 잠긴 사건을 누르면
- A: 목록에서 막고 안내만 띄운다 — 막는 곳이 하나 더 생기고 안내가 목록 안에 박힌다.
- **B(선택): 지금처럼 S-20으로 간다.** S-20이 지면은 읽게 두고 "시작하기" 자리에 점선 "잠김" 도장과 이유 한 줄을 둔다. 주소로 바로 들어와도 같은 화면이다.

### 3. 잠긴 이유(건수)는 어디서 가져오는가
- API 16에는 `unlock`이 없다(BE-146에서 목록에만 넣었다). API 1의 `nextStepAt - completedCases`는 "다음 단계까지 남은 수"라, 그 단계에서 이 사건이 열린다는 보장이 없다(예: 완료 0건일 때 7 ~ 12번째 사건은 3건을 마쳐야 열리는데 "1건"이라고 알리게 된다 — PR #396 리뷰).
- 사건 상세 · 목록에 사건별 `unlockAt`을 서버가 내려 준다 — 정확하지만 서버 변경이 다시 필요하다. 필요해지면 따로 정한다.
- **선택: S-20은 건수를 약속하지 않고 "다른 사건을 마치면 새 사건이 차례로 열려요."로 알린다.** 잠김 자체는 `locked`로 알리므로 건수는 부가 정보다. 1면 포스트잇의 "새 기사"는 단계 전체를 가리키므로 `unlock` 값이 맞아 그대로 둔다.

### 4. 머리기사 · 추천 · "체험할 수 있는 기사 수"
- 잠긴 사건을 준비 중과 같은 취급으로 뒤로 민다(`isClosed`). 눌러 보라고 권하는 자리에 누를 수 없는 사건이 앞서지 않게 하려는 FE-102 원칙과 같다.

## 선택한 방법과 이유
- **서버가 정한 `locked`를 그대로 따른다.** 단계 값 · 순서는 서버가 원본이라 화면에 복제하지 않는다. 필드가 없는 응답(구버전 · 일부 목)은 열린 것으로 본다(`utils/caseUnlock.js`).
- **409 `CASE_LOCKED`는 시작 버튼에서 다시 불러와 그린다.** 다른 곳에서 열어 둔 화면 · 단계가 바뀐 경우에 잠김 도장으로 바뀐다(오류 문구를 따로 두지 않는다).
- 1면 포스트잇에 "사건 N건을 더 마치면 새 기사가 열려요."를 붙였다(잠긴 사건이 있을 때만). 건수는 응답 최상위 `unlock`(`nextStepAt - completedCases`)이다.

## 고려한 제약 사항
- 서버 API 16에 `unlock`이 없어 S-20은 목록을 한 번 더 부른다(잠긴 사건에서만).
- **메인 신문(landingPage)**은 머리기사를 참여 수로 고르는 장식 지면이고 사건을 시작하는 곳이 아니라 바꾸지 않았다. **커뮤니티 메인 "이 사건 판결하기"**는 커뮤니티 API(C-6)의 `case`에 `locked`가 없어 그대로 "이 사건 판결하기"로 보이고, 누르면 S-20이 잠김을 알린다. 6막 "다른 사건 보기"는 목록으로 보낼 뿐이라 영향이 없다. 두 곳에 잠김을 보이려면 C-6에 `locked`를 더하는 서버 변경이 필요하다.
- 목(mock)은 사건 5가 잠겨 있다가 사건을 하나 마치면 열린다. 실제 서버의 단계 값은 흉내 내지 않는다.

## 추후 재검토가 필요하면
- 잠긴 사건이 많아져 목록이 답답해 보이면 잠긴 기사의 본문을 줄이거나 색인 면에서 모아 보이는 것을 검토한다.
- C-6 · 메인 신문에 잠김을 보이려면 서버가 `locked`를 내려 줘야 한다.
