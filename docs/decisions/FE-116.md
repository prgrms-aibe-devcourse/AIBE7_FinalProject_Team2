# FE-116 의사결정 기록

> FE-114([FE-114 의사결정 기록](FE-114.md)) 후속. 카드 아래 줄 · 레벨 · 직업 연동에서 남은 것을 묶은 이슈다.

## 문제 / 배경
- 커뮤니티 명함 · 랭킹에 레벨 · 직업 · 카드 아래 줄이 반영되지 않았고, 경험치 진행률이 없었으며, 줄 종류 · 레벨 접두는 이 브라우저에만 저장됐다.
- 커뮤니티 API는 서버에 아직 없다.

## 검토한 대안
- 서버 저장 준비 A: 플래그 상수로 켠다. BE 배포와 프론트 배포를 사람이 맞춰야 하고, 어긋나면 400이 난다.
- 서버 저장 준비 B: P-5 `profileSettings`에 `cardLine`이 오면 서버가 지원하는 것으로 본다(자동 감지).
- 커뮤니티 연동 A: 실서버 연동을 기다린다. B: 목 글쓴이를 서버 계약 모양으로 맞춰 두고 API가 생기면 같은 모양으로 오도록 BE에 요청한다.

## 선택한 방법과 이유
- 서버 저장은 B. 응답마다 지원 여부를 다시 판단해 서버가 바뀌거나 롤백돼도 모르는 칸을 보내지 않는다. 저장이 거절되면 실패한 요청이 바꾼 칸만 되돌린다. 목은 항상 두 칸을 내려 이 경로를 쓴다.
- 커뮤니티는 B. 목 글쓴이를 `level` · `job { code, name }` · `cardLine { line, showLevel }`로 맞췄다. BE 요청 사항은 Jira FE-116에 적었다.
- 경험치 진행률은 L-1의 `xp` · `currentLevelXp` · `nextLevelXp`로 계산하고 최고 레벨은 막대를 채운다.
- 목 커뮤니티 경험치는 명세 11장 수급처(글 30 · 판결 공유 +20 · 댓글 10 · 좋아요 2와 상한)를 따른다. 서버에서는 BE가 `LevelService.award`로 지급한다.

## 고려한 제약 사항
- 커뮤니티 실서버 연동과 실제 지급은 서버 API가 생긴 뒤에 한다.
- 커뮤니티 목 글쓴이 이름에는 공백이 남아 있다(글 · 댓글이 이름을 키로 묶여 있다).

## 추후 재검토가 필요하면
- 커뮤니티 API가 생기면 목 모양을 실제 응답에 맞춘다.
