# FE-87 의사결정 기록

> 메인 화면(S-01) 점검. PR #265 (`feature/FE-87-main-screen-review`).
> 지금 화면이 어떻게 생겼는지는 [`frontend/src/pages/landing/README.md`](../../frontend/src/pages/landing/README.md), 화면별 크기 · 자리 기준은 [`DESIGN.md`](../../DESIGN.md) "크기 · 자리 기준 (화면별)"에 있다. 이 문서는 **왜 그렇게 정했는지 · 무엇을 시도하고 버렸는지**를 적는다.
> 대부분은 사용자(김해송)가 화면을 직접 보며 준 피드백을 한 단계씩 반영한 결과다. "(사용자)"는 사용자 결정 · 피드백, 나머지는 구현하며 정한 것이다.

## 문제 / 배경

- **첫 화면**: 좁거나 세로로 긴 창에서는 책상 그림이 줄어 낮아지고, 그 아래 서비스 소개가 첫 화면에 같이 들어와 시선을 뺏었다.
- **서비스 소개**: 책상 아래 "이렇게 체험해요"가 평범한 종이 한 장(흐름 한 줄 + 세 판결 단어 + 버튼 두 개)이라, 손으로 만지는 책상 세계와 분위기가 끊겼다. 내용도 약속만 있고 결과 장면이 없어 세 판결이 무엇을 비교하는지 보이지 않았다.
- 점검하며 함께 드러난 것: 헤더 로고 줄바꿈(중간 폭), 오버스크롤 흰 틈, 화면 전환 중 푸터 움직임 등.

## 1. 첫 화면: 어떤 크기에서도 책상만

목표(사용자): **첫 화면에는 책상만 꽉 차게**. 책상 그림은 기준 좌표계(1672 × 941)를 통째로 줄이는 방식이다.

| 시도 | 결과 |
| --- | --- |
| 책상 판만 위로 늘림 | 물건 · 패드는 그대로라 위쪽에 빈 나무만 길게 남음(사용자: 어색) |
| 책상을 키워 화면을 덮고 넘치는 쪽을 자름 | 좁은 창에서 노트북 · 서류철이 잘려 메뉴를 못 누름 → 버림 |
| 세로로 긴 화면용 세로 배치(노트북 · 서류철을 아래로) | **소품 배치 순서는 유지**(사용자) → 버림 |
| 신문 · 서류철을 세로로 늘려 흡수(신문 최대 1 : 1.83) | 신문이 지나치게 길고 서류철 비율이 바뀌어 어색(사용자) → 버림 |
| **최종** | 장면 높이 = 화면 높이 − 헤더. 그림을 장면 안에 들어가게 줄이고(`--desk-scale` = min(폭 / 1672, 높이 / 941)), 남는 쪽으로 책상을 늘린다 |

최종 규칙:
- 늘어난 높이는 **신문만 기본의 1.2배까지**(`--ng` ≤ 142) 흡수하고, 다른 물건은 비율을 바꾸지 않는다(사용자).
- 대신 남는 높이가 클수록 신문 밖 소품(노트북 · 엽서 · 펜 · 서류철 · 커피잔 · 포스트잇 · 캐릭터)을 **모양 그대로 키우고 조금 더 기울인다**. "늘리는 것보다 각도를 바꾸는 편이 자연스럽다"(사용자). "큼직큼직해도 좋다"(사용자)는 피드백으로 확대 폭을 키워 신문 최대 1.3배 · 다른 소품 1.35 ~ 1.5배, 남는 높이 800 기준 px에서 최대(`--t`).
- 좁은 가로 화면은 세로 여유가 없어 소품이 안 커졌고 엽서 · 서류철 · 커피잔이 특히 작았다(사용자) → 책상 배율 자체(화면 폭)를 보고 작은 소품을 따로 키운다(`--k` = max(세로 여유, 배율 0.85 → 0.5)). 신문 · 노트북은 공간을 다투므로 세로 여유만 따른다.
- 노트북은 신문 쪽 모서리, 서류철은 오른쪽 끝을 고정점으로 커져 신문을 덮지 않는다(노트북은 대신 화면 왼쪽 밖으로 조금 더 나감).
- 남는 높이는 여백비를 고려해 나무 띠에는 조금만(0.1) 주고 신문 · 서류철 위아래로 보낸다.
- 세로로 긴 화면에서 내로(네이비)가 패드(네이비) 위에 묻혔다 → 포스트잇 · 내로를 **패드 윗변 위 나무**에 고정하고 신문 제호를 가리지 않게 오른쪽 귀 쪽으로 비킨다. 포스트잇은 신문 제호를 덮어도 되고(사용자) **가장 먼저 눌러 보길 바라는 놀이**라 책상에서 첫 Tab이다.
- 모바일(720px 이하) 메뉴 카드도 첫 화면을 채운다.

## 2. 서비스 소개를 집무실 바닥으로

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| 판결문 한 장(주문 · 이유 · 결재 칸) | 세계관에 맞고 작업이 작음 | 책상에서 공간이 이어지는 느낌이 없음 |
| 책상 서랍(스크롤하면 열림) | 놀이 요소 큼 | 연출이 크고 모바일 처리가 까다로움 |
| 책상 앞 기록철(인덱스 탭) | 5막 파일철 재사용 | 메인만의 인상이 약함 |
| 360도 뷰 · 1인칭 복도 | 공간감 | 원근 → "2D 평면, 물건이 기울지 않음" 팀 결정과 충돌. 원근 속 글자 읽기 어렵고 WebGL · 모바일 성능 · 움직임 줄이기 대체 필요 |
| **탑뷰 방 구조(선택, 사용자 10/22)** | 같은 시점 · 같은 2D 평면으로 공간이 이어짐, 모바일은 세로로 쌓기 좋음 | – |

함께 정한 규칙:
- **은유 범위를 넓혔다**: "판사의 책상 위 물건" → "판사의 집무실에 있을 물건"(의자 · 러그 · 문 등). 집무실 밖 은유는 여전히 금지(DESIGN.md 갱신).
- **글자는 바닥에 직접 쓰지 않는다.** 바닥에 놓인 종이 위에만 쓴다(탑뷰에서 읽히는 유일한 자리).
- 그림은 책상처럼 CSS만(이미지 파일 없음). 색은 `--color-room-*` 역할 토큰을 새로 두고 펠트 · 나무 · 크라프트 팔레트를 재사용.
- 책상은 좌표계째 줄이지만 방은 글자가 많아 같은 방식이면 모바일에서 읽히지 않는다 → 방은 방 폭(`cqw`)과 책상 배율로 계산하는 반응형 배치, 그림만 탑뷰로 맞춘다.
- 실제 사용자 반응 · 통계가 없어(PRODUCT.md) 수치를 지어내지 않는다. 미리보기 수치는 목데이터로 밝힌다.

## 3. 의자 · 안내문 · 남불 놀이

**의자**
- 같은 방 안 물건이라 책상 소품과 같은 배율(높이 기준 = 책상 위 신문 폭 × 책상 배율). 1인용이 좁아 보여 가로를 넓혔다(정사각 아니어도 됨, 사용자).
- 바닥 한가운데 의자는 떠 보였고, 안내문과 한 줄에 두면 좁은 화면에서 안내문이 잘렸다 → **책상 밑으로 쭉 밀어 넣어** 등받이 · 팔걸이 끝만 책상 가장자리 아래로 보이게(사용자). 책상 장면을 위에(z-index) 그려 가린다. 모바일은 메뉴 카드 밑으로.
- 가운데 의자는 시선을 끊어(사용자) 폭을 1.6배로 줄이고 오른쪽으로 치우쳐 왼쪽 아래(안내문 쪽)로 7도 튼다. 오른쪽 위 의자 → 왼쪽 안내문 → 러그로 시선이 대각선으로 흐른다.

**안내문 종이("이렇게 체험해요")**
- 제목만 남기고(설명은 러그가 한다) 바닥에 놓인 줄 칸 종이 한 장.
- 자리 · 크기를 고정하지 않는다(사용자): 폭은 책상 배율에 비례(140 ~ 520px, 넓은 화면에서 이전의 1.5배 이상), 왼쪽 여백 25 ~ 100px(넓을수록 시원하게, 사용자), 책상 가장자리에서 최대 100px(처음 50px → 늘림, 사용자).
- 좁은 화면에서 안내문을 의자 아래로 내리면 책상에서 멀어져 튀어 보여, 안내문은 늘 의자 왼쪽 옆에 두고 **의자가 안내문과 최소 10px 떨어지도록 오른쪽으로 밀린다**(사용자). 의자 오른쪽은 벽 밖으로 잘려도 책상 밑이라 어색하지 않다.
- 제목이 책상 그림자에 가려 종이 가운데로 옮겼다(크기 그대로).

**놀이(사용자)**
- 종이 왼쪽 위 귀퉁이가 늘 들썩이고 마우스를 올리면 더 크게 일렁인다(처음 오른쪽 아래 → 오른쪽 위 → 왼쪽 위로 옮김, 사용자). 누르면 러그 쪽(거의 아래, 살짝 오른쪽)으로 러그 · 러그 위 서류 **위를** 지나 끌려가며 치워지고 밑의 **남불**이 드러난다. 책상 위 남불을 여기로 옮겨 "내로 = 책상 포스트잇 밑, 남불 = 바닥 안내문 밑"으로 짝을 이룬다.
- 구현 고민:
  - 들썩임은 `@property --curl`(숫자)을 애니메이션해 clip-path로 귀퉁이를 자르고 접힌 뒷면(::after)을 그린다. 그림자는 바깥 버튼의 filter가 맡아 clip-path에 잘리지 않게.
  - 치울 때 들썩임(매 프레임 다시 그리는 clip-path)과 날아가는 움직임이 겹치면 잔상이 남아, 치우는 동안 들썩임을 멈춘다. 그래도 남던 L자 그림자는 치우기 시작할 때 filter를 떼서 없앴다.
  - 종이가 떠 보여(사용자) 자기 그림자는 짧게, 책상 그림자를 넓혀 안내문 윗부분에 드리운다(바닥에 붙어 보이게).
  - 화면 제목(h2)은 낭독기용으로 종이와 따로 둬, 치워도 구역 이름이 남고 포커스가 그쪽으로 옮겨진다(CodeRabbit 리뷰).
  - 움직임 줄이기 · 치우는 중에는 호버 애니메이션도 끈다(CodeRabbit 리뷰).

## 4. 러그와 종이

### 4-1. 내용: 러그 = 내가 하는 일, 판결 = 끝에 얻는 것

- 처음 러그 · 탁자 글이 정의만 늘어놓고 서로 겹쳐(둘 다 "세 판결 비교") 물건과 내용이 따로 놀았다(사용자: "붕 뜬다"). 목업(`Claude outputs/mockups/메인_집무실_러그스툴_내용_시안_2026-10-23.html`)으로 시안을 비교해 정했다.
- 러그 종이는 **체험 속 물건의 축소판**이고 순서가 곧 흐름: 뉴스만 본 나(책상 신문과 같은 머리기사 스크랩) → 첫인상(징역형 / 벌금형 체크 엽서) → 내 판결(판단 요소마다 무겁게 · 해당 없음 · 가볍게 파일철) → 모든 사실을 본 나(형량을 적고 도장 찍은 판결문). 잇는 줄 없이 표시(빈 원 → 마름모 → 꽉 찬 원)만 둔다.
- 판결 미리보기: 시안 A(목데이터 수치) · B(수치 없이 막대만) 중 **A**(사용자). 수치가 기준점이 될 우려가 있어 AI 판결 하나만 "징역 6년 · 목데이터 · 법률 자문 아님"으로 밝히고, 실제 판결은 흐리게 가리고 "맨 마지막에 공개" 봉인 띠(앵커링 방지, PRODUCT.md).
- 판단 요소 예시(범행 경위 · 피해 회복 · 반성 여부)는 특정 사건이 아닌 일반 항목이다.

### 4-2. 판결을 올려 둘 자리: 탁자 → 스툴 → 러그 위

| 단계 | 내용 | 바꾼 이유 |
| --- | --- | --- |
| 긴 탁자 하나에 세 판결 | 같은 종이 · 같은 크기(대등) | 완전한 일자라 단조로움(사용자) |
| 원형 스툴 세 개(선택) | 대안: 사이드 테이블에 부채꼴 · 3단 결재 서류함은 맨 위 · 위 칸이 더 중요해 보여 "세 판결은 대등" 원칙과 충돌 | – |
| **스툴 삭제, 러그를 아래로 늘려 판결을 러그 위로**(사용자) | 러그 종이와 같은 규칙(종이 · 기울기 · 겹침). 러그 한 장 안에서 "하는 일 → 얻는 것"이 이어짐 | 스툴이 러그와 따로 놀았다 |

- 판결 셋 중 "내 판결" 종이는 지웠다(형량을 적는 판결문 = 모든 사실을 본 나와 겹친다). AI 판결은 가운데, 실제 판결은 왼쪽 아래.
- 판결 두 장은 앞 종이 **밑에** 깔린다(AI 판결은 판결문 밑, 실제 판결은 AI 판결 밑, 사용자). 앞 단계가 위에 놓여 순서가 읽힌다.

### 4-3. 종이 크기 · 비율

- 넓은 화면에서 종이가 가로로만 길어졌다(사용자) → 처음엔 모든 종이를 세로 : 가로 0.8 ~ 1.5로 묶었다(`aspect-ratio: 5 / 4` 하한 + grid 칸 폭 넓히기). → 종이별로 비율을 지정받아(사용자) 바꿨다.
- 최종(세로 : 가로, 허용 ±0.05): 뉴스만 본 나 1.2W × 1.5(다른 종이보다 20% 크게) · 첫인상 0.9W × 0.7 · 내 판결 W × 0.7 · 모든 사실을 본 나 1.2W × 0.64W(나중에 가로 1.2배 · 세로 0.8배로, 사용자) · AI 판결 0.9W × 0.7 · 실제 판결 1.15W × 0.7W.
- **grid 칸 폭으로는 화면마다 종이 폭이 달라 비율을 지킬 수 없다** → 기준 폭 `--W`(= min(420px, 방 폭 24%, 러그 안에 들어가는 폭))로 크기를 계산하고 자리도 W 단위(`--x` · `--y`)로 직접 놓는다. 종이 안 글자 · 간격도 `--u` = W / 300에 비례시켜 어떤 폭에서도 비율이 그대로이고 글이 넘치지 않는다.

## 6. 신문 끝자락 → 사건 목록 전환

요구(사용자, 단계별로 나옴): 들어 올리는 연출 → **들어 올린 그 신문이 화면을 채울 것** → 다 로딩된 뒤 시작 · 중간에 화면이 사라지지 않을 것 → 스크롤이 튀지 않을 것 → 잡아당김과 커짐을 동시에 · 더 높이 → 들어 올릴 때와 커질 때 내용이 같을 것 · 경계에서 속도가 0이 되지 않을 것(최저 속도가 최고의 30% 이상) → 고정 이미지와 이어질 것 · 기울기 유지.

| 시도 | 방식 | 버린 이유 |
| --- | --- | --- |
| 1 | 끝자락을 0.38초 들어 올린 뒤 책상 신문과 같은 `from: 'desk'`(사건 목록 지면이 화면 아래에서 새로 올라옴) | 들어 올린 신문과 **다른 종이가 새로 나타남**(사용자) |
| 2 | 끝자락을 장식 층에 본떠 화면 크기까지 키우고, 빈 종이로 사건 목록에 넘김(`from: 'flip'`, 6막 "다른 사건 보기" 이음 재사용) | 키우는 동안 글자가 걷혀 빈 종이 → 기사가 다시 페이드인, **중간에 화면이 사라짐**(사용자) |
| 3 | 메인에서 끝자락을 들어 올린 채 사건 목록 로딩을 기다렸다가, 실제 사건 목록 지면이 끝자락 자리에서 커짐(`from: 'tail'`) | 들어 올리던 복제본(채우기 전 표지)과 사건 목록 지면(머리기사 · 사진)이 **내용이 달라 바뀌어 보임**, 들어 올림이 멈춘 뒤 커짐이 따로 시작(사용자) |
| 4 | 들어 올림 · 커짐을 모두 사건 목록 지면 하나가, 키프레임 셋 + 구간별 easing으로 속도 이어 붙이기 | 누르기 전 고정 이미지(기울어진 표지)와 이어지지 않음, 두 구간 이음새가 어색(사용자). 들어 올림이 제자리를 지나치면 경계에서 반전 → 속도 0 |
| 5 | 끝자락 기울기 제거 + 처음부터 크로스페이드(3 ~ 20%)하며 하나의 연속 경로 | 속도감은 좋음(사용자). 그러나 **기울어져 있어야 하고**, 끝자락 자체가 먼저 들어 올려져야 함(사용자) |
| **6 (선택)** | 5의 연속 경로 + 2 · 3의 구성: 누른 순간의 끝자락(기울기 · 들썩임 포함)을 맨 위 층에 본떠 **바로** 들어 올리고, 들어 올린 뒤 그 밑에서 같은 자리 · 폭 · 기울기로 함께 움직이던 사건 목록 지면으로 넘겨 화면을 채움 | – |

선택한 방식의 세부 고민:
- **한 장처럼 보이는 둘**: 본뜬 끝자락(face)과 사건 목록 지면(paper)이 매 순간 같은 자리 · 폭 · 기울기다. 넘길 때 blur(최대 3px)로 두 상태가 겹쳐 보이는 것을 가린다(emil-design-eng 스킬). 머리기사가 채워지면 끝자락도 다시 본떠 사건 목록 첫 머리기사와 같게 했다. 그래도 두 지면은 다른 화면이라 레이아웃 차이가 남는다(사용자: 어쩔 수 없음) → 바뀌는 시간을 늘려 "바뀌고 있음"을 보여 준다.
- **움직임은 구간을 이어 붙이지 않고 동시에 겹친다**(시도 4의 이음새 문제): 올라감(iOS 서랍 곡선 `.32, .72, 0, 1`, 처음부터 빠르고 부드럽게 멈춤) · 커짐 + 기울기 풀림(조금 늦게 붙는 ease-in-out `.65, 0, .35, 1`) · 벽선 열림(30 ~ 80%) · 지면 교체 · 메인 흐려짐(30 ~ 100%). 곡선마다 진행이 달라 CSS 곡선 하나로 쓸 수 없어 **48단계 자리를 미리 계산해 WAAPI 키프레임**(transform · clip-path · opacity · filter만)으로 넘긴다 — 사건 목록을 그리는 중에도 메인 스레드와 무관하게 돈다(animation-performance 스킬). ease-in은 쓰지 않는다(emil-design-eng).
- **기울어진 지면을 벽선에서 자르기**: 지면은 기울어져 있지만 벽선은 화면 가로선이라, 자기 좌표의 polygon으로 자른다.
- **누른 순간의 모습 잡기(`tailPose`)**: 기울이기 전 상자를 재고 버튼 · 지면 각각의 transform 행렬을 합쳐 기울어진 지면의 왼쪽 위 모서리와 각도를 구한다(들썩이는 중에 눌러도 그 각도에서 이어짐).
- **로딩**: 사건 목록이 덜 그려졌으면 지면 교체 직전에서 멈춰 기다린다(최대 1.2초, 책상 신문과 같은 `drawn`). 눌렀을 때 바로 움직이기 시작해 반응이 늦지 않다.
- **스크롤 튐**: 사건 목록은 메인을 흐려지는 배경(`.paper-ghost`, 헤더 없이 맨 위부터 그리는 고정 층)으로 남기고 라우터는 스크롤을 맨 위로 올린다. 스크롤 값만 빼면 헤더 높이(53px)만큼 튀어, 넘어가기 전 · 후 자리 차이만큼 메인을 되돌린다(프레임마다 러그 위치를 재서 확인).
- **푸터 움직임**: 사건 목록 CSS의 `.case-list-page .site-footer` 규칙이 배경으로 남긴 메인 푸터에도 걸려 이용약관 줄이 밀렸다(사용자, 스크롤바가 보이는 상태에서만 드러남) → 지면 안(`.paper .site-footer`)으로 한정.

**너비별 시간**(사용자 피드백으로 여러 번 조정):
- 처음 0.9초가 중간 너비에서 "휙 바뀌는" 느낌(사용자) → 바꾸는 시간을 늘림. 그런데 늘린 값을 **좁은 너비(720px 이하)에 잘못 적용**했다(사용자가 말한 화면이 중간 너비였음). 좁은 너비는 1.3 → 1.5 → 1.8초까지 늘었다가 "너무 느리다"(사용자)로 기본으로 되돌림.
- 너비 구간 정의(사용자): 창 크기로 1326 ~ 738px = 메인 신문 폭이 줄어드는 **중간 너비**, 737px 이하 = 메인 디자인이 바뀌는 **좁은 너비**. 코드로 확인하니 이 숫자는 창 크기 관찰값이고, 실제 기준은 책상이 폭 때문에 줄어드는 조건(`fit`: 폭 / 1672 < 높이 / 941, 창 높이에 따라 변함)과 landing.css의 720px(CSS px, 창 테두리 · 스크롤바만큼 작음)였다. 처음엔 숫자를 박지 않고 메인이 같은 조건으로 판정해 넘기는 방식(`from.middle`)으로 중간 너비만 따로 맞췄다.
- 중간 너비 1.3초 → 1.1초(사용자). 그 뒤 **넓은 · 좁은 너비도 중간 너비에 맞추라**(사용자)고 해서, 너비별 구분을 없애고 모든 너비에 같은 속도를 쓴다: **1.1초**, 지면 교체 29 ~ 67%(들어 올림 약 0.32초 · 바뀜 0.42초 · 커짐 0.36초). 판정 코드(`from.middle`)도 없앴다. 넓은 · 좁은 너비는 이전 0.9초(지면 교체 26 ~ 42%)보다 조금 느려진다.

## 7. 러그 밑 성향 테스트 서류철

- 맨 아래 서류철을 없애 성향 테스트 입구가 집무실에서 사라졌다 → 러그 오른쪽 아래 **귀퉁이 밑에 깔아 바깥으로 조금 삐져나오게**(사용자). 귀퉁이는 마우스를 올렸을 때만 들썩이고(밑의 서류철이 잠깐 비침), 누르면 접혀 올라가 서류철이 드러난다.
- **접기를 2D로**: 러그 본체를 그 삼각형만큼 `clip-path`로 비우고, 귀퉁이 한 장(앞면 = 러그 무늬 · 테두리, 뒷면 = 러그 밑면)을 대각선 축 `rotate3d(1, -1, 0, 180deg)`로 뒤집는다. **원근(perspective)을 주지 않아** 2D 평면 결정을 지킨다. 앞면 대각선을 2px 넘겨 잘린 이음매가 비치지 않게 했다.
- **누르는 자리**: 들썩이는 동안 귀퉁이가 움직여도 마우스가 빠지지 않게 누름 영역(삼각형)은 접히는 한 장과 따로 둔다. 접기 전에는 삐져나온 서류철도 접는 자리(사용자) — 서류철을 누르면 먼저 접히고, 접힌 뒤 누르면 성향 테스트. 서류철에 올려도 귀퉁이가 들썩인다.
- **접기 움직임**: 처음엔 CSS transition이었으나, 마우스를 올린 채(들썩이는 애니메이션 중) 누르면 애니메이션이 끊기며 transition이 시작되지 않아 **한 프레임에 접혀 버렸다**(rAF로 각도를 재서 확인, 사용자: "접히는 애니메이션 넣어줘"). 누를 때 지금 각도를 읽어 WAAPI로 접힘 · 펼침까지 이어 간다(0.6초).
- **크기**: 약 160px → 러그 폭의 40%(책상 위 서류철 정도, 사용자) → 48%(20% 더, 사용자). 접히는 귀퉁이도 비례(28% → 36%). 삐져나온 정도는 처음 고정 px였다가 "2% 정도 늘려"(사용자)를 서류철 폭 대비 비율로 바꿔 반영(가로 10.3% · 세로 12.4%). 러그 폭을 방 폭(`cqw`)으로 계산한 변수(`--rw`)를 서류철 · 귀퉁이가 함께 쓴다. 서류철 안 이름표는 서류철 폭 기준(`cqw`, 서류철이 container)으로 맞추고, 접으면 드러나는 오른쪽 아래쪽으로 옮겼다.
- **전환 정리(팀원 리뷰, `af28053` 이후)**: 세 가지를 고쳤다.
  - 본뜬 끝자락은 `.room` 밖(body)에 붙어 `:where(.room) :where(span)`의 블록 규칙을 못 받았다 → 머리기사 단(`.news-kicker` · `.news-deck` · `.news-byline`)이 inline으로 이어 붙어 눌렀을 때 배치가 바뀌어 보였다(복사본의 `display`가 `inline`임을 계산 값으로 확인). 끝자락 규칙에 `span`을 더해 둘 다 같은 블록 규칙을 받는다(우선순위 0이라 기존 규칙은 그대로 이김). 프레임마다 위치 · 크기만 재서는 잡히지 않는 종류였다 — 검증은 계산 스타일도 함께 비교한다.
  - `ghost`는 있는데 넘겨받은 한 장(`takePaper()`)이 없으면 `is-spreading`도 `is-rising`도 안 붙어 `paper-rise`가 안 돌고 2초 폴백까지 뒤에 남긴 메인이 보였다 → 그 길에서는 연출을 포기하고 `ghost`도 바로 걷는다.
  - 연출 시작 전 · 도중에 다른 화면으로 가면(Esc · 헤더) 맨 위 층(z-index 1000)에 본뜬 끝자락이 새 화면 위에 남았다 → 시작 전 `active()` 확인, 도중에는 0.1초마다 확인해 층을 바로 걷고, 끝나고 클래스를 걷을 때도 `active()`를 본다(연출 도중 Esc로 확인: 층 0개).
- **접근성(CodeRabbit 리뷰)**: 접기 전에는 서류철(`.rug-folder`)과 귀퉁이 버튼(`.rug-flap`)이 같은 동작(접기)이라 Tab 정지점이 겹치고, 서류철의 이름("판결 성향 테스트")은 실제 동작(접기)과 달랐다 → 접기 전에는 서류철을 Tab · 낭독기에서 빼고(`tabIndex -1` + `aria-hidden`, 책상 엽서와 같은 방식), 접힌 뒤 다시 보이게 한다. 접기 · 펴기 때마다 동기화한다(`exposeStash`).
- 러그 자리 · 기울기(−0.6도)는 감싼 칸(`.room-rug-wrap`)으로 옮겨 서류철 · 귀퉁이가 함께 기운다. 러그는 순서 목록(`ol`)이라 서류철 · 귀퉁이 버튼은 목록 밖 형제로 둔다(흐름 단계 수가 바뀌지 않게).

## 8. 함께 고친 것

## 검증 방법

- 헤드리스 크롬 + CDP 스크립트로 확인했다(playwright 없음). 정지 화면은 스크린샷, **움직임은 `requestAnimationFrame`으로 매 프레임 위치 · 크기 · transform을 기록해 숫자로** 봤다(스크린샷 연사는 한 장 60 ~ 100ms라 속도 · 이음새를 못 봄). 예: 전환 경계 속도, 스크롤 튐(53px), 접기가 한 프레임에 끝나는 문제.
- 호버는 `Input.dispatchMouseEvent`로 실제 마우스를 움직여 확인했다(클릭 함수로는 `:hover`가 안 생김).
- 스크롤바를 숨기고(`--hide-scrollbars`) 재면 스크롤바 폭 차이로 생기는 버그(푸터 밀림)가 가려져, 레이아웃 이동은 스크롤바를 켠 채 다시 쟀다.
- 헤드리스로 못 본 것: 오버스크롤 색, 실기기 터치, 체감 속도 → 사용자 확인.

## 고려한 제약 사항

- 2D 평면 · 원근 없음(팀 결정): 360도 · 1인칭 · 원근 접기를 쓰지 않는다. 귀퉁이 접기도 원근 없이 납작하게 뒤집는다.
- 집무실 물건 은유만, 글자는 종이 위에만, 수치는 지어내지 않고 목데이터로 밝힌다(PRODUCT.md).
- 세 판결은 대등(같은 종이 · 같은 크기, 부채꼴 · 위아래 서열 금지), 실제 판결은 마지막까지 가린다(앵커링 방지).
- 움직임 줄이기 · 연출 끄기: 모든 들썩임 · 접기 · 전환은 건너뛰거나 길이 0(끝 상태 유지). 전환은 바로 사건 목록으로.
- 이미지 작업은 GPT Pro 팀원 담당이라 이번엔 CSS 그림으로 자리와 크기만 맞췄다.

- 책장 · 창문 등 방을 더 채울지(지금은 내용이 있는 물건만 둔다).
