# BE-114 의사결정 기록

## 문제 / 배경
- 프로필카드 아래 줄(`cardLine`)과 레벨 표시(`cardLevel`)를 서버에 저장해야 한다. 프론트(FE-116)는 P-5 `profileSettings`에 `cardLine`이 오면 서버가 지원하는 것으로 보고 자동으로 PATCH에 함께 보낸다.

## 검토한 대안
- 대안 A: `profile_setting`에 칸 두 개 추가 (선택)
- 대안 B: `profile_deco`(P-7 전체 저장)에 추가 — 화면마다 따로 저장하는 값이 꾸미기 저장에 덮어씌워질 수 있다
- 대안 C: `cardLevel`을 문자열("true")도 받기 — 기존 칸 검증과 달리 느슨해진다

## 선택한 방법과 이유
- A. BE-104에서 부분 저장(PATCH)을 위해 나눈 테이블이라 같은 이유로 여기에 둔다. 기존 행은 `DEFAULT`로 채워져 마이그레이션이 칸 추가만으로 끝난다(BE-60).
- `cardLevel`은 JSON boolean만 받는다. 문자열이나 null은 기존 칸과 같이 400 `VALIDATION_ERROR`.
- `cardLine` 값 검증은 DB CHECK와 요청 검증(`ProfileSettingsPatch`) 둘 다 둔다. 요청 검증이 먼저라 잘못된 값이 500이 되지 않는다.

## 고려한 제약 사항
- 배포 순서 조율 불필요: 응답에 `cardLine`이 없으면 프론트가 브라우저에만 저장한다.
- 다른 사람에게 보여 주는 쪽(커뮤니티 API, BE-115)이 이 값을 읽는 것은 이번 범위 밖.
