# FE-110 의사결정 기록

## 문제 / 배경
- #288 · #290 · #292 · #293 · #294 · #295 리뷰에서 차단 사유는 아니지만 고칠 만한 지적이 20개 나와 한 이슈로 묶었다.
- 이 중 판단이 필요했던 것만 적는다(나머지는 문구 · 클래스 · 주석 수정).

## 검토한 대안
- **마이페이지 조회 실패 시 첫 광고 칸(항목 1)**: ① 조회 실패일 때 "판결 성향 테스트"를 그대로 보이고 누르면 이동 / ② 칸은 두고 누를 수 없게 막기 / ③ 첫 칸을 빼고 두 칸만 두기.
- **`@property` 미지원 브라우저(항목 8)**: ① 결정 기록에 지원 범위만 적기 / ② JS로 지원을 확인해 표시를 달고 그때만 애니메이션 켜기.
- **3막 임시 식별값(항목 16)**: ① 화면을 그릴 때 만들기(기존) / ② 서명할 때 만들기.
- **`award`의 없는 익명 ID(항목 19)**: ① 앞에서 사용자를 확인해 0을 돌려주기 / ② 계약을 주석으로 남기기.

## 선택한 방법과 이유
- 항목 1은 ③. ①은 이미 테스트한 사람에게 테스트를 권하고 이동시킨다. ②는 눌러도 반응 없는 칸이 남는다. 상태를 모르면 권하지 않는 것이 안전하고, 두 칸이어도 6막과 같은 광고 단 모양은 유지된다.
- 항목 8은 ②. 구현이 몇 줄이고(`main.js` 한 줄 + CSS 선택자 한 곳), 모르는 브라우저에서 뚝뚝 끊기는 것보다 쉬는 모양이 낫다. 지원 범위(사파리 16.4)는 결정 기록 `FE-96.md`에도 적었다.
- 항목 4는 "오늘의 지면" 칸에 `is-today`를 붙여 내 결과가 순서 · 클래스 없음이 아니라 이름으로 찾게 했다(6막 광고 단은 클래스만 늘었다).
- 항목 20은 `ProfileDecoService` · `LevelService`에 이미 읽은 `ProfileStats`를 받는 `view(userId, stats)`를 더하고 `MyPageService.build`가 한 번만 읽어 넘기게 했다. 반환 구조는 그대로라 호출하는 쪽은 바뀌지 않고(기존 `view(userId)`는 위임), 통계 읽기만 2번에서 1번으로 준다.
- 항목 16은 ②. 서명은 `position: absolute`로 얹혀 있어 서명할 때 붙여도 레이아웃이 움직이지 않는다. 서명하지 않으면 `nlnb-anon-sign`이 저장되지 않는다. 실패 시 지우고 다시 서명할 때 새로 만든다.
- 항목 19는 ②. 호출하는 곳이 아직 없고, 커뮤니티 BE가 붙을 때 그쪽이 확인한 사용자를 넘기는 쪽이 맞다. 동작을 바꾸지 않아 테스트가 늘지 않는다.

## 고려한 제약 사항
- 선행 조건이 남은 항목은 FE-112로 옮겼다: 항목 5 · 6(BE 일반 회원가입 · 로그인 API가 열린 뒤), 항목 9(들썩임 비용, 사파리 · 실기기 측정 후).

## 추후 재검토가 필요하면
- 마이페이지 조회가 자주 실패하면 두 칸 상태가 자주 보인다. 그때는 실패 안내와 다시 시도를 광고 단에 둘지 검토한다.
