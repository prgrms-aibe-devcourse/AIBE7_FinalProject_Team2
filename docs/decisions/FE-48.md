# FE-48 의사결정 기록

## 문제 / 배경
- FE-43(5막 파일철) 머지 뒤 판결 체험을 처음부터 끝까지 다시 돌려 보고 나온 흐름 개편 묶음이다.
- 3막 "법률 안내"와 4막 "판결 전 정리"가 5막 참고 정보와 겹쳤고, 5막은 버튼 · 확인 상자가 많아 서류에 서명하는 느낌이 약했다.
- 함께 반영: 5막 형량 칸이 잠기면 입력한 숫자를 비우는 수정, 대본 없는 사건의 사건 상세를 신문 지면으로 통일(아래).

## 검토한 대안
- 4막 처리
  - 대안 A: 4막을 막 칩 줄에 남기고 자동으로 건너뛴다. 서버 진행 상태(`REVIEWED` → S-05)와 주소는 그대로.
  - 대안 B: 4막을 없애 7막 구성으로 바꾼다. 서버 상태 · API · 주소 · 막 번호가 모두 바뀌어 별도 이슈 규모다.
- 3막 법률 안내를 지울 때 서버 진행 기록
  - 법률 안내 장면에 서버 진행 기록(섹션 4 시작 · `confirm: 4`)이 걸려 있었다. 그대로 지우면 API 7 step 4가 안 가서 `REVIEWED`가 되지 않는다.
- 5막 장 이동
  - 대안 A: 탭은 자유 이동, 다음 장 버튼 유지(FE-43).
  - 대안 B: 다음 장은 종이 모서리로만 넘기고, 탭은 펼쳐 본 장까지만(사용자 결정).
- 확정 방식
  - 대안 A: "판결을 확정할까요" 확인 상자 + 버튼(FE-43).
  - 대안 B: 마지막 장에 정한 내용 · 주의사항 · 서명란, 서명으로 확정(사용자 결정).

## 선택한 방법과 이유
- 4막은 대안 A(사용자 결정). 3막 마지막 "판결로"와 S-04의 확정 뒤 이동을 S-06(판결 입력)으로 바꾸고, S-05에 들어오면 상태가 `REVIEWED`일 때 기록을 바꿔(`replace`) S-06으로 넘긴다. 막 칩 "4막"도 같은 경로로 5막에 도착한다. 4막 대본은 막 칩 이름 때문에 남겨 둔다.
- 4막 내용은 5막 첫 장 "사건 요약"으로 옮겼다. 데이터는 API 6(`review`)의 섹션 1(사건 개요)과 `summary`(핵심 사실)이고, API 6은 `PRE_JUDGED` ~ `REVIEWED`에서 열려 5막(`REVIEWED`)에서도 부를 수 있다. 판결 입력(API 8)과 함께 받되, API 6이 실패해도 판결은 할 수 있게 그 장만 안내 문구를 보인다.
- 3막 법률 안내 4장면 · 카드 2장(law · guide)을 지우고, 피고인 신문 끝에 마무리 두 줄을 넣었다(내로 검사 "이상으로 피고인 신문을 마치겠습니다." · 남불 변호인 "변호인도 추가 질문 없습니다."). 서버 진행 기록은 이 두 줄로 옮겼다(섹션 4 시작 = 검사 마무리, `confirm: 4` = 변호인 마무리). 남불은 A씨 자리에서 변호인 의상 · 자리로 돌아온 뒤 말한다.
- 5막 장은 사건 요약 → 참고 정보 → 판단 요소 → 최종 판결 → 확정. 다음 장은 종이 오른쪽 아래 말린 모서리(누르면 넘어감, 마우스를 올리면 넘실거림)로만 넘긴다. 탭은 펼쳐 본 장까지만 열리고, 아직 안 본 장을 누르면 탭이 짧게 움찔하며 화면 읽기 프로그램에 "모서리를 넘겨 주세요"를 알린다(`aria-disabled`).
- 확정은 서명. 서명란을 누르면 확정할 수 있는지 먼저 보고, 안 되면 사유를 보여 주며 서명란이 움찔한다. 되면 서명 획이 0.9초 동안 그려진 뒤 판결을 보낸다(되돌릴 수 없는 일이라 서명하는 순간을 눈으로 보게). 실패하면 서명을 지우고, 형량 범위 · 집행유예 오류는 최종 판결 장으로 돌아가 해당 칸에 포커스를 준다. 움직임 줄이기면 서명이 바로 나타난다.
- 5막 판결 진행 대사는 내로가 "법정 진행(서기)" 역할로 말한다. 5막에서 검사 역을 맡은 내로가 판사 역을 할 수 없어서(한 사건 한 배역 한 캐릭터) 새 역할을 뒀다. 전용 이미지가 없어 평상복 이미지 + "법정 진행" 이름표로 구분하고, 이미지 생성은 COMMON-44로 연계했다.
- 7막 시작의 "실제 재판부의 판결" 장면을 지웠다(판사 대사로 바로 시작).
- 1 · 2 · 8막 신문 무대의 조작 줄을 화면 맨 아래 가로 전체 종이 띠로 바꿨다. 캐릭터보다 위에 겹치고(발이 띠 뒤로), 안의 버튼은 대사창 폭에 맞춰 놓아 눈의 흐름이 대사창과 같다. 아이폰 홈 바 높이만큼 아래를 띄운다.
- 모바일: 탭 다섯 장이 한 줄에 들어가게 고른 장만 번호 + 이름, 나머지는 번호만 보인다(이름은 화면 읽기용으로 남김). 서명 줄의 "재판장" · "(서명)"은 줄바꿈하지 않는다.

## 대본 없는 사건 상세도 신문 지면 (FE-43 5차 조정에서 옮김)
- 사건 디테일(S-20)에서 대본이 없는 사건은 "오려 낸 기사" 카드(테이프 붙인 종이, 개요 · 사건 정보 상자)로 보였다. 대본 사건(1번)만 신문 지면이라 같은 신문에서 고른 기사인데 화면이 둘로 갈렸다.
- 모든 사건이 같은 신문 안쪽 면(`caseNewspaper`)을 쓰게 했다. 캐릭터 · 대사 없이 지면만 보이고, 기사 본문이 없으면 짧은 소개 한 단락만 싣는다(`paperFromCase`가 이미 그렇게 채운다. 없는 기사 문구를 지어내지 않는다).
- 버튼은 대본 사건과 같은 "시작하기"로 통일했다(하던 체험이면 오른쪽 귀 "이어서 하기" · "결과 다시 보기"). 동작은 그대로 API 2 응답 상태로 이어서 볼 화면으로 보낸다.
- 오려 낸 기사 그리는 코드와 스타일은 쓰는 곳이 없어져 지웠다. 자료를 불러오는 동안 · 오류일 때의 종이 한 장(`detail-clip`)만 남겼다.

## 고려한 제약 사항
- 서버 진행 상태 · API · 주소는 바꾸지 않았다(4막 S-05 주소 · `REVIEWED` 상태 유지).
- 확정 로직(보내는 값 · 형량 범위 · 집행유예 조건)은 FE-43과 같다. 바뀐 것은 확정을 부르는 방식(확인 상자 → 서명)이다.
- 목 데이터에는 1번 사건 개요만 있어 다른 사건의 "시작하기"는 목 모드에서 "찾을 수 없어요"로 끝난다(이전 코드도 같음).

## 추후 재검토가 필요하면
- 4막 주소 이름을 바꾸고 막을 다시 묶는 방식(사용자 결정: 추후 생각).
- 서기 전용 이미지가 생기면(COMMON-44) 5막 판결 진행 장면 이미지를 바꾼다.
- 모바일 실기기에서 말린 모서리 · 서명 · 하단 띠(홈 바 여백)를 확인하지 못했다.
