# FE-48 의사결정 기록

## 문제 / 배경
- FE-43(5막 파일철) 머지 뒤 판결 체험을 처음부터 끝까지 다시 돌려 보고 나온 흐름 개편 묶음이다.
- 3막 "법률 안내"와 4막 "판결 전 정리"가 5막 참고 정보와 겹쳤고, 5막은 버튼 · 확인 상자가 많아 서류에 서명하는 느낌이 약했다.
- 함께 반영: 5막 형량 칸이 잠기면 입력한 숫자를 비우는 수정, 대본 없는 사건의 사건 상세를 신문 지면으로 통일(아래).

## 검토한 대안
- 4막 처리
  - 대안 A: 4막을 막 칩 줄에 남기고 자동으로 건너뛴다. 서버 진행 상태(`REVIEWED` → S-05)와 주소는 그대로.
  - 대안 B: 4막을 없애 7막 구성으로 바꾼다. 서버 상태 · API · 주소 · 막 번호가 모두 바뀌어 별도 이슈 규모다.
- 3막 법률 안내를 지울 때 서버 진행 기록
  - 법률 안내 장면에 서버 진행 기록(섹션 4 시작 · `confirm: 4`)이 걸려 있었다. 그대로 지우면 API 7 step 4가 안 가서 `REVIEWED`가 되지 않는다.
- 5막 장 이동
  - 대안 A: 탭은 자유 이동, 다음 장 버튼 유지(FE-43).
  - 대안 B: 다음 장은 종이 모서리로만 넘기고, 탭은 펼쳐 본 장까지만(사용자 결정).
- 확정 방식
  - 대안 A: "판결을 확정할까요" 확인 상자 + 버튼(FE-43).
  - 대안 B: 마지막 장에 정한 내용 · 주의사항 · 서명란, 서명으로 확정(사용자 결정).

## 선택한 방법과 이유
- 4막은 대안 A(사용자 결정). 3막 마지막 "판결로"와 S-04의 확정 뒤 이동을 S-06(판결 입력)으로 바꾸고, S-05에 들어오면 상태가 `REVIEWED`일 때 기록을 바꿔(`replace`) S-06으로 넘긴다. 막 칩 "4막"도 같은 경로로 5막에 도착한다. 4막 대본은 막 칩 이름 때문에 남겨 둔다.
- 4막 내용은 5막 첫 장 "사건 요약"으로 옮겼다. 데이터는 API 6(`review`)의 섹션 1(사건 개요)과 `summary`(핵심 사실)이고, API 6은 `PRE_JUDGED` ~ `REVIEWED`에서 열려 5막(`REVIEWED`)에서도 부를 수 있다. 판결 입력(API 8)과 함께 받되, API 6이 실패해도 판결은 할 수 있게 그 장만 안내 문구를 보인다.
- 3막 법률 안내 4장면 · 카드 2장(law · guide)을 지우고, 피고인 신문 끝에 마무리 두 줄을 넣었다(내로 검사 "이상으로 피고인 신문을 마치겠습니다." · 남불 변호인 "변호인도 추가 질문 없습니다."). 서버 진행 기록은 이 두 줄로 옮겼다(섹션 4 시작 = 검사 마무리, `confirm: 4` = 변호인 마무리). 남불은 A씨 자리에서 변호인 의상 · 자리로 돌아온 뒤 말한다.
- 5막 장은 사건 요약 → 참고 정보 → 판단 요소 → 최종 판결 → 확정. 다음 장은 종이 오른쪽 아래 말린 모서리(누르면 넘어감, 마우스를 올리면 넘실거림)로만 넘긴다. 탭은 펼쳐 본 장까지만 열리고, 아직 안 본 장을 누르면 탭이 짧게 움찔하며 화면 읽기 프로그램에 "모서리를 넘겨 주세요"를 알린다(`aria-disabled`).
- 확정은 서명. 서명란을 누르면 확정할 수 있는지 먼저 보고, 안 되면 사유를 보여 주며 서명란이 움찔한다. 되면 서명 획이 0.9초 동안 그려진 뒤 판결을 보낸다(되돌릴 수 없는 일이라 서명하는 순간을 눈으로 보게). 실패하면 서명을 지우고, 형량 범위 · 집행유예 오류는 최종 판결 장으로 돌아가 해당 칸에 포커스를 준다. 움직임 줄이기면 서명이 바로 나타난다.
- 5막 판결 진행 대사는 내로가 "법정 진행(서기)" 역할로 말한다. 5막에서 검사 역을 맡은 내로가 판사 역을 할 수 없어서(한 사건 한 배역 한 캐릭터) 새 역할을 뒀다. 전용 이미지가 없어 평상복 이미지 + "법정 진행" 이름표로 구분하고, 이미지 생성은 COMMON-44로 연계했다.
- 7막 시작의 "실제 재판부의 판결" 장면을 지웠다(판사 대사로 바로 시작).
- 1 · 2 · 8막 신문 무대의 조작 줄을 화면 맨 아래 가로 전체 종이 띠로 바꿨다. 캐릭터보다 위에 겹치고(발이 띠 뒤로), 안의 버튼은 대사창 폭에 맞춰 놓아 눈의 흐름이 대사창과 같다. 아이폰 홈 바 높이만큼 아래를 띄운다.
- 모바일: 탭 다섯 장이 한 줄에 들어가게 고른 장만 번호 + 이름, 나머지는 번호만 보인다(이름은 화면 읽기용으로 남김). 서명 줄의 "재판장" · "(서명)"은 줄바꿈하지 않는다.

## 2차 조정 (사용자 피드백)
- **막 재구성(화면 표시만)**: 8막 → 6막(1 첫인상 · 2 재판 · 3 내 판결 · 4 AI 판결 · 5 실제 판결 · 6 세 판결 비교). 대본 · 코드의 막 번호(1 ~ 8)와 주소는 그대로 두고 막 칩만 묶었다(`ACT_GROUPS`). 막 번호를 지금 바꾸면 대본 · 테스트 · 목 데이터 · 막 이동이 함께 흔들려서, 주소 이름 변경 · 사건별 후기(`/summary` 자리)와 함께 **BE-82**에서 한 번에 정리한다. 막 이름은 화면 문구와 맞췄다("AI 판결" 표기 원칙, 6막 화면의 "내 판결 · AI 판결 · 실제 판결").
- **재판 진행 해설 = 볼따구**: 해설 장면에 작은 내로(피고인 신문 구간은 남불)가 대사창 위 모서리에 뿅 나온다(대본 `cameo`). 배역이 아니라 데포르메 모습이라 이름표는 "내로 볼따구"이고 같은 배역 규칙에서 빠진다. 볼따구 컷은 지금 `idle-thinking` · `idle-sorry` 두 표정뿐이라 `idle-thinking`을 쓴다.
- **말풍선 꼬리**: 상자 무대(재판 ~ 실제 판결)에서 꼬리를 이름표 안쪽(23%, 카드 장면 21%)으로 옮겨 겹치지 않게 했다(측정: 이름표 오른쪽 끝 < 꼬리 위치).
- **3막(구 5막) 판결 진행**: 판사 내로("이제 판결을 내려 주십시오. …"). 판사가 재판장(사용자)에게 "재판장께서"라고 하지 않게 문구를 다듬었다. 서기 역할이 없어져 COMMON-44는 삭제 예정.
- **4막(구 6막) AI 판결**: 남불 "이제 AI 판사의 판결을 확인해 볼게요."로 시작(AI 판사는 다음 장면에 등장), 끝은 내로 "AI 판사는 {형량}을 선고했어요." · 남불 "그렇다면 실제 판결은 어떨까요?". 형량 뒤 조사는 `objectParticle`로 붙인다.
- **3막 파일철 탭 규칙 변경**: 펼쳐 본 장의 **바로 다음 장까지** 탭으로 열린다. 확정 장은 판결이 다 정해졌을 때만 열린다(형벌 · 범위 안 형량 · 감경 후 형벌 · 집행유예를 체크했다면 기간). 집행유예를 체크하면 다시 잠기고 기간을 고르면 열린다. 잠긴 확정 장을 누르거나 최종 판결 장의 모서리를 넘기면 탭이 움찔하고 **빠진 칸이 반짝인다**(형벌을 안 골랐으면 "1. 형벌 종류"). "사유로 막기"(서명할 때 확정 불가 사유를 보여 주던 것)는 탭 단계로 앞당겨졌다.
- **해금 책갈피**: 새로 열린 장의 탭 앞에 내로 얼굴 책갈피(장식)를 끼운다. 캐릭터 고르기(마이페이지)는 후속.
- **서명 때 스크롤**: 서명 중 서명란을 `disabled`로 바꾸면 눌린 버튼이 포커스를 잃어(실제 마우스 클릭으로 확인) 화면이 튈 수 있었다. `aria-disabled`로 상태만 알리고 중복 누름은 `sign()`이 막는다.
- **캐릭터 크기**: 1막 신문 무대(키 300px, 발이 화면 아래로 50px)와 6막(키 210px, 20px 떠 있음)을 키 250px · 발이 하단 조작 줄 뒤로 조금 들어가게 같은 값으로 맞췄다.

## 3차 조정 (사용자 피드백, A 묶음)
- **2막 시작**: 빈 법정(캐릭터 숨김, 대본 `hideCast`)에서 0.5초 뒤 볼따구 내로와 대사가 함께 나온다(대본 `delay`). 앞 장면에서 넘어올 때만 기다리고, 움직임 줄이기면 바로 나온다.
- **볼따구 위치 · 효과**: 내로는 무대 가운데에서 조금 왼쪽 아래(40%), 남불은 가운데에서 오른쪽 · 조금 더 아래(62%, 가운데 피고인석의 A씨 역과 겹치지 않게 — 대칭으로 두지 않음), 이름표는 다른 대사와 같은 자리, 꼬리 없음. 나올 때 0.22초 · 사라질 때 0.16초 뿅.
- **가운데 꼬리**: 말하는 캐릭터가 가운데 피고인석(`spots: stand`)에 서 있으면 꼬리도 가운데(A씨 역 남불, 내로도 같은 규칙).
- **의상 유지 원칙**: 대사 · 이유 없이 의상을 바꾸지 않는다. 3막 판결 진행 · 판결 보드에서 남불이 최후진술 때 입은 A씨 역 의상을 그대로 입도록 대본에서 덮어쓰던 모습을 뺐다(테스트 추가).
- **4막 시작 데포르메 = 란마**: 낱장 컷이 없어 란마 시트의 두 번째 포즈(비스듬히 선 전신)를 잘라 배경을 지우고 `public/images/characters/deform/{naero,nambul}_ranma.webp`로 뒀다(look `deform:ranma`). 배역이 아니라 모습이라 이름표는 "남불 란마".
- **책갈피 = 진행 표시**: 펼쳐 본 가장 뒤 장의 탭 바로 뒤에 늘 끼워 두고(마지막 장이면 탭 줄 끝), 뒤로 넘겨도 자리를 지킨다. 서류철 가장자리를 넘어 종이 위까지 걸치게 내리고, 종이 위 여백을 늘려 제목과 아주 살짝 닿게 했다. 리본은 청동색(종이와 구분).
- **탭 키보드**: ←→로 옮기면 포커스가 탭에 남는 것을 실제 키 입력으로 확인했다.
- **서명 스크롤(원인 확인 · 해결)**: 서명이 끝나면 4막(AI 판결)으로 넘어가는데, 라우터가 화면을 바꿀 때마다 `window.scrollTo(0, 0)`을 해서 맨 위로 튀었다. 판결 화면과 4막 화면은 무대 자리가 같으므로 이 이동에만 `navigate(…, { keepScroll: true })`를 쓴다. 새 화면은 처음에 "불러오는 중"만 있어 문서가 짧아지며 스크롤이 0으로 깎이므로, 다 그린 뒤 원래 위치로 돌린다(640px 창에서 서명 전 143 → 넘어간 뒤 130).
- **서명 순간 카드 안쪽이 맨 위로(재보고, 1700px · 카드 안 스크롤)**: 테스트 환경(headless Chrome)에서는 재현되지 않았다. 서명하는 순간 일어나는 일은 상태 갱신(`update`)으로 정한 내용 목록을 통째로 다시 그리는 것과 버튼 상태 변경인데, 통째로 갈아끼우면 브라우저의 스크롤 기준점(scroll anchoring)이 사라져 위로 튈 수 있다. 두 가지로 막았다: ① 정한 내용이 그대로면 다시 그리지 않는다, ② 서명하는 동안(확정 요청이 끝날 때까지) 카드 안쪽 스크롤을 누른 순간 위치에 묶어 둔다(강제로 0으로 바꿔도 원래 자리로 돌아오는 것을 확인). 실제 환경에서 다시 확인이 필요하다.
- **판결 카드 키보드**: 카드가 열리면 포커스가 카드 전체(`board`)에 있어 ←→ · Space가 아무 일도 하지 않았다(무대는 입력 카드에서 키를 양보한다). 입력 카드가 `data-autofocus`로 첫 포커스를 정할 수 있게 하고, 판결 파일철은 지금 장의 탭을 고른다.
- **볼따구 크기 · 뿅**: 2.5배(무대 높이 19% → 47.5%). 나올 때 0 크기에서 발밑을 기준으로 커진다(사라질 때는 0으로).
- **6막 엔딩**: 선택지 `메인으로`(강조, 판사의 책상) · `여기 남아있기` · `리뷰하기` · `공유하기`. 리뷰하기는 사건별 후기 화면이 생기기 전까지 엽서 한 장이 떠오르는 임시 화면(BE-82 · 후속 이슈).
- **원클릭 `다른 사건 보기` 삭제(의도)**: 예전 마지막 선택지의 `다른 사건 보기`는 `메인으로`와 기능이 거의 겹쳐 뺐다. 사건 목록은 `여기 남아있기` 뒤 신문 왼쪽 귀 `← 다른 사건 보기`로 간다.
- **여기 남아있기 화면**: 제호 양옆 귀 — 왼쪽 "다른 사건 보기"(신문을 위로 접은 뒤 1면 S-02로), 오른쪽은 아직 정하지 않은 자리라 "고민 중" 메모만. 지면 맨 아래 "메인으로" 구역을 지우고 우하단에 떠 있는 "메인으로" 버튼을 뒀다. 누를 수 있는 칸은 마우스를 올리면 표시한다.

## 대본 없는 사건 상세도 신문 지면 (FE-43 5차 조정에서 옮김)
- 사건 디테일(S-20)에서 대본이 없는 사건은 "오려 낸 기사" 카드(테이프 붙인 종이, 개요 · 사건 정보 상자)로 보였다. 대본 사건(1번)만 신문 지면이라 같은 신문에서 고른 기사인데 화면이 둘로 갈렸다.
- 모든 사건이 같은 신문 안쪽 면(`caseNewspaper`)을 쓰게 했다. 캐릭터 · 대사 없이 지면만 보이고, 기사 본문이 없으면 짧은 소개 한 단락만 싣는다(`paperFromCase`가 이미 그렇게 채운다. 없는 기사 문구를 지어내지 않는다).
- 버튼은 대본 사건과 같은 "시작하기"로 통일했다(하던 체험이면 오른쪽 귀 "이어서 하기" · "결과 다시 보기"). 동작은 그대로 API 2 응답 상태로 이어서 볼 화면으로 보낸다.
- 오려 낸 기사 그리는 코드와 스타일은 쓰는 곳이 없어져 지웠다. 자료를 불러오는 동안 · 오류일 때의 종이 한 장(`detail-clip`)만 남겼다.

## 고려한 제약 사항
- 서버 진행 상태 · API · 주소는 바꾸지 않았다(4막 S-05 주소 · `REVIEWED` 상태 유지).
- 확정 로직(보내는 값 · 형량 범위 · 집행유예 조건)은 FE-43과 같다. 바뀐 것은 확정을 부르는 방식(확인 상자 → 서명)이다.
- 목 데이터에는 1번 사건 개요만 있어 다른 사건의 "시작하기"는 목 모드에서 "찾을 수 없어요"로 끝난다(이전 코드도 같음).

## 추후 재검토가 필요하면
- 주소 이름 · 막 번호(대본 키) 정리, 사건별 후기 페이지 — BE-82.
- 볼따구 컷 표정 추가(지금 두 표정), 책갈피 캐릭터 고르기(마이페이지).
- 모바일 실기기에서 말린 모서리 · 서명 · 하단 띠(홈 바 여백)를 확인하지 못했다.
