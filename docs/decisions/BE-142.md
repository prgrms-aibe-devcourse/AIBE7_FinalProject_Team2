# BE-142 의사결정 기록

> 근거: FE-138(로그인 전 마이페이지, 같은 브랜치 · PR). 계약은 API 명세 13장 I-1(v0.73)

## 문제 / 배경
- 로그인 전 마이페이지가 "일러스트 N장"을 보여 주려 한다. 화면의 대본으로 센 값은 사건 1건 분량뿐이고, 서버에는 일러스트 총량이 없다(서버는 대본을 모른다, API 명세 P-9).
- 김해송 결정(10/29 ~ 30): 총 일러스트는 **사건 컷과 아이콘을 포함한 모든 숫자**(루트의 대체 SVG 5개 · `desk-felt.webp` 배경은 제외)를 서버가 준다.
- 이미지는 `frontend/public/images`에만 있고(프론트 컨테이너가 서빙) 백엔드는 이미지 파일이 없다.

## 검토한 대안
- 목록 파일 + 어긋남 테스트(선택): 백엔드 리소스에 한 줄 한 장의 목록을 두고 줄 수로 센다
- 이미지 폴더를 서버가 직접 센다: 배포가 프론트 · 백엔드 컨테이너로 나뉘어 백엔드에는 그 폴더가 없다(공유 볼륨을 새로 만들어야 한다)
- DB 테이블: 이미지를 더할 때마다 마이그레이션이 필요하고 BE-60(main은 추가만) 규칙과도 번거롭다
- 설정 상수(숫자 하나): 이미지를 더해도 숫자를 잊으면 틀리고, 틀렸는지 알 방법이 없다
- 응답 위치: API 1 `summary`에 넣기 / **새 공개 API**(선택). API 1의 `summary`는 필터와 무관한 사건 건수(칩 옆 표시)용이라 성격이 다르다

## 선택한 방법과 이유
- 목록 파일(`illustration-images.txt`)은 `tools/illustrations/update-manifest.sh`로 만든다. 사람이 줄을 손으로 고치지 않아 실수가 없고, 전체를 다시 만들면 되어 간단하다.
- **어긋남은 CI가 막는다**: `IllustrationCatalogTest`가 목록과 이미지 폴더(`cases` · `characters` 아래 `.webp`)를 견주고, 어긋나면 스크립트를 실행하라는 메시지로 실패한다. 이미지만 바뀐 PR에서도 돌도록 backend CI의 `paths`에 `frontend/public/images/**`를 더했다(성향 OG 입력 `frontend/og/**`와 같은 방식, BE-73).
- 종류별 개수(`byKind`)는 파일이 든 폴더 경로로 센다. 화면은 지금 총 개수만 쓰지만, 값이 따로 필요해지면(예: 아이콘 몇 장) 응답을 바꾸지 않고 쓸 수 있다.
- 시작할 때 한 번 읽어 두고 요청마다 다시 세지 않는다. 이미지 폴더가 바뀌려면 새 배포가 필요하므로 값이 어긋날 일이 없다.

## 고려한 제약 사항
- 백엔드 테스트는 저장소 안에서(`backend` 폴더 기준 `../frontend/public/images`) 돈다(PersonalityContentSeedTest와 같은 전제). 백엔드만 따로 받아 테스트하는 환경에서는 이 테스트가 실패한다.
- 세는 범위(`.webp`, `cases` · `characters`)는 스크립트와 테스트가 같은 규칙을 쓴다. 범위를 바꾸면 둘을 함께 고친다.

## 현재 한계 (감수하기로 한 것, 10/30)
- 이 API의 총 개수는 **저장소 이미지 기준**이다. BE-141 규칙(DB 저장값 우선, 없으면 규칙 주소)을 따르지 않는다: 공개 여부를 보지 않아 비공개 사건의 컷 · 공용 컷 · `case-1.webp`도 세고, DB에만 있는(S3 업로드) 이미지는 세지 않는다. 마이페이지 컬렉션도 같은 한계다(화면에 박힌 대본의 사진 주소를 쓴다).
- 이 차이는 **감수한다.** 가능한 한 DB 기준으로 저장소를 최신화하는 것이 원칙이고, 관리자가 DB(S3)에 사진을 올릴 때 같은 파일을 저장소에도 올리고 목록을 갱신하면 어긋나지 않는다.
- DB 저장값 · 공개 사건 기준으로 바꾸는 일과 컬렉션 사진을 서버 값 기준으로 바꾸는 일은 **필수가 아닌 후속 이슈 BE-143**으로 묶어 두었다.

## 추후 재검토가 필요하면
- 이미지를 프론트 이미지와 분리해 CDN · 스토리지로 옮기면 목록 파일 대신 스토리지 목록을 센다.
- "모을 수 있는(컬렉션) 일러스트" 총량이 필요해지면 대본(사건 컷 · 의상) 기준으로 따로 센다. 이 API는 서비스의 모든 일러스트 수다.
