# BE-118 의사결정 기록

## 문제 / 배경
- 실제 판례 21건을 공개하기로 했다(10/28 팀 결정, "일단 전부 추가하고 근거를 더 모은 뒤 제외할 사건을 제외"). 사전 학습 의심 · 권리자 · 본인 요청 등으로 **공개한 뒤에 내려야 할 사건**이 생길 수 있다.
- 지금은 공개(A-13)만 있고 되돌리는 API가 없다(API 명세 8-2 "공개 취소는 이번 단계에 두지 않는다", 8-3 #2). 내리려면 DB를 직접 고쳐야 한다.
- 팀 결정(10/28): 2단계로 나눈다 — **1단계 숨김**(이번 이슈), **2단계 권리 요청에 따른 삭제(파기)**(정책을 정한 뒤).

## 결정
### 1. API — `POST /admin/cases/{caseId}/unpublish` (A-13-14)
- 본문 `{ "reason": "…" }`, 사유 필수 1 ~ 200자(앞뒤 공백 자름, A-10 반려 사유와 같은 방식). 왜 내렸는지 나중에 알 수 있어야 한다.
- 응답은 A-6과 같은 형식(A-13과 같음).
- 거절: 사건 없음 404 `CASE_NOT_FOUND`, 공개 중이 아님 409 `INVALID_STATE`(사유 코드 `CASE_NOT_PUBLISHED`, 기존 `CASE_PUBLISHED`와 같은 자리), 사유 문제 400 `VALIDATION_ERROR`(`reason`).
- 다른 상태 변경과 같이 사건 행을 먼저 잠근다(`findByIdForUpdate`) — 공개와 공개 취소가 동시에 들어와도 한쪽이 먼저 끝난 상태를 보고 판단한다.

### 2. 상태 — `PUBLISHED → REVIEW`, `published_at` 지움
- 새 상태(`HIDDEN` 등)를 만들지 않는다. 상태 CHECK · 관리자 목록 필터 · 화면 라벨을 모두 바꿔야 하고, "검수 중으로 돌아가 고친 뒤 다시 공개"라는 흐름이 `REVIEW`와 같다.
- `DRAFT`로는 돌리지 않는다 — 8-3 #3 "`REVIEW → DRAFT` 경로는 두지 않는다"와 같은 이유(누가 손댄 사건).
- `published_at`은 지운다. 다시 공개하면 그때 시각이 새로 기록된다. 언제 내렸는지는 감사 로그에 남는다.

### 3. 지우지 않는 것
- 사건 · 판단 요소 · 형벌 규칙 · 원본 정보 · 공개 판결(`judgment.is_published`) · 사진 · 지면 · 대본 · 사용자 체험 · 성향 기여 기록을 모두 그대로 둔다. 1단계는 **숨김**이다.
- 공개 판결을 그대로 두므로 다시 공개할 때 판결을 새로 승인할 필요가 없다(공개 조건은 A-13이 다시 판정).

### 4. 감사 로그 — `CASE_UNPUBLISH` (V34)
- `detail`에 `reason`을 남긴다. 대상은 `CASE` + 사건 ID.
- DB CHECK `chk_admin_audit_log_action`은 고쳐 쓸 수 없어 V34에서 지우고 전체 목록으로 다시 만든다(V32까지의 값 + `CASE_UNPUBLISH`). 앞 값을 빠뜨리면 그 행동의 기록이 운영에서야 실패하므로, **enum의 모든 값을 DB가 받는지 확인하는 테스트**를 같이 넣었다(`AdminAuditLogTest.constraints_acceptEveryAuditAction`).

## 공개 취소 뒤 사용자에게 보이는 것 (코드로 확인한 범위)
| 화면 · API | 공개 취소 뒤 | 근거 |
| --- | --- | --- |
| 사건 목록(API 1) · 사건 상세(API 16) | 사라짐 · 404 | `LegalCaseRepository`의 `PUBLISHED` 조건. 테스트로 확인 |
| 신문 지면(API 17) · 대본(API 18) | 404 | `findPublishedById` |
| 체험 진행 · 결과(API 2 ~ 15) | 404 `CASE_NOT_FOUND` — **이미 끝낸 체험의 결과도 다시 볼 수 없다** | `MyExperienceService.getMyExperience`가 사건 공개 여부를 먼저 본다 |
| 마이페이지 체험 이력 · 성향 기여 | **남는다**(사건 제목 포함) | `MyPageService`는 사건 상태를 보지 않는다. 이력에서 결과로 들어가면 위처럼 404 |
| 커뮤니티 | 해당 없음 | 서버 API 없음(목업) |

- 마이페이지에 제목이 남는 것은 1단계 범위 밖으로 둔다. 성향 점수는 체험 완료 시점에 고정 저장된 값이라(성향 산식 3-4) 숨김으로 바꾸지 않는다. 권리 요청으로 지워야 하면 2단계에서 함께 정한다.

## 확인 필요 (팀)
- **공개 취소 뒤 판결 교체**: `REVIEW`로 돌아가므로 판결 교체(A-9) · 내용 수정(A-11)이 다시 열린다. 판결을 바꿔 다시 공개하면 이미 체험한 사용자의 비교 결과가 바뀐다(8-3 #1 "공개한 사건은 판결 교체 금지"의 이유와 충돌). 1단계는 코드로 막지 않고 운영 규칙("내린 사건의 판결은 바꾸지 않는다, 바꿔야 하면 새 사건으로 적재")으로 둔다. 코드로 막으려면 "한 번이라도 공개된 사건" 표시가 필요하다(`published_at`을 지우므로 감사 로그나 별도 칸) — API 명세 8-3 #8.
- 관리자 화면(S-19)의 공개 취소 버튼 · 사유 입력은 프론트 이슈로 따로 둔다(FE-127).
- **공개 취소해도 판결 후보 승인은 남는다.** 승인 취소 API는 없고(반려는 공개 판결이 된 후보를 409로 막는다), 사건이 비공개인 동안 같은 주체의 다른 후보를 승인해야 바뀐다. 10/28 운영 공개 시험(#12)에서 확인 — 승인은 되돌릴 수 없는 동작으로 안내한다.

## 범위 밖
- 2단계 삭제(파기): 권리 요청 절차 · 지울 범위(사용자 체험 · 성향 기여 포함 여부) · 보관 기록 정책을 정한 뒤.
