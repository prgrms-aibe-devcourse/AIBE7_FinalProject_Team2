# FE-93 의사결정 기록

> 근거: 커뮤니티 화면 critique(28/40, 2026-10-26) · FE-89(`docs/decisions/FE-89.md`) · DESIGN.md "The 16px Input Rule" · PRODUCT.md 원칙 1

## 문제 / 배경
- critique에서 커뮤니티(메인 · 목록 · 상세)의 확실한 결함과 하나의 제품 문제가 나왔다.
  - 결함: 입력칸 13px(iOS 사파리 확대), 목 참여 수에 "목데이터" 표기 누락 · 딱지 대비 4.3 : 1, 남의 글 판결 카드에 "내 판결" 라벨, 추천 사건 제목이 링크가 아님, 프로필카드 글자 9.8px(시상대) · 4.8px(판결 클립 미니 카드).
  - 제품 문제: 사건을 아직 판결하지 않은 사람에게 남의 형량("징역 12년")이 먼저 보인다. "판단은 사용자의 것"(PRODUCT 원칙 1)과 부딪친다.

## 검토한 대안
- **판결 전 판결 카드**: A 지금처럼 보여 줌 / B 판결 전이면 숨김 / C 판결 전이면 접고 "그래도 보기"로 펼침. A는 앵커링을 그대로 두고, B는 이미 결과를 알고 온 사람까지 막는다. C는 기본값으로 앵커링을 줄이되 선택은 사용자에게 둔다.
- **판결 여부를 아는 방법**: ① 화면이 내 판결 목록을 따로 불러와 사건 id로 비교 / ② 글 응답에 `viewerJudged`(보는 사람이 그 사건 판결을 확정했는지)를 서버가 실어 줌. ①은 요청이 하나 늘고 목록 · 상세마다 비교 코드가 생긴다. ②는 화면이 값만 읽는다.
- **미니 성향카드 글자**: 카드 비율(`cqi`)을 바꿈 / 미니 카드를 장식으로 보고 글자로 대신 읽힘. 카드는 마이페이지 공용 컴포넌트라 비율을 바꾸면 다른 화면이 같이 바뀐다.

## 선택한 방법과 이유
- 판결 카드는 **C**(10/26 김해송 결정), 판결 여부는 **②**. `foldedVerdict(post, makeCard)`가 `viewerJudged === false`일 때만 접는다. 값이 없으면(필드가 없는 응답) 지금처럼 보여 준다.
- 라벨은 남의 글에서 "글쓴이 판결", 작성창 미리보기만 "내 판결"(`verdictCard`의 `label` 인자).
- 미니 카드는 `aria-hidden`(성향 이름은 이미 카드 옆 글자로 있다), 시상대 카드만 글자 하한 `max(11px, 9.1cqi)`를 커뮤니티 CSS에서 준다(공용 컴포넌트는 건드리지 않음).
- 목데이터 딱지의 `opacity: .85`는 지웠다. 11px 글자가 흐려져 대비가 AA 아래였다. 전역 스타일이라 사이트 전체 딱지가 조금 진해진다.

## 레벨 단상은 가장 큰 요소로 둔다 (제품 결정, critique 질문 반영)
- critique는 "판결은 경쟁이 아니다"는 서비스에서 레벨 순위 단상이 메인에서 가장 큰 요소여도 되는지 물었다. **그대로 두기로 했다.**
- 이유: 단상은 경쟁이 아니라 **동기 부여**(우리 콘텐츠를 더 많이 해 주길 바라는 마음)이고, 마이페이지에서 꾸민 카드를 **자랑할 자리**이기도 하다.
- 레벨 설계 방향: 레벨은 **커뮤니티 활동 60% · 판결 체험 40%**로 구성한다(성향과 무관은 그대로, FE-89). 아직 구현 전이고 레벨 산식은 BE와 확정한다.
- 따라서 단상을 "같은 사건에서 다른 사람들이 고른 요소" 비교표로 바꾸는 안은 이번에 채택하지 않는다.

## 빈 상태를 채웠다 (critique 질문 반영)
- 글 · 랭킹이 하나도 없는 첫 방문에서 슬라이드 섹션은 통째로 사라지고 랭킹은 한 줄 안내뿐이었다.
- 슬라이드 자리에 빈 스크랩 칸(어떻게 채워지는지 + 사건 목록 링크), 시상대는 빈 자리를 점선 카드로 남기고 안내 한 줄. 랭킹이 1 ~ 2명뿐인 중간 상태도 같은 방식으로 빈 자리를 보인다. 오른쪽 "많이 본 글"도 비면 안내 한 줄.
- 대안: 섹션을 아예 숨기기(지금까지) / 데모 콘텐츠로 채우기 / 빈 자리를 보여 주기. 숨기면 서비스가 비어 보이고, 데모는 가짜 활동을 만든다. 꾸민 카드를 올릴 자리를 보여 주는 쪽이 단상의 목적(동기 부여)과 맞다.

## 고려한 제약 사항
- 커뮤니티 API는 아직 목 전용이다. `viewerJudged`는 임시 이름이고, 목은 체험 기록이 사건 1 하나뿐이라 사건 1만 판결 여부를 본다. 실제 API 설계 때 BE와 이름 · 의미를 확정한다.
- `viewerJudged`의 실제 기준은 API 1 `myStatus`와 같게 둔다: 보는 사람의 익명 ID(쿠키) 기준으로 그 사건의 최신 체험이 판결 확정 이후인지, 로그인했다면 그 회원에 연결된 익명 ID까지 포함, 쿠키도 로그인도 없으면 `false`. 지금 목은 로그아웃이면 항상 `false`라 익명으로 판결을 끝낸 사람도 접히는데, 이는 목의 단순화다.
- 글 본문에 형량을 직접 쓴 경우는 접지 않는다. 판결 카드만 대상이다.

## 추후 재검토가 필요하면
- **목록 · 상세의 3열 포럼 틀과 SNS형 피드**를 집무실 은유(편지 더미 · 주석 달린 사건 파일 등)로 바꾸는 안은 후속 이슈 FE-94로 한다.
- 프로필카드 메모(`.my-card-note`)가 색 띠 위에서 3.5 : 1 — 공용 카드(`personCards.css`) 수정이 필요해 이번 범위에서 뺐다.
- 모바일 터치 크기(화살표 34px · 21px 높이 링크) · 필터 접기는 `adapt`로 따로 한다.
