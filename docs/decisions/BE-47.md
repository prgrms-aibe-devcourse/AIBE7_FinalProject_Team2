# BE-47 의사결정 기록

> 소급 작성(COMMON-39). 근거: PR #86 본문. 후속은 BE-48 · BE-49 기록.

## 문제 / 배경
- 판단 요소를 4개 가치관 축(사과와 진정성 · 잘잘못의 기준 · 원칙과 관계 · 질서와 기회)으로 분류해 성향 계산에 쓸 수 있어야 했다.

## 검토한 대안
- 대안 A: 임베딩으로 축을 분류한다.
- 대안 B: 판단 요소를 만드는 LLM 호출 안에서 분류까지 하고, 스키마 검증과 키워드 교차 확인으로 보완한다.

## 선택한 방법과 이유
- 대안 B(임베딩은 쓰지 않는다). 추출기 `extract-v5`가 요소마다 축을 반드시 고르게 하고(맞는 축이 없을 때만 null), 스키마에 `valueAxis`를 필수로 넣는다. null이거나 `summaryTag` 키워드와 어긋나 보이면 경고하고 최종값은 관리자가 고친다.
- `factor.value_axis`는 nullable + 4개 축 CHECK. 사전 판단(OVERVIEW)과 형량 선택은 성향 계산에서 제외하되, 제외는 계산하는 쪽에서 처리하고 컬럼에는 모든 요소의 값을 둔다.
- 축 값 목록은 `tools/ai-judgment/common.py` 한 곳에 두고 Java `ValueAxis` · V9 CHECK과 함께 고칠 곳을 주석으로 남겼다.

## 고려한 제약 사항
- 기존 사건 backfill(`R__15`)은 사건 내용이 들어가므로 공개 저장소에 두지 않고 비공개 저장소 PR에서 했다.
- 관리자가 축을 수정하는 API는 BE-43에서 한다. 그 전에는 컬럼이 nullable이라 DB에서 값만 바꾼다.
