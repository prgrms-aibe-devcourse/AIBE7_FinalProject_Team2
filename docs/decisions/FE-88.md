# FE-88 의사결정 기록

> 근거: PR #264 · FE-77(카드 공개) · DESIGN.md 스코프 테마 규칙

## 문제 / 배경
- 커뮤니티 글쓴이가 닉네임 + 책갈피 얼굴 하나로만 보여, 마이페이지에서 만든 프로필카드 · 성향카드 꾸미기가 남에게 보일 곳이 없었다.
- 두 카드는 커뮤니티에서 항상 공개로 이미 정해져 있다(`myProfileEdit.js`, 공개 성향카드는 `shownCard.js`).

## 검토한 대안
- **명함 모양**: A 두 장 나란히 / B 겹친 두 장(누르면 앞뒤 교체) / C 가로 명함 한 장 + 클립으로 꽂은 성향카드. A는 두 카드가 다 보이고 마이페이지 카드와 생김이 같다. B는 자리를 덜 쓰지만 뒤 카드가 가려진다. C는 새 모양이라 카드와 달라진다. 나무 받침(명함꽂이)은 시안에서 보고 뺐다.
- **카드 색**: 마이페이지에서 만든 그대로(커피) / 커뮤니티 색(네이비). 네이비로 하면 같은 꾸미기라도 성향카드 바탕이 달라져 "내가 꾸민 모습"이 아니게 된다.
- **노출 위치**: 상세만 / 상세 + 작은 창 / 목록 · 상세 · 작은 창 모두.

## 선택한 방법과 이유
- A안, 커피 색 그대로, 노출은 ① 목록 작은 명함 ② 상세 명함 칸 ③ 닉네임 · 작은 명함을 누르면 펼쳐지는 작은 창. 판결 공유 글은 내 판결 카드에 글쓴이 성향카드를 클립으로 꽂는다.
- 카드를 그리는 조각은 `components/personCards.js`로 떼어 마이페이지와 커뮤니티가 같은 코드를 쓴다(꾸미기가 어긋나지 않게).
- 커피 색은 마이페이지 전체가 아니라 카드 칸(`.cm-cards`) 안에서만 덮어쓴다(DESIGN.md 스코프 테마 규칙과 같은 방식). 꾸미기 색(`--deco-*`)은 `.my-page, .cm-cards`가 한 선언을 공유한다.
- 카드 꾸미기 창의 미리 보기 칸은 커뮤니티 명함 칸 바탕(`--palette-paper-50`)과 같게 해, 꾸미는 동안 남에게 보일 배경에서 본다.
- 작은 창은 브라우저 `popover`(auto)로 만든다: 바깥 클릭 · Esc 닫기와 맨 위 층 표시가 기본 제공된다.
- 성향으로 거르기 · 정렬 · 순위는 넣지 않는다(편 가르기 · 앵커링 방지).

## 고려한 제약 사항
- 커뮤니티 API가 아직 없어 목 전용이다. 글 · 댓글의 `author`에 `profileCard`(P-7 꾸미기 칸 + `portrait`) · `shownType`(`slot` · `type` · `deco`) · `intro` · `level` · `job` · `completedCount`가 붙는 모양을 목(`communityMockData.js`)에서 먼저 정했다. 실제 API를 만들 때 BE와 확정한다. 이때 **다른 사람에게 보일 칸 목록**도 함께 정한다: 두 카드의 공개는 FE-77에서 정했지만 한 줄 소개 · 레벨 · 직업 · 체험한 사건 수까지 공개할지는 아직 정한 곳이 없다(PR #264 리뷰).
- 레벨 · 직업 · 체험한 사건 수는 마이페이지(`MOCK_PROFILE`)처럼 서버 값이 없어 목이고, 명함 칸 제목 옆에 "목데이터"를 표기한다.
- 작은 카드(폭 160px 미만)는 그림 위 여백(200px 카드 기준 22px)을 폭에 비례해 줄인다(`portraitFit.js`에 옵션을 함수로 받는 길을 열었다).

## 화면 세 구간
- 넓은 화면(≥ 1024px) 3열 / 좁은 화면(721 ~ 1023px) 1열 · 글쓰기는 덮는 창 / 모바일(≤ 720px) 1열 + 명함은 카드 위 · 소개 아래, 작은 창은 아래에서 올라오는 판, 말머리 · 사건 딱지는 닉네임 아래 줄, 판결 클립 카드 축소.
- 좁은 화면은 2열(타임라인 + 글쓰기 칸)도 검토했으나 일단 1열로 둔다(범위가 커지고, 본문 폭 700px 안팎이면 명함이 넓은 화면 배치 그대로 들어간다).
- 720px은 공통 헤더가 두 줄이 되는 경계와 같게 맞췄다.

## 추후 재검토가 필요하면
- 좁은 화면 2열 배치.
- 실제 기기(iOS Safari 등)에서 아래 판(`popover`)과 안전 영역(`env(safe-area-inset-bottom)`) 확인.
- 공개 성향카드를 서버가 내려줄 때 이미지 번호(내로 · 남불 대역) 선택 방식은 `personalityMockApi.js`와 같은 규칙을 따른다.

## 2차 (후속 PR)

### 문제 / 배경
- PR #264 머지 뒤 화면을 다듬으며 나온 것: 좁은 화면에서 위 칸과 글 목록이 구분되지 않음, 사건 거르기 목록이 길어질수록 고르기 어려움, 작은 카드(명함 작은 창 · 판결 클립 · 랭킹)에서 아치 그림 창만 짧아짐, 사파리에서 글쓴이 작은 창이 화면 끝까지 늘어남.

### 검토한 대안
- **사건 거르기**: 고르기 목록(select) 유지 / 검색창 + 아래 결과 목록. 사건이 늘면 목록이 길어져 검색창으로 바꿨다. 결과 정렬은 제목이 단어로 시작하는 사건 먼저(나머지는 원래 순서). 가나다순 · 글 수 순은 앞 일치가 묻히거나 인기 사건 쏠림이 생겨 뺐다.
- **작은 카드 비율**: 작은 카드용 칸 크기를 따로 정하기(1차 방식, 크기마다 손봐야 함) / 카드 안 칸 · 여백을 모두 카드 폭 비례로. 비례로 바꿨다.
- **사파리 작은 창**: 위치(아래 · 오른쪽)만 비우기로는 그대로였다. 카드 높이까지 px로 박고, popover 기본 `overflow: auto`를 끄는 쪽을 택했다.

### 선택한 방법과 이유
- 카드 자신의 `padding`은 자기 폭(cqi)을 쓸 수 없어(%는 부모 폭 기준) 0으로 두고, 이름 · 그림 창 · 한 줄 칸이 cqi 마진으로 여백을 갖는다. 줄 높이는 `aspect-ratio`가 정한 높이를 fr로 나눈다. cqi 기준이 안쪽 170px → 198px로 바뀌어 글자 · 책갈피 값을 같은 px가 나오게 다시 계산했다(200px 카드는 이전과 같다). 66 ~ 240px에서 그림 창 비율이 0.641 ~ 0.647로 같다.
- 성향카드 그림도 프로필카드처럼 가로로 긴 그림은 창 세로 가운데에 둔다(`centerWide`).
- 글쓴이 작은 창은 카드 두 장 위 · 소개 아래의 240px 상자. 사파리가 grid 안 `aspect-ratio` 카드 높이를 크게 잡아 상자가 늘어나므로 작은 창 카드는 높이까지 px로 준다.

### 고려한 제약 사항
- 카드 스타일은 FE-79에서 `components/personCards.css`로 옮겨졌다. 이 PR의 카드 수정은 그 파일에 들어간다.
- 사파리는 헤드리스로 확인할 수 없어 사용자 확인에 기댄다.
