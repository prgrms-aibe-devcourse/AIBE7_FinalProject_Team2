# COMMON-41 의사결정 기록

## 문제 / 배경

2026-10-16 자동화 파이프라인 구성 계획 회의에서, 확장 단계 "서비스 안 생성 파이프라인"(REQ-040 ~ 045)에 신문 지면 콘텐츠 생성과 사건 스크립트 생성을 추가로 검토하기로 했다. 이때 사건 사진은 "AI가 직접 생성하지 않고 이미지 생성용 프롬프트만 제공하는 방식"으로 잠정 검토했었다(v5.13, `ai-judgment-pipeline.md` v2.5).

이번 COMMON-41에서는 이 세 콘텐츠(신문 지면·사건 스크립트·사건 사진)의 구체적인 범위와 방식을 확정했다. 담당: C 백승호(`docs/wbs.md` v1.27).

## 검토한 대안

### 1. 신문 지면 · 사건 스크립트의 데이터 구조

- **대안 A — 새 스키마를 설계한다.** 콘텐츠 종류별로 별도 데이터 구조를 처음부터 만든다. 자유도는 높지만, 프론트가 이미 구현해 쓰고 있는 구조와 이원화되어 프론트 수정 비용이 커진다.
- **대안 B(선택) — PR #138(`frontend/src/content/case-1/script.json`)의 구조를 재사용한다.** 이 파일에는 이미 신문 지면용 `paper`(headline·deck·photo·caption·article·extraPhotos) 필드와, 내로·남불 대사용 `acts.steps`(say·text·look·focus·choices 등) 필드가 정의되어 있고 프론트 렌더러(`stage.js`)가 이를 소비하는 중이다. 생성 파이프라인이 이 구조 그대로 JSON을 출력하면 프론트 쪽 수정 없이 바로 연결할 수 있다.

### 2. 사건 사진 생성 방식

- **대안 A — 프롬프트만 생성하고 사람이 직접 이미지 생성 도구를 돌린다(v5.13 검토안).** AI 호출 범위를 좁게 가져갈 수 있지만, 사건이 늘어날수록 사람이 매번 프롬프트를 받아 수동으로 이미지를 생성·검수·업로드해야 해서 "자동 생성 파이프라인"의 취지와 어긋난다.
- **대안 B — 기존 "재연 컷" 방식처럼 내로·남불이 사건 당사자를 직접 연기한다.** 지금 공용 재연 컷 · 사건별 재연 컷(`character/cuts/reenact/`)이 이 방식이다(README 기준 "사건 1 = 남불이 A씨, 내로가 B씨" 식 역할 순환). 그림체 일관성은 보장되지만, 사람이 사건마다 역할·의상을 정해 수작업으로 그려야 해서 자동 생성과는 맞지 않고, 마스코트가 실제 사건(특히 강력범죄)의 가해자·피해자를 직접 연기하는 모양이 되어 부담스럽다.
- **대안 C(선택) — Cloudflare AI(Workers AI)로 직접 생성하되, 등장인물은 얼굴 없는 회색 엑스트라로 그린다.** 사람 수작업 없이 파이프라인이 사진까지 바로 만들 수 있고, 엑스트라를 익명·무표정 회색 인물로 한정해 ① 내로·남불이 사건을 연기하는 모양을 피하고 ② 특정 인물처럼 보일 수 있는 구체적 얼굴 생성을 애초에 배제한다. 내로·남불은 이 사진들에는 등장시키지 않고, 기존처럼 스크립트 대사 화면 등 다른 화면에서만 계속 등장시킨다.

## 선택한 방법과 이유

- **신문 지면 · 사건 스크립트**: 대안 B. `script.json`의 `paper` · `acts.steps` 구조를 그대로 재사용한다.
  - 신문 지면: 메인 화면에서 신문을 눌렀을 때 사건 사진 옆에 보이는 작은 요약 글(헤드라인·부제·캡션·본문).
  - 사건 스크립트: 내로·남불이 주고받는 대사(`say` 화자 ID·`text` 대사·`look` 표정/포즈·`choices` 선택지 등 기존 필드 그대로).
- **사건 사진**: 대안 C. Cloudflare AI로 직접 생성한다.
  - 신문용 **사건 대표사진**과 사건 안에서 쓰는 **사건 발단 사진** 두 종류를 만든다.
  - 그림체는 내로·남불 세계관(따뜻한 색감·플랫 셰이딩·종이 질감 배경)에 맞추되, 등장인물은 **얼굴 없는 회색 인간(엑스트라)**으로 그린다.
  - 내로·남불 본인은 이 사진들에 넣지 않는다.

## 고려한 제약 사항

- 내로·남불은 고양이·불꽃 마스코트라 사람 그림체(엑스트라)와는 별개 디자인이다. 프롬프트에서 "내로·남불 세계관과 같은 전체 톤(배경·채색)"과 "엑스트라는 디자인된 캐릭터가 아닌 익명 인물"을 분명히 구분해 지시해야, 두 그림체가 한 화면에서 어색하게 섞이지 않는다.
- 사용할 Workers AI 모델은 아직 정하지 않았다. 참조 이미지 입력 지원 여부는 모델별로 다르며, `@cf/black-forest-labs/flux-2-dev`는 최대 4개의 참조 이미지를 지원한다. 텍스트 프롬프트만 사용하기로 결정한다면 이는 Workers AI의 공통 제약이 아니라 COMMON-41의 프로젝트 선택으로 기록해야 한다. 그 경우 기존 샘플 이미지(`peanutboi710/NaeLawNamBul_Images`)를 보고 스타일을 글로 정의하는 작업이 필요하다.
- 기존 "재연 컷"(내로·남불이 사건을 연기하는 방식)은 폐기하지 않고 그대로 남긴다. 이번 결정은 **새로 추가하는 "사건 대표사진"·"사건 발단 사진"에 한정**되며, 기존 재연 컷의 역할·용도와는 구분해서 봐야 한다.

## 추후 재검토가 필요하면

- 구체적인 REQ 신설 여부, 생성 시점(오프라인 파이프라인 vs 서비스 안 실시간), 담당 Agent, 데이터 구조(저장 위치·필드명)는 이 문서에서 다루지 않았다. COMMON-41의 남은 완료 조건(`requirements-specification.md`·`ai-judgment-pipeline.md` 반영, 이번 커밋으로 처리)과 별개로, 실제 구현 설계는 후속 이슈에서 정한다.
- Cloudflare AI 호출 비용·요청 한도·응답 시간은 검토하지 않았다. 실제 연동 전에 확인이 필요하다.
- "얼굴 없는 회색 엑스트라" 프롬프트의 구체적 문구(인체 비례, 포즈, 표정 유무 등)는 아직 정하지 않았다. 실제 생성 테스트를 하면서 다듬어야 한다.

## 재검토 (BE-91 PR #202 — 사건 사진 "AI 직접 생성" 결정 재뒤집기)

위 "대안 C"(Cloudflare AI 직접 생성)를 실제로 구현(BE-89·BE-91)해 호출해 보니, 그림 품질이 사건 내용을
반영하지 못할 정도로 기대에 못 미쳤다. 그래서 사건 사진만 다시 **대안 A 방향(프롬프트만 제공)**으로
되돌렸다 — 다만 "사람이 프롬프트를 받아 수동으로 이미지를 생성·검수·업로드"하는 흐름 자체를 실제로
구현했다는 점이 v5.13/대안 A 검토 때와 다르다(그때는 구현 없이 방향만 적어 뒀다).

- **신문 지면 · 사건 스크립트 결정(대안 B, `script.json` 구조 재사용)은 그대로 유지한다.** 이번 재검토는
  사건 사진에만 해당한다.
- 프롬프트는 영문이 아니라 **한글**로 짓는다 — AI가 이미지를 직접 만들지 않고 사람이 참고할 문구만
  주므로, 모델의 언어 제약에서 자유롭다.
- 프롬프트는 관리자가 매번 설명을 적는 게 아니라, **사건의 `overview`·`factor`·`chargeName`을 Gemini가
  읽고 자연스러운 한글 프롬프트로 지어준다.** "얼굴 없는 회색 엑스트라" · 내로·남불 미등장 규칙은 그대로
  유지하되, 지시문에 고정 문구로 넣는다.
- 상세 구현 의사결정(스키마 변경, Gemini 클라이언트, S3 업로드 API 설계)은 `docs/decisions/BE-91.md`
  "재검토" 절을 본다.
