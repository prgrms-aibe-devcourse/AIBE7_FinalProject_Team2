# FE-165 의사결정 기록

## 문제 / 배경
- BE-167로 내 글 삭제 API(`DELETE /community/posts/{id}`)가 생겨, 글 상세에 삭제 버튼이 필요하다.
- 삭제는 되돌릴 수 없고 댓글 · 좋아요도 함께 사라져서 실수로 누르면 피해가 크다.

## 검토한 대안
- 확인 방식: (A) `window.confirm` → 프로젝트 화면 톤과 안 맞고 포커스 · 접근성 제어가 어렵다. (B) 모달 대화상자 → 파괴적 동작 하나에 비해 무겁고 포커스 가두기 · 스크롤 잠금이 따라온다. (C) 같은 자리에서 확인 상자로 바뀌는 인라인 확인 → 화면 이동 없이 가볍고 기존 `.cm-action` 줄에 그대로 들어간다.
- 삭제 뒤 이동: (A) `push` 이동 → 뒤로 가기로 지운 글(404)에 돌아온다. (B) `replace` 이동 → 기록에서 글 상세가 빠진다.
- 목 모드 XP: (A) 서버처럼 XP도 거두기 → 목 레벨 저장소 구조(`given` · `daily`)를 건드려야 해 범위가 커진다. (B) 목은 글 · 댓글 · 좋아요만 지우기.

## 선택한 방법과 이유
- 확인은 (C): 확인 상자가 열리면 포커스를 안전한 "취소"에 두고, 취소 · Esc는 삭제 버튼으로 돌려준다.
- 이동은 (B) `replace`.
- 목은 (B): 서버와 다른 점(XP 미회수)은 목 함수 주석에 적었다.
- 내 글 판별은 서버가 주는 `post.mine`만 쓴다(프론트가 닉네임으로 추측하지 않는다). 서버가 403으로 다시 막는다.

## 고려한 제약 사항
- 모바일(≤720px) 조작 44px 이상(FE-158), 호버는 `(hover: hover) and (pointer: fine)` 안에서만(터치는 `:active`).
- 관리자 화면 삭제 버튼(A-42)은 이 이슈 범위 밖.

## 추후 재검토가 필요하면
- 실제 서버 연결 상태의 브라우저 확인(403 · 404 안내 문구)은 아직 못 했다. 단위 테스트는 목 API 계약만 덮는다.
