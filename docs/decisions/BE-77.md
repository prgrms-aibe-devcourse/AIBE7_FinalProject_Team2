# BE-77 의사결정 기록

> 근거: [PR #198](https://github.com/prgrms-aibe-devcourse/AIBE7_FinalProject_Team2/pull/198) · [정민석님 리뷰](https://github.com/prgrms-aibe-devcourse/AIBE7_FinalProject_Team2/pull/198#pullrequestreview-5579743940)

## 문제 / 배경

- 초기 요구는 진행 중에도 1막부터 다시 보기의 엽서를 복원하도록 API 3에 사전 판단 구간을 추가하는 것이었다. 이에 따라 전용 DTO·조회·테스트와 조기 공개 예외를 작성했다.
- PR #198 리뷰에서 기존 핵심 기획인 “사전 판단은 최종 비교에서 처음 공개”와 충돌하고, 조기 공개 예외에 대한 합의 근거가 없다는 지적을 받았다.
- 2026-10-20 팀 논의 결과를 사용자가 이번 수정 요청으로 전달했다. 확정 규칙은 진행 중 재조회 금지, 1막부터 다시 보기 삭제, 완료 후 결과 화면의 독자 의견에서 처음 선택한 형량 공개, 재판부 비교 방향의 서버 계산이다. 별도 회의록·Jira 댓글 링크는 이번 요청에 제공되지 않았다.

## 검토한 대안

- API 3 조기 공개 유지 또는 특정 진행 상태부터 허용: 최신 기획의 진행 중 재조회 금지와 맞지 않아 채택하지 않는다.
- PRE 기록 누락 때 null을 반환하며 상태 조회 유지: 리뷰 제안이지만 사전 판단 필드 자체를 철회하므로 별도 예외 처리가 필요하지 않다.
- 프론트 label 파싱 유지: 문구 변경에 취약하고 기존 서버 비교 규칙과 중복되므로 채택하지 않는다.

## 선택한 방법과 이유

- API 3 변경을 철회한다. API 2·3은 기존 `ExperienceResponse`의 5개 상태 필드를 공유하고, `ExperienceService.getMyExperience()`는 소유권을 검증한 체험을 DTO로 변환하는 기존 읽기 전용 구현으로 복원한다.
- API 3 전용 DTO·테스트·JudgmentRepository 의존성을 제거한다. 상태 조회에서 PRE 기록을 읽지 않으므로, 그 기록이 누락돼도 추가 필드 때문에 상태 조회까지 500으로 실패하지 않는다. API 14의 데이터 불일치 정책은 바꾸지 않는다.
- API 3은 완료 여부와 관계없이 사전 판단·AI·재판부 판결·비교 결과를 응답하지 않는다. 처음 선택한 형량은 COMPLETED 이후 API 14로 결과 화면의 독자 의견에서 확인한다.
- API 14 최상위 `preToCourt.direction`은 유지한다. 이미 조회한 PRE와 COURT에 `PreToFinalDirection.of()`를 적용하므로 추가 판결 조회나 새 계산 규칙이 없다.
- **재판부가 더 무거우면 HEAVIER**, 더 가벼우면 LIGHTER다. SAME은 같은 형벌 종류 및 사전 판단 구간에 속한다는 뜻이며 정확히 같은 형량을 뜻하지 않는다. 기존 프론트 PRE_HEAVIER/PRE_LIGHTER와는 관점이 반대다.

## PR #198 리뷰 반영

1. 핵심 규칙 합의 근거: 위에 사용자 전달 팀 결정의 날짜·내용·출처 한계를 기록하고 조기 공개 예외를 철회했다.
2. PRE 누락 시 상태 조회 500: API 3의 PRE 조회 자체를 제거하고 상태 조회가 정상 응답하는 회귀 테스트를 추가했다. API 14의 기존 불변식은 유지한다.
3. 방향 관점: [API 명세](../api-specification.md) API 14에 “재판부가 더 무거우면 HEAVIER”를 명시했다.
4. 프론트 후속: API 3 Mock에 사전 판단을 추가하던 계획은 취소한다. 1막부터 다시 보기 UI·불필요한 캐시 복원 제거, API 14의 기존 사전 판단 표시 유지, Real/Mock `preToCourt` 및 편집부 의견·대사 연동이 후속 범위다.
5. 표현·형식: 문서 상단에 PR 근거를 추가했다. 철회된 테스트의 반복 FQN 사용은 파일 삭제로 제거되고 새 회귀 테스트는 static import를 사용한다. 커밋 메시지·squash 제목 변경은 Git/PR 변경 금지에 따라 이번 작업에서 수행하지 않는다.

## 고려한 제약 사항

- 공개 시점·상태 전이·판단 수정 금지·성향 산식·스키마·마이그레이션은 변경하지 않는다. BE-77이 추가한 API 3 예외만 문서에서 제거하고 API 14 계약과 여러 줄 응답 예시는 유지한다.
- 프론트 파일은 수정하지 않는다. 정책 확정과 실제 프론트 반영은 별개이며, 원격 develop과 담당자의 실제 작업 브랜치 상태는 조사 결과에서 구분한다.
- 테스트는 BE-87 전용 PostgreSQL·Redis 및 Gradle/초기화기 보호 설정을 유지한다. 개발 DB·비공개 자료를 사용하지 않는다.

## 검증

- API 2·3의 전체 상태에서 기존 5개 필드만 반환하며, 저장된 PRE가 있어도 판단 정보가 노출되지 않는지 검증한다.
- API 3에서 PRE 누락이 상태 조회를 막지 않는지 검증한다. 기존 소유권·상태 불변 테스트도 유지한다.
- API 14의 방향·경계·집행유예·형벌 종류·감경·label 독립성 테스트와 COMPLETED 이전 차단 테스트는 유지한다.
- 초기 구현의 전체 632건 통과 기록은 API 3 철회 전 결과다. 최종 수정의 실제 실행 결과는 아래에 별도로 기록한다.
