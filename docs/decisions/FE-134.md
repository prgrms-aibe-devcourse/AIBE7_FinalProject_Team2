# FE-134 의사결정 기록

공개 로그인 화면의 관리자 로그인 안내 문구 정리 (FE-117 후속). 담당 D(정민석). BE-134 · FE-133 · FE-135와 한 PR.

## 문제 / 배경

- 2026-10-29 운영 점검: 일반 사용자 `/login`의 아이디 칸 아래에 "회원 아이디에는 @가 없어요. 관리자는 이메일로 로그인해요."가 보였다(PR #308 리뷰로 넣은 문구).
- 일반 사용자에게 필요 없는 정보이고, 관리자 계정이 이메일이며 같은 칸으로 로그인된다는 것을 외부에 알려 준다. 관리자 API는 비로그인 · 회원 토큰 모두 401이라 보안 구멍은 아니다 — 노출 정보를 줄이는 개선이다.

## 검토한 대안

- **A안 — 문구만 정리(선택)**: 안내를 회원 기준 "가입할 때 만든 아이디를 입력해 주세요."로 바꾼다. 관리자는 지금처럼 같은 칸에 이메일을 넣는다. 로그인 동작은 바뀌지 않는다.
- B안 — 관리자 로그인 화면 분리(`/admin/login`): 라우팅 · API 분기 · 관리자 세션 처리까지 바뀌어 범위가 크다. 지금 문제(공개 화면의 안내)는 A안으로 풀린다. 필요해지면 별도 이슈로 본다.

## 선택한 방법과 이유

- 원래 문구의 목적(회원이 이메일을 넣어 관리자 로그인으로 가는 실수 줄이기)은 잃는다. 회원 아이디는 영문 · 숫자 · 밑줄이라 이메일을 넣을 일이 드물고, 넣으면 "아이디 또는 비밀번호가 맞지 않아요"가 나와 다시 확인하게 된다.
- 관리자 로그인 방법은 공개 화면이 아니라 팀 문서(`frontend/src/pages/login/README.md` "관리자 로그인 방법")에 남겼다.
- 개발용 목 모드 안내("@가 있는 아이디는 관리자")는 목 모드에서만 보여 그대로 둔다.
