# BE-132 의사결정 기록

> 담당 정민석 (D) · 관련: BE-4(공통 에러 응답)

## 문제 / 배경
- 2026-10-29 운영 점검에서 없는 API 주소(404) · 지원하지 않는 메서드(405) · 지원하지 않는 Content-Type(415)이 HTTP 상태는 맞지만 본문 `code`가 모두 `VALIDATION_ERROR`("요청 값이 올바르지 않습니다.")로 내려왔다.
- 원인: BE-4 리뷰 때 Spring MVC 예외를 `handleExceptionInternal` 한 곳에서 받도록 바꾸면서(빠뜨린 예외가 500으로 새지 않게), "API 명세에 대응 코드가 없다"는 이유로 4xx를 모두 `VALIDATION_ERROR`로 통일했다. 그 뒤 Spring 6.1부터 없는 주소도 `NoResourceFoundException`으로 이 통로를 지나게 되었다.
- 화면 · 로그에서 잘못된 경로 호출이 입력값 오류로 읽힌다.

## 검토한 대안
- 대안 A: `NoResourceFoundException` · `HttpRequestMethodNotSupportedException` · `HttpMediaTypeNotSupportedException`마다 `@ExceptionHandler`를 둔다. `ResponseEntityExceptionHandler`가 이미 같은 예외를 처리하고 있어 두 군데가 겹치고(같은 예외의 핸들러 중복은 시작 오류가 난다), BE-4 리뷰의 "한 곳으로 통일" 방향과도 어긋난다.
- **대안 B(선택): `handleExceptionInternal`은 그대로 두고, 4xx일 때 상태 코드로 에러 코드를 고른다**(404 · 405 · 415만 따로, 나머지 4xx는 `VALIDATION_ERROR`). 한 곳 통일 · 405 `Allow` 헤더 유지 · 500으로 새지 않음을 모두 지킨다.

## 선택한 방법과 이유
- `ErrorCode`에 `NOT_FOUND` · `METHOD_NOT_ALLOWED` · `UNSUPPORTED_MEDIA_TYPE` 추가, `ApiExceptionAdvice.codeFor(statusCode)`로 고른다.
- HTTP 상태 코드는 바꾸지 않는다. 바뀌는 것은 본문 `code` · `message`뿐이다.
- 도메인 404(`CASE_NOT_FOUND` · `EXPERIENCE_NOT_FOUND` 등)는 `BusinessException`이라 이 통로를 지나지 않아 그대로다.
- 406(Accept 불일치)처럼 본문을 실을 수 없는 경우 · 그 밖의 4xx는 지금처럼 `VALIDATION_ERROR`다.

## 고려한 제약 사항
- 화면은 이 세 경우를 개발 오류로 보고 일반 오류 안내를 띄우므로, 코드가 바뀌어도 화면 동작은 같다(프런트에 `VALIDATION_ERROR`로 분기해 경로 오류를 다루는 곳이 없음을 확인).
- API 명세 이력 번호: v0.63은 BE-83(PR #335)이 쓰고 있어 v0.64를 썼다. 먼저 머지되는 쪽이 번호를 갖는다.
