# BE-163 의사결정 기록

BE-159(PR #414) 리뷰에서 나온 후속이다. 관리자 블록 재생성을 반영할 때, 다시 만들지 않은 블록의 검수 결과(`review`)를 어디까지 갱신할지 정한다.

## 문제 / 배경

- 블록 재생성(BE-129 2차)은 고른 블록과 그 뒤 블록만 다시 만든다. 파이썬은 대본 전체를 검사하지만, 결과의 `review`에는 다시 만든 블록의 항목과 `REVIEW_FAILED`만 담는다. 백엔드는 반영(A-13-17) 때 다시 만든 블록의 `review`만 바꾼다.
- 그래서 다시 만들지 않은 블록의 `review`는 그 블록을 만들 때 계산한 값으로 남는다. 다음 경우에 관리자 화면이 실제와 어긋난다.
  - 그 뒤에 검사가 추가됐다. 예: BE-159의 `CARD_LIST_INVALID` · `CARD_LIST_EMPTY`. U4만 다시 만들면 기존 U2의 빈 카드 경고가 보이지 않는다.
  - 앞 블록이 바뀌었다. 예: `cascade: false`로 U0만 다시 만들면, U2의 신문 질문 대응 경고(`ISSUE_QUESTION_MISMATCH`)는 옛 U0 기준으로 남는다.
- 지킬 결정이 있다. 재생성이 만들지 않은 블록의 오류를 덮어써 **승인된 블록을 "오류 블록"으로 만들면 안 된다**(PR #378 리뷰, `script_regenerate.py` 모듈 설명). 블록에 오류가 있으면 `publishable`이 거짓이 되고 승인할 수 없다.

## 검토한 대안

- 대안 A, 다시 만들지 않은 블록의 `review`를 통째로(오류 + 경고) 새 값으로 바꾼다: 가장 정확하다. 하지만 승인된 블록에 새 오류가 붙으면 그 블록의 `publishable`이 거짓이 되고, 공개 중인 사건은 관리자가 고르지 않은 블록 때문에 공개 조건이 깨진다. 위 결정과 정면으로 어긋난다.
- 대안 B, **경고만** 새 값으로 바꾸고 오류는 그대로 둔다: 경고는 공개 · 승인을 막지 않으므로 승인 상태 · `publishable`이 바뀌지 않는다. 새 검사와 바뀐 앞 블록에 따른 경고는 화면에 나타난다. 다만 새로 생긴 **오류**(예: 사건 내용을 고친 뒤 입력에 없는 숫자)는 여전히 보이지 않는다.
- 대안 C, 새 오류는 승인하지 않은 블록에만 붙인다: 승인 여부에 따라 같은 오류가 보였다 안 보였다 해서 관리자가 헷갈린다. 승인한 블록이 나중에 반려되면 그 사이의 오류가 사라진 채 남는다.
- 결과에 실을 위치:
  - 기존 `review`에 섞기: 백엔드가 블록 단위 항목을 이미 걸러 내고(`REVIEW_FAILED`만 대본 전체 `review`로 저장), 파이썬 계약("다시 만든 블록 것만")을 바꿔야 한다.
  - 새 필드 `unchangedWarnings`(`{단위: [경고]}`): 옛 계약을 그대로 두고, 이 필드가 없는 옛 결과(파이프라인 배포 전)는 지금처럼 동작한다.

## 선택한 방법과 이유

- **대안 B + 새 필드**로 했다.
- 파이썬(`script_regenerate.unchanged_warnings`):
  - 다시 만들지 않은 **지금 있는** 블록마다 새 경고 목록을 `unchangedWarnings`에 담는다. 다시 만든 블록 · 없는 블록은 넣지 않는다.
  - 경고가 없는 블록도 빈 목록으로 넣는다. 옛 경고(이제 해당하지 않음)를 지우기 위해서다.
  - 검수가 돌지 못했으면(`REVIEW_FAILED`) 빈 객체를 보낸다. 옛 경고를 지우지 않고 둔다.
- 백엔드(`CaseScript.applyRegeneration` → `CaseScriptBlock.replaceWarnings`):
  - 결과에 있는 단위 중 다시 만들지 않았고 블록이 있는 것만, 그 블록 `review`의 경고를 새 값으로 바꾼다.
  - 오류는 그대로 둔다. 새 값에 오류가 섞여 와도 버린다.
  - 내용 · 판 · 승인 상태 · `publishable`은 바꾸지 않는다.
  - 모르는 단위 키는 버린다.
- 반영 전에 "요청한 뒤 블록 판이 바뀌었으면 거절"(A-13-17)이 이미 있다. 그래서 새 경고는 지금 블록 값을 검사한 결과임이 보장된다.

## 고려한 제약 사항

- 새로 생긴 **오류**는 이번에도 다시 만들지 않은 블록에 붙지 않는다. 사람이 고친 문장을 다시 검사하는 일은 BE-154(관리자가 고친 대본 문장 서버 재검사)가 다룬다. 블록 하나를 다시 검사하는 경로가 생기면 그쪽에서 오류까지 갱신하는 것이 맞다.
- A-13-16 미리보기 응답은 바꾸지 않았다. 다시 만들지 않은 블록의 경고는 반영한 뒤 블록 화면에서 보인다. 미리보기에 보이려면 프론트 변경이 필요해 범위 밖으로 뒀다.
- 공개 응답(API 18)에는 `review`를 싣지 않으므로 사용자 화면은 바뀌지 않는다.

## 추후 재검토가 필요하면

- BE-154에서 블록 단위 재검사가 생기면, 그 결과를 같은 방식(오류 · 경고 모두)으로 블록에 반영할지와 이 경고 갱신을 그쪽으로 합칠지 다시 본다.
- 관리자가 반영 전에 "다른 블록에 경고가 새로 생긴다"를 미리 알아야 한다는 요구가 생기면, A-13-16 미리보기에 `unchangedWarnings`를 싣는다.
