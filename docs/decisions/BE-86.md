# BE-86 의사결정 기록

## 문제 / 배경

COMMON-40(generate 모델 고정) 테스트를 하려면 Google genAI · Groq · NVIDIA NIM 등 여러 공급자의 키를 매번 `export`해야 해 번거롭다. `tools/ai-judgment/.gitignore`에는 이미 `.env`가 "API 키 파일" 용도로 올라가 있었지만, 실제로 `.env`를 읽는 코드는 없었다 — 지원을 전제만 해 두고 비워 둔 상태였다.

## 검토한 대안

### 1. `.env`를 어떻게 읽을 것인가

- **대안 A — `python-dotenv` 패키지를 쓴다.** 가장 적은 코드로 되지만, 이 폴더의 "설치 없이 실행" 원칙(`llm.py` 모듈 설명 1번째 줄, `urllib`만으로 HTTP를 직접 부르는 이유와 같다)을 깬다.
- **대안 B(선택) — 표준 라이브러리만으로 직접 파싱한다.** `KEY=VALUE` · 주석 · 따옴표 · `export ` 접두어 정도만 지원하면 되므로 코드량이 크지 않다.

### 2. `.env`를 어느 시점에 적용할 것인가

- **대안 A — 각 CLI 진입점의 `main()` 맨 앞에서 적용한다.** 명시적이라 읽기 쉽지만, `generate.py` · `pipeline.py` · `case-extractor/extract_case.py` · `case-extractor/court_draft.py` · `rag_store.py` 등 진입점이 여럿이고 앞으로도 늘어난다. 하나라도 빠뜨리면 그 도구만 `.env`를 못 읽는다.
- **대안 B — `llm.api_key()` 안에서 적용한다.** 실제로 키를 찾는 단 하나의 함수라 가장 좁은 지점처럼 보였다. 그런데 Claude 모델 경로(`case-extractor/extract_case.py`의 `call_claude`)는 `anthropic.Anthropic()` SDK가 `ANTHROPIC_API_KEY`를 **자기가 직접** `os.environ`에서 읽고, `extract_case.py`도 이 경로에서는 `llm.api_key()`를 일부러 부르지 않는다(`if provider != "claude": api_key(provider)`). 그래서 `api_key()`에만 넣으면 **가장 많이 쓰는 비식별화 기본 경로(Claude)가 빠진다.**
- **대안 C(선택) — `llm.py`를 불러오는 시점(모듈 최상위)에 한 번 적용한다.** 저장소의 모든 LLM 호출 경로(`generate.py` · `pipeline.py` · `case-extractor/*.py` · `rag_store.py` · 앞으로 추가될 도구까지)가 결국 `import llm`을 거친다. 모듈을 불러오는 순간 환경변수가 채워지므로, 그 뒤에 Claude SDK가 직접 읽든 `llm.api_key()`로 찾든 모두 같은 값을 본다.

## 선택한 방법과 이유

### 1. 표준 라이브러리로 직접 파싱 (대안 B)

새 모듈 `env_file.py`에 파싱 · 적용 로직을 모았다. `python-dotenv`가 주는 기능(변수 보간, 멀티라인 값 등) 중 이 프로젝트가 실제로 쓸 것은 `KEY=VALUE` · 주석 · 따옴표 벗기기 · `export ` 접두어뿐이라 과한 기능을 끌어오지 않았다.

### 2. `llm.py`를 불러오는 시점에 적용 (대안 C)

`llm.py` 맨 위에서 `env_file.ensure_loaded()`를 한 번 부른다. 이렇게 하면:

- **진입점을 하나하나 고칠 필요가 없다.** 지금 있는 도구는 물론, 앞으로 `import llm`(또는 `from llm import ...`)만 하면 자동으로 `.env`를 읽는다. 실제로 이번 작업에서 `generate.py` · `pipeline.py` · `case-extractor/*.py` · `rag_store.py` 중 어느 파일도 고치지 않았다.
- **Claude SDK 경로도 빠짐없이 덮는다.** `case-extractor/extract_case.py`는 `from llm import ...`로 `llm.py`를 먼저 불러온 뒤에 `call_claude()`를 실행하므로, `anthropic.Anthropic()`이 `os.environ`을 읽는 시점에는 이미 `.env` 값이 채워져 있다.
- 유일한 예외는 `llm.py`를 아예 거치지 않는 코드다. 지금 이 폴더에는 그런 LLM 호출 경로가 없다(확인: `grep`으로 `llm`을 불러오지 않으면서 `OPENAI_API_KEY` 등을 직접 읽는 곳이 없음을 확인했다).

### 3. 우선순위: 셸 환경변수 > `.env` 파일 > `tools/ai-judgment/.env` 안에서도 먼저 읽은 파일

`apply_env_files`는 **아직 설정되지 않은** 키만 채운다. 이미 설정된 값을 덮지 않는 이유는 `GROQ_API_KEY=... python3 generate.py ...`처럼 **한 번만 다른 키로 돌리는 흔한 패턴**을 막지 않기 위해서다. `.env` 파일을 쓰는 사람도 특정 실행만 다른 키로 덮어 쓸 수 있어야 한다.

같은 이유로 찾는 위치도 두 군데(`tools/ai-judgment/.env` → 저장소 루트 `.env`)를 **순서대로** 읽어 먼저 읽은 쪽이 이기게 했다. 도구 폴더만 떼어 쓰는 사람과 저장소 전체를 체크아웃해 쓰는 사람 모두를 맞추기 위해서다(`tools/ai-judgment/.gitignore` 주석 "이 폴더만 따로 쓸 때를 위해"와 같은 전제).

### 4. 값은 어디에도 남기지 않는다

`apply_env_files`가 남기는 안내는 **불러온 변수 이름만**이다(`.env에서 환경변수를 읽었습니다: GROQ_API_KEY, OPENAI_API_KEY`). `llm.py`의 기존 원칙("API 키는 환경변수로만 읽는다. 코드 · 출력 파일 · 오류 메시지에 키를 남기지 않는다")을 `.env` 경로에도 그대로 지켰다.

### 5. 파일 권한 경고

`.env`는 API 키를 담는 평문 파일이다. 다른 사용자도 읽을 수 있는 권한(그룹 · 전체 읽기)이면 경고한다. Windows는 `st_mode`로 ACL이 드러나지 않아 이 검사를 하지 않는다(과거 BE-34의 HTTPS 인증서 코드도 같은 이유로 플랫폼별 분기를 뒀다).

## 고려한 제약 사항

- **설치 없이 실행**: 표준 라이브러리(`os` · `stat` · `pathlib`)만 썼다.
- **기존 `api_key()` 동작을 바꾸지 않음**: `.env` 로딩은 `api_key()` 밖에서 끝나고, `api_key()` 자체는 `os.environ`만 본다는 계약을 그대로 유지했다. 기존 테스트가 전부 통과한다.
- **테스트 격리**: `importlib.reload(llm)`로 모듈 재적재를 테스트하면 `llm.LLMError` 등 클래스 객체가 새로 만들어져, 이미 `from llm import LLMError`로 가져다 쓴 다른 테스트 파일(`test_pipeline.py` · `test_model_compare.py`)의 예외 클래스 동일성이 깨진다(실제로 재현 확인함 — 테스트 실행 순서에 따라 멀쩡한 테스트가 무더기로 실패했다). 그래서 "`llm.py`를 불러오면 `.env`가 적용된다"는 보장은 별도 프로세스(`subprocess`)에서 검증해 현재 테스트 프로세스의 모듈 상태를 더럽히지 않게 했다.
- **DB 접속 값도 같은 통로를 쓴다**: `pipeline.py`의 `DB_URL` · `DB_USERNAME` · `DB_PASSWORD`도 `os.environ`에서 읽으므로 `.env`로 함께 줄 수 있다(코드 추가 없이 자동으로 됨). 다만 이 값은 파이프라인이 띄우는 자식 프로세스(`psql`)에도 전체 환경변수와 함께 전달되므로, `.env`에는 API 키 · DB 접속 정보만 두고 다른 비밀값을 섞지 않도록 README에 적었다.

## 추후 재검토가 필요하면

- 지금은 `.env` 파일 하나짜리 값만 지원한다(멀티라인 값 · 변수 참조(`${OTHER_VAR}`) 같은 `python-dotenv`의 확장 문법은 지원하지 않는다). 필요해지면 그때 추가한다.
- `tools/ai-judgment/.env.example`은 develop 기준 공급자(`openai` · `anthropic` · `gemini`)만 적었다. BE-84(Groq · NVIDIA NIM 공급자 추가)가 먼저 머지되면 `GROQ_API_KEY` · `NVIDIA_API_KEY` 항목을 이 파일에 추가해야 한다.
