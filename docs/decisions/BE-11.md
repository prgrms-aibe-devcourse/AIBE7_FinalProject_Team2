# BE-11 의사결정 기록

> MVP 단계(WBS 2.6) · PR #62 · 담당 백승호

## 문제 / 배경
- 사전 판단 · 최종 판결(USER/AI/COURT) · 매트릭스 · 공통점/차이점 규칙 문장을 한 번에 보여주는 세 판결 비교 API(API 14)를 구현해야 했다.
- API 명세가 매트릭스 분류 규칙 문장의 문장 틀과 사전→최종 방향이 "SAME"일 때의 요약 문구를 "구현 때 정한다"로 열어 두고 있어, 직접 정해야 했다.

## 검토한 대안
- **을/를 조사 판정 로직**: BE-10에서 만든 `UserSummarySentence`에 이미 비슷한 조사 판정 코드가 있었다. 이 이슈에서 또 필요해지면서, 중복 구현할지 공용화할지 검토했다.
- **문장 틀 결정 범위**: 명세가 열어 둔 문장 틀 전체를 리뷰에서 함께 정할지, 구현자가 먼저 정하고 리뷰로 조정할지 검토했다.

## 선택한 방법과 이유
- 을/를 조사 판정 로직은 `KoreanParticle` 공용 유틸로 추출해 `UserSummarySentence`와 공유했다. 같은 판정 로직이 두 곳에 따로 있으면 조사 규칙이 바뀔 때 한쪽만 고치는 실수가 생기기 쉽기 때문이다.
- 문장 틀과 "SAME" 요약 문구는 직접 정하고 PR에 "임의로 정했다"고 명시해 리뷰에서 조정 가능하도록 열어 두었다. 명세가 모든 경우의 문구를 미리 정의하기엔 조합이 많아 구현 시점에 결정하는 편이 현실적이었다.
- `ComparisonMatrix`/`MatrixRow`/`MatrixCategory`로 매트릭스 분류(ALL_SAME/ONLY_ME_MISSED/DIVERGED)를, `PreToFinalDirection`으로 사전 판단 구간 대비 최종 판결 방향(HEAVIER/SAME/LIGHTER)을 분리된 타입으로 두어, 각 분류 로직을 독립적으로 테스트할 수 있게 했다.

## 고려한 제약 사항
- FE-9(세 판결 비교 화면)가 이 API를 그대로 연동해야 하므로, 응답에서 `judgments`가 `{USER, AI, COURT}` 키를 가진 객체 형태라는 점을 프론트와 맞춰야 했다.
- ERD 6장 가상 살인 사건 예시 데이터 · API 명세 샘플 응답과 수치가 일치해야 했다 (단위 테스트로 검증).

## 리뷰 반영
- 규칙 문장에 요약어를 사용하도록, 응답 키 순서를 고정하도록, 조회를 1회로 합치도록 수정했다 (3936644).
