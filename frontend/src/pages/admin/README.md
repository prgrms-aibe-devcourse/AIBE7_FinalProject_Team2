# admin

**S-19 관리자 검수** 화면이다 (FE-16, WBS 7.5.7). 자동 적재한 사건(`DRAFT`) · 판결 후보(`PENDING`)를 검수해 공개하고(FE-16), 원본 판결문으로 사건을 등록한다(FE-45). API는 [API 명세 8장](../../../../docs/api-specification.md) A-1 ~ A-15.

| `adminListPage.js` | `/admin` 검수 사건 목록(A-5). 검수할 사건 · 공개 사건의 새 후보 · 공개한 사건 탭, 20건씩 |

## 원칙

- **사용자 화면과 분리한다.** 사용자 api(`src/api`)와 에러 이동(`app/errorRedirect.js`)을 쓰지 않는다. 관리자 코드 · CSS는 `/admin`으로 들어올 때만 불러온다(`routes.js` 동적 import).
- **내부 정보를 밖에 남기지 않는다.** 원본 판결문 · 생성 정보는 화면에만 그리고 브라우저 저장소에 넣지 않는다. 요청은 `cache: 'no-store'`. 목도 상태를 메모리에만 두고 로그인 여부만 `sessionStorage`에 둔다.
- 값은 모두 `textContent`로 넣는다(원문 · 모델 출력에 HTML이 섞여도 실행되지 않음).
- 상태를 바꾼 뒤에는 A-6을 다시 불러와 전체를 다시 그린다(사건 상태 · 공개 조건이 함께 바뀜). 다시 그린 뒤 누른 자리로 돌아가 포커스를 두고, 펼친 후보는 다시 펼친다(FE-105).
- 후보 승인은 그 후보의 "자세히 보기"를 한 번 연 뒤에만 된다(내용을 보지 않고 공개 판결로 정하지 않게, FE-105).
- 위험 작업 확인 기준 · 완료 알림줄(`ctx.notify`) · 포커스 규칙은 [DESIGN.md](../../../../DESIGN.md) "관리자 화면 규칙"을 따른다.
- **사진 · 지면 · 대본은 A-6에 없어 따로 불러온다**(A-13-5 · A-13-7 · A-13-10). 사건 상세를 그릴 때 한 번에 같이 불러 화면이 한 번만 깜빡이게 한다. 없는 것(`PAPER_NOT_FOUND` · `SCRIPT_NOT_FOUND`)은 null로 두고 그 부분만 비운다.
- **공개 사건은 사진 · 지면을 바꿀 수 없다**(A-11과 같은 규칙). 버튼을 숨기지 않고 잠근 뒤 이유를 적는다 — 왜 못 바꾸는지 모른 채 찾아 헤매지 않게.
- **신문 지면은 공개 조건이다**(BE-147, `NO_PAPER`). 다른 조건과 같이 `publishReadiness.reasons`로 공개 섹션에 나오고, 지면을 만들면 A-6을 다시 불러 사라진다. 지면이 있다는 것만 보므로, 내용은 "공개 전 확인" 네 번째 항목(제목 · 부제 · 본문이 사건 사실과 맞고 판결 · 형량을 암시하지 않는지)으로 관리자가 읽어 확인한다. 대표사진은 공개 조건이 아니다(없으면 사용자 화면이 공용 컷).
- **대본은 사건 공개를 막지 않는다.** A-6의 `script` 요약(`exists` · `reviewStatus` · `publishable` · `scriptStatus`)을 읽어 공개 준비 화면에 경고로만 보여 준다. `publishReadiness.reasons`에는 들어가지 않는다(BE-108 결정). 공개한 사건의 대본이 점검 중이면 맨 위 공개 영역에 알린다.
- **대본 블록은 모양을 따로 알지 않고 그린다**(FE-148). 블록 값의 문자열 자리를 JSON Pointer로 꺼내 한 자리씩 보이고 고친다 — 검수 결과 `path`와 같은 자리라 오류가 그 문장 밑에 붙는다. 블록 모양이 바뀌어도 화면을 고치지 않는다.
- **공개 중 대본을 고치기 전에는 묻는다**(FE-148, BE-126 2차-2). 사용자에게 나간 대본(`releasedAt`)이 공개 중(`READY`)일 때 블록 반려 · 문장 수정 · 대사 수정 · 통거절은 다시 승인할 때까지 대본을 점검 중으로 만든다(사용자 체험이 잠김). 서버는 막지 않아 화면이 확인을 받는다. 이미 점검 중이거나 나간 적 없는 대본은 묻지 않는다.
- **길이 규칙은 말하는 대사 자리에만**(BE-153). 100자 · 2줄은 U1 해설 · U2 공소 · 입장 · 쟁점 해설 · 신문 질문 · U4 의견 · U3 대사에만 걸고, 설계도 · 카드 · 신문 답은 500자까지다. 자리 목록(`SPOKEN_PATHS`)은 계약 파일 `spokenPaths`와 같은지 테스트가 본다.
- **고친 문장은 다시 검사하지 않는다**(BE-154 전까지). 고치기 폼이 금지어 · 형량 표현 · 말투를 직접 확인하라고 안내한다.
- **블록 승인 버튼은 서버와 같은 조건으로 잠근다**(A-13-18): 대본 조건(멈춤 · 만들지 못한 것 · 대본 전체 검수 오류) → 블록 오류 → 승인을 막는 낡음. 낡음은 "확인했음"으로 풀 수 있다(새로 생긴 민감 플래그는 서버가 409로 막는다).
- **대사 수정은 `stopped`를 먼저 본다.** 호출 한도로 멈춘 대본은 빠진 줄 자체가 없어 고쳐도 승인할 수 없다 — 그때는 "다시 생성"으로 안내한다.
- 사건 등록(FE-45)은 파이프라인을 서버가 실행하는 방식이다. 판단 요소 구성 · 형벌 규칙은 여전히 파이프라인 · SQL 경로이고 이 화면은 검수 · 수정 · 공개 · 등록 시작만 한다.
- 요약어 후보는 **제안만** 보여 준다. 요약어 수정 API가 없어서 바꾸는 버튼은 없다.

## 목으로 확인

`npm run dev` → `http://localhost:5173/admin`. 아무 이메일 · 비밀번호로 로그인된다(비밀번호 `wrong`이면 실패). 사건 등록은 `/admin/register`(목록의 "+ 사건 등록")에서 해 볼 수 있고, 원문에 `[실패]`를 넣으면 실패 화면을 볼 수 있다. "예시 PDF 내려받기"로 받은 PDF를 다시 넣으면 원문과 항목이 자동으로 채워진다. 사건 #12(적재됨) · #13(공개됨, 새 AI 후보 1건)이 있고, 새로고침하면 처음 상태로 돌아간다.

## 실제 API

A-1 ~ A-13은 BE-39 · BE-41 ~ BE-43으로 구현돼 있다. `VITE_API_MODE=real`로 연결해 확인한다. **A-14 · A-15(사건 등록)와 A-16 ~ A-41(운영 메뉴)은 초안 계약이라 서버 구현 전에는 목으로만 동작한다.** 서버를 만드는 쪽은 [API 명세 8-4](../../../../docs/api-specification.md)를 기준으로 한다.
