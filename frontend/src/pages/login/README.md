# login

**S-12 로그인** 화면 틀이다 (FE-52, IA 4장 `/login`).

| 파일 | 내용 |
| --- | --- |
| `loginPage.js` | `renderLoginPage(container, { api, navigate })` — 화면을 그린다 |
| `login.css` | 로그인 화면 스타일 |

## 구성

- 공통 헤더 → 가운데 카드: 제목 · "로그인하지 않아도 모든 판결 체험을 할 수 있어요"(REQ-003) · 카카오 로그인 버튼 · 또는 · 아이디 · 비밀번호 폼 · 회원가입(준비 중).
- **사용자 로그인 API가 아직 없다**(카카오 로그인 검토 중). 목 모드에서는 개발용 목업 로그인(`mocks/authMockApi.js`)이 받아 어떤 값이든 로그인되고, 카드에 "개발용 목업 로그인" 안내가 붙는다. 실제 모드에는 `api.login`이 없어 누르면 "준비 중" 안내만 나온다.
- 로그인하면 닉네임을 `utils/session.js`에 두고 메인으로 간다(로그인 화면은 기록에서 바꿔치기해 뒤로 가기로 돌아오지 않는다). 공통 헤더의 "로그인" 자리에 닉네임이 나오고, 누르면 마이페이지(S-17)로 간다. 닉네임이 길면 줄여 보인다.
- 이미 로그인한 채로 `/login`에 오면 누구로 로그인했는지와 마이페이지 · 로그아웃을 보여 준다. 로그아웃은 마이페이지 맨 아래에도 있다.
- 빈칸으로 제출하면 오류 문구(`role="alert"`)를 보여 주고 첫 빈칸으로 포커스를 옮긴다(`aria-invalid`). 카카오 버튼은 카카오 디자인 가이드 색(`--color-kakao`)을 쓴다.
- 실제 로그인이 생기면: `realApi.js`에 같은 이름의 `login({ method, id, password })` · `logout()`을 붙이고 응답 `{ nickname }`을 맞춘다. 카카오는 리다이렉트 방식이 될 가능성이 커서 그때 버튼 동작을 바꾼다.
