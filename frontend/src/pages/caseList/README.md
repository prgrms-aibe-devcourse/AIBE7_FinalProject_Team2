# caseList

**S-02 사건 목록** 화면이다.

| 파일 | 내용 |
| --- | --- |
| `caseListPage.js` | `renderCaseListPage(container, { api, navigate, from })` — 목록을 그리고, 고른 기사를 사건 정보(S-20)로 펼친다 |
| `caseList.css` | 사건 목록 화면 스타일 |

## 사용하는 API

`api` 객체로 주입받는다. (지금은 [`mocks/`](../../mocks/README.md)의 목 구현)

| 호출 | API | 동작 |
| --- | --- | --- |
| `api.getCases(crimeType)` | API 1 `GET /cases` | 사건 목록. 범죄 유형 탭(`MURDER` · `FRAUD` · `INJURY` · `ROBBERY` · `THEFT`)으로 필터 |

- **기사 고르기 (FE-32, 흐름 목업 ②)**: 책상(S-01)에서 집어 든 신문이다. 지면 오른쪽 위에 남불의 안내(오늘 지면의 사건 수)를 적은 정사각형 포스트잇이 붙어 있고(FE-56에서 왼쪽 → 오른쪽), 누르면 떼어져 날아간다(FE-50, 포커스는 첫 탭으로). "신문 내려놓기" 버튼은 없앴다(FE-50) — 책상으로는 정보 줄 왼쪽의 "← 메인으로"와 Esc로 간다(FE-56: "처음으로" · "서비스 소개"는 뺐다). 위에는 모든 화면과 같은 공통 헤더가 붙는다(라우터). 기사(머리기사 제목 · 사진 · 머리기사 단 · 추천 · 다른 사건)를 누르면 그 기사의 제목이 S-20 사건 정보의 큰 제목 자리로 커지며 날아간다(FE-118, `utils/articleZoom.js` — 지금 지면을 본뜬 한 장을 띄워 두고 `navigate('caseDetail', { caseId, from: 'paper' })`, S-20이 제목을 받는다). 머리기사 단 · 사진을 누르면 머리기사 배너 제목이 날아간다. 움직임 줄이기면 연출 없이 바로 간다. 키보드 · 화면 낭독기는 기사 안의 "사건 펼쳐 보기" 버튼으로 고른다. **체험 시작 · 이어서 하기는 S-20에서 한다**(API 명세 5장 S-02 확장). Esc는 책상으로.
- **면 넘기기 (FE-118)**: 유형 탭 하나가 신문 한 면이다(전체 = 1면 → 살인 · 사기 · 상해 · 강도 · 절도). 탭 말고도 지면 아래 양 모서리의 종이 귀(`components/folderParts.js` `paperFold`, 오른쪽 "사기면 →" · 왼쪽 "← 1면"), 화면 양옆 화살표(넓은 화면, 마우스용이라 낭독기 · 탭 순서에서는 뺀다), 키보드 ← →(글자 칸 · 수정 키 제외), 손가락 밀기(`utils/newspaperFaces.js` `swipeStep`)로 넘긴다. 뒤 면으로는 한 장이 오른쪽에서 왼쪽으로 넘어가고, 앞 면으로는 거꾸로 앞 면이 왼쪽에서 넘어와 덮는다(`pageTurn.js` `back`). 귀 · 화살표 · 키보드 · 밀기로 넘기면 새 면은 맨 위부터 보이고, 키보드로 귀를 눌렀으면 포커스는 새 면의 탭으로 간다. 기사를 누르는 것은 언제나 사건 정보로 가는 길이고 넘김은 이 조작으로만 한다. 면은 지금처럼 주소 `?type=`에 남는다(replaceState — 면마다 방문 기록을 쌓지 않는다).
- **빈 칸 채움 (FE-118)**: 기사가 모자라 비는 칸을 사건이 아닌 작은 지면으로 채운다. 추천 사건이 한 건뿐이면 비는 반쪽에 세 개를 세로로, "이번 호 다른 사건" 마지막 줄의 빈 칸(넓은 화면 6칸 기준 `emptySlots`, 태블릿 3칸 · 모바일 2칸에서 남는 뒤쪽 칸은 CSS가 숨긴다), 다른 사건이 아예 없는 면은 아래에 세 칸 한 줄. 내용은 법정 상식(1막 막간과 같은 `content/courtFacts.json`)과 판결 성향 테스트 광고(누르면 `/test`)이고, 둘 이상이면 맨 앞 하나가 광고다. 눌러도 사건으로 가지 않는다.
- 책상에서 왔으면(`from: 'desk'`) 메인 책상에서는 지면이 화면 아래에서 올라오고 뒤에 남긴 책상이 흐려진다(FE-50, `.is-rising` · `.paper-ghost`). 올라오는 도중 기사가 채워져 끊기지 않게, 사건 목록을 그리고 첫 사진들을 디코딩할 때까지(최대 1.2초) 지면은 아래에 멈춰 두었다가 한 번에 올린다(`.is-going`). 좁은 화면 메뉴 · 비교 화면에서 왔으면 지면이 한 번 다가오며 나타난다(`.is-arriving`). 메인 맨 아래 신문 끝자락에서 왔으면(`from: 'tail'`, FE-87) 같은 방식으로 메인을 뒤에 남겨 두고, 메인이 본떠 넘긴 끝자락이 곧바로 위로 잡아당겨지며 커지고, 들어 올린 뒤 그 밑에서 같은 자리 · 같은 폭 · 같은 기울기로 함께 움직이던 이 지면으로 넘어가 제자리로 온다(`.is-spreading`, `spread` → `utils/tailSpread.js`). 넘어가기 직전까지 다 그려지지 않았으면 그 자리에서 기다린다. 새로고침 · 뒤로 가기로는 되풀이하지 않는다. 움직임 줄이기면 연출 없이 바로 바뀐다.
- **FE-102 (critique 반영)**: 사건 순서는 지금 체험할 수 있는 사건이 먼저, 그다음 참여 많은 순이다(머리기사 · 추천 칸에 "준비 중"이 앞서지 않게). 포스트잇 문구는 체험 가능한 사건 수에 맞춘다. 고른 유형 탭은 주소 `?type=`에 남고(replaceState), 탭에는 건수 글자가 붙고 요약은 고른 면에 맞춰 바뀌며, 탭을 눌러도 포커스가 새로 그린 같은 탭에 남는다. 목록을 받기 전 · 오류에서도 탭 줄을 그대로 둔다(로딩 중에는 누를 수 없고, 아래 푸터 · 안내는 감춰 CLS를 없앴다). 포스트잇은 떼기 전에는 오른쪽 귀를 감추고, 같은 사건의 제목 · 사진 · 기사 단은 호버를 함께 보인다.
- **진행 상태 배지 (FE-19, REQ-010 · FR-1-6)**: API 1의 `myStatus`로 분류명 줄 오른쪽에 배지를 단다. `null`(체험 전)이면 배지 없음, `IN_PROGRESS`면 "진행 중", `COMPLETED`면 "완료". 세부 상태(7단계)는 목록에 보이지 않는다.
- 신문 1면 구성(FE-18, 시안 v12): 참여 많은 순으로 첫 사건이 머리기사(배너 제목 · 메인 사진 · 오른쪽 머리기사 단), 다음 2건이 추천 사건, 나머지는 "이번 호 다른 사건" 띠로 간다. 사건 수가 적거나 유형 탭으로 거르면 있는 만큼만 그린다.
- **공개 범위**: 목록은 처음 판단(S-03) 전 화면이라 사건 정보는 제목 · `shortIntro` · `keywords` · `crimeCategoryLabel` · `participantCount`만 쓴다. 상세 사실 · 판단 요소 · 양측 주장 · 형량은 쓰지 않는다. 머리기사 안내 글과 추천 사건의 [알아두기]는 사건과 무관한 고정 문구(`LEAD_GUIDE` · `TYPE_NOTES`).
- 기사 제목 · 부제 · 본문은 `headline` · `deck` · `article`(문자열 배열)을 쓴다. **API 1에 아직 없는 제안 필드**라 지금은 목 데이터에만 있고, 값이 없으면 사건 제목 · `shortIntro`와 고정 문구로 채운다. 본문은 S-03 사건 개요 수준의 사실만 쓴다.
- 이미지가 없으면(`thumbnailUrl`이 `null`) 유형별 연출 이미지(`public/images/case-*.svg`)를 쓴다. 난이도 · 예상 시간은 표시하지 않는다.
- 공통 헤더 대신 신문 제호를 그리고, 법적 고지는 공통 푸터([`components/siteLayout.js`](../../components/siteLayout.js))를 지면 맨 아래에 붙인다.
- 요청 · 응답 형식은 [API 명세서](../../../../docs/api-specification.md) API 1을 따른다.
