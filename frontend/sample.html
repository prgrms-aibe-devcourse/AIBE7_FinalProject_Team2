화면 이동 · API 연결 · 에러 처리를 눌러 보며 확인하는 페이지입니다. 지금 API 모드:

0. 기준 사건

아래 링크와 API 호출에 쓸 사건이에요. 사건 목록(API 1)에서 불러와요. 실제 백엔드의 사건 ID는 시드 적재 순서에 따라 1이 아닐 수 있어요.

목 모드에서는 사건 1번만 S-03 이후 화면과 연결돼요. 나머지 사건은 사건 목록 · 체험 시작까지만 동작해요.

1. 앱 실행과 API 모드

cd frontend
npm install
npm run dev                         # 목 데이터로 동작 (기본, 백엔드 필요 없음)
VITE_API_MODE=real npm run dev      # 실제 백엔드로 요청 (백엔드를 8080에서 먼저 실행)
  • .env.example을 복사해 .env.local로 두면 VITE_API_MODE를 파일로 정할 수 있어요 (.env.local은 커밋하지 않아요).
  • 실제 모드에서 개발 서버는 /api 요청을 localhost:8080으로 넘겨요. 같은 주소로 요청하니 CORS 설정이 필요 없고, 익명 ID 쿠키(NLNB_AID)도 그대로 붙어요.

4. 에러 코드와 화면 이동

화면이 API를 부를 때 src/app/errorRedirect.js가 에러를 보고 맞는 화면으로 보내요 (API 명세 1-5 · 1-6). 이동은 replace라서 뒤로 가기를 눌러도 같은 에러로 되돌아오지 않아요.

에러 코드언제이동
INVALID_STATE지금 체험 단계에서 할 수 없는 요청에러의 currentStatus에 맞는 화면 (아래 표)
EXPERIENCE_NOT_FOUND체험을 시작한 적이 없거나 쿠키가 없음사건 목록 (S-02)
CASE_NOT_FOUND없는 사건 · 비공개 사건404 · 오류 화면 (S-14). 단, 목록의 startExperience는 화면이 직접 안내해요
그 밖의 코드VALIDATION_ERROR, OUT_OF_ALLOWED_RANGE 등이동하지 않아요. 화면이 코드별로 안내해요

5. 사건 제목은 어디서 와요?

S-04 이후 화면의 API에는 사건 제목이 없어서(정합성 점검 D-01 미결정), 사건 목록 응답(API 1)에서 caseId로 찾아 상단 바에 넣어요. 새로고침해도 목록을 다시 불러 채워요. src/app/caseHeader.js 한 곳만 바꾸면 되니, API가 제목을 주도록 정해지면 그때 교체해요.
